# 位置环调试与使用说明

2026-10-29 新增：[客户位置指令幅相测试模式](客户位置指令幅相测试说明.md)。`test_mode=2` 逐帧执行 Excel 的300 Hz/1～15 Hz指令；`test_mode=1` 复现 Word 的40点/1～30 Hz流程，都是0→2→0°。下文 R17 实测与配方仍为历史已验证依据。新编译固件尚未烧录，capture 已改为复用 union，地址必须由对应 ELF 解析；原有轨迹使用 `test_mode=0`。

作者：Codex。更新：2026-10-29。适用：STM32G431 伺服主控、MT6701 电机反馈、MPT T485 输出轴反馈，当前 R17 固件。源码入口见[架构说明](架构说明.md)，原始过程见[位置环实机调试日志](log/2026-10-29_位置环续调与反馈链路检查.md)。

## 1. 当前能做到什么

位置环输出电机速度指令，复用速度环和电流环。位置误差按输出轴度数计算，减速比为202。**位置/MPT的1 ms是任务调度周期，不能理解为闭环带宽1 kHz。**

| 项目 | 当前值或已测结果 |
| --- | --- |
| 固件默认位置参数 | Kp=72 /s、最大电机转速5500 rpm、死区0.0055° |
| 普通目标和阶跃加速度 | 300000 rpm/s；与用户速度模式的9000 rpm/s默认值不同 |
| 有限正弦试验 | 显式选择7500 rpm，运行期间使用1200000 rpm/s；结束后恢复普通斜坡 |
| 轨迹速度前馈 | `feedforward_gain=0.6`；测纯反馈带宽必须显式设为0 |
| 位置/MPT查询 | 配置1 ms，主循环执行；本次实测约1 kHz，受后台任务影响 |
| 带盘、±2°纯反馈带宽 | 最佳工作点约18.5 Hz；其他已测起点约15～18 Hz，尚未全角度稳定20 Hz |
| R17带盘+2°阶跃 | 10%～90%上升20 ms、2%整定55 ms、超调1.35%、末端误差约0.0032° |
| 同次使能FF=0.6对比 | 10 Hz稳态trace RMS误差1.215°→0.616°；14 Hz为1.490°→0.838° |

上午空载、下午增加惯量盘，不能跨这两批数据比较增益优劣。最佳18.5 Hz由18.5/18.6 Hz有效测点夹住；R17重启后换了起点，稀疏测点插值约17.6 Hz，不是最佳值的精确复现。没有将前馈跟踪结果当作纯反馈带宽，也没有把未完成或限幅点当作带宽证据。

电流策略仍为`CURRENT_LIMIT_HARDWARE_ONLY=1`、`FLT_MAX`，软件电流幅值限幅/跳闸及I²t约束关闭。本文命令中的15 A峰值、5 A最大相RMS是**主机试验停止条件**，依赖主机成功读取并下发停止；不能替代硬件OCP，也不代表长时间连续热稳态已经验收。

## 2. 用Watch操作普通位置模式

默认上电会加载有效电机零点；无有效记录时尝试有限对齐，随后进入位置保持。上一次停机不意味着复位或重新上电后仍停机。启动详情见[架构说明](架构说明.md)。

1. 写`g_user_control.enable=0`，等待`status.state=0`，并确认实际PWM已关闭。
2. 设置`g_user_control.mode=5`，设置`g_user_control.position.target_deg`。首次验证建议先设0。
3. 如需修改位置Kp、最大转速或死区，在输出关闭且重新使能**之前**设置`g_output_position.kp_per_s`、`max_motor_rpm`、`deadband_deg`。这三个控制参数在位置arm时锁存，不能靠运行中改显示字段验证新参数。
4. 写`g_user_control.enable=1`，等待`status.state=2`、`status.active_mode=5`且`status.fault=0`。
5. 修改`g_user_control.position.target_deg`为`2.0`，即相对此次使能零点到达+2°；之后改为0返回零点，改为−2到达−2°。普通目标按给定值变化，不自动生成正弦或往复轨迹。
6. 停机写`g_user_control.enable=0`，再读回状态和PWM；这是撤去输出请求，不是减速停车或机械锁止。

`target_deg`是**本次位置使能会话内的绝对目标**：720表示正向两圈，随后180表示回到半圈位置，不是再转180°；重新使能会重建零点。不要把这个目标当作MPT的绝对单圈角度。累计会话位置不做断电保存。

普通使用只操作统一用户入口，不同时写旧的`g_speed_run.enable`或`g_output_position.command`。下述开发脚本会协调内部接口，不能再由Watch或另一个程序并行发运动命令。

## 3. 复现有限扫频和阶跃

### 环境与前置检查

在仓库根目录运行PowerShell。使用Python及NumPy，绘图另需Matplotlib；脚本使用已配置的CMSIS Debugger扩展中的pyOCD/GDB和Keil STM32G4xx DFP包，路径见[测量脚本](../control_analysis/scripts/measure_position_response.py)及其基类。不是独立的串口上位机。

本次确认的探针为J-Link **150710982**，目标为STM32G431伺服主控板。以连接的板卡和匹配AXF为准，不能从Keil当前打开的其他项目推断板卡身份。脚本会从指定AXF解析地址/ABI，先完整比较Flash装载镜像，再检查输出、标定和反馈；不匹配或已有故障时拒绝启动，不自动清故障或烧录。

**固件默认Kp=72，而当前脚本的`--kp`默认仍为80。** 两者不是同一个参数来源；脚本默认最大转速5500 rpm，两个主机电流停止门槛默认均为0（关闭）。下面所有运动命令都显式写出72、转速和停止条件，不能省略后按R17结果解释。

先仅做只读检查；该命令不主动停掉已经运行的电机，前置要求仍是输出关闭：

```powershell
python software/control_analysis/scripts/measure_position_response.py tmp/position_check_01 --axf software/control_analysis/results/position_tuning_20261029/flash_r17/firmware.axf --probe 150710982 --swd-frequency 50000
```

查看生成的`before.json`、`rate_off.json`和`preflight_*.bin/.log`：镜像匹配，MOE关闭，标定有效，MPT有效且无错误。读取率用两次`requests`差值除以MCU时间差，本次实测约1 kHz；响应延迟看`latency_last_us/max_us`，**2 ms是超时门槛，不是实际读取延迟**。

所有输出目录必须是不存在的新目录；以下带`--run`命令会实际启动电机。此次文档整理只核对命令与脚本接口，没有再次执行这些运动命令。

### ±2°纯反馈扫频

```powershell
python software/control_analysis/scripts/measure_position_response.py tmp/position_frd_01 --axf software/control_analysis/results/position_tuning_20261029/flash_r17/firmware.axf --probe 150710982 --run --kp 72 --amplitude 2 --frequencies 14,16,17,18,18.5 --feedforward 0 --max-motor-rpm 7500 --duration 6 --max-phase-peak 15 --max-phase-rms 5 --swd-frequency 50000
```

这是逐频正弦，不是连续chirp。每点6秒包含两端包络；稳定窗口排除至少0.5秒、至少2周期的起振/退振包络，须累计至少20个稳定周期。不要把6秒缩短后仍默认相同有效性。7500 rpm是有限试验显式选项，普通位置默认仍为5500 rpm；8500 rpm是当前位置软件允许的配置上限，不是已验收运行转速。

### 同起点前馈对比

```powershell
python software/control_analysis/scripts/measure_position_response.py tmp/position_ff_pair_01 --axf software/control_analysis/results/position_tuning_20261029/flash_r17/firmware.axf --probe 150710982 --run --kp 72 --amplitude 2 --frequencies 10,14 --feedforward 0.6 --compare-feedforward --max-motor-rpm 7500 --duration 6 --max-phase-peak 15 --max-phase-rms 5 --swd-frequency 50000
```

每个频率先FF=0，再FF=0.6，全部在同一次arm内完成。`trace_10_ff0.bin`与`trace_10_ff0.6.bin`分开保存，避免覆盖。相同负载、起点和增益下比较误差，不把两种FF混成一条传递函数。

### +2°有限阶跃

```powershell
python software/control_analysis/scripts/measure_position_response.py tmp/position_step_01 --axf software/control_analysis/results/position_tuning_20261029/flash_r17/firmware.axf --probe 150710982 --run --kp 72 --step 2 --max-motor-rpm 5500 --max-phase-peak 15 --max-phase-rms 5 --swd-frequency 50000
```

脚本强制阶跃FF=0，包含约50 ms预触发记录，使用普通300000 rpm/s斜坡。阶跃结束回到会话起点；其超调和整定不能由正弦扫频结果替代。

## 4. 读结果与生成图

| 文件/字段 | 解释 |
| --- | --- |
| `summary.json` | 实际参数、已完成测点、错误与最终停机检查；异常退出也要保留 |
| `symbols.json` | 指定AXF中的地址及结构体/数组长度，不能用旧地址代替 |
| `*_position/mpt/trajectory/frd.bin` | 原始内存读回，用于追查解析及传输问题 |
| `trace_*.bin/.csv` | 稳态位置波形；配对模式文件名含FF，使用测点的`trace_file`定位 |
| `firmware_frd` | 固件长窗口增益、相位、Welch相干性、周期数、分段数及有效性 |
| `steady_tracking_rms_deg` | 稳态trace内的实际目标－反馈RMS误差，包含相位跟踪误差 |
| `rms_error_deg` | 全轨迹统计，包含包络；不与另一窗口RMS直接混比 |
| `residual_rms_deg` | 反馈对正弦拟合的残差，不是跟踪RMS误差 |
| `phase_rms_a`、`current_samples` | 20 kHz三相平方和除以实际样本数再开方，正弦只积累稳态窗口 |

有效频点须完成轨迹、`linear_valid=true`、FRD `valid=1/reject=0`、`coherence≥0.9`、`segments≥2`、稳定周期≥20，速度和斜率限制计数均0，并核对幅值/频率与本次请求一致。高相干性不单独证明所有非线性效应都不存在。`coherence_bin`是单bin留证值，恒接近1，不能用它验收。

拒绝码：1无样本，2速度**或斜率**限制，3参考能量/数值退化，4周期不足，5相干性不足，7幅值退化，8分段不足；6已经退役，正相位本身不构成非因果。以实际固件为准，不按历史头文件注释中的32字节结果或旧周期直接解码。

只用同负载、同增益、同FF、相近起点的相邻有效测点夹住−3 dB交点。未夹住时只能报告已测频点/界限；不能跨无效点插值，也不能拼接不同工作点。本次18.5 Hz最佳值的严格来源见[校验JSON](../control_analysis/results/position_tuning_20261029/loaded_bandwidth_verified.json)。

R17参考ABI：MPT 108字节、位置56字节、轨迹84字节、FRD 40字节、trace 64行×16字节=1024字节。实际读取仍以AXF解析的大小为准；例如不能按历史100/101行读当前数组。旧`commission_mpt_position.py`是legacy路径，不作为本页高频扫频入口。

## 5. 停机和故障排查

脚本arm时设置并读回10秒主机失联超时；测试中更新心跳。有限轨迹结束后仍可能保持位置并使能PWM，脚本还要在`finally`请求停机，再检查硬件和故障。失联保护需要MCU正常执行，不能代替实时停机读回；重启也会重建启动流程。

正常停机应读到：`g_user_control.enable=0`，`g_user_control.status.state=0`，`g_output_position.state=0`，以及TIM1 BDTR（`0x40012C44`）的MOE位`0x8000`清零。故障停机可能保留位置故障态2；是否已撤去PWM仍以MOE读回为准，不通过清故障凑成状态0。无故障的干净停机还要求runtime/FOC故障为0。本次最终BDTR为`0x02002054`；判断标准是MOE位，不要求整个寄存器永远等于该数。

| 现象 | 操作与判读 |
| --- | --- |
| Flash/ABI不匹配 | 停止实验，使用与板上镜像一致的AXF；不要按旧地址写控制RAM |
| 读回失败、J-Link消失 | 当前PWM状态是未知，不能把“读不到”解释为关闭；先处理主功率和连接，再只读确认。不要在PWM状态未知时盲目复位或烧录 |
| MT6701持续`FF FF FF`、有效帧为0 | 检查电机反馈供电、线缆、有效性及错误计数；MPT正常不代表电机换相反馈正常 |
| 峰值/RMS主机停止 | 保留实际样本、阈值和未完成点，不当成MCU硬件过流或有效带宽；门槛不因追求20 Hz而自动提高 |
| `FOC_FAULT_PWM_WRITE=0x40` | 读首故障`g_tim1_pwm_commit_fault`、采样窗口/截止拒绝计数；本次R14/R15曾为截止不足，不是硬件过流。R16已将快速ADC路径统计移到PWM提交之后，原2 µs门槛保留 |
| `cleanup_error` | 分别看`final_bdtr.bin`、runtime/FOC故障及日志；MOE已关但故障仍锁存也会使检查抛异常，不能笼统称“未停机” |
| `.rejected.bin`或`rejected_*` | 保留原始读回。当前脚本对参考正弦一致性异常只复读一次；不通过时停止，不靠改相位符号/手修trace生成有效结果 |

`enable=0→1`不会清掉底层锁存故障。先确认输出关闭并保存故障现场，再按已定位原因处理；不要直接覆盖故障标志继续扫频。
