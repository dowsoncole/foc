# 全系统上位机读写参数表

版本：公开参数字典草案V1，2026-10-22。适用于[串口PC通讯方案](2026-10-22_串口PC通讯实施方案_规划记录.md)、[整定](2026-10-22_闭环整定模块实施方案_规划记录.md)、[保护](2026-10-22_故障保护模块实施方案_规划记录.md)和[系统性能评估](2026-10-22_系统性能评估实施方案_规划记录.md)。本轮只写文档，没有实现协议或新增固件字段。

## 1 范围与阅读方式

本文定义全系统对上位机开放的逻辑参数、状态、结果对象和动作接口。当前代码主要依靠调试器Watch与单向波形输出，**没有实现这张表的通用读写协议**。表中的“已有”只表示源码存在可映射的含义，不表示PC现在能按该ID访问。

本版列出13个参数域、473项逻辑参数和44项动作。它是完整公开接口规划，首版实现应按能力逐步开放；不要求一次把全部功能编译进当前已接近满载的RAM，也不为每一项重复保存一份值。

参数ID是稳定的16位逻辑编号，不是RAM地址、结构体偏移或Modbus寄存器地址。`axis_id`作为独立字段；设备级项使用0xFFFF，轴级项首版使用0。不同硬件/功能通过能力位与描述符发现，未实现返回UNSUPPORTED，不能返回伪造的0。

覆盖正式运行、板级信息、电机/传动、两编码器、电流采样、各控制环、整定、保护、通信、评估、诊断与受限调试。内部HAL句柄、函数指针、DMA缓冲、积分器写入、MOE/CCR直写和保护旁路不开放。原始数据与故障历史通过分页对象读取，避免把数组当成一段可任意读写的内存。

来源标记：`E`=已有源码字段/常量；`A`=由已有数据适配或换算；`N`=新增能力。复合来源表示部分已有。每个分组的“映射来源”给出证据路径；默认/约束列的“现”指代码值，“建议”指未来初始化建议，“待标定”不能用于运行。

## 2 类型、权限、生效与持久化

### 2.1 线上类型

| 记号 | 编码 | 规则 |
|---|---|---|
| U8/I8/U16/I16/U32/I32/U64/I64 | 固定宽度整数，小端 | 超范围拒绝，不截断 |
| B | U8布尔，0/1 | 其他值拒绝 |
| E16 | U16枚举 | 描述符列合法值与含义；未知值拒绝写入 |
| M32/M64 | U32/U64位集 | 保留位必须为0；快照保证64位无撕裂 |
| F32 | IEEE754 binary32，小端 | 写入必须有限；额外范围按描述符校验 |
| TEXT | UTF-8长度限定字节串 | 不含隐式C终止符；最大长度在描述符声明 |
| HASH | 固定32 B SHA-256 | 用于版本/实验数据追溯，不等于身份认证 |
| OBJ | 版本化只读记录对象 | 用对象ID/偏移/长度/CRC分块，不裸传C结构体 |
| U8V/U16V | 有界U8/U16数组 | 元素数与长度显式编码，配置动作整体提交；不做任意内存块写入 |

参数表中F32单位为SI，特别声明的rpm、µs、ms、ns、deg和ADC累加码除外。位置正式目标/反馈使用I64的nrad（10⁻⁹ rad）或编码器计数；局部误差用F32 rad。I64只负责传输/存储，实时算法可先整数相减再转局部浮点；nrad分辨率不代表传感器实际精度。

V1的type_id固定为：1 U8、2 I8、3 U16、4 I16、5 U32、6 I32、7 U64、8 I64、9 F32、10 B、11 E16、12 M32、13 M64、14 TEXT、15 HASH、16 OBJ、17 U8V、18 U16V。unit_id由同版本单位字典返回，必须区分A峰值/A RMS、motor rad/load rad、电角rad、pu和ADC累加码；仅有相同数值类型不允许互换。

### 2.2 访问类别

| 类别 | 读写与允许状态 | 生效 | 持久化 |
|---|---|---|---|
| F | 固件/硬件描述只读 | 编译/初始化确定 | 随固件或工厂信息 |
| R | 状态/测量只读 | 读取快照 | 不自动写Flash |
| K | 标定结果只读 | 专用标定/导入命令成功后发布 | 经验证后显式保存标定集 |
| P | 可读写配置；仅停止、MOE=0、无活动实验，部分需维护模式 | 写入pending，事务验证后原子提交active | COMMIT只到RAM；SAVE_PROFILE成功才持久化 |
| L | 可读运行请求；仅通过SET_TARGET完整命令写 | 当前租约有效，指定控制周期边界接受 | RAM；设备上电/新控制会话时清除，不因SERVO_START清除刚接受目标 |
| X | 实验/评估配置可读写；对应模块IDLE | 一组配置校验后冻结到会话 | RAM；可另存PC方案，不自动Flash |
| T | 通讯/遥测服务配置可读写 | 完整配置在后台边界生效 | 首版会话RAM，不自动Flash |

F不表示硬件永远不能改，而是本版不提供在线重配。R/K禁止通用WRITE，不能靠写结果值绕过标定或评价。P不是裸写active字段；任何配置、目标和标定变化应更新版本，令受影响的整定/评估结论失效。保存参数不保存running、MOE、租约、实验状态、故障复位请求或瞬时积分值。

配置读取指定视图ACTIVE/PENDING/FACTORY/SAVED，默认ACTIVE；PENDING必须带transaction_id。不支持的视图明确拒绝。同一ID只有一个权威所有者，其他模块引用其版本；例如电机R/L不在AutoTune中另存一套可独立写的正式配置。

### 2.3 每个参数必备的描述符

描述符包括ID、规范名、类型、字节长、单位、来源/坐标、访问类别、合法范围/枚举、默认是否有效、允许状态、依赖参数、持久化域、更新速率、支持的读取视图、能力位、schema版本。动态范围还返回版本，例如硬件电流上限及热降额后的实时上限分别提供。

`UNSET`通过valid=0表达，不用NaN或0同时表示“未配置”和有效零。运行测量带value_status、sample_time_us、sample_sequence、snapshot_group、profile_revision、continuity_epoch；STALE返回可展示的旧值时必须显式标旧，不能进入控制或验收。

批量读取只保证同一个snapshot_group在同一快照内一致。跨组同时性要通过测量快照服务；不能逐个读取Id/Iq/角度后声称它们来自同一ADC周期。

## 20 参数读写协议、事务和调用示例

外层沿用PcLink的24 B头、最大256 B payload、CRC-32C。参数操作的message_type与parameter_id是两个命名空间，建议冻结如下类型：0x0100 DESCRIBE_LIST、0x0101 DESCRIBE_GET、0x0102 READ_PARAMS、0x0103 WRITE_PENDING、0x0104 QUERY_OPERATION、0x0105 ACTION_REQUEST；请求/响应由flags区分。能力不足的旧固件不能接收这些消息。

READ_PARAMS逻辑输入为axis_id、view、profile_kind/profile_id（访问非默认配置集时）、transaction_id（读pending时）、snapshot请求和ID列表；响应为共同快照元数据以及逐项`parameter_id/type_id/unit_id/value_status/value_length/value`。设备级与轴级项不得混在同一个axis_id批次；不同组返回独立元数据或明确不是同步快照。所有P配置由明确的profile作用域定位，不能通过修改eval选中的规则隐式更换另一个请求正在读写的配置。

WRITE_PENDING输入为transaction_id、expected_revision和逐项`parameter_id/type_id/unit_id/value_length/value`。仅修改P类的pending；每个响应给接受/拒绝原因。完整事务按声明长度、成员清单和hash封闭后才能VALIDATE。错误字段不能被静默钳位后当成原请求提交。X/T配置用对应CONFIGURE动作，L使用SET_TARGET，K通过专门标定/导入，R/F永远拒绝WRITE。

跨字段验证至少包括：min<max；R/L/电流换算为有效正数；齿比非零；编码器能力/极对数匹配；电压与采样窗口匹配；电流/热/速度/行程边界协调；估计器/环路采样频率与参数稳定性；所有条件单位一致；更改传感器/极对/齿比后旧标定与外环验收失效；实验频段与实际记录率相容。

典型读写步骤：

1. 连接后读取system协议、字典版本/hash、boot_id及capabilities；PC按DESCRIBE加载实际支持的参数，不假定整个草案都实现。
2. 调电流PI：停止并确认MOE=0 → BEGIN_PROFILE(CONTROL,base_revision) → WRITE_PENDING(0x5010—0x5017) → VALIDATE_PROFILE → COMMIT_PROFILE → 读回ACTIVE及revision → 进行有限验证 → 需要持久化时SAVE_PROFILE。中途失败不部分覆盖active。
3. 设速度：获得lease → 用SET_TARGET提交motor_velocity_rad_s及有效期 → 检查接受值和applied_cycle；START是独立请求。上位机显示rpm只做`rad/s×60/(2π)`换算。
4. 做位置20 Hz评估：先检查POSITION与反馈源能力 → CONFIGURE_EVAL指定coordinate/幅值/频段/规则 → START_EVAL → 查询operation → 读取eval.metrics/FRF/report → 检查有效性及坐标来源，再展示结论。
5. 故障恢复：读first_cause和快照 → 消除原因 → RESET_FAULT → 验证状态；不会恢复上一次START或目标租约。

掉线、重复包、序号回绕、设备重启和Flash保存中断均按PcLink/ParameterStore规则处理。重连后先查询最后operation，不用新ID盲目重发启动或提交；保存失败不谎报持久化成功。
