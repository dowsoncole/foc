# 测功机串口基线与加载测试前置核查（2026-10-27）

## 目标与现状

目标是测量包含 202:1 减速器的舵机输出轴转矩、转速与机械功率曲线，直至实际可控极限。测试开始前，用户报告速度模式停机：`g_user_control.status.state=4`、`fault=3`、`active_mode=4`、`calibration_valid=1`。这些字段只表明用户层收到后端故障，尚不能区分速度试验、输出位置、FOC、运行时与驱动故障。

## 仪器与协议

资料：`C:/Users/penghao/Desktop/Servo_9948/测功机通讯/通讯说明.pdf`，设备为 HLT-151 动态扭矩传感器。COM11 是 USB 转 485 口，Modbus RTU 19200、8N2、站号 1 已实测连通。`03H` 读取 `0x0000` 起 6 个寄存器，依次为 32 位转矩、转速、仪表功率；`0x0008` 起 2 个寄存器读转矩小数位。每帧检查地址、功能码、长度与 Modbus CRC16。通讯说明的 `05H` 清零以及 `10H` 配置命令都未发送。

该资料只规定传感器的读取、清零和参数写入，没有测功机加载器的制动力给定、制动停止或急停接口。用户随后确认制动负载由本人手动逐级增加；PC 只负责记录 HLT-151 数据，不能通过 COM11 自动卸载。

读取脚本：`software/control_analysis/scripts/read_hlt151.py`。输出原始值、物理转矩、输出轴转速、按 202:1 推算的电机转速、仪表功率原始值及按 `T × 2πn/60` 计算的输出轴机械功率。仪表功率寄存器的缩放说明存在歧义；需在非零转速和转矩下与计算功率交叉核对，暂不把原始寄存器值标成 W 或 kW。

## 当前只读实测

先执行文档目录中现有 `485连通测试_debug.py`：发送 `01 03 00 00 00 02 c4 0b`，收到 `01 03 04 ff ff ff c8 ba 71`，CRC 正确，即原始转矩 -56。随后读取小数位为 2，得到 -0.56 N·m，转速和仪表功率均为 0。连续 5 秒共 40 个 CRC 正确采样，原始记录在 `software/control_analysis/results/dyno_20261027/idle_baseline.csv`：输出轴转速全为 0 rpm，转矩 -0.59 至 -0.39 N·m，平均 -0.51625 N·m。尚不清楚负数来自传感器零漂、传动预载还是安装方向，不能自动消零或当作堵转转矩。

2. 用户已确认手动加载；开始前仍需确认能够立即卸载制动负载，并约定每个负载平台的保持时间与停机信号。当前 HLT-151 串口只能观测。
3. 确定传感器安装在减速器输出轴，确认零负载点、额定量程以及实际电机和功率板的测试边界。当前工程 `CURRENT_LIMIT_HARDWARE_ONLY=1`，软件电流幅值限制已绕过，不具备凭软件给定安全持续堵转的依据。

正式运行时，应分别标注传感器测得的轴端 `T_out`（N·m）、`n_out`（rpm），推算的 `n_motor≈202n_out`（rpm）及 `P_out=T_out·2πn_out/60`（W）。减速器有损耗，不能把输出轴机械功率直接标为电机电功率。堵转点 `n_out≈0` 时机械输出功率趋近 0，即使转矩很大。
