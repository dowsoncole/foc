## 已完成

1. 实测内部 ZERO_POS 从已知 0 变为 0x70F，两次慢速寄存器读取一致。
2. 新固件启动/周期检查 0x009、0x00A；不同于期望 0 时锁存 0x40，
   撤销角度、速度和电角反馈。实板 observed=1807、mask=3、latched=1，
   输出 OFF、calibration_ok=0，已确认拒绝异常配置。
3. OFF/暂停采集下仅恢复易失零点，两个寄存器回读均为 0；未发 0x5 自动置零
   或 0xC EEPROM 编程。原始角回到 925225，与故障前有效值差约 0.0101°机械角。
4. 编码器、速度/校准/I²t、FOC/PWM/ADC 时序 C 回归及 Python 16 项检查通过。

## 边界与最后可确认状态

- 故障参考配置已确认并恢复，但异常改写的触发源仍未定位；不能把
  SPI 命令错位假设或“常开 SPE”当作已证明的根因/修复。
- 未证明历史 78.3°电角度变化与此次配置变化一一对应。
- 轮询每字段正常约 6.4 ms，存在检测延迟；寄存器读没有 CRC。
- SPI 10.5 MHz / 20 us 相位 / VERY_HIGH、FOC、新鲜度与热预算未改。
- 启动历史电角零位无效；不应用先前被拒绝的 5.581142 rad 拟合值。
- 恢复后有意保持 OFF、采集暂停和故障锁存。后续连接在 500 kHz / 100 kHz
  均报 Get IDCODE error；重启命令尚未执行，健康启动/连续采集和高速未验证。
  Windows USB 仍能识别状态 OK 的 STM32 STLink，当前故障是目标芯片访问失败，
  目标供电/SWD 状态需检查。
- 热债种子已记为保守值 83.0 A²·s；后续至少携带该值，并与仍可读历史记录
  取最大值。MCU 复位不等于物理冷却，不能直接复位清零再跑。

## 工具与源码

当前安装 CMSIS 调试扩展为 1.10.0。脚本兼容显式设置 `SERVO_PYOCD`，
例如指向当前扩展 `tools/pyocd/pyocd.exe`；Python 的 GDB 默认取同级
`tools/gdb/bin/arm-none-eabi-gdb.exe`，也支持 `SERVO_GDB`。
两个 PowerShell GPIO 工具另支持 `-ProbePath`。切换工具路径不会自动连接、
复位、解除故障、写 EEPROM 或启动电机。

`source_snapshot` 保留关键固件/保护、测试、诊断脚本及文档，不是可独立
编译的完整工程；`evidence` 保留本次关键原始回读和异常配置拦截记录。
同目录测试日志均为离线回归，不等同于电机运行验收。完整证据索引见
`software/servo_v1/MDK-ARM/docs/encoder/spi_logic_analysis_2026-10-22.md` 第 22 节。
接下来的验收顺序是 OFF-only 配置/健康启动/CRC 稳定性、合格校准、再分级升速；
本包不自动执行这些动作。
