# 串口PC通讯模块实施路径

基线：2026-10-22 当前源码。本文设计可维护的PcLink模块及其PC配套软件边界，不实现代码。首版沿用USART1、921600 baud、8N1与现有RS485方向控制，服务状态读取、参数管理、闭环整定、运动命令和故障诊断。

## 1 现状与最终能力

当前[waveform_uart1_port.c](../../servo_v1/Tests/Src/waveform_uart1_port.c)负责USART1初始化、DMA1 Channel3发送和PA8方向控制；编码器使用DMA1 Channel1/2。端口会把帧复制到持久缓冲，并等待UART TC后释放发送方向，这些正确的生命周期应保留。

当前[波形协议](../架构说明.md)主要服务遥测，尚不是完整双向控制协议。需要新增RX DMA/缓冲、帧解析、命令与应答、会话、参数事务、故障事件和数据回读；不能仅在现有波形帧中增加一个“写变量”命令就作为长期接口。

最终能力分三类：实时控制仍在MCU；PC发有限运动/实验请求并查看结果；离线或后台PC分析负责拟合和优化。串口中断不执行控制器、整定算法、Flash写入或复杂业务。

## 2 模块分层与统一结构体

建议目录 `Communication/PcLink/Inc`、`Communication/PcLink/Src`。硬件适配单独放入BoardPorts或Modules；具体目录与Keil/CMSIS工程清单同步。

| 层 | 职责 | 不承担的业务 |
|---|---|---|
| UART port | DMA、环形接收、TC/IDLE/错误、RS485方向与时间 | 不解释电机参数，不打开MOE |
| framing | 字节流同步、长度、版本、CRC、分帧 | 不直接调用Servo或整定 |
| session | 会话、请求号、去重、超时、控制租约 | 不把心跳当成电流环存活 |
| dispatcher | 消息权限/状态校验、业务端口路由 | 不修改其他模块内部结构体 |
| data service | 遥测订阅、故障事件、实验分块回读 | 不阻塞控制ISR等待带宽 |
| application ports | Profile、Servo、Safety、AutoTune适配 | 不泄漏HAL/UART到业务模块 |

统一入口为每链路一个 `pc_link_t`，支持按axis_id路由到轴服务。首版只有一轴也保留明确轴编号。

| 子结构 | 字段类别 | 所有权 |
|---|---|---|
| config | 波特率、最大帧/负载、时隙、队列容量、协议版本 | 初始化/停机配置 |
| transport | DMA位置、RX/TX状态、方向、线上完成标志 | UART端口唯一写者 |
| parser | 同步状态、已收长度、截止时间、CRC状态 | 后台解析器 |
| session | boot_id、session_id、请求去重缓存、租约、能力集 | 后台会话管理 |
| command | 有界请求队列、进行中任务ID、结果缓存 | dispatcher与任务完成邮箱 |
| telemetry | schema、抽样周期、通道、队列、丢样计数 | 控制侧发布快照，后台发送 |
| transfer | 实验ID、块号、总长、校验、回读游标 | 数据服务 |
| diagnostics | CRC错、溢出、重发、延迟、忙次数、最大队列深度 | 各源计数，快照导出 |
| ports/workspace | 接口表、context、外部分配缓冲和长度 | Init绑定，不动态扩容 |

统一结构体只负责链路生命周期，不复制整个Safety或AutoTune对象。共享通用请求/响应类型，模块之间通过回调和显式上下文调用。`PcLink_GetStatus`返回只读快照；外部不直接写busy、seq或DMA指针。

## 3 MCU接口和执行上下文

| 拟定接口 | 调用上下文 | 输入/输出与限制 |
|---|---|---|
| PcLink_Init | 上电、输出关闭 | port/config/workspace；校验容量和DMA资源 |
| PcLink_OnRxProgress | UART/DMA ISR | 发布DMA生产位置/错误标志；固定工作量 |
| PcLink_OnTxWireComplete | UART TC ISR或有界端口服务 | 通知最后停止位已经发出，可释放方向 |
| PcLink_OnTransportError | UART/DMA ISR | 记录ORE/FE/NE/DMA错误；恢复工作交后台 |
| PcLink_Service | 后台、分片 | 消费有限字节数、解包、路由和发送，返回待处理状态 |
| PcLink_PublishSample | 控制ISR，按配置抽样 | 复制固定快照到SPSC队列；满时丢遥测并计数 |
| PcLink_PublishEvent | Safety/AutoTune后台适配 | 提交带事件ID通知；可靠回读由源模块保留 |
| PcLink_GetStatus | 后台 | 一致诊断快照，不触发I/O |
| PcLink_CloseSession | 后台/监督请求 | 撤销控制租约、丢弃旧业务请求、保留故障历史 |

业务端口分别为 `servo_service`、`parameter_service`、`tuning_service`、`fault_service`、`snapshot_service`，每个端口只暴露其公开API。协议解析成功不意味着业务条件满足，dispatcher还必须检查当前状态、有效性、范围、profile版本和任务互斥。

新增`evaluation_service`承接独立SystemEval配置、启动、取消与报告读取。公开ID、字段类型、单位、访问权限、配置事务和完整动作表统一在[上位机读写参数表](2026-10-22_上位机参数字典草案_规划记录.md)维护；其中F/R/K/P/L/X/T类别是协议契约，不是对内部全局变量开放任意写入。

控制命令在主循环转为请求邮箱，在下一个规定控制边界原子接收。若主循环可能被现有I²C阻塞10 ms以上，需要先把相关事务改成有界服务或给协议独立有界调度，再声称命令延迟已满足指标。

## 4 UART、DMA与RS485接入

1. 由PcLink统一拥有USART1。旧波形模块改为生产数据或调用PcLink传输端口，不再独立初始化UART、DMA和PA8。
2. 保留DMA1 CH3作为TX的候选配置；RX选择未占用的DMA通道并绑定USART1_RX请求。先核查全部DMA/IRQ/DMAMUX资源，不能与编码器CH1/CH2冲突。
3. RX首版采用DMA环形接收，IDLE/半满/满中断只通知新增字节。DMA会覆盖旧数据，因此维护生产进度和已消费计数；不能只看当前位置而无法区分绕回次数。
4. 后台每次最多解析固定字节/帧数量，剩余留到下次；缓冲溢出时丢弃受损段、重新同步并计数，不能将被覆盖的数据作为完整命令执行。
5. TX帧使用持久化缓冲，排队后到TC前不可复用。DMA TC只表示数据进入UART，不表示停止位已经上线路；以UART TC决定释放RS485方向。
6. DE提前/保持、收发切换、发送时回显/接收禁用由实际收发器电气时序决定，用逻辑分析仪验证。UART错误恢复必须保留故障计数，不进行无限重试。

首版为点对点半双工：PC是总线主站，设备只在请求回复或已授予的有限数据窗口内发送。主站每次最多授予一帧或固定短窗口，防止遥测长时间占用线路。无空闲时隙就没有可靠STOP入口，不能让设备无限自由推流。

若以后接多节点RS485，需要另外设计地址、仲裁和时隙；当前axis_id不是总线地址，不宣称首版已支持多设备总线。

## 5 推荐二进制帧V1

以下为拟定协议。正式实现时应冻结字段表、端序、CRC和金样本，PC与MCU共用同一版本规范。

| 偏移 | 长度/B | 字段 | 定义 |
|---|---:|---|---|
| 0 | 2 | magic | 固定字节A5 5A，用于字节流同步 |
| 2 | 1 | protocol_version | 首版1；不支持则拒绝 |
| 3 | 1 | header_length | 首版24；首版不接受任意扩展长度 |
| 4 | 2 | message_type | 命令、应答、事件、遥测、数据块类别 |
| 6 | 2 | flags | REQUEST/RESPONSE/EVENT及保留位；非法组合拒绝 |
| 8 | 4 | session_id | 当前握手会话；0仅用于发现/握手 |
| 12 | 4 | sequence | 请求号；应答回显；事件使用独立事件序列语义 |
| 16 | 2 | payload_length | 0—256，先验证再使用 |
| 18 | 2 | reserved | 首版必须为0 |
| 20 | 4 | sender_time_us | 发送端32位微秒时刻，仅用于本端时序关联 |
| 24 | 0—256 | payload | 消息类型规定的序列化内容 |
| 24+payload_length | 4 | crc32c | 对24字节头及payload计算，尾部自身不参与 |

多字节整数统一小端。浮点若使用，明确IEEE754 binary32，并逐字段校验NaN/Inf；不得直接memcpy原生C结构体上线路，以免填充、对齐和编译器差异破坏协议。位置可用带单位比例的int64计数/定点数表示，不能靠无限增长的float角度表达绝对多圈位置。

CRC采用CRC-32C：反射多项式0x82F63B78，初值0xFFFFFFFF，结果异或0xFFFFFFFF，按字节反射处理，结果小端传输。算法金样本ASCII `123456789` 的CRC为0xE3069283，线上尾字节为83 92 06 E3；同时必须提供至少一份完整命令帧的独立PC/MCU金样本测试。

最大帧284 B，在921600、8N1下纯线上时间约3.082 ms。RX不因magic出现在payload中而提前截帧；正常按长度收取并验CRC。长度非法或CRC失败时从候选起点向后移动一个字节重新找同步，每次Service有扫描预算，避免恶意/噪声输入占满CPU。半帧超时丢弃且统计，不能长期占用解析器。

sender_time_us约71.6分钟回绕；它不是PC与MCU已经同步的证明。实验数据使用设备采样序号和扩展64位时间/epoch，PC接收时间仅用于通信诊断。设备可扩展32位时基，但必须在足够短的间隔更新，避免漏掉多次回绕；已有DWT在168 MHz下约25.6秒回绕，需要单独处理。

## 6 会话、请求去重与启动许可

握手流程：HELLO读取协议/设备信息 → PC提出会话标识与随机挑战 → 设备回显挑战、报告boot_id并建立唯一活动会话 → PC按能力发请求。boot_id使用可证明变化的启动计数或可靠随机标识；不要把每次上电都为0的RAM计数当启动唯一标识。

session_id只用于会话隔离，不提供密码学身份认证。握手后运行命令还携带当前boot_id/控制租约标识，设备拒绝旧启动周期的排队帧；只用32位session_id不能彻底排除重启后的旧帧碰撞。旧租约在重启/断线后永不自动恢复。

请求唯一键为当前会话、sequence和请求内容hash。收到重复请求且内容相同，返回缓存状态/结果；相同序号不同内容返回冲突。缓存必须有明确容量和有效期；过旧序号返回STALE，而不是再次执行非幂等动作。序号将回绕前主动重新握手，不在同一活动会话无限循环复用。

所有启动/整定/提交命令还带 operation_id，用业务层防重复。PC超时可用相同请求号重试，或查询operation状态；不能默认失败后用新请求号再启动一次。STOP按目标轴和租约幂等处理。

心跳与控制租约：可先采用100 ms心跳、300 ms过期作为台架起点，实际值按PC抖动、总线负载和允许停机时间冻结。只有当前控制者的合法心跳续期；普通遥测包、旧会话数据和CRC错帧均不续期。租约失效上报Safety，由它决定受控停止或Trip。

有限整定实验有设备端deadline和能量/位移限制。首版默认PC租约丢失即取消实验并执行规定停止；后续若允许独立运行，必须作为显式能力和实验策略，不能因未收到数据就无期限继续。

## 7 消息与服务接口

| 消息组 | 首版请求 | 应答/动作边界 |
|---|---|---|
| 发现与能力 | HELLO、GET_CAPABILITIES、GET_STATUS | 固件版本、轴、编码器来源、支持环路、最大帧、实际采样率、单位schema |
| 运行控制 | ACQUIRE_CONTROL、RELEASE_CONTROL、HEARTBEAT、START、STOP、SET_TARGET | 通过Servo公开接口，返回接受/拒绝原因；不直接改MOE |
| 参数 | GET_PROFILE、BEGIN_PROFILE、WRITE_PROFILE、VALIDATE_PROFILE、COMMIT_PROFILE、ABORT_PROFILE | 事务及版本检查，正式应用条件由ParameterStore决定 |
| 整定 | GET_TUNE_CAPABILITIES、CONFIGURE_TUNE、START_TUNE、ABORT_TUNE、GET_TUNE_STATUS、SUBMIT_CANDIDATE、VALIDATE_CANDIDATE、COMMIT_CANDIDATE | 返回experiment_id和状态；长期操作分离ACK与完成事件 |
| 故障 | GET_FAULT_STATUS、READ_FAULT_EVENTS、ACK_EVENT_CURSOR、REQUEST_FAULT_RESET | ACK只确认读到事件；Reset由Safety检查 |
| 遥测 | CONFIGURE_STREAM、GRANT_TX_WINDOW、STOP_STREAM | 返回实际接受的通道/频率；不保证无带宽上限 |
| 实验数据 | LIST_RESULTS、READ_RESULT_META、READ_RESULT_BLOCK | 按实验ID/块号回读，整体校验，支持断点续传 |
| 性能评估 | CONFIGURE_EVAL、START_EVAL、ABORT_EVAL、SUBMIT_EVAL_ANALYSIS、COMPARE_EVAL | 独立规则、结果有效性、基线比较；不能由候选自行改门槛 |

应答至少包含request sequence、operation_id、状态码、当前状态、相关版本及拒绝细节。区分 `ACCEPTED`、`IN_PROGRESS`、`COMPLETED`、`REJECTED`、`ABORTED`；“ACK已收到”不等于“电机已到位”或“参数已保存”。

参数事务：BEGIN声明目标域、基线版本、总长 → 分块WRITE到暂存区 → VALIDATE检查CRC/模式/范围/依赖 → COMMIT在停机或明确允许的边界原子生效。中途断线只丢弃未提交内容，active保持原样。运行中不支持的参数更新返回WRONG_STATE，不做半更新。

首版不开放任意地址读写、任意寄存器写入或直接清Safety结构体。参数按稳定ID、类型、单位、范围、可写状态和版本暴露；固件不认识的ID必须拒绝。

参数字典补充了SAVE_CALIBRATION、CONFIGURE_LINK和CONFIGURE_COMMISSION，分别负责标定结果持久化、停机/无租约时的链路政策配置、有限投运配置。持久化标定不保存运行状态；新有限投运入口不沿用旧kind7忽略duration的连续运行语义。

## 8 遥测、波形与有限串口带宽

921600、8N1的理论字节率为92160 B/s，还要扣除头尾、主机请求、应答、换向和空闲间隔。4个float通道在20 kHz下仅样本值就需要320000 B/s，因此不可能经当前串口连续全量发送。

默认方案：控制ISR以1 kHz或更低频率抽样；快环频响优先传单频累积结果；需要原始快环波形时先采入共享缓存，实验后分块读取。带宽不足只丢遥测或降低订阅，不拖慢控制ISR。

示例带宽预算：每帧打包8个样本，每样本4个float加32位采样序号共20 B，另加12 B批次元数据，总payload172 B，帧200 B。1 kHz采样对应125帧/s、25000 B/s，占理论字节率约27.1%，未含轮询/换向。正式配置建议总线平均占用≤60%，为命令、应答和故障保留裕量。

遥测schema包含通道ID、单位、比例、采样率、坐标侧别、profile版本；样本含序号和有效性。丢样必须产生可见的序号缺口和计数。抽取前按用途做抗混叠或限制可解释频段；1 kHz显示曲线不能用于证明数kHz电流频响。

发送优先级：必要命令应答/停止状态 → 故障事件 → 整定状态与结果 → 普通遥测。已开始的帧不任意截断；用最大帧和短授予窗口约束阻塞。队列满时先丢旧遥测，控制应答有保留容量；即使事件通知丢失，PC仍可按事件序号回读Safety历史。

## 9 延迟、时隙与断线策略

通信延迟分为PC排队/USB延迟、线路等待、物理传输、MCU解析、业务接受和实际动作，必须分别测量。普通PC操作系统调度没有硬实时保证，不能仅由波特率推出“PC急停必定在几毫秒生效”。

建议首版验收两个可测指标：满帧接收完成后，STOP请求在MCU内被接收处理≤1 ms；在已声明的主站轮询和最高合法遥测负载下，从STOP首字节开始上线到业务接受≤10 ms。若后台阻塞导致失败，应修改调度而不是仅增大超时。最终运动停止时间由Safety和机械条件决定，串口STOP不能替代硬件故障关断。

RS485换向采用显式主站授权，双方在TC与guard time之后改变驱动权。设备发送一个最大帧需要约3.1 ms，授予窗口还必须限定总帧数；否则即便每帧都短，多帧连续发送仍可能饿死主站。

拔线/PC退出：MCU继续完成本地控制周期，租约到期触发规定停止。重连：先读boot_id、故障、运行状态与未结束operation，清理旧待发命令，再建立新租约；UI不得自动重放上一次START或COMMIT。

## 10 PC端结构与最小可用工具

PC先实现可脚本调用的通信核心和命令行工具，再扩展GUI；避免把协议解析、整定优化和按钮回调混在一个窗体类中。

| PC单元 | 职责 |
|---|---|
| serial_transport | 串口连接、读写线程/事件、超时、原始帧诊断 |
| protocol_codec | 与MCU相同的字段/CRC/解析测试，不依赖UI |
| device_session | 握手、重试去重、operation跟踪、租约、能力 |
| device_services | Servo、Profile、Safety、AutoTune的类型化调用 |
| experiment_store | 原始数据、配置hash、结果与元数据版本，保留设备时间 |
| tuning_analysis | 频响、拟合、候选设计和验证报告，不能直接发低层启动字节 |
| presentation | 状态、曲线、故障、进度；明确显示估算/实测坐标与数据缺口 |

一个完整用户流程为：连接并识别固件 → 读取故障与标定状态 → 选择可用实验 → 查看限值与当前profile → 启动有限实验 → 等待完成或取消 → 回读数据并分析 → 提交候选验证 → 查看与基线的比较 → 停机提交正式参数。对调用方提供相同服务接口，GUI和自动化脚本不各自实现一套协议。

记录包建议包括session/boot/experiment ID、固件hash、参数与单位schema、采样率、设备时间、原始数据校验、分析程序版本和结论。PC端保存失败应可重试回读，不把“窗口上显示了一条曲线”当作实验归档成功。

## 11 分步骤实施和节点验收

| 节点 | 具体实施 | 验收标准 |
|---|---|---|
| C0 资源与协议冻结 | 盘点USART/DMA/IRQ/RS485接线，冻结帧表、单位、错误码和资源预算 | 与编码器无资源冲突；现有UART只有一个所有者；PC/MCU能独立生成相同完整金样本 |
| C1 传输端口 | DMA环形RX、持久TX、TC换向、错误恢复、有限服务 | 逻辑分析仪验证DE与最后停止位；分片/粘包/满环/串口错误可恢复；重复开关连接无死锁 |
| C2 解析器 | 长度/版本/CRC、同步恢复、扫描预算 | 全部字节切分位置、随机噪声、丢字节/插字节、恶意长度、payload内magic、CRC错均覆盖；无越界、无错误业务执行 |
| C3 会话与只读 | HELLO/能力/状态、session/boot、去重缓存 | 重启/断线/旧包/序号复用不会串会话；1000次连接重连测试无资源泄漏；同一请求重复不重复执行 |
| C4 受控写与参数事务 | Servo请求、租约、Profile事务 | 半包/半参数/掉线/提交时重启后active始终完整；非法状态拒绝；STOP幂等；故障Reset不启动 |
| C5 遥测与事件 | 订阅、带宽准入、短窗口、事件游标与分块回读 | 最高合法负载下STOP延迟满足第9节；丢样可见、错误块可重读；事件通知丢失仍能回读首因 |
| C6 整定端到端 | 实验配置/启动/取消、候选提交/验证/正式提交 | 一次电流频响实验可完整完成；PC崩溃和断线有界结束；重复START/COMMIT不重复动作；候选版本错拒绝 |
| C7 性能与耐久 | 真实串口、RS485换向、长时间负载、回绕 | 至少2小时最高合法负载，覆盖时间回绕；无解析死锁和错误命令执行；控制deadline零违例、故障注入仍在时限内 |
| C8 版本兼容 | 旧波形迁移、未知字段/命令、能力降级 | 不支持版本明确报错；PC不把新枚举解释为旧含义；Legacy只读模式与新协议互斥且可识别 |

解析器测试建议包括至少百万字节级随机/截断输入，并使用主机内存检查工具；真实线路的错误注入测试不能被主机解析测试替代。消息处理覆盖所有可能状态和重试位置，尤其是“动作已完成、应答丢失”的情况。

## 12 内存、迁移和交付完成条件

建议PcLink常驻RX/TX/解析工作区合计≤3 KiB，例如RX环1024 B、2个最大TX帧568 B，剩余分配解析暂存/去重/队列元数据；不要为每种消息再复制一个256 B缓存。具体对齐和栈占用以sizeof/map为准，必须先回收当前测试大缓冲。

迁移顺序：先把现有波形UART端口转为统一传输所有者 → 只读状态协议 → 会话和参数事务 → 遥测/事件 → 整定命令 → PC分析。旧波形格式如果保留，提供显式Legacy模式；不在同一未知字节流自动猜测两套协议，以免把旧数据误识别成命令。

模块完成需同时交付：MCU端口/协议/服务测试、PC客户端核心与最小操作工具、协议版本文档和金样本、总线时序波形、延迟/负载结果、断线/重启/重发测试、内存与控制WCET增量。只完成收发字符串或漂亮曲线不等于完成PcLink。

联动契约：PcLink把实验请求交给[AutoTune](2026-10-22_闭环整定模块实施方案_规划记录.md)，把租约与通信状态交给[Safety](2026-10-22_故障保护模块实施方案_规划记录.md)，把运动请求交给Servo。它只搬运并验证请求，控制周期与最终保护始终由MCU内部独立执行。
