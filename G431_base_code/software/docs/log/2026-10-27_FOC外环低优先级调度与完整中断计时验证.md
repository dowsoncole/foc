# FOC 外环低优先级调度与完整中断计时验证

## 目标与验收范围

用户希望完整 ADC/FOC 中断接近 20 µs，而不是仅算法内核接近 20 µs；明确允许调整外环调度，并要求验证控制表现。保留 10 kHz 电流环、保护、采样窗口及 PWM 提交截止检查。

本轮完成代码、主机等价性和输出关闭的板上时序验证；真实闭环阶跃在使能前被安全门阻止，尚未完成动态验收。不能据此宣布性能无变化或达到 20 µs。

## 测试环境与安全状态

- STM32G431VBTx，SystemCoreClock=168 MHz；Keil ArmClang 6.24，O3、LTO、标准浮点语义，保留 NaN/Inf 检查。
- ST-LINK：E1007200D0D2139393740544；STM32CubeProgrammer 2.20.0 下载并校验，pyOCD 只做调试访问。此前 pyOCD 擦写失败，因此本轮不再用其下载。
- Tektronix MDO34 C064843，固件 v1.15.18，PyVISA USB 读取；CH1=PA0、CH2=PD2、CH3=PB7，PB7 低有效。
- 计时夹具 `FOC_TARGET_IRQ_PROFILE=1`：真实 ADC、SPI、FOC 及 PWM 规划执行，逻辑 armed，但不调用输出使能；MOE 实读为 0，BDTR=0x02002054。静止零速给定，不能代表带载闭环。
- 最终工程移除夹具宏，默认 0；全量重编译正式镜像、下载校验。停在 main 入口把本次 `g_speed_run.enable` 置 0，再运行，最终确认 MOE=0、CPU Running。源码的上电自动对齐/启动默认没有改动，复位仍可能启动！

## 修改内容

1. Keil 启用 LTO，并同步 CMSIS 工程编译/链接选项。
2. PWM 采样规划增加“最近候选点已安全则直接返回”的精确快速路径；边沿、窗口、比较顺序及原回退搜索不变。
3. 连续运行增加短 ADC 路径，避开未启用的录波/有界测试分支。保留三相有限值与原电流策略、峰值与首次超过 5 A 现场、驱动安全、FOC、PWM 检查、运行及电流遥测。异常仍走原故障捕获路径。
4. 速度环改由 PendSV（优先级 14）执行；TIM1/SPI DMA=0、ADC=1、SysTick=15。位置环本来就在主循环，继续保持。
5. ADC 每约 1 ms 锁存反馈、请求时间、上一电流周期的饱和状态与 q 电流误差，最后发布 pending。PendSV 消费期间禁止覆盖请求；PI 完成后一次 32 位浮点写入发布 Iq。
6. PI 的 dt 使用请求时刻，不使用 PendSV 晚到的时刻，避免产生 1.1 ms 外环周期。电流环继续逐周期取最新角度，而不是使用外环锁存角度。
7. 即时停止、编码器失效、超速、ADC 间隔检查仍在 ADC；外环超过 2 ms 未更新会停止。外环被 ADC 故障抢占后，不得覆盖故障或发布新 Iq；保留首个故障原因。
8. 新增 PendSV 增加嵌套栈需求：启动文件栈由 0x400 增至 0x800，未使用的 0x200 堆取消。业务源码未使用动态分配；将来引入 malloc 必须重新规划。正式 RW+ZI=32544 B，距 32 KiB 上限仅剩 224 B，后续增加静态 RAM 必须检查 map。栈预算包括 2048 B 预留，不是只有 224 B 栈。

原始数据及各阶段镜像见 [foc_irq20_20261027](../../control_analysis/results/foc_irq20_20261027/)。DWT 每项除以 168 得 µs。

| 阶段 | 平均完整计时点耗时 | 最大值 | 说明 |
| --- | ---: | ---: | --- |
| 原始真实 IRQ 夹具 | 26.164 µs | 29.155 µs | before_trace.bin，含启动/外环更新 |
| LTO + PWM 规划快速路径 | 24.496 µs | 27.310 µs | after_trace.bin |
| 外环移出、连续运行短路径，中间版本 | 22.137 µs | 22.137 µs | fast_steady_trace.bin；尚未锁存请求反馈，不是最终版 |

最终 DWT 普通周期 3766 cycles=22.417 µs，请求周期 3856 cycles=22.952 µs，锁存增加 90 cycles=0.536 µs。均值各阶段约为：入口至控制步骤 3.554 µs、反馈/保护 3.872 µs、算法与接口检查 9.708 µs、PWM 3.988 µs、控制器尾部 0.298 µs、业务尾部及诊断 1.048 µs。

MDO34 冻结同一帧，2 ms / 100 万点，2 ns 间隔；19 个完整 PA0 脉冲：普通周期约 22.498～22.510 µs，两个请求周期为 23.036 / 23.046 µs。数据见 [scope_final](../../control_analysis/results/foc_irq20_20261027/scope_final/)。PA0 覆盖完整业务 IRQ，未人为提前拉低；硬件异常入栈、GPIO 前的软件和异常返回不包含在脉宽内。DWT 采点早于末尾 GPIO，因此与示波器有小差异。

读取脚本：[read_scope_foc_timing.py](../../control_analysis/scripts/read_scope_foc_timing.py)。脚本临时单次采集，结束恢复原时间档、采集模式及运行/停止状态。

CORDIC、内核放 SRAM、尺寸优化和输出辅助拆分曾试验，收益不足且 SRAM 方案余量过小，未保留这些方案。最终仍用原浮点内核，无定点替代、无 fast-math、无保护削减。

## 主机验证

- `Tests/Host/run_tests.ps1`：FOC、调制、7200 电角度及不同采样序列的窗口、PWM 故障冻结和提交余量统计全部通过。
- `run_foc_equivalence.ps1` 对第二轮前基线：100000 PI、200000 调制、200000 电流步、40000 电压步，输出、积分与故障逐位一致。
- `run_speed_tests.ps1`：原速度/对齐/PRBS/限流策略/看门狗回归通过；新测试比较 300 个周期的新旧 PI 结果，模拟 25 µs PendSV 延迟，仍逐位一致。确认每周期最新角度、给定保持、停止、反馈失效、外环饿死超过 2 ms 后故障。
- 等价性是相同输入与采样时刻的数值验证，不证明被控对象在新增一拍电流给定延迟下动态响应完全相同。

## 真实动态验证尝试与未完成项

用户确认机械安全后，调用限速 30 motor rpm 的现有位置验收脚本，计划先普通电压零位校准，再低速方向测试、+1° 与回原点；不绕过校准与故障门。

结果：[mpt_position_20261027_105635](../../control_analysis/results/mpt_position_20261027_105635/)。起始输出角 356.8826°，不满足脚本要求的 20°～340°，使能之前断言停止；因此对齐及闭环运动均未执行。最终 MOE=0。需先在安全条件下把输出轴移到区间内，重新完成闭环阶跃及对比，不能标记“动态验收通过”。

该次 OFF 快照已有 36 次 SPI CRC 错误，运行、控制器、PWM 拒绝及截止超时均为零；通信问题不能视为已解决，也不能凭此归因于 FOC 超时。后续运动验证要同时监测错误增量。

最终结论：完整脉宽约 22.5 / 23.0 µs，外环造成的周期增量已显著缩小，但没有达到严格 20 µs；正式固件已恢复，本次运行停止，带载动态验证待完成。
