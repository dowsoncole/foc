# 2026-10-21 控制周期修复与重新整定日志

## 1. 范围与恢复连接

用户确认目标板已恢复供电。使用原 ST-Link（E1007200D0D2139393740544）、STM32G431VBTx、1 MHz SWD 恢复实机测试。固定电角度 0，位置开环，D/Q 电流 PI 闭环。未修改用户确认的硬件电路，未假定已测得电机 R/L 或实际母线电压。

所有测试使用固件内有界采集，完成后自动关闭输出，再连接 GDB 读取。未在有电流输出时单步控制中断。保留 0.25 A 相电流保护、0.02 pu 电压限幅、±0.01 pu 积分限幅；只测试单轴 ±0.1 A 以内。输出关闭并不表示主电源断开。

## 2. 为什么必须重新测量

恢复供电后，旧配置 Kp=0.0025、Ki=1.6 的负 Q 轴 0.1 A 短测出现明显不重复：一次末段约 -0.079 A，另一次约 -0.117 A，延长记录后约 -0.100 A。不能仅按一次短测选择“最优”。进一步读取编码器诊断，发现每次 2048 次电流更新伴随约 2048 次 ISR 超时。

新增 `g_current_test_timing`，直接记录控制调用前的 CPU DWT 周期及样本数。168 MHz CPU 下：

| 固件 | 首末 DWT 周期 | 更新数 | 实际更新周期 | ISR 最大耗时 |
|---|---|---:|---:|---:|
| 原 O1/full | 3131672857 → 3166053454 | 2048 | 约 99.98 μs | 12985 周期，约 77.3 μs |
| O3/full | 3111518361 → 3145898828 | 2048 | 约 99.98 μs | 12443 周期，约 74.1 μs |
| O3/std | 3145423719 → 3162613598 | 2048 | 约 49.99 μs | 初测 7666 周期，约 45.6 μs |

计算：`((last-first) mod 2^32) / 168000000 / (samples-1)`。首末时间差对应 samples-1 个间隔，不是 samples 个间隔。DWT 回绕已在评分脚本处理。

原 PWM 采样周期变量仍报告约 50 μs，软件序号也连续；这两个条件无法证明硬件触发没有漏掉。`deadline_rejections=0` 只说明 PWM 提交窗口检查未拒绝，不能代替完整 ISR 运行时间检查。旧记录的时间轴/IAE 需作废或重新标定，旧记录未删除。

## 3. 修改与构建证据

- `main.c`：增加独立 DWT 时间诊断，保留固定角度、保护和自动停机流程。
- `servo_v1.csolution.yml`：速度优化 `optimize: speed`，对应本次 cbuild 的 O3。
- `servo_v1.cproject.yml`：`-ffp-mode=std -fno-finite-math-only`。
- `servo_v1.uvprojx`：同步优化与浮点设置。实测构建使用 cbuild/AC6 6.24；没有将其描述成已在 Keil GUI 单独验证。
- 原 `full` 模式下，反汇编显示电流换算的整数转 float 反复调用 `_dsub`、`_d2f` 软件双精度路径。只升 O3 不够；尝试 `full -fno-rounding-math` 也未消除这些调用，未下载该无效变体。
- 改为 std 后，电流换算使用 `vcvt.f32.u32/s32` 硬件指令。没有启用 fast-math；显式保留非有限数语义。反汇编核实 `FOC_PI_IsValid` 仍有与 `0x7f800000` 比较的 NaN/Inf 拒绝分支。
- Arm 对浮点库模式的说明：[Arm Compiler Reference Guide](https://documentation-service.arm.com/static/671fa191ad463325b23263ce)。std 与 full 的区别包含非正规数/异常/舍入语义，不只是优化级别。工程不使用动态舍入模式；未来引入依赖该语义的算法时应重新审查。
- 构建产物：Code=50836，RO=1376，RW=416，ZI=25336；成功下载。日志 `results/pi_hardware_fp_build.log`。
- 一次 cbuild 自动清理导致生成目录缺少 groups.cmake/components.cmake，首次构建失败；再次正常生成后成功。失败日志保留，未下载失败产物。

## 4. 20 kHz 下重新比较

ADC 保持 42 MHz、12.5 周期采样、16 倍过采样；控制反馈未加平滑滤波。以下均为 0→0.05 A、另一轴给定 0，两轴相同 PI。每四次更新平均保存一点，共 512 点、约 102.3 ms；统计最后 128 点。Kp 为 pu/A，Ki 为 pu/(A·s)，不是每周期积分系数。

| Kp / Ki | D 平均误差 mA | D 标准差 mA | Q 平均误差 mA | Q 标准差 mA |
|---|---:|---:|---:|---:|
| 0.005 / 0.2 | -6.240 | 9.125 | -17.148 | 12.941 |
| 0.0025 / 0.8 | -0.909 | 9.109 | -0.564 | 11.315 |
| 0.0025 / 1.6 | -0.376 | 9.007 | -0.510 | 12.530 |
| 0.0025 / 3.2 | +0.227 | 9.877 | +0.250 | 12.429 |
| 0.00125 / 1.6 | -0.17 | 9.42 | +0.72 | 11.18 |

D 轴 0.0025/1.6 对应 `pi_timing_hwfp_d`，其余对应 `pi_hwfp_*`。全部完成且无过流、无饱和；本轮累计 ISR 超时为 0。编码器 DMA busy 计数仍增加，说明还存在调度余量问题；固定角度不使用该角度反馈，不能据此宣称速度/位置环也已验证。

结论：增大 Ki 明显改善有限时间内的平均跟踪，但波动未一致降低。3.2 虽降低本轮 IAE，并未证明更稳。四点平均后的标准差不是原始 20 kHz 电流纹波；八点平均后数值降低也不能当成 PI 抑制噪声的证据。首次 90% 穿越与最大超调容易被噪声触发，不能直接作为可靠带宽/超调结论。

## 5. 复现与原始证据

实际可执行脚本：`scripts/run_pi_candidate.ps1`、`scripts/score_pi_capture.py`、`scripts/require_current_off.gdb`、`scripts/start_bounded_capture.gdb`。前者连接本地 3333 的 pyOCD，先确认输出关闭，配置参数并请求应用，再武装有界采集，等待自动停止后导出 512 个 `<I7f` 记录。二进制/配置/启动/结束日志/JSON 同名保存，不依赖串口图像读数。

下面命令可直接复制；通常由助手执行，用户无需操作终端。前提为工程根目录、目标已连接、pyOCD gdbserver 已运行，且确认当前输出关闭。

```powershell
& software/control_analysis/scripts/run_pi_candidate.ps1 -Tag repeat_d -Kp .0025 -Ki 1.6 -Axis 0 -Amplitude .05 -Average 4
& software/control_analysis/scripts/run_pi_candidate.ps1 -Tag repeat_q -Kp .0025 -Ki 1.6 -Axis 1 -Amplitude .05 -Average 4
```

标签应使用新名称，避免覆盖历史记录。`score_pi_capture.py` 现在从 read.log 读取 DWT 验证更新周期；超过 50 μs±1 μs 标记 timing_valid=false。没有 DWT 信息的旧记录不能自动视为有效。168 MHz 是本次工程的 CPU 时钟，修改时钟后必须同步评分脚本。

串口额外验证：COM11、921600，3 秒捕获 82919 字节，成功解析 2590 帧，CRC/协议错误均 0。开头 31 字节重同步对应接入时非整帧起点；原始 `results/uart_dma_recheck.bin` 保留。此证据用于确认 DMA 发送路径，不代表电流动态指标。
