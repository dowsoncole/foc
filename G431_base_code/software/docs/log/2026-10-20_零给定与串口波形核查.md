# 零给定与串口波形核查

## 结论

截图显示 active_stage=DQ_PI_CLOSED_LOOP、running=1、output_armed=1、output_enabled=1、fault_flags=0。代码路径为 ADC 反馈 → D/Q 变换 → 参考减反馈 → 双 PI → 电压限幅/调制 → PWM 写入。因此截图与源码支持“闭环路径已启用”，但零给定静态数据不能证明非零指令跟踪性能或最优 PI。

截图 Id≈5.90 mA、Iq≈19.75 mA，属于瞬时反馈。闭环不要求带测量噪声的反馈每个采样都精确为零。此前默认电压标度 24 V 未测量，所以 Watch 的 output_*_voltage_v 仅作为按配置换算的量。

## 串口实测

起初 Win32_SerialPort 只返回 COM1，进一步使用 Get-PnpDevice -Class Ports -PresentOnly 找到 FTDI USB Serial Port (COM11)。因此已修正“没有 USB 串口”的初步判断：不能只依赖第一种枚举方式。

以 .NET SerialPort 打开 COM11，921600、8N1，关闭 DTR/RTS，无发送命令，只读取约 3 秒，随后关闭释放串口。收到 32839 字节。

现有 PythonExample/servo_transport.py 的 WaveformParser 解析出：

- V2 二进制协议，帧头 A5 5A，mode=2，通道 ID=4/5/6/7；
- 927 个有效 D/Q 帧；
- 121 次 CRC 拒绝、23 次帧序号跳变统计、238 次 ADC 序号异常统计；
- 不能据此声称链路无错误，也不能把有效帧当等间隔时间序列。

| 通道 | 平均 A | 标准差 A | 最小 A | 最大 A |
|---|---:|---:|---:|---:|
| Id 指令 | 0 | 0 | 0 | 0 |
| Id 反馈 | 0.001441 | 0.031287 | -0.083 | 0.066 |
| Iq 指令 | 0 | 0 | 0 | 0 |
| Iq 反馈 | 0.001153 | 0.030064 | -0.069 | 0.071 |

统计来自通过 CRC 的帧，不是独立电流仪器读数。结果说明 MCU 有发送波形数据，零指令反馈均值接近零，仍有波动。尚未定位 CRC/序号异常原因，也未操作用户当前的上位机界面，所以不能断言用户界面不显示的具体原因已修复。

接收设置应为 RS485、COM11、921600、V2 协议。发送内容不是 ASCII 数字文本，也不是 VOFA JustFloat。源码 USART1 TX/RX 为 PA9/PA10，PA8 控制 RS485 方向，默认四通道输出请求频率 1000 Hz。
