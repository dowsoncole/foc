# servo_v1 代码审查报告

审查基线：2026 年 10 月 22 日当前工作目录源码。目标：易维护、可预测的实时性能、20 Hz 位置闭环、200:1 减速器。当前只有电机轴编码器，后续增加输出轴编码器；允许误差尚未量化。

**结论：现有 FOC 算法与硬件分层值得保留，已具备电流闭环和速度调试基础；进入位置闭环前，应先补齐统一保护、反馈连续性、参数管理和内存预算。** 20 kHz 电流环执行频率不等于电流带宽，也不证明负载端具备 20 Hz 位置带宽。

本次只交付文档，不修改固件源码，不烧录、不启动电机。源码检查覆盖 Core、FOC、Servo、四组 Modules、Tests、工程配置及相关 HAL 调用语义。厂商 HAL/CMSIS 未逐行作为自研代码审计；板级保护接线、传感器电气特性和机械频响仍需实测。优先级含义：P1 是正式闭环前应解决的问题，P2 是影响正确性、扩展或维护的问题，P3 是改善项。

## 已确认的问题

### R01 P1 CPU 异常后没有主动关闭功率输出

证据：[异常处理](../../servo_v1/Core/Src/stm32g4xx_it.c)，`HardFault_Handler`、`MemManage_Handler`、`BusFault_Handler`、`UsageFault_Handler` 均直接死循环；[Error_Handler](../../servo_v1/Core/Src/main.c) 第 1715 行仅关中断并死循环。TIM1 的 Break/Break2 在 [tim1_pwm.c](../../servo_v1/Modules/Three_Phase_Driver/Src/tim1_pwm.c) 第 399 行附近被禁用。

触发条件：MOE 已打开时发生 CPU 异常，或进入上述致命错误处理。TIM1 是独立运行的外设，停止软件不会自动清除 MOE，因而最后一组占空比可能持续输出。驱动芯片自身保护不能替代控制器失效后的关断路径。

建议：建立不依赖 HAL 状态、堆栈大对象或通信的最小 `PowerStage_TripImmediate`；异常入口首先关闭硬件输出，再记录有限故障信息。结合实际原理图验证 Break/比较器/驱动器故障链路；IWDG 只作为最终失活兜底，不替代快速关断。

验收：在无功率或受控台架上注入异常，示波器同时观察异常探针与栅极输出；证明关断时间小于预先定义的 `T_trip_max`，复位后不自动重启。

### R02 P1 普通运行缺少独立的 ADC 控制链失联保护

证据：[ServoManager_Service](../../servo_v1/Servo/Src/servo_manager.c) 第 216 行 RUNNING 分支只检查运行请求与 MOE；[SpeedCommission_Service](../../servo_v1/Servo/Src/speed_commission.c) 第 136 行的后台 ADC 超时仅用于合成角度诊断；普通连续速度模式默认 `timeout_ms=0`，主机看门狗不启用。项目没有自定义 `HAL_ADC_ErrorCallback`。`Encoder_RecordFocIsrCycles` 超时只记数。

触发条件：PWM 定时器继续运行，但 ADC 触发、JEOS 中断或控制回调停止。依赖该回调执行的限流、编码器新鲜度检查和停机判断也一起停止。即便主机心跳正常，也不能证明电流环存活。

建议：用独立定时器或 PWM 周期检查“最后成功采样”和“最后成功控制提交”的序号/时间戳；区分 ADC 故障、回调缺失和 PWM 提交超时。独立观察者直接触发保护，不能只在被监测的 ISR 内检查自己的间隔。补齐 ADC HAL 错误转发。

验收：关闭 ADC 触发、屏蔽 ADC IRQ、模拟转换错误及阻塞控制回调；每种情况均能在配置的有限时间内清 MOE并锁存正确原因。主机测试复现见[验证记录](2026-10-22_文档汇总验证与证据记录.md)。

### R03 P1 电流零偏校准没有质量判定

证据：[current_sampling.c](../../servo_v1/Modules/Current_Sampling/Src/current_sampling.c) 第 173—183 行：采满样本即求均值并发布 `CAL_DONE`；采集的 `calibration_min/max` 没有参与成功判定。

触发条件：模拟输入钉在 0/满量程、放大器未正常偏置，或校准过程噪声很大。只要样本数量满足，仍会得到“校准完成”；钉死输入还可能被减去错误偏置后表现为零电流。

建议：校验均值允许范围、与 ADC 两端的距离、峰峰值/方差、连续序号与采样耗时，明确区分样本不足、量程异常、噪声过大。阈值来自板上零电流统计，不凭空填数。校准 API 本身应拒绝运行中请求；目前唯一正常调用在启动阶段，但函数没有输出关闭约束。

验收：0、满量程、两路失配、噪声超限和缺样输入全部拒绝；正常零电流在温度/供电条件变化下重复校准，记录偏置分布。

### R04 P1 实测相电流保护没有覆盖所有运行模式

证据：[main.c](../../servo_v1/Core/Src/main.c) 第 930 行附近，仅 `CURRENT_OPEN_LOOP && output_armed` 才调用 `SpeedCommission_PhaseCurrentFault`；NORMAL 分支只调用 FOC。`FOC_AlgorithmStep` 第 340 行限制的是**参考电流矢量**，不是测量相电流上限。

影响：NORMAL 的有限但过大的实测电流不会触发当前的采样幅值保护；电压开环也不经过该入口。参考限幅不能覆盖接线、参数、采样极性异常。普通连续模式还有明确写出的实验性幅值保护旁路，这属于当前配置事实，不能当作默认产品策略。

建议：从 speed commissioning 中抽出独立保护模块，所有能打开 MOE 的模式共用一次采样检查；区分瞬时保护、I²t、测量有效性和实验许可。先核实硬件 OCP、量程与电机额定值，再配置边界，不能照搬调试宏中的候选数值。

验收：对每种模式分别注入 NaN、Inf、有限过流和采样饱和；保护动作与模式无关，实验许可不能关闭基础硬件保护和反馈失效保护。

### R05 P2 切换 NORMAL 会丢弃已接受的电流 PI 整定结果

证据：[main.c](../../servo_v1/Core/Src/main.c) 第 364 行的调试阶段加载 `g_current_tuning.gains`；第 413—432 行模式配置在非 CURRENT_OPEN_LOOP 时固定写入 `kp=0.1, ki=5`，并改变电流、电压和积分限幅。默认调试 PI 为 `kp=0.0025, ki=1.6`。

触发条件：完成电流整定后切换到 NORMAL。输出会先关闭，因而不是带电瞬切，但再次启动并没有使用刚验证的控制器；Kp 从默认调试值到正常值相差 40 倍。

建议：建立与运行模式分离的 `controller_profile`，包含 D/Q 增益、母线归一化基准、采样周期、滤波版本、限幅和验证状态。模式只选参考源及策略；应用参数时按版本原子提交。

验收：用不同 D/Q 增益完成调试，切换所有模式再回来，验证增益与 profile ID 保留；不允许未经验证的替代参数静默生效。

### R06 P2 长时间丢失编码器后多圈位置连续性无法证明

证据：[encoder.c](../../servo_v1/Modules/Encoder/Src/encoder.c) 第 223—234 行按最短单圈差更新 `multi_turn_count`；第 338—355 行在长间隔后允许新有效帧重新发布；[encoder_frame_guard.h](../../servo_v1/Modules/Encoder/Inc/encoder_frame_guard.h) 的允许位移随间隔增大。快照只有角度、速度和电角度有效位，没有多圈连续性有效位。

触发条件：采集间隔足够长，实际位移可能超过半圈。恢复后的单圈角度无法判断跨过几圈，却会重新发布有效快照。当前电角度换相可接受重新取得单圈位置，但后续位置环不能据此认为绝对多圈位置仍可靠。

建议：新增 `position_valid/continuity_epoch`；超过可证明无混叠的间隔就锁存多圈位置失效。重新取得单圈角度不能自动解除位置失效，应重新回零或由独立绝对位置源恢复。速度历史也应按恢复策略重新建立。

验收：丢帧期间模拟整圈加小角度、反转和跨零位，恢复后电角度可重新有效，但位置环必须拒绝失去连续性的多圈位置。

### R07 P2 编码器配置 API 接受会使角度归一化不终止的有限值

证据：[encoder.c](../../servo_v1/Modules/Encoder/Src/encoder.c) 第 95 行用循环加减 2π；第 419 行只验证偏置有限，第 425 行关中断后调用归一化。对 `1e20f`，减去 2π 不改变 float 的数值，循环不会退出。

范围：当前 SpeedCommission 调用对偏置另有限幅，因此这不是当前正常启动必现的问题；它是可复用公共 API 的真实输入契约缺陷。

建议：在关中断前拒绝超范围配置并做有界归一化；限定义极对数范围，禁止在实时回调里执行与参数大小成比例的循环。

验收：极大有限值、NaN、Inf、负偏置和边界角度均在固定时间内成功或明确拒绝。主机超时复现见验证记录。

### R08 P2 故障邮箱存在读后清零竞态

证据：[servo_manager.c](../../servo_v1/Servo/Src/servo_manager.c) 第 116 行附近 ISR 使用 `pending_faults |= fault`，Service 第 151 行附近先读取、再写零；两步之间无临界区。

触发条件：ISR 在主循环读取后、清零前发布新故障，新位被清掉。当前固件没有调用 `ServoManager_RaiseFaultFromIsr` 的活跃入口，所以应作为保护模块接入前的 API 缺陷处理，不声称目前已经发生漏故障。

建议：原子交换邮箱，或在极短临界区中读取并清除；不同 ISR 发布可采用每源单写邮箱再合并，避免多个 `|=` 写者。故障动作先于上报，锁存位与事件队列分开。

验收：在读取、清除和多个发布者之间注入抢占，证明每一种故障至少被锁存一次；事件队列满不影响硬件关断。

## 对 20 Hz 位置闭环的主要约束

### C01 速度反馈滤波应优先重新设计

`encoder.c:14` 设置 `tau=10 ms`，第 149—188 行使用 20 点跨度差分和一阶滤波。名义 20 kHz 下，差分跨度约 1 ms；一阶滤波截止频率约 15.9 Hz，在 20 Hz 的幅值约 0.62、相位约 −51.4°，还未计入差分窗口和执行延迟。这不能直接证明闭环必然不稳定，却足以否定“只在现有速度环外加位置 PID 即可保证 20 Hz”的做法。

建议把控制用速度估计与显示滤波拆开，比较可调带宽差分滤波、αβ/PLL 估计器，并用相同噪声、时延、转速条件验证。保留原始时间戳，按实际速度内环频响设计外环。

### C02 调试速度斜坡不能直接充当位置轨迹限制

当前 `SPEED_RUN_RAMP_RPM_S=300`。对减速比 N=200，输出轴 `θ=A sin(2πft)` 所需电机速度和加速度为：

```text
ωm_peak = N × 2πf × A
αm_peak = N × (2πf)² × A
```

以输出轴幅值 1°、频率 20 Hz 为例，电机峰值约 4189 rpm、峰值加速度约 55,122 rad/s²。仅从现有 300 rpm/s 斜坡反推，在 20 Hz 允许的正弦幅值只有约 0.000570°。这些是运动学计算，不是电机扭矩能力结论。

应把连续速度调试斜坡与正式轨迹规划分离；位置带宽验收必须写明幅值、负载、母线、温度和限幅状态，避免把速度/加速度受限当作小信号带宽不足。

### C03 RAM 和栈必须先留预算

本次完整 AC6 6.24 构建：Code=62,216 B，RO=1,392 B，RW=4,892 B，ZI=25,988 B。RW+ZI=30,880 B，占工程分配的 32,768 B 的 94.24%，剩余 1,888 B。

主要常驻对象：`g_current_loop_test` 16,572 B、`g_speed_test` 4,416 B、`g_adc_noise` 4,128 B。启动文件预留栈 1,024 B、堆 512 B，已包含在 RAM 总量内。链接器报告最大栈 `504 bytes + Unknown`，不能覆盖函数指针和中断嵌套的完整实际路径，不能据此宣布栈足够或已经溢出。

建议共享互斥实验缓冲区、采集与正式运行配置分离、将在线单频累积统计替代长期高频全量缓存。对位置环、第二编码器、通讯 RX/TX、整定、故障快照逐项列预算；测量最坏中断嵌套下栈水位，再决定栈大小。

### C04 当前快照时间不等于电流采样和电压作用时间

编码器 `sample_cycle` 标记异步传输启动附近；FOC 直接使用最新快照，未分开补偿电流采样时刻与 PWM 生效时刻的角度。ADC 触发点又随占空比移动。旧帧允许保留至约 150 μs；8500 rpm、2 极对时，150 μs 对应约 15.3° 电角变化，此处只是现有速度上限下的误差量级计算。

建议记录采样事件与执行事件的时间戳，明确传感器锁存和内部延迟，分别计算 Park 与逆 Park 所需角度。预测须设最大年龄并在恢复/加减速时验证，不能用预测掩盖长期坏帧。

### C05 调度应以 PWM 周期为基准并明确截止时间

当前速度 PI 在 ADC 回调中用 DWT 判断是否过去 1 ms，`tick_cycle=now` 会累计调度滑移；ADC 触发相位变化也使调用间隔变化。实测 dt 积分有价值，但它不等同于固定速率外环调度。

建议用周期序号确定每 N 周期执行哪个外环，结合时间戳校验真实 dt；超期不无限补跑积压控制步。先测含抢占的最坏执行时间、最长关中断区、距离下一次 PWM 提交的最小裕量，再决定速度/位置任务频率。不要仅比较平均 ISR 时间与 50 μs。

### C06 200:1 换算不能替代负载侧测量

当前只能闭合电机位置及其除以 200 的估算输出位置，不能观测减速器间隙和扭转。后续负载编码器用于位置反馈，电机编码器继续负责换相及速度反馈；这是成熟的双编码器结构，但增加输出编码器并不自动消除共振。参见 [Synapticon 双环结构](https://www.synapticon.com/en/motion-control-academy/dual-loop-positionsregelung) 与 [maxon 双环说明](https://support.maxongroup.com/hc/en-us/articles/360012314820-EPOS4-Dual-loop-control)。

## 应保留的设计

- FOC 算法无 HAL 依赖，通过端口回调接硬件，已有主机测试。
- PWM 三相占空比与 ADC 触发点统一规划、提交，并检测窗口/截止时间。
- SPI DMA 生命周期有明确所有权、异常复位和帧校验，不在高优先级中断等待 SysTick。
- 编码器快照通过短临界区发布，区分机械角、电角度和速度有效性。
- 电流控制对有限性、参考矢量、调制能力及积分饱和已有处理。
- 快速采集与波形传输分离，UART DMA 拷贝持久化帧避免使用栈缓冲。

## 实施顺序

1. 修复 R01—R04，建立所有模式共用的失活关断与故障注入验收。
2. 统一 profile、状态机、数据连续性；收敛 main.c 职责；先释放内存。
3. 测量 ADC→控制→PWM 时延，重新设计控制用速度估计，验证电流与速度频响。
4. 实现电机端位置环与受约束轨迹，明确 200:1 坐标换算与回零策略。
5. 接入输出轴编码器，识别两质量机械模态，再调负载位置闭环。
6. 在前三项基础上集成[整定模块](2026-10-22_闭环整定模块实施方案_规划记录.md)、[保护模块](2026-10-22_故障保护模块实施方案_规划记录.md)和[通讯模块](2026-10-22_串口PC通讯实施方案_规划记录.md)。

最终验收以同一工况下的频响、跟踪误差、扰动恢复、温升/电流、故障关断时间和最坏执行时间为准。编译成功和主机测试通过只能证明对应软件检查通过。
