# FOC 热路径等结果优化与验证日志

## 目标与验证边界

用户要求缩短 FOC 执行时间，并保持现有功能和控制表现。本轮保留浮点算法、PI 参数、积分与抗饱和规则、电压限幅、过调制、PWM 与 ADC 时序，以及全部故障检查。不采用降低精度的定点替换、快速数学编译选项或取消保护。

已修改源码、构建固件并通过主机回归；尚未下载或验证板上耗时。`pyocd list` 返回 `No available debug probes are connected`。MDO34 可以连接，但板上仍是原有固件，其波形不能用于证明此次优化的收益。本轮没有修改示波器采集状态，也没有控制电机运行。

## 修改内容

### 1. 线性调制独立为短执行路径

文件：`software/servo_v1/FOC/Src/foc_modulation.c`。

- `FOC_ModulationCompute()` 根据已有的调制模式分派，当前正常运行配置的 `FOC_MODULATION_LINEAR_ONLY` 进入 `modulation_linear()`。
- 过调制和非法模式继续进入原有通用实现 `modulation_generic()`。
- 线性路径复制原算法的参数验证、跨度检查、模长平方检查、开方与限幅比较、三相投影、零序注入、占空比钳位、电压重构及扇区判断。
- 保持 `0.999999f` 边界系数、`sqrtf`、浮点除法及表达式顺序，没有改变径向限幅，也没有用近似值替代输出。
- 两个私有实现使用 `noinline`，使线性路径不再承担通用 OVM 函数的浮点寄存器保存开销。

代价是增加少量 Flash 代码；没有新增控制状态或缓冲区。

### 2. 固定大小清零直接生成写零指令

新增内部头文件：`FOC/Src/foc_memory.h`。

- ArmClang 支持时，`FOC_CLEAR_OBJECT()` 使用 `__builtin_memset_inline()`；其他编译器继续使用标准 `memset()`。
- 仍将对象的所有字节清零，包括填充字节，保留无效输入时清零输出的行为。
- 替换调制输出、电压命令输出和算法复位输出的固定大小清零。
- 避免为了调用 `__aeabi_memclr4` 而保存实时路径中仍需使用的浮点参数。

ArmClang V6.24 的最终目标汇编已检查：

| 线性调制路径 | 修改前 | 修改后 |
| --- | --- | --- |
| 清零库调用 | `BL __aeabi_memclr4` | 直接写零，无库调用 |
| 浮点寄存器保存 | `VPUSH {d8-d15}`，64 字节 | 无 `VPUSH` |
| 浮点寄存器恢复 | `VPOP {d8-d15}`，64 字节 | 无 `VPOP` |
| 进入调制实现 | 原单一函数 | 分派后尾跳转，无新增调用栈层 |

上述是目标指令证据，不等于实测节省了多少微秒；核心寄存器仍可能需要正常保存。

### 3. 复用已计算的基波 D/Q 电压

文件：`FOC/Src/foc_algorithm.c`。

抗积分饱和判断已计算 `fundamental_d/fundamental_q`，发布遥测时直接使用相同值。没有改动 PI 更新、条件积分判断或回退时机。

### 4. 补齐正常模式已有的分段计时

文件：`Core/Src/main.c`。

原有 `g_speed_profile[5]` 在调试电流模式中设置了起点，但正常模式快速分支没有设置，不能直接拿来分析正常 FOC。现补齐正常模式起点、反馈结束和总耗时记录。

| 元素 | 正常模式含义 |
| --- | --- |
| `[0]` | 调用采样周期更新和控制器前的 `DWT->CYCCNT` 原始值 |
| `[1]` | 至反馈回调结束的累计周期数 |
| `[2]` | 至进入 PWM 写入回调的累计周期数 |
| `[3]` | 至 PWM 写入回调完成的累计周期数 |
| `[4]` | 至 `FOC_ControllerStep()` 返回的累计周期数 |

运行时可用 `[2]-[1]` 估计算法及接口检查耗时，用 `[3]-[2]` 观察 PWM 规划/提交耗时。此数组不覆盖 ADC IRQ 全部耗时；PA0 仍表示原有完整 IRQ 探针范围。正常运行且回调均执行时各字段才可比较。数组是逐项发布的最新值，在线读取可能跨周期，分析偶发慢周期需要一致的单周期快照，不能将不同周期的字段相减。
