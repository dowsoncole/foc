# FOC 第二轮：PI 内联优化与实机验证

## 结果与范围

本轮在上一轮优化的基础上，继续保持浮点计算结果、PI 参数、积分更新顺序、限幅与保护逻辑不变，消除 FOC 电流环中两次跨编译单元的 PI 函数调用。

STM32G431 / 168 MHz 的同镜像前后对照结果：线性未饱和平均耗时由 8.668297 µs 降为 8.284368 µs；线性饱和由 8.974690 µs 降为 8.561000 µs，分别再缩短 4.43% 和 4.61%。该时间是 `FOC_AlgorithmStep()` 本体，不包含完整 ADC 中断、反馈通信或 PWM 提交。

主机 540,000 组对照与 MCU 60,192 对状态检查均逐字节一致。正式固件已重新构建、下载并通过 ST 工具校验，最终处于运行但输出关闭状态。

## 源码修改

新增 `software/servo_v1/FOC/Src/foc_pi_inline.h`，作为仅供 FOC 内部使用的实现头文件：

- `FocPi_IsValidInline()` 保留原有 kp、ki、积分值、积分上下限的全部合法性检查。
- `FocPi_TryStepInline()` 保留输出指针检查、先写零的失败输出行为、误差和周期检查。
- 保留原有积分表达式 `integral + error * ki * period_s`，不改变乘法和加法顺序。
- 保留积分上下限钳位，以及 `kp * error + integral` 输出表达式。
- 不缓存 PI 参数、不降低检查频率、不增加定点量化、不启用快速数学选项。

`foc_pi.c` 中公开的函数名和行为保持不变，转调同一内联实现，避免两套 PI 实现逐渐出现差异。`foc_algorithm.c` 的 D/Q 两路 PI 使用内部内联入口。短路求值保持不变：D 轴失败时不会继续 Q 轴计算；算法仍按原逻辑复位。

ArmClang V6.24 的目标汇编检查确认，`FOC_AlgorithmStep()` 中原有的两条 `BL FOC_PI_TryStep` 已消除，浮点寄存器保存范围由 `{d8-d15}` 变为 `{d8-d14}`。这些是生成代码证据，实际收益另以 DWT 测量。

## MCU 实机对照

继续使用上一轮的专用测试入口 `Tests/Target/foc_timing_benchmark.h`，将基线切换为本轮修改前快照。基线的 PI 与调制公开函数均保留 `noinline` 调用边界，避免与测试入口处于同一编译单元而被额外内联，影响对照公平性。

测试在电机外设初始化之前执行；专用镜像不启动 TIM1、ADC、SPI 或 MOE。相同参数和输入分别执行前后算法，逐次交替调用顺序。每组预热 32 次，正式计时 10,000 次；计时屏蔽中断，因此不包含抢占。每次比较整个算法对象，包括积分状态。共计 60,000 对正式计时，含预热共 60,192 对状态检查，差异为零。

| 工况 | 修改前平均 / µs | 修改后平均 / µs | 节省 / µs | 降幅 |
| --- | ---: | ---: | ---: | ---: |
| 线性未饱和 | 8.668297 | 8.284368 | 0.383929 | 4.43% |
| 线性饱和 | 8.974690 | 8.561000 | 0.413690 | 4.61% |
| OVM1 | 12.814179 | 12.455512 | 0.358667 | 2.80% |
| OVM2 | 13.659417 | 13.256108 | 0.403308 | 2.95% |
| 负角度归一化 | 10.477720 | 10.064029 | 0.413690 | 3.95% |
| 无效角度复位 | 0.616508 | 0.589995 | 0.026512 | 4.30% |

本轮不同于上一轮的测试镜像代码布局，基线均值不必与上一轮完全重合。应使用同一镜像内的前后配对结果评估收益，不直接跨批次相减或叠加百分比。

生产镜像仍保留原来的上电自动启动设置。本次调试为保持输出关闭，在 `main` 入口断点处，将 RAM 中的 `g_speed_run.enable` 置零，再继续启动。入口停点、写零、移除断点和继续运行必须在同一个探针会话内完成：pyOCD 默认断开会话后可能恢复执行，不能跨会话假设目标仍停在入口。

最终完整会话验证到入口 PC=`0x0800d17c`，在启动消费请求之前写入 `g_speed_run.enable=0` 后正常继续。最终读取：

- 核心 Running。
- `g_speed_run.enable=0`。
- TIM1 BDTR=`0x02002054`，MOE=0。
- `runtime.running/output_request/output_armed/precharge_in_progress/output_enabled` 均为零，安全门有效。
- 控制器故障为零。
- PWM 窗口拒绝及提交时限拒绝均为零。

此 RAM 操作只影响本次启动，没有更改持久启动配置；下次复位仍按原有启动策略执行。
