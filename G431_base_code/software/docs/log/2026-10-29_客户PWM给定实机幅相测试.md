## 连接、烧录和读取故障处理

1. 初次只读发现PWM开启。完整核对板上R17镜像，首次块读7个字有差异，两次单字重读均匹配预期后确认88080字节完全一致；随后通过匹配ABI的正常使能/停机入口关闭输出，读回MOE=0。
2. 烧录新镜像后，通用下载脚本首次块读校验失败，启动流程被拒绝。没有跳过校验执行运动。重新读取94760字节全部匹配新AXF；此轮重读无需修正任何字。
3. 旧运行上下文在新程序写入后停在HardFault。校验与OFF检查通过后，通过受控复位到main断点，先置两个enable=0，再恢复初始化。新固件正常运行，BDTR=0x02002054。
4. 第一次测量入口仍因块读差异在RAM写入前拒绝，保留`xlsx_run1`。主机增加稀疏差异单字双读：每个4KiB块最多16个差异字，必须两个独立回读均完全匹配预期；持续差异直接拒绝，保存原始块、重读和最终`verified_flash.bin`。主机回归验证真实持续差异不能被“修正”为预期。
5. `xlsx_run2`与`xlsx_repeat`正常完成，两轮均通过完整镜像核对、OFF预检和10秒心跳保护，未触发主机15A峰值/5A累计RMS停止条件。无故障自动清除、无运动期间复位。
6. 对测量报告增加限幅点可见曲线，避免只画少数通过资格的点。检查并修正Word120秒模式的主机RMS计数上限为2404000（约120秒×20kHz加容差）；本轮Excel60秒计数约1200000不受此问题影响。Python回归22项通过。

新AXF SHA256：`a04dd0f9b345095676b85f1b57731d66dc9721ab9194e6dc0aa715a8f84d3f85`；板上仍为该客户模式固件，默认位置参数仍为Kp72/5500rpm。不能以历史R17的AXF直接调试此版本RAM。
