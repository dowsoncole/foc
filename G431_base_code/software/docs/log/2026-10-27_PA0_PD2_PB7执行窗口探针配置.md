# 2026-10-27 PA0、PD2、PB7 执行窗口探针配置

## 目的

使用示波器或逻辑分析仪直接观察三个关键中断/回调的实际执行时间。

## 最终引脚定义

| 引脚 | 拉高时刻 | 拉低时刻 | 表示的时间 |
|---|---|---|---|
| PA0 | `ADC1_2_IRQHandler()` 入口 | ADC电流处理、FOC运算、电压写入TIM1完成，且即将退出ADC中断 | 完整ADC/FOC中断时间 |
| PD2 | `TIM1_UP_TIM16_IRQHandler()` 入口 | 更新中断处理完成，即将退出中断 | 完整TIM1更新中断时间 |
| PB7 | `Encoder_TransferComplete()` 入口拉低 | SPI DMA数据检查、解析和反馈更新完成，回调即将返回时拉高 | DMA接收完成回调的软件处理时间（低有效） |

PA0、PD2空闲时为低电平；PB7空闲时为高电平、回调期间为低电平。PA15、PB9不再作为执行窗口探针，初始化后保持低电平。

## 代码位置

- `Core/Inc/timing_probes.h`：三个探针的快速置位和复位函数。
- `Core/Src/stm32g4xx_it.c`：PA0和PD2的中断入口、出口边界。
- `Modules/Encoder/Src/encoder.c`：PB7的DMA完成回调边界。
- `Core/Src/gpio.c`：PA0、PD2输出初始化。
- `Core/Src/main.c`：PB7初始化，并将停用的PA15、PB9保持为低电平。

## 与旧用途的关系

PA0、PD2原先分别用于通信错误和CRC错误锁存。为保证执行时间波形不被故障标记永久拉高，这两个旧故障输出函数现保留接口但不再操作GPIO。故障信息仍可通过软件诊断结构体查看。

同日曾采用PA15表示FOC、PB9表示更新中断；本记录中的PA0、PD2映射为最终配置。

## 注意事项

PA0的高电平覆盖ADC中断从入口到退出的墙钟时间。如果更高优先级的TIM1更新中断或SPI DMA中断在其间抢占，PA0仍保持高电平，同时PD2或PB7会在PA0脉冲内部出现，因此PA0脉宽会包含被抢占的时间。

PB7低电平只表示DMA完成后的软件回调处理时间，不包含此前SPI在线传输时间。

## 验证结果

- Keil目标 `servo_v1` 编译通过：0 Error、0 Warning。
- 编码器主机测试的普通模式通过，包括PA0、PD2、PB7置位/复位断言。
- 故障触发诊断模式仍在原有 `MT6835_SPI_IsBusy()` 状态断言处失败，与本次GPIO换脚无关。
- 尚未在板上使用示波器核对实际脉宽和嵌套关系。

## TIM1更新中断精简

MDO34通过PyVISA读取到PD2高电平稳定约26.05 us。定位到SSI片选延时使用`volatile`循环，实际耗时远大于注释中的1 us。现已将编码器实时启动路径改为SPI1、DMA1和NVIC寄存器直接操作，片选延时改用DWT周期计数；初始化阶段保留HAL配置。修改后Keil编译为0 Error、0 Warning，需重新下载后复测PD2实际脉宽。

寄存器精简版下载后，PyVISA复测PD2高电平为5.034～5.035 us。随后按要求将SPI目标提高到10 MHz；168 MHz外设时钟没有精确10 MHz分频档，最终使用16分频得到10.5 MHz。MT6701的24位SSI线上传输时间由约18.29 us缩短为约2.29 us。

FOC耗时优化：PB7改为低有效，便于直接观察DMA回调是否嵌入PA0窗口；硬件限流模式下编译期删除不再使用的参考矢量`fabs/sqrt/div`计算；正常控制模式跳过调试与投运分支；ADC电流换算改为预计算比例系数乘法，取消每周期的浮点除法。Keil构建通过，FOC主机测试全部通过，需下载后用MDO34复测PA0脉宽及跳动。
