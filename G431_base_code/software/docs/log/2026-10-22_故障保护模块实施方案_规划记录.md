# 故障保护模块实施路径

基线：2026-10-22 当前源码。本方案用于现有STM32G431伺服及后续20 Hz位置环、200:1减速器、双编码器扩展；仅为实施设计。目标是一个统一管理、跨模式生效、动作确定、可测试、可追溯的Safety模块。

## 1 当前问题与目标

目前保护分散在FOC、ServoManager、main、SpeedCommission、编码器与驱动监控中。已有有效的输入有限性检查、PWM写入检测、编码器时效检查及部分调试保护，但它们尚未形成覆盖全部输出模式的体系。

优先解决的证据见[审查报告](2026-10-22_文档汇总代码审查记录.md)：异常死循环未关MOE；普通运行缺独立ADC存活监督；零偏校准缺质量门槛；实测电流限制未覆盖NORMAL；故障邮箱存在潜在丢位竞态。不能只新增一个故障枚举而保留这些动作缺口。

目标原则：**故障源负责提供可信事实，Safety决定动作等级并锁存原因，PowerStage执行撤销输出，ServoLifecycle管理停止与恢复。** 快速硬件关断不等待主循环、通讯或日志；故障信息丢失不得导致保护动作丢失。

## 2 高内聚结构与职责边界

建议目录 `Servo/Safety/Inc`、`Servo/Safety/Src`，分为：

| 单元 | 职责 |
|---|---|
| safety_manager | 配置、状态机、事件合并、锁存、复位条件 |
| safety_fast | 样本有效性、电流/速度/位置快速限值、状态相关检查 |
| safety_watchdog | 独立监视采样、控制提交与关键服务进度 |
| safety_thermal | 经标定的I²t/热模型与降额状态 |
| safety_event | 首因、快照、有限历史、溢出统计 |
| safety_port | 时钟、直接关断、状态读取、受控停止请求 |

Safety不拥有PID、不生成轨迹、不操作UART协议、不依赖某种调试模式的全局变量。Safety可要求减少可用电流/速度上限，但由ControlRuntime在统一限制合并点执行；最终限制为硬件上限、运行配置、热降额和实验租约的最严格交集。

统一入口为每轴一个 `safety_manager_t`。它可与其他模块在 `axis_context` 中聚合，但外部只能读取快照或调用接口。

| 子结构 | 必需内容 | 所有权 |
|---|---|---|
| config | 参数版本、阈值、迟滞、消抖时间、动作、恢复条件 | 停机校验后发布不可变快照 |
| runtime | 状态、当前动作、运行模式/生命周期、降额比例 | 管理器维护，不让协议直接改字段 |
| fast_state | 连续超限计数、采样序号、反馈年龄、热累积 | 指定实时执行点唯一写者 |
| watchdog | 最后有效采样/提交进度、使能时刻、监督期限 | 被监测者发布进度，独立观察者读取 |
| fault_latch | active、latched、first_cause、sequence | 有界原子操作或单写合并 |
| source_mailboxes | 每中断源的事件位/序号、简短快照 | 每源单写，后台原子取走 |
| event_history | 固定长度历史、丢事件计数、读游标 | 后台；不参与关断是否执行 |
| reset | 请求ID、稳定恢复计时、禁止恢复原因 | 后台状态机 |
| ports/diagnostics | context、立即关断、测时、动作延迟统计 | 初始化绑定；诊断只读导出 |

建议第一版使用32位故障位集配合独立数值故障码，不直接让多个上下文并发读写64位掩码。将“是否关断”的最短路径与完整事件结构复制分离。

## 3 分层动作及唯一输出权限

| 层 | 适用故障 | 执行方式 |
|---|---|---|
| 硬件异步关断 | 短路、严重过流、驱动器故障等实际可接入信号 | 驱动自身保护、比较器/TIM1 Break或外部门控，按原理图核实 |
| 快速软件Trip | 非有限反馈、采样异常、严重电流超限、PWM失败、CPU异常 | 最短端口直接撤销MOE/必要的栅极使能，再记原因 |
| 独立存活监督 | ADC停止、控制无进展、提交连续缺失 | 不依赖被监测回调的定时源检查，超时执行Trip |
| 受控停止 | 主机租约超时、可控的轨迹越界、可恢复设备异常 | 保持可信反馈按受限轨迹减速，超时/反馈失效升级Trip |
| 告警/降额 | 温度接近边界、短时可容忍通信错误、剩余裕量降低 | 显示、记录并降低允许工况，不自动清除严重锁存 |

在当前代码中，`Tim1Pwm_EmergencyStop`清MOE可作为最小动作基础；需验证栅极引脚的实际关断状态、死区、驱动使能和失电行为。硬件Break目前未启用，未来能否使用、极性如何、滤波是否合适，必须由原理图与台架确认，不在文档中假定已经接通。

PowerStage正常使能只有一个所有者：ServoLifecycle。测试模式、整定、预充、NORMAL均通过同一路径申请输出。Safety可随时撤销使能许可；重新使能必须重新经过生命周期检查。禁止主循环稍后写MOE而覆盖刚发生的Trip：使能临界区内再次核对锁存序号、许可和硬件故障输入。

“清MOE”表示停止主动电磁控制，不保证带重力/弹性负载保持原位。若系统需要机械制动或安全保持，必须增加相应硬件与动作序列。本文的软件保护不是经过认证的STO功能，不能用命名代替硬件与系统验证。

## 4 接口与调用上下文

| 拟定接口 | 调用方/上下文 | 合同 |
|---|---|---|
| Safety_Init | 上电、输出关闭 | 绑定配置和端口，默认禁止输出 |
| Safety_ValidateConfig / StageConfig | 后台、停机 | 校验单位、上下限、阈值顺序、硬件能力和版本 |
| Safety_CheckSample | ADC控制ISR | 使用同一采样序列的原始码、相电流、时间戳；返回限制与动作 |
| Safety_CheckControl | 控制ISR | 检查参考、算法输出、限幅持续时间、PWM提交状态 |
| Safety_PublishProgress | 对应生产者 | 发布成功序号和时刻；进入ISR不能等同于成功完成控制 |
| Safety_Supervise | 独立定时ISR | 监督实际进展、反馈年龄与使能后首帧期限 |
| Safety_TripFromIsr | 任意可用故障ISR | 立即幂等关断，再发布定长原因；不得等锁或发串口 |
| Safety_ReportEvent | 后台或指定源邮箱 | 上报驱动I²C状态、通信异常等，不掩盖硬件动作 |
| Safety_Service | 后台、分片 | 合并事件、热降额、受控停机/复位政策、生成报告 |
| Safety_RequestReset | 后台 | 请求复位；返回拒绝原因，不直接开输出 |
| Safety_GetStatus / ReadEvents | 后台 | 带序号的一致快照、首因和事件游标 |

Fault/HardFault入口应调用更小的板级 `PowerStage_TripImmediate`，不依赖完整manager、堆分配、HAL句柄锁或格式化日志；记录能力可降级。故障入口本身若已破坏栈，不能指望复杂C调用仍可靠，因此必须保留独立硬件关断/看门狗兜底。

API统一返回OK、INVALID、BUSY、WRONG_STATE、UNSAFE、UNSUPPORTED等明确结果。`Reset`、`Report`、`Trip`可重复调用；重复Trip只允许提高严重程度，不得降低已执行动作。

## 5 故障分类与策略表

每条策略应是可版本化的数据记录：code、source、severity、检测条件、时间窗、动作、锁存规则、恢复条件、快照字段。固定代码含义，不因位顺序变化让旧PC误解故障。

| 故障 | 检测点 | 首版建议动作 | 恢复条件 |
|---|---|---|---|
| 硬件短路/OCP/驱动严重故障 | 硬件链路及输入脚 | 立即Trip、锁存 | 原因排除且驱动状态稳定；必要时电源循环 |
| CPU异常/断言致命错误 | 异常入口 | 最小关断、保留可用复位原因 | 重启到禁止输出态，需新启动请求 |
| ADC超时/错误/量程钉死 | 独立监督+原始码检查 | Trip、锁存 | 重新初始化及校准通过 |
| 校准质量失败 | 校准结束 | 禁止使能、锁存原因 | 在零电流和输出关闭条件重新校准 |
| 采样NaN/Inf/非法配置 | 快速路径 | 同周期Trip | 修正来源，复位后重验 |
| 实测相电流瞬时超限 | ADC快速检查 | Trip；严重点不消抖 | 电气与参数检查后显式复位 |
| 热过载/I²t耗尽 | 固定周期积分 | 先降额或按边界Trip | 温度/热状态恢复，不能通过重启任意清债 |
| 换相角过期/编码器故障 | 快照年龄/报警 | 超过允许保持时间即Trip | 单圈恢复稳定且重新申请使能 |
| 多圈连续性丢失 | 编码器位置状态 | 退出位置控制，按反馈能力停机 | 回零或独立绝对位置恢复；不能只等下一好帧 |
| 双编码器差异超界 | 对齐后的机械模型 | 警告/受控停止/Trip分层 | 区分正常弹性/齿隙与传动失效，再恢复 |
| 超速/越界/跟随误差 | 控制节拍 | 按停止距离与严重度分层 | 位置可信、回到允许范围并复位 |
| PWM提交失败/连续过期 | 提交接口+独立监督 | Trip | 诊断时序、窗口及外设后重启 |
| Vbus欠压/过压、温度超界 | 已验证测量或驱动状态 | 限制/停机/Trip | 恢复到迟滞区并稳定足够时间 |
| PC控制租约失效 | 独立时基+协议会话 | 受控停止；反馈失效则Trip | 新会话/新命令，不自动续跑 |
| 遥测队列满/普通CRC错 | 后台统计 | 计数、降遥测速率 | 不单次触发电机故障；连续控制丢失由租约处理 |

当前没有可靠Vbus/温度采样时，必须标记该检测能力不可用；固定24 V配置不是欠压/过压测量。原始ADC单点接近量程可能由真实大电流导致，应将其作为测量/过流危险处理，不能仅当滤波噪声丢弃。

跟随误差阈值必须使用负载rad或明确的电机rad，结合轨迹与持续时间。用户当前“误差尽量小”不能直接转为某个保护阈值；先在安全行程内采集正常误差包络，再以机械允许误差冻结保护界限。显示性能指标与保护阈值分别管理。

## 6 采样保护、热模型与滤波

瞬时过流判断检查实测两相电流及第三相重构、原始ADC量程、数据有限性与新鲜度。由于第三相由前两相计算，三相和为零在数学上天然成立，不能把这个恒等关系当作独立传感器诊断；需要原始量程、相间响应、外部测量或独立硬件信号补充。

严重超限走即时路径；靠近阈值的持续超限可配置很短时间窗，但必须依据器件容许能量选择，不能用长消抖掩盖危险尖峰。去毛刺、迟滞与滤波分别说明用途和最坏增加的延迟。

现有[过载保护](../../servo_v1/Servo/Inc/speed_overload_guard.h)可作为I²t实现参考，但其候选额定参数不是电机与功率级的认证值。建议先统一相电流RMS、峰值、dq幅值的约定，再定义热量：例如固定时间基准上累计超过持续电流平方的部分，并依据已校核热时间常数加入冷却。短时电流尖峰由独立瞬时保护覆盖。

热累积必须使用有效实测电流及实际dt，丢样不能视作零电流；失去可信采样直接进入失效保护。热债跨模式保留，实验取消不清零。掉电后的热状态通过温度测量、持久化与保守冷却等待中的可行组合处理；没有依据时不允许“重新上电立即满负载”。

热模型验收使用已知恒定/阶梯电流的解析结果、实际负载温升与冷却记录，覆盖重启与缺样。模型允许的软件过载范围必须始终落在器件SOA和已核实电机允许区间内。

## 7 独立监督与动作时间预算

至少区分三种存活：采样是否进展、控制与PWM提交是否成功、整机后台是否进展。PC心跳只能证明通信，不能替代前两项。

建议由独立硬件定时器监督ADC与提交序号，优先级和最坏抢占经过测量后确定。只在TIM1周期中监督可发现ADC失活，但不能独立发现TIM1本身停摆；若采用它必须再补独立时基。SysTick可被高优先级中断饥饿，不适合作为唯一实时保护时钟。

定义冻结的时限，而不是泛称“快速”：

| 参数 | 定义 | 建议建立方式 |
|---|---|---|
| T_hw_trip | 硬件故障发生到栅极关断 | 原理图/器件规格给边界，示波器验证 |
| T_fast_trip | 被采样检测到严重故障到撤销输出 | 快速路径WCET+抢占+输出传播；与器件允许能量比较 |
| T_no_adc | 最后成功采样到失活判定 | 高于正常最坏间隔及抖动，低于可接受失控时间 |
| T_no_commit | 最后成功控制提交到失活判定 | 区分可接受一次失败与持续失败 |
| T_supervisor | 独立监督周期 | 验证 `T_no_adc + T_supervisor + Jmax + T_disable ≤ 允许失活关断时间` |
| T_controlled_stop | 请求到停止完成的最大时间 | 由速度、惯量、允许减速度、行程和再生能力决定 |
| T_iwdg | 最终看门狗复位期限 | 超过正常服务最坏时间，小于系统允许失活时限 |

名义20 kHz系统可先评估“连续2个周期无有效采样、随后在1个周期内检测”的150 μs量级目标，但这只是设计起点；动态采样相位、外设时序及器件安全边界验证后才能冻结。若硬件要求更快，就必须依赖硬件保护，不能靠修改文档阈值达成。

被监测者应在真正完成工作后发布进度。监督者维护上一观察序号并验证前进，不能只看某个不断写新的“活着”标志。首个ADC样本、启动预充和输出关闭状态都有不同的合法等待期，均需有限上界。

IWDG由监督逻辑在多条关键进度均正常时允许喂狗，不能在任意主循环或定时中断中无条件喂狗。看门狗复位前的输出风险仍由硬件和最小关断链处理；复位后根据复位原因留存诊断，不自动启动。

## 8 并发、首因与事件快照

当前ServoManager的“读pending再清零”存在中间插入ISR时丢位的可能。迁移时采用经测试的原子交换，或每源单写邮箱+极短关中断取走。若多个ISR都写同一位集，简单volatile `|=`不是充分保证。

快速故障先Trip，再记录小型事件。首因在第一次有效锁存时固定；后续故障作为伴随事件记录。对同时发生的事件，保存时间戳和优先级，允许记录“顺序无法区分”，不要伪造精确因果。

快照建议含：boot_id、fault_sequence、时间戳、周期号、mode/state、profile ID、原始ADC/相电流、Id/Iq、速度/位置有效位、角度年龄、PWM状态、Vbus/温度有效位、主机租约、过载热状态。复制有固定上限，背景补充字段必须标记为事后数据。

事件队列满：递增overflow计数、保留首因及最新动作等级，不能清锁存或阻塞ISR。通讯确认只推进“已读游标”，不执行FaultReset。故障历史和控制许可是独立状态。

## 9 状态机、复位和停止策略

```text
INIT_INHIBITED → READY → MONITORING
MONITORING → DERATED → MONITORING（仅告警恢复允许）
MONITORING / DERATED → STOPPING → READY或TRIPPED
任意活动状态 → TRIPPED → RECOVERY_CHECK → READY
```

进入READY只表示允许生命周期再次检查，不表示开输出。Trip锁存后要求显式Reset、新的启动请求及对应反馈条件。不能因为PC重连、故障位暂时消失或上电加载了旧命令而自动重启。

Reset门槛：输出关闭、硬件故障解除并稳定、必要的ADC校准通过、配置合法、编码器相关有效性满足、热状态允许、旧控制租约撤销。多圈位置丢失后，清故障不等于重新回零；保留独立的位置有效位。

受控停止只在电流和换相反馈可信时执行，使用现有轨迹限制并考虑再生Vbus。缺失反馈、超过停止期限、继续加速或行程不足即升级动作。负载保持/制动硬件存在时定义交接顺序；未知时先在台架明确风险边界，不能用一种停法覆盖所有机械负载。

## 10 分阶段实现与验收

| 节点 | 具体实施 | 必须满足的验收 |
|---|---|---|
| S0 保护规格 | 盘点原理图、驱动保护、ADC量程、电机/减速器/负载允许值；定义时限和停止类别 | 所有可使能模式列全；每个严重故障有检测点、动作、时限、恢复条件；未知硬件值标阻塞对应功率实验 |
| S1 立即关断 | 最小PowerStage Trip、CPU异常入口、使能仲裁、锁存序号检查 | 无功率下注入异常/故障；所有模式禁止继续使能；实际栅极撤销时间在冻结边界内 |
| S2 模块骨架 | manager、端口、配置、原子邮箱、首因和事件历史 | 主机测试覆盖所有状态转移；抢占交错不丢锁存；队列满不阻止Trip；任何非法配置拒绝 |
| S3 采样/热保护 | 全模式公共实测电流、校准质量、量程、有限性、I²t | 0/满量程/NaN/Inf/有限过流/缺样全部覆盖；恒流热模型时间误差在离散周期容差内；模式切换不清热债 |
| S4 独立监督 | ADC与提交进度、首帧期限、独立定时器、IWDG策略 | 分别停止ADC触发、屏蔽ADC IRQ、阻塞控制提交、停止PWM时基、饿死后台；用探针实测每条监督和关断路径 |
| S5 运动与双编码器 | 超速/限位/跟随误差、连续性、双编码器差异、受控停止 | 正反向与边界运动通过；丢帧恢复不伪造位置有效；受控停止失败必升级；不能以失效反馈做继续运动依据 |
| S6 通讯与整定集成 | 租约失效、实验撤销、事件回读、Reset事务 | PC拔线/进程退出/重复命令/整定取消都可控；复位不自动开输出；AutoTune不能扩大硬件保护范围 |
| S7 台架与回归 | 故障矩阵、最坏负载与供电工况、长时间运行 | 每个故障均保存条件、波形、动作延迟、首因和复位结果；全部硬门槛通过，零误启动、零漏锁存 |

S4的异常注入先使用无功率、低母线或等效信号台架，逐步验证真实功率条件。需要证明的是保护能在定义边界内动作；不能仅凭“串口打印了故障”验收。

## 11 验收记录模板与资源约束

每项用例记录：case_id、固件hash、Safety配置hash、模式、初始状态、注入方式、物理故障时刻、检测时刻、MOE变化时刻、栅极变化时刻、事件码、恢复步骤、结果、测量不确定度。对CPU崩溃这类故障，软件日志可能不完整，示波器与复位原因是主要证据。

建议Safety常驻RAM≤1 KiB；详细历史按需求占共享诊断区或后台缓冲，先做sizeof/map核算。快速路径只做固定次数检查，单位换算系数预计算，禁止格式化、I²C阻塞、Flash写入和无界重试。加入Safety前后都测控制链最坏执行与采样截止裕量，不能因保护代码导致频繁控制超期。

维护要求：新增运行模式必须自动继承公共保护；新增故障必须补策略记录与注入用例；修改保护阈值应生成新配置版本并重验受影响边界。普通调试命令不提供“关闭所有保护”的后门。

与[整定模块](2026-10-22_闭环整定模块实施方案_规划记录.md)及[PC通讯](2026-10-22_串口PC通讯实施方案_规划记录.md)联调时，保持同一原则：实验与通讯能请求动作、获取状态，不能绕过Safety许可直接操作功率输出。
