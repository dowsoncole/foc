# 编码器 SPI 时钟调整为 5 MHz 档位

## 变更原因

当前 10.5 MHz 编码器时钟运行不稳定，按要求降低到约 5 MHz。STM32G431 的 SPI 分频只能取 2 的幂；SPI1 内核时钟为 168 MHz，因此没有精确 5 MHz 档位，采用 `/32`，实际 SCK 为 **5.25 MHz**。

## 修改内容

- `MT6701_SSI_PRESCALER`：`SPI_BAUDRATEPRESCALER_16` 改为 `SPI_BAUDRATEPRESCALER_32`。
- 通用 SPI1 编码器配置同步由 `/16` 改为 `/32`，避免切换编码器后端时配置不一致。
- GPIO 输出速度仍为 `GPIO_SPEED_FREQ_VERY_HIGH`，本次只修改 SCK 分频。
- SPI 模式、DMA、中断优先级、100 µs 采集周期、CRC、反馈新鲜度和 FOC 调度均不改变。

## 时序影响

- 24 位 MT6701 SSI 纯线上时间由约 `24/10.5 MHz = 2.286 µs` 增至 `24/5.25 MHz = 4.571 µs`。
- 仍远小于 100 µs 控制周期，但 DMA 完成回调相对 TIM1 更新中断约晚 2.29 µs；需通过实机错误计数和波形确认稳定性，不能仅凭降频宣布故障已解决。

历史日志中的 10.5 MHz、5.25 MHz 对照属于当时实验记录，保持原文，不按当前配置回写。

## 验证结果

- `run_speed_tests.ps1` 与 `run_tests.ps1` 全部通过。
- Keil ArmClang 全量重编译通过：0 error、0 warning；Code=70808、RO=1368、RW=5128、ZI=27416 bytes。
- 正式镜像保存于 `control_analysis/results/encoder_spi5m_20261027/`，通过 STM32CubeProgrammer 下载并逐字节校验成功。
- 运行后 SPI1 `CR1=0x00000325`，其中 `BR[2:0]=100b`，确认硬件实际为 `/32`，即 5.25 MHz。
- 为避免本次下载后自动带动电机，在 `main` 入口将本次 RAM 中的 `g_speed_run.enable` 写为 0；随后 CPU 正常运行，TIM1 `BDTR=0x02002054`，MOE=0。源码中的上电自动启动默认值没有修改，后续重新复位仍会走原自动启动流程。

本轮只确认配置、构建、下载和寄存器生效；尚未用错误计数或示波器对 5.25 MHz 的通信稳定性做新的持续实测。
