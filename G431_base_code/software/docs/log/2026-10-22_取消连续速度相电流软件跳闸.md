## 3. 代码实现

配置位置：`software/servo_v1/Servo/Inc/speed_commission.h`：

```c
#define SPEED_RUN_PHASE_TRIP_A 15.0f
#define SPEED_RUN_PHASE_TRIP_ENABLED 0U
```

`0U`表示连续速度模式关闭相电流幅值跳闸。15 A常量保留用于对齐阈值及以后显式恢复开关时的配置，不再是当前连续速度模式的幅值停机条件。

新增可主机测试的判定函数，位于 `Servo/Src/speed_commission.c`：

```c
uint8_t SpeedCommission_PhaseCurrentFault(float u_a, float v_a, float w_a,
                                         float threshold_a) {
    if (!isfinite(u_a) || !isfinite(v_a) || !isfinite(w_a) ||
        !isfinite(threshold_a) || threshold_a <= 0.0f) return 1U;
    if (!SPEED_RUN_PHASE_TRIP_ENABLED &&
        g_speed_test.active.kind == SPEED_CONTINUOUS_KIND &&
        (g_speed_test.state == 1U || g_speed_test.state == 2U)) return 0U;
    return (fabsf(u_a) > threshold_a || fabsf(v_a) > threshold_a ||
            fabsf(w_a) > threshold_a) ? 1U : 0U;
}
```

`Core/Src/main.c`仍要求模式正确且输出armed后才调用上述判定；返回故障时，原记录原始ADC、撤输出、锁存CURRENT_INVALID、Stop并立即return的流程不变。因此这次没有改动驱动器故障处理、控制器内部故障定义或编码器逻辑。

## 5. 对原17.338 A记录的ADC只读复核

已查配置：12位ADC、注入组每rank过采样16次、无右移；raw和offset均使用同一累加格式。最大16×4095=65520，可容纳在uint16；先以int32作差，再应用极性，最后只除16一次。没有找到这里的×16重复换算或整数溢出错误。

换算系数为：

```text
k = 3.3 / (16 × 4095 × 0.007 × 6.1)
  = 0.001179538650 A/累加码
U = -(45546 - 33729) × k = -13.9386082 A
V = -(19182 - 33881) × k = +17.3380394 A
W = -(U + V)           =  -3.3994312 A
```

这里33729/33881是由该次原始码与已记录电流反算出的零偏，并非新增外部测量。它们不能与后来重新上电的另一组零偏33744/33897混用。原始平均12位码约2846.625和1198.875，对应输入约2.294 V和0.966 V，未到ADC数字饱和；这说明故障记录确实来自显著变化的原始输入码，不只是串口显示错误。

PWM规划使用完整16次序列时长：每rank约9.524 μs、总19.048 μs，约3201个168 MHz计时tick。没有发现“实际跑16次，但只预留1次窗口”的明确错误。然而，规划窗口不等于已经证明运放在实际开关干扰后稳定；当前采样有效性检查及故障记录也不足以复原每次实际ADC/PWM时序。

待证的软件风险包括：HAL在FOC回调返回后才清JEOS/JEOC，动态触发点和接近50 μs的最长完整IRQ可能产生事件交错。现有数据没有证明实际吞事件，更不能证明它导致该电流值。此前13504 cycles记录是编码器 `feedback_age_cycles`，不是ADC控制间隔，不作为漏采证据。

因此本次既不宣布“确有17 A物理电流”，也不宣布“肯定是ADC噪声”。没有为取消跳闸而修改换算比例、隐藏峰值或把坏采样伪装成零电流。

## 6. 2 A电源限流的解释边界

电源端电流不能直接代替电机端相电流。PWM驱动器存在电压/电流变换和绕组续流；输入电流值不足以独立证明相电流峰值小于某个数值。该原理可查电机厂商 [maxon的PWM驱动电流测量说明](https://support.maxongroup.com/hc/en-us/articles/360012273994-Motor-current-measurement-in-case-of-a-PWM-power-amplifier)。这解释为什么用户给出的2 A设定不构成17 A读数必假的证明，不用于反过来证明本次读数必真。

本次遵照用户明确要求修改软件阈值，而不是基于“电源2 A保证电机相电流安全”的假设。硬件实际OCP阈值和动作能力没有在本次重新测量；保留其代码路径不等于完成对它的独立安全验收。
