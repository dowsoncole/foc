# 上电电流校准与编码器零点独立管理和持久化

## 需求与原有行为

用户要求每次上电实际执行约 1 ms 的电流校准；把编码器零点校准封装为隔离的业务模块，由独立结构体接收 D 轴电压和持续时间，默认 1.5 V、3 s；结束后存储，下次启动自动读取，当次不重启也能使用新零点。

原代码电流采样使用 `CurrentSampling_LoadBoardCalibration()` 直接装入 U=1893、V=1892 的历史常量。编码器自动启动每次执行 kind 10 电压对齐，零点在 RAM 中提交，没有持久化。

## 电流校准修改

1. 保留 OPAMP/ADC 启动后的 20 ms 模拟链稳定时间，这与约 1 ms 的校准采集时间分开。
2. 每次上电调用 `CurrentSampling_RequestCalibration()`，20 kHz 下目标 20 帧 U/V 完整注入序列。
3. 校准期间阻止 FOC 回调，并要求 MOE 始终为 0。
4. 完整采满后才提交均值；原始码触及 0/4095、任一相窗口跨度超过 64 码、采样不足超时均判失败。失败不提交新零偏。
5. 采样等待最长 5 ms；上电失败进入既有错误处理，不能用历史常量绕过。

## 编码器业务层

- `Servo/Inc/encoder_calibration.h`、`Servo/Src/encoder_calibration.c`：不依赖 HAL、SPI、FOC、SpeedCommission 类型；通过端口协调执行、停止、时间、存储和应用。
- 唯一管理对象 `g_encoder_calibration`，包含 `command/state/fault/requested/active/direction/pole_pairs/candidate_offset_rad/offset_rad/valid/loaded_from_storage/save_count/queued_ms`。
- 用户设置 `requested.d_voltage_v`、`requested.duration_s` 后写 `command=1`；`command=2` 取消。默认 1.5 V、3 s。
- 电压 `(0,2.8] V`，时间 `0.05～10 s`；实际执行还检查名义母线 18～28 V，以及电压不超过母线的 10%。10 s 上限保证 168 MHz DWT 单次计时不跨完整计数范围。
- 排队时复制本次配置到 `active`，后续改变 requested 不影响当前激励。
- 既有 kind 10 路径作为电压执行适配器，复用驱动安全、预充电、电流采样就绪、编码器有效性和 PWM 提交检查。
- 对齐时间结束前，用有效的最后受激原始角度计算 `wrap(-direction*pole_pairs*raw*2π/2²¹)`。ADC 只捕获结果，不擦写 Flash。
- 主循环确认输出请求、armed、预充电、控制器运行和硬件 MOE 均关闭后才保存；SPI 事务忙时稍后重试，避免让未完成事务跨越擦除停顿。
- 保存、读回校验成功后执行 `Encoder_ConfigureMotor()`，同步更新速度控制器的零点和 calibration_ok；重建测速历史，正常控制等待新的有效快照。用户主动重新校准结束后停机，由原有运行命令再次启动。

## 持久化与链接布局

- STM32G431VB 为 128 KiB Flash；预留最后两个 2 KiB 页面：`0x0801F000`、`0x0801F800`，页号 62、63。
- Keil 的 IROM 和实际 scatter 文件上限改为 `0x1F000`，CMSIS 工程也使用同一 scatter 文件。
- 每份记录 48 字节：magic、version、sequence、direction、pole_pairs、offset、voltage、duration、CRC32、reserved、64 位提交标志。
- 读取时只接受完整记录，按递增序号选择最新值，方向和极对数必须与当前配置匹配。
- 保存只擦除另一页，逐双字写入，最后写提交标志。未完成写入或 CRC 错误不能替代上一份有效记录。
- 存储使用底层 Flash 寄存器，关闭输出且处于前台时才执行；临界区保存/恢复 PRIMASK，DWT 检查忙等待，复位数据缓存后读回校验。
- Flash 写入会暂停同 Bank 的代码与中断，因此绝不在带输出的实时控制周期中执行。保存后测速历史重建，允许反馈恢复后再启动。
- 整片擦除、下载器选择全片擦除会丢失校准值；普通运行和上电读取不擦写。

## 上电及立即使用

存在有效 Flash 零点：电流校准 → 编码器初始化 → 读取/应用零点 → 等待反馈有效 → 原有自动位置保持。

无有效零点：电流校准 → 等待反馈 → 默认电压对齐一次 → 关闭输出 → 保存/应用 → 等待新反馈 → 原有自动位置保持。故障不自动重试。

- `run_calibration_tests.ps1`：20 帧采集、未采满不提交、回调屏蔽、超时/DWT 毫秒回绕、ADC 触轨、MOE 约束；自定义配置锁定、输出关闭后才保存/应用、模拟重启读取、保存失败、取消、故障和等待超时；48 字节记录逐字节破坏与缺失提交标记检查。
- `run_speed_tests.ps1`：原速度/保护/外环调度/电压对齐回归通过；增加真实速度执行器的 1.0 V、0.1 s 对齐及结果提交测试；硬件电流策略回归通过。
- Keil 全量构建：0 error、0 warning；RAM 包含既有 2 KiB 栈，新增业务结构体采用窄状态字段并复用 main 生命周期内的配置副本，避免缩减采集缓冲区。

补充回归：`run_tests.ps1 -GccPath ...` 的 FOC/PI/电压执行/调制/7200 个电角度采样窗口测试全部通过；`run_encoder_tests.ps1` 的诊断模式 0、1、2 全部通过。清理了其中三处历史测试假设：旧 100 µs 截止时间、等待诊断使能前不采集数据、PA15 探针；测试现按 50 µs、持续采集及 PA0 的现有实现断言，没有改变生产编码器行为。

## 实机停机验证

1. 烧录前读取 `0x0801F000`、`0x0801F800`，记录区域均为空白；当前固件下载只擦除程序对应的第 0～36 页，没有擦除预留页。
2. 正式固件编译为 Code=74060、RO=1368、RW=5168、ZI=27584，0 error、0 warning。链接实际加载区域上限 `0x1F000`；RAM 区域大小 `0x7FF0`，包含既有 2 KiB 栈。
3. 使用复位停机与 main 断点，在执行任何上电运动流程之前把 RAM 中 `g_speed_run.enable` 设为 0，再运行初始化与主循环。
4. 两次启动均得到 `calibration_state=3 (DONE)`、`calibration_sample_count=20`、`calibration_target_samples=20`。第一次 U/V 零偏为 1894/1893，最终固件再次启动为 1892/1895，说明每次确实重新采集，而非装载历史常量。
5. `g_encoder_calibration` 状态空闲、command=0、requested=1.5 V/3 s、valid=0、loaded_from_storage=0；与 Flash 无有效记录相符。
6. `TIM1->ARR=4200`，`BDTR=0x02002054`，MOE=0；最终 RAM 自动运行标志保持 0。

正式产物保存在 `software/control_analysis/results/calibration_business_20261027/production.axf`、`production.hex`。本轮没有施加对齐电压，也没有向 Flash 写入虚构零点；实际带电压编码器对齐、真实 Flash 保存及断电重启读取仍需实机验收。源代码保留用户原有的自动启动设置：下次复位若仍无有效记录，将按默认配方校准一次并保存。

## 用户“继续”后的带电实机验收与衔接修复

本节为上述停机验证之后的新增实测，已执行真实默认电压对齐和 Flash 保存。

### 开始前的驱动状态

读取到 GPIOE IDR=`0x4000`：READY=1、nFAULT=0；驱动工作状态 FAULT，STATUS=`0x88`，软件保留历史欠压锁存。当前 STATUS 不报告持续欠压、过热或 VDS 保护。MOE=0、运行请求为 0。

通过现有 `DRV_REQ_CLEAR_FAULT` 请求清除历史锁存，没有直接改 READY/nFAULT 或软件故障判断。下一次监控后 STATUS=`0x80`、GPIOE IDR=`0xC000`、驱动状态 READY，才发起校准。

### 第一轮真实校准与发现的问题

以 `g_encoder_calibration.command=1` 请求默认 1.5 V、3 s。完成时：

- 独立校准状态 DONE=4、fault=0、valid=1、save_count=1。
- 75 条 40 ms 间隔电压执行记录，elapsed 约 3.00005 s。
- 得到零点位模式 `0x3EC32BE0`，即约 `0.3811941147 rad`。
- 校准对象 offset、速度参数 electrical_offset、编码器内部 electrical_offset、Flash 记录 offset 完全一致。
- 第 62 页记录 sequence=1，CRC=`0xD3930B8E`，末尾提交标记完整；第 63 页仍为空白。
- 完成后 MOE=0，运行和控制器故障为 0。

随后发起原有位置启动命令，被拒绝且 `g_output_position.fault=5`。源码核对发现：保存成功后 `g_speed_test.state` 仍为 DONE=3，而位置启动接口要求底层执行器 IDLE=0。这是状态交接问题，零点计算与存储已成功。

修复：`MainEncoderCalibration_Apply()` 仅在电压执行器成功完成、无故障、输出关闭时释放其 state 到 IDLE；独立校准对象继续保留 DONE 结果。上电首次校准衔接也改为检查独立对象 DONE 与底层 IDLE。更新主机回归覆盖此交接，未清除任何真实运行故障。

### 修复后的验收

1. Keil 编译 0 error、0 warning，Code=74088、RO=1368、RW=5168、ZI=27584；修复版已烧录。下载只擦除程序页 0～36，已有第 62 页记录保留。
2. 启动读取第一次存储结果，`loaded_from_storage=1`、valid=1、calibration_ok=1，零点仍为 `0x3EC32BE0`；未重新对齐、未增加写入次数。
3. 再次发起默认对齐。成功后独立 state=4、底层 state=0，结果同为 `0.3811941147 rad`。第 63 页新增 sequence=2、CRC=`0x8B8DA2A6`，第 62 页 sequence=1 保留。
4. 不复位，直接写原位置 command=1，运行约 0.7 s：位置 state=1、fault=0；速度 state=2、fault=0；FOC 与运行故障均为 0，MOE=1。目标和实际位置位模式均为 `0x43B27262`，位置误差为 0，未要求额外位置移动。
5. 写原位置 command=2 后，MOE=0、enable=0，正常停机。
6. 进行一次正常复位、保留源代码默认自动启动：约 0.7 s 后，校准对象 state=IDLE、loaded_from_storage=1、valid=1、save_count=0，位置保持已正常运行，故障均为 0。这证明启动直接读取已存零点并跳过 3 s 对齐。随后正常停止。
7. 第三次默认对齐，用来验证已有记录页面的实际擦除和复用：第 62 页变为 sequence=3、CRC=`0x0AA8C781`；第 63 页 sequence=2 保留。结果依旧为 `0.3811941147 rad`，校准无故障且 MOE 自动关闭。
8. 最后复位时在 main 停住并设 enable=0，确认最新固件能加载存储零点；最终保持停机，位置/FOC/运行故障均为 0，BDTR=`0x02002054`、MOE=0、enable=0。
