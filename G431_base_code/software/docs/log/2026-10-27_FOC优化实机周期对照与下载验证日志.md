# FOC 优化实机周期对照与下载验证

## 结论

STM32G431、168 MHz 实测证实此次等结果优化有效：线性未饱和平均节省约 0.481 µs，线性饱和平均节省约 0.576 µs。修改前后完整算法对象在目标 MCU 上比较一致。

这是算法本体 `FOC_AlgorithmStep()` 的周期对照，不是完整 ADC IRQ 时间或带载闭环性能验收。此前示波器观测的约 3.4 µs 波动尚未证实消除。

优化后的正式固件已下载并校验。最终 MCU 正常运行、输出请求为零、控制器故障为零、MOE 关闭。编码器仍有偶发 CRC 错误。

## 设备与初始状态

- 探针：ST-LINK，序列号 `E1007200D0D2139393740544`。
- MCU：STM32G431，Device ID `0x468`，Rev X，Flash 128 KiB。
- ST 工具读取目标电压约 3.24 V。
- 主频：通过 `SystemCoreClock` 与测试结果头读取，168,000,000 Hz。
- 初始 MCU 运行，TIM1 BDTR=`0x02002054`，MOE=0。
- 初始软件有旧的故障锁存，不能把旧的运行片段当成本轮同条件对照。

下载前备份整个 128 KiB Flash 到 `software/control_analysis/results/foc_target_20261027/original_flash.bin`。SHA256 为 `6042C2F9FFC595706FB5D88B116A8E46445AAF7B508A922FD8927BB8409106C6`。

## 实机测试方法

新增测试入口 `software/servo_v1/Tests/Target/foc_timing_benchmark.h`，仅在 `FOC_TARGET_TIMING_BENCHMARK=1` 的专用测试构建中运行。

1. 使用原工程的 `HAL_Init()` 和 `SystemClock_Config()`，随后立即执行测试。
2. 此测试不初始化电机外设，不启动 TIM1/ADC/SPI，不设置 MOE；测试结束保持在等待循环。
3. 同一镜像包含保存的修改前算法及当前算法，参数、输入和调用方式相同。
4. 修改前调制函数标记为 `noinline`，避免与其测试调用者处于同一编译单元而被跨函数内联，保持原分离编译的调用边界。
5. 两侧通过相同的 volatile 函数指针调用，逐次交替先后顺序，减少固定调用次序的偏差。
6. 每组先预热 32 次，再分别计时 10,000 次。时间包含 DWT 读数及间接调用开销，两侧相同，未人为扣除。
7. 计时期间暂时屏蔽中断，计时结束恢复原中断状态。因此结果用于算法比较，不包含 ISR 抢占和外设竞争。
8. 每一对计算后，逐字节比较整个 `foc_algorithm_t`，包括输出和 PI 积分状态；预热样本也参与一致性检查。

共计 60,000 对计时样本、60,192 对状态检查，差异计数为零。未饱和组使用零积分增益，避免长时间累计后变成饱和组；其余有效组使用同一组非零积分增益，保持前后状态同步。

| 线性饱和 | 9.681685 | 9.105705 | 0.575979 | 5.95% |
| OVM1 | 12.839440 | 12.740039 | 0.099402 | 0.77% |
| OVM2 | 13.714440 | 13.555515 | 0.158926 | 1.16% |

## 下载异常与恢复

首次使用 pyOCD 的 Pack Flash 算法下载测试镜像，出现 `flash erase sector timed out`。随后读到向量表区为 `0xffffffff`、CPU Lockup；MOE 仍为零。此次擦除已影响程序区，原镜像的完整 Flash 备份已提前保存。

改用 ST 官方 `STM32_Programmer_CLI.exe` V2.20.0，以 Under Reset、硬件复位连接方式下载。测试镜像和最终正式镜像均得到 `Download verified successfully`，随后执行复位启动。没有继续使用失败的 pyOCD 擦写算法。

测试镜像及构建日志保存在结果目录的 `benchmark.axf`、`benchmark.hex`、`benchmark_build.log`。

## 正式固件恢复与状态检查

- 已移除工程中临时添加的 `FOC_TARGET_TIMING_BENCHMARK=1`，测试入口默认值为 0。
- 工程文件中的其他已有定义保持原样。
- 正式构建：`0 Error(s), 0 Warning(s)`，Code=65768、RO-data=1384、RW-data=5136、ZI-data=27224 字节。
- 正式镜像：结果目录 `optimized.axf`、`optimized.hex`。
- `optimized.hex` 的 SHA256：`C11B6DEC5D64A47806A0E11A64901813810566E506007544A3C4AFE9389B5C25`。
- 构建日志：`production_build.log`。

正式固件保留原有上电自动启动配置。复位恢复后，观察到已有自动启动流程曾设置输出请求并使能 MOE；已通过原有 `output_request=0` 接口停止，没有修改启动策略、PI 配置或保护规则。不能把本轮所有步骤描述为“从未使能 MOE”；只有专用算法测试镜像明确不启用电机外设。

最终重复检查：

- 核心状态 Running。
- TIM1 BDTR=`0x02002054`，MOE=0。
- `runtime` 前六字节为 `[0,0,0,0,1,0]`，即停止、无输出请求、未武装、无预充、安全门有效、输出关闭。
- `g_foc_controller.fault_flags=0`。
- PWM 窗口拒绝和提交时限拒绝均为零。

## 编码器独立观测

在正式固件输出关闭期间，用非停止读取获取相隔约 2 秒的两次诊断快照：

- 有效完成计数增加 20,077。
- CRC 错误增加 3。
- busy、启动错误、传输错误、角度跳变错误、FOC 截止超时计数均未增加。

原始快照为 `off_encoder_1.bin`、`off_encoder_2.bin`。停机时仍有 CRC 错误，说明当前通讯问题并没有随此次算法优化消失；本记录不把 CRC 根因直接归到 FOC。

## 尚未完成的验收范围

此次已证明算法本体变快且目标 MCU 上计算状态一致。完整 ADC 中断的前后波形对照、运行工况下的慢周期捕获，以及带载电流/速度/位置表现仍需单独验证，不能以本轮平均算法时间替代。
