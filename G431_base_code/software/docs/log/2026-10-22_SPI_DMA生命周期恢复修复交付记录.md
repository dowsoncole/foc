# 编码器 SPI/DMA 恢复修复交付

日期：2026-10-22（北京时间）。目标：STM32G431VBTx，Keil target `servo_v1`。

已完成软件修复、主机验证和固件构建。本次没有下载或运行新固件；下载前 ST-Link 从系统中断开，用户要求先交付代码和固件。实际启动/带载 CRC 故障是否消除仍待实板验证。

## 文件

- `firmware.hex`：Intel HEX 固件，包含 Flash 地址。
- `firmware.axf`：带调试符号的固件，用于 Keil 或调试器。
- `firmware.bin`：完整 Flash 加载镜像，烧录起点 `0x08000000`，长度 62064 字节。
- `firmware.map`、`build.log`：链接布局及最后一次构建结果。
- `source/`：本次编码器收发、协议、服务、IRQ、探针及主机测试相关源码快照。完整固件工程仍在工作区 `software/servo_v1/`。
- `analysis_reviewed.md`：复核后的分析文档。
- `analysis_before_review.md`：复核前说明的存档，仅用于追溯，不作为当前结论。
- `encoder_tests.log`：真实驱动/协议/编码器服务的寄存器故障注入测试结果。
- `verify_encoder_artifacts.py`：只读核对 AXF、HEX、BIN 的完整 Flash 加载数据，不连接硬件。

## 软件修复

1. 异步 SPI/DMA 启动、结束和恢复由驱动统一拥有，移除与 HAL 私有 DMA 回调混用的快速重装路径。
2. DMA RX/TX 错误、SPI OVR/MODF/FRE、未完成 RX TC、超时 Abort 都走有界清理。异常时释放 CS、停 DMA 并 RCC 复位，不在关中断或最高优先级 ISR 里等待 SysTick。
3. 正常帧结束关闭 SPE；启动前建立模式 3 空闲电平，满足片选建立时间，再开 DMA 请求。重新启动前清除残留 DMA 标志和待决中断。
4. 软件所有权空闲时，残留 BSY/CNDTR/通道状态触发清理，而不是无限拒绝恢复。复位使用初始化时保存的配置，保留 MODF 可能清除的主机位。
5. 同步和异步事务互斥，片选只由收发驱动管理，阻塞调用遇忙不再误释放 DMA 的 CS。阻塞接口仅供线程上下文。
6. CRC、合法传感器报警、物理角度步长和 150 µs 新鲜度检查继续生效；恢复不会清除控制器故障或自动重新使能电机。

## 验证

- 编码器主机测试通过：TX 单独错误及 RX/TX 同时异常、SPI OVR/MODF、卡住的 BSY、冻结 SysTick 的 Abort、重复 IRQ、残留通道、互斥、恢复后重新采集、CRC 拒绝、时间戳不刷新、DWT 回绕、连续坏帧过期和传感器报警。
- 速度环主机回归通过，其中 CRC 的全部 16777216 个输入与原位算法一致。
- FOC 主机回归通过，包含 PI/限幅/故障、调制及实际 ADC 采样窗口。
- 逻辑分析仪解析器 13 项测试通过。
- Keil ARM Compiler 6.24：`0 Error(s), 0 Warning(s)`；Code=60492，RO=1392，RW=4892，ZI=25844。
- AXF/HEX/BIN 全部 62064 字节加载数据一致，包含 RW 初始化尾部。本次旧的 `verify_flash_image.py` 只比较 61884 字节的 `ER_IROM1` 执行区，不适用于完整 BIN；因此使用本包的新验证器核对 ELF `PT_LOAD`。这是文件一致性验证，不是板端 Flash 读回。

复验命令（在本目录）：

## 实板尚待验收
