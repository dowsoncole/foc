## 来源与口径

用户先提供 `0——20251024 测试问题反馈.docx`，要求位置模式按给定指令观察幅值、相位并生成 Markdown 说明；随后补充 `客户需求PWM给定方式.xlsx`。

Word 文字序列为 1501～1520～1500 μs、每周期 40 点，1～30 Hz、每频点运动 2 秒和休息 2 秒。附图正负正弦与文字单边序列有冲突，33 μs 也应为 33.333 ms。保留文字口径为 `test_mode=1`，总时长 120 秒。

补充 Excel 的可见表 `PWM table due 1 sec!B1:P301` 明确列出 1～15 Hz、每秒 300 个逐帧脉宽，另一可见表 `QTY of PWM Signals` 使用 300 Hz。它与 Word 的 333 Hz 和完整 40 点序列有差异。因此新增 `test_mode=2` 严格复制 4500 个值，每列的一秒序列重复两次，每频点休息 2 秒，总时长 60 秒。上位机 `--customer-protocol` 默认选择此 Excel 模式；Word 需显式 `--customer-source word`。Excel 未给出 16～30 Hz 逐帧数据，没有外推。

Excel 原文件 SHA256：`a106c254ccb2f595118bef84115075920d0de21538f7eea85644652a6ba658f1`。

4500 个 `PWM-1500` 字节 SHA256：`6ef3a8b871ce95ea824741f29d082f665001385478c52530d84f592d1753421d`。只读提取后逐个核对生成表，**4500/4500 一致**。1～15 Hz 各列的最大非 DC DFT bin 均与列头频率一致；各列基波峰值不同（约0.796～0.884°），不能统一拿 2° 当基波分母。

隐藏的 `АФЧХ` 表有历史幅相数据和边界，但相位公式的弧度/度标注冲突、延迟单位可疑，空延迟还生成 0；没有把这些数值当作新实测、自动验收条件或相位算法依据。隐藏计算表的正弦表达式也没有覆盖可见逐帧指令。

## 实施

- `g_output_position_customer.test_mode` 在轨迹 command=1 时锁存；0 为旧轨迹，1 为 Word，2 为 Excel。上电默认为 0，不自动执行新流程。控制入口仍是位置模式 5。
- 相对起点执行 0～2° 指令，FF 固定 0，普通斜坡 300000 rpm/s。Kp72、默认5500 rpm、原三环参数、MPT反馈、电流 FLT_MAX/硬件OCP策略及 PWM 写入门槛均未修改。
- 以绝对毫秒时间定位指令槽，避免累计取整漂移；Excel 300 Hz 帧边界在 1 ms 调度上量化为 3/4 ms。记录真正漏过的帧槽，不把原表有意跳过幅值点视为 MCU 漏点。
- 每组 2 秒运动窗口对参考和实际各做带 DC 的基波最小二乘，发布基波幅值、增益、主值相位、样本数和异常 flags。结果为包含启动暂态的短窗口估计，未冒充原稳态正弦 FRD/Welch 带宽证据。
- 30行×32字节结果和原64行×16字节trace共用1024字节union。原 `output_position_test_t` 保持84字节；`position_abi.py` 能解析新 union 与旧 R17 冻结 ELF。
- 幅相结算只在前台进行；故障/停机后的部分结果在前台收尾，不在20kHz ISR或关中断的停机临界区里执行拟合、对数与反正切。
- 主机沿用全 Flash 匹配、OFF 预检、10秒心跳保护、状态/电流检查与 finally 停机。异常时也尝试保存部分结果。报告输出 Markdown、CSV、JSON 和幅相图。离线导出需指定与运行相符的 xlsx/word 来源。
