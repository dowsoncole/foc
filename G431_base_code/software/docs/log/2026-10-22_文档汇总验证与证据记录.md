# 2026-10-22 构建、主机测试与复现实验记录

## 1 验证范围与结论

本次为代码审查和文档编写，没有修改固件源码，没有烧录、连接功率台架或驱动电机。执行了完整Keil重编译、三组现有主机测试，以及三个针对审查结论的临时主机复现实验。

完整构建与三组测试通过。复现实验确认三个当前行为：普通连续速度模式在ADC回调停止后仍维持运行请求；极大有限电角偏置会导致配置函数不返回；长时间编码器失联后多圈位置仍会按最短单圈差更新且没有连续性失效标志。

复现成功表示“问题被观察到”，不表示问题已经修复。主机桩不能证明实际栅极关断时间、PWM时序或负载位置带宽；这些必须按后续模块路径在目标板验收。

## 5 三个问题的最小复现

临时测试复用原主机桩和辅助函数；只在临时目录产生包装翻译单元，把原测试main改名后加入专用入口。没有改动原测试文件。以下步骤足以按相同源文件重建复现，具体辅助函数名来自现有测试。

### E1 普通连续速度模式失去ADC回调

步骤：在速度测试环境执行`reset(7)`、`arm()`、正常`run_ms(100)`；随后只将DWT推进`SystemCoreClock/10`，不再执行ADC参考回调；调用一次`SpeedCommission_Service(0)`。

观察：

```text
after 100 ms without ADC callback: state=2 fault=0 enable=1
```

意义：连续模式后台没有因此撤销运行请求，验证R02缺口。桩中的enable不是物理MOE，不能把这条主机日志描述为示波器已观察到栅极维持100 ms。真实输出后果需结合PWM独立运行与目标板故障注入验证。

### E2 极大有限偏置导致归一化不结束

步骤：在编码器测试环境初始化后调用`Encoder_ConfigureMotor(1, 2, 1.0e20f)`；设置3 s外部进程执行上限。

观察：进程超过3 s被终止。该项预期是超时，因此复现实验成功，但不是函数成功返回。临时汇总中的编译退出码0不应误读为被测进程正常退出。

依据：float为1e20量级时减2π不改变数值，循环条件持续成立；实际源码在关中断段执行该归一化。当前SpeedCommission另有限幅，因此报告将其定位为公共API输入契约缺陷，不称当前正常启动必现。

### E3 长失联后多圈位置没有连续性标记

步骤：初始化并配置编码器；在DWT=8400时接收raw=100000的合法帧；时基推进1 s后接收raw=100010的合法帧；读取快照。

观察：

```text
after 1 s missing feedback: valid=1 delta_count=10 faults=0
```

意义：这两个单圈采样既可能相隔10个计数，也可能相隔整圈加10个计数；现有算法只能选择最短差，但没有额外标明多圈连续性已不可证明。实验并未测到真实轴转了一圈，它证明接口无法区分这些物理可能性。
