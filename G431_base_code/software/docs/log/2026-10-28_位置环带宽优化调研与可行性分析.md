## 1. 电流环：调试优化过程还原

### 1.1 当前生效参数

**注意单位**：电流环 PI 输出是 **pu（标幺电压）**，不是伏特。母线基准 24 V。

### 1.2 整定方法演进（三阶段）

1. **2026-10-20 模型初值阶段**：MATLAB `tune_current_pi.m` 有限网格搜索 + 合成数据自检。结论被明确否定——电机 R/L 从未实测，「示例参数不应用于实际电机」（`2026-10-20_固定零电角度DQ电流环工作日志.md` 第 7~8 节）。
2. **2026-10-21 实测候选比较阶段**：12 组实机候选实测比较，选出 `Kp=0.0025 / Ki=1.6` 作为折中候选（`2026-10-21_PI候选实测比较与续测状态.md:31-48`）。
3. **2026-10-27 标定后重整定（当前版本）**：先完成真实安培比例标定，再对 5 组候选做阶跃 + 10~1200 Hz 正弦扫频，综合时域与频响选定 `0.05/100`。

### 1.3 旧增益为什么必须换（关键教训）

旧 `Kp=0.0025` 在 0.30 A 阶跃起始只给出 `0.0025 × 0.30 × 24 = 0.018 V` 比例电压，响应需 55 ms，10 Hz 已明显衰减（`2026-10-27_电流环时域与频域优化.md:56`）。新 Kp 对应 0.36 V，提高 20 倍；Ki 每拍积分增量提高 62.5 倍。

### 2.2 调试演进：带宽从 12.6 Hz → 85.9 Hz

**阶段一（10-21）：PRBS 辨识 + MATLAB pidtune**
- 旁路速度 PI、保留电流内环，采集真实 Iq PRBS → 速度响应，做 TF/ARX/OE 对照、独立数据验证、spafdr 与相干性分析。
- 修正激励更新与采样节拍不同步后，重复周期输入一致率由 97~98% 提到 **100%**（`2026-10-21_速度闭环详细工作日志.md:343-364`）。
- 实测闭环：**共振峰 +9.10 dB @ 8.55 Hz**，−3 dB 跨越 **12.57~12.92 Hz**。
- MATLAB `bandwidth(g)` 返回 15.91 Hz，但**最低频增益异常偏低（−5.18 dB），被明确拒绝作为验收带宽**（`未注明日期_MATLAB速度辨识与整定结果汇总.md:45`）。
- 阶跃：正向 +2 rad/s 超调 **31.06%**、上升 43.2 ms；反向超调 13.31%、上升 33.7 ms；**调节时间三组全部「未达到」**。
- **模型验证拟合仅 52.55%（零偏置）/ 65.05%（同步修正后），未通过 70% 联合门槛 → 候选 PI 明确「尚未通过性能验收」**（同上 `:9`、`:16`）。

**阶段二（10-28）：正弦扫频实测 FRD + balanced 重整定（当前版本）**
- 方法改为**逐频正弦外部激励实测闭环 FRD**，再 MATLAB pidtune 设计，候选交叉频率扫 5~20 Hz，最终选「balanced」档（≈8 Hz 请求交叉）。
- 实测闭环带宽 **85.886 Hz**（80~100 Hz 区间插值），峰值增益仅 **+0.845 dB**（共振峰被压掉）。

- 来源：`results/speed_response_20261028/balanced_matlab_measured_evaluation.json:187-307`。

### 2.3 速度环带宽提升的三个决定性改动

1. **速度反馈滤波 τ 从 10 ms 降到 1 ms**（`encoder.c:18`）。10 ms 一阶低通在 16 Hz 处已产生 45° 相位滞后，是原判定「最大瓶颈」（`电流环速度环验收标准.md:23,62,185`）。降到 1 ms 后 20 Hz 处滞后仅 4.4°（推导：`atan(2π·20·0.001)`）。
2. **电流环带宽先行提升** 500~600 Hz（10-27 完成），为速度环提供了内环支撑。
3. **PI 由「PRBS 辨识 + 低拟合度模型」改为「实测 FRD + pidtune」**，绕开了拟合度只有 52~65% 的不可靠模型。

## 3. 位置环：实现深度剖析

### 3.1 控制结构（级联）

```
输出轴位置 P + 轨迹速度前馈 (200 Hz, MPT T485 RS485 编码器)
        ↓ motor_rpm
电机速度给定斜坡 (2000 rpm/s, 位置模式)
        ↓
速度 PI (1 kHz, MT6701 编码器, τ=1 ms)
        ↓ iq_reference
电流环 PI (20 kHz, Kp=0.05/Ki=100)
        ↓
SVPWM → STSPIN32G4 → 电机 → 202:1 减速器 → 输出轴
```

来源：`Servo/Src/output_position.c`、`2026-10-26_MPT输出轴位置闭环接入与实机验收.md:94-96`。

### 3.2 控制律（`output_position_math.c:3-18`，全文 18 行）

```c
uint8_t OutputPosition_Compute(float target,float actual,float kp,
                              float max_rpm,float deadband,int32_t direction,float *rpm)
{
  if(!rpm || !isfinite(target) || !isfinite(actual) || !isfinite(kp) ||
     !isfinite(max_rpm) || !isfinite(deadband) ||
     kp<=0 || kp>10 || max_rpm<=0 || max_rpm>OUTPUT_POSITION_MAX_MOTOR_RPM ||
     deadband<0 || deadband>1 || (direction!=1 && direction!=-1)) return 0;
  float error=target-actual;
  if(!isfinite(error)) return 0;
  /* omega_output[deg/s] * gear_ratio / 6 = motor RPM. */
  float result=fabsf(error)<=deadband ? 0 : error*kp*(202.0f/6.0f);
  if(result>max_rpm) result=max_rpm;
  if(result<-max_rpm) result=-max_rpm;
  *rpm=result*(float)direction;
  return 1;
}
```

**逐行剖析：**

| 行 | 内容 | 评注 |
|---|---|---|
| 8 | `kp>10` 直接返回 0（故障） | ⚠️ **硬性瓶颈**。kp 上限 10 → 带宽上限 `10/2π = 1.59 Hz` |
| 13 | 死区内 P 输出置 0，否则 `error*kp*202/6` | 202/6 = 33.667，即每 1° 输出轴误差产生 33.667·kp rpm |
| 13 | **纯 P，无积分项** | 稳态误差靠速度前馈补偿，无零稳态误差保证（摩擦/负载扰动下会有常值偏差） |
| 14-15 | 对称限幅 ±max_rpm | 限幅即饱和，大误差时环变成非线性 |
| 16 | 乘 direction | 已实机标定为 +1 |

调用侧叠加前馈（`output_position.c:114-118`）：

```c
if(!OutputPosition_Compute(target,actual,kp,max_rpm,deadband,direction,rpm)) return trip(3);
g_output_position.error_deg=target-actual;
*rpm += g_output_position.velocity_deg_s*(202.0f/6.0f)*direction;   // 速度前馈
if(*rpm>max_rpm) *rpm=max_rpm;                                      // 前馈后再限幅
if(*rpm<-max_rpm) *rpm=-max_rpm;
```

**完整控制律**：
```
motor_rpm = direction × [ P(error) + velocity_ff × 202/6 ]，限幅 ±max_motor_rpm
P(error) = (|error| ≤ deadband) ? 0 : error × kp × 202/6
```

### 3.4 反馈通道：MPT T485 输出轴编码器

- 型号 MBS-15-32-A-17M-T-N-C-M，USART1（PA9/PA10/PA8 方向），**2,500,000 baud，8N1**，T485 协议（非普通 R485）。
- 发 `0x1A`，收 11 字节；角度 **17 位，131072 counts/rev**。
- **每 5 ms 仅发起一次读取**（`mpt_t485.c:114`），响应超 2 ms 未完成记超时。
- RX 用 DMA1 Ch3，PA8 方向翻转用 TIM7 单脉冲 + DMA1 Ch4 自动写 BSRR，CPU 不关中断等待。
- 角度展开：相邻单圈差值 >512 counts 判为跳变 `trip(4)`（`output_position.c:109`）；**不做最短路径折返**（359°→1° 按负方向走 358°）。
- 实测：静止通讯 6.3 万帧，CRC/格式/状态/超时/UART 五类错误均为 0；闭环运行期间读取频率实测 **200.0 Hz**。

### 4.2 目标工况需求 vs 硬件极限

正弦 `θ_out(t) = A·sin(2πft)`，A = 2°，f = 20 Hz：

```
电机侧幅值      A_m  = A·(π/180)·N = 0.03491 × 202 = 7.051 rad
峰值转速        v_m  = A_m·ω      = 7.051 × 125.66 = 886.1 rad/s = 8461 rpm
峰值角加速度    α_m  = A_m·ω²     = 7.051 × 15791  = 111347 rad/s²
所需扭矩        T    = J·α_m      = 8.651e-6 × 111347 = 0.963 N·m
所需电流        I    = T/Kt       = 0.963 / 0.0252 = 38.2 A
```
（推导，公式与代入值如上）

| 需求项 | 需要 | 硬件极限 | 超出倍数 | 判定 |
|---|---|---|---|---|
| 电机峰值转速 | 8461 rpm | 9000 rpm（软件）/ **~7900 rpm（实测可持续）** | 0.94× / **1.07×** | 实测已越界 |
| 电机峰值电流 | **38.2 A** | 5 A 额定 / 7.4 A 最大连续 | **7.6× / 5.2×** | **不可达** |
| 所需扭矩 | 0.963 N·m | 0.177 N·m 最大连续 | **5.4×** | **不可达** |
| 速度指令变化率 | 1.06×10⁶ rpm/s | 2000 rpm/s（位置模式斜坡） | **531.6×** | **不可达** |
| 速度前馈 | 251.3 °/s | ±75 °/s（超限 trip） | 3.4× | **触发故障停机** |

**结论：±2° 幅值与 20 Hz 频率同时满足，在当前电机 + 202:1 减速器上物理不可达。**
瓶颈是**扭矩/电流**（7.6 倍超载），属硬件极限，**与控制器参数无关，任何调参都无法解决**。

### 4.3 斜坡限幅对正弦频率的约束（缺陷 D2 量化）

幅值 A [rpm]、频率 f 的正弦，其速度指令峰值变化率为 `A·2πf`。斜坡限幅 R [rpm/s] 因此把频率上限压到 `R/(A·2π)`：

| 斜坡 R | A=67 rpm | A=423 rpm | A=2500 rpm | A=8461 rpm（±2°@20Hz） |
|---|---|---|---|---|
| **2000 rpm/s（当前）** | 4.75 Hz | 0.75 Hz | 0.127 Hz | **0.038 Hz** |
| 20000 rpm/s | 47.5 Hz | 7.53 Hz | 1.27 Hz | 0.376 Hz |
| 200000 rpm/s | 475 Hz | 75.3 Hz | 12.7 Hz | 3.76 Hz |
| 1063285 rpm/s（目标所需） | — | — | 67.7 Hz | 20.0 Hz |

**即：±2° 幅值下，现有 2000 rpm/s 斜坡把正弦频率上限锁死在 0.038 Hz，比 20 Hz 目标低 526 倍。**
这也解释了为何现有实测只在 0.1 Hz 做正弦——0.1 Hz 已需 5316 rpm/s，**本身就超出当前斜坡 2.7 倍**（现有测试靠 10 s 五次多项式平滑过渡规避了突变，`output_position.c:88-93`）。

### 4.4 相位预算：为何 200 Hz MPT 反馈撑不到 20 Hz（缺陷 D7 量化）

> ⚠️ **本节结论已被推翻，保留仅供追溯（千问工作助理 2026-10-28 修订）**
>
> 本节假设「MPT 反馈总延迟 8 ms = 5 ms 轮询 ZOH + **~2 ms 响应** + ~1 ms 计算保持」。
> 其中「~2 ms 响应」是把 `mpt_t485.c:121` 的**超时保护门限**当成了器件实际响应
> 时间，属错误假设。后续解析器件数据手册（`hardware/芯片资料/MPT Magnetic
> Encoder Datasheet v0.6(1).pdf` → 解析件 `MPT_datasheet.md:612-613`）发现：
> - 器件 **Update Rate = 50 kHz**，内部每 20 µs 更新一次单圈绝对角度；
> - RS485 单次往返**线时间仅 48 µs**（(1+11) 字节 × 10 bit ÷ 2.5 Mbaud）；
> - 故「2 ms 响应」不成立，**5 ms 轮询是纯软件选择，不是硬件极限**。
>
> 严格延迟模型重算（见 §8.1）：5 ms 轮询时 20 Hz 处 **PM = 32.5°**（仍 FAIL），
> 1 ms 轮询时 **PM = 61.3°**（PASS）。
> **本节「11.3°」与「必须换反馈源」两个结论均不再成立**——维持 MPT 反馈
> 并把轮询周期降到 1 ms 即可支撑 20 Hz，这正是用户选择的方案。
> 下方「改用 MT6701 得 58.1°」的对比也随之失去意义：1 ms 轮询的 MPT
> 通道（61.3°）已优于该估算值。

位置环开环 = 位置控制器 × 速度闭环 × 积分器(1/s) × 反馈延迟。在 20 Hz 处：

| 环节 | 相位滞后 | 依据 |
|---|---|---|
| 速度→位置积分器 1/s | **−90.0°** | 结构固有 |
| MPT 反馈总延迟 8 ms（5 ms 轮询 ZOH + ~2 ms 响应 + ~1 ms 计算保持） | **−57.6°** | ⚠️ 该延迟假设已推翻，见上方修订说明 |
| 速度闭环 @20 Hz | **−21.1°** | `balanced_matlab_measured_evaluation.json:247,268`（实测） |
| **开环总相位** | **−168.7°** | |
| **相位裕度** | ~~**11.3°**~~ ⚠️ 已推翻 | 该值建立在错误的「8 ms 延迟」假设上；严格模型下为 32.5°（5 ms 轮询）/ 61.3°（1 ms 轮询），见 §8.1 |

**改用电机侧 MT6701 @1 kHz 反馈**（延迟约 1.5 ms）：

| 环节 | 相位滞后 |
|---|---|
| 积分器 1/s | −90.0° |
| 反馈延迟 1.5 ms @20 Hz | −10.8° |
| 速度闭环 @20 Hz | −21.1° |
| **开环总相位** | −121.9° |
| **相位裕度** | 58.1°（⚠️ 该对比已失去意义：1 ms 轮询的 MPT 通道得 61.3°，已优于此估算值） |

**~~结论：20 Hz 位置带宽在架构上要求电机侧高频反馈~~**

**修订后结论（千问工作助理 2026-10-28）：20 Hz 位置带宽要求的是「低反馈延迟」，而不是「电机侧反馈」。**
MPT 输出轴通道在 **1 ms 轮询**下总延迟约 **1.05 ms**（轮询半周期 0.5 ms + RS485 线时间 48 µs + 位置环 ZOH 半周期 0.5 ms），在 20 Hz 处仅吃掉 **7.6°** 相位，配合实测速度环 −21.1° 后相位裕度达 **61.3°**，满足验收要求 ≥45°。
本轮已按此实施：`OUTPUT_POSITION_PERIOD_MS` 由 `5U` 改为 `1U`（`mpt_t485.h:33`），反馈源仍为用户指定的输出轴 MPT，未切换到电机侧。

**但必须强调**：延迟只影响**相位裕度**，不影响**交越频率**（纯延迟 `e^{-jωT_d}` 幅值恒为 1）。
所以「带宽能到 20 Hz」的另一半条件是解除 `kp` 上限——原 `kp>10` 硬编码使 `fc` 被锁死在 `10/2π = 1.59 Hz`，这才是带宽数字上不去的直接原因（缺陷 D1）。两项改动缺一不可，见 §8.2。

## 6. 待用户决策的关键歧义

用户原话「当正负 2° 正弦扫频时，带宽可以到 20 HZ」存在两种互斥解读：

**解读一（小信号带宽口径）**：用**小幅值**扫频测闭环 −3 dB 带宽，要求该带宽值 = 20 Hz；「±2°」指工况/行程范围上限，不是扫频激励幅值。
→ **技术上可尝试**，但需先解决反馈延迟（B1/B2），且 ±2° 大信号下仍会饱和。这与项目自身验收文档 `:17` 的定义一致。

**解读二（字面满幅跟踪）**：以 ±2° 幅值真实跟踪 20 Hz 正弦。
→ **物理不可达**（§4.2，需 38.2 A / 7.6 倍超载）。必须放宽到 §4.5 包络内，例如「±2° 时 7.23 Hz」或「20 Hz 时 ±0.272°」。

两种解读导致完全不同的实施路径与验收标准，且涉及硬件安全，故中断确认。

## 8. 本轮实施记录（2026-10-28，千问工作助理）

### 8.1 严格反馈延迟模型（取代 §4.4 的估算）

位置环开环：`L(s) = kp · H_speed(s) · e^{-s·T_d} / s`

**关键推导：减速比 202 完全抵消。** 固件链路为
`error_deg --P(kp·202/6)--> rpm_cmd --H_speed--> rpm_actual --×6/202--> output_deg_s --1/s--> output_deg`
（`output_position_math.c:41` 与减速比反算）。代入后 202 消掉，故设计位置环**无需知道电机惯量、Kt、减速比**，只需实测 `H_speed` 频响。这是本轮能用离线脚本定量的根本原因。

**延迟 T_d 的严格分解**（三段串联，全部真实存在）：

| 环节 | 5 ms 轮询 | 1 ms 轮询 | 依据 |
|---|---|---|---|
| MPT 采样保持（半个轮询周期） | 2.50 ms | 0.50 ms | 主机按周期轮询，测量值平均等半周期才被取用 |
| RS485 线时间 | 0.048 ms | 0.048 ms | (1+11) 字节 × 10 bit ÷ 2.5 Mbaud，`mpt_t485.c:15` |
| 位置环 ZOH（半个更新周期） | 2.50 ms | 0.50 ms | 输出保持到下个周期 |
| **T_d 合计** | **5.05 ms** | **1.05 ms** | |

注：`mpt_t485.c:103` 把 `last_good_ms` 记为**请求时刻** `started_ms`，所以轮询周期与线时间都真实计入延迟，不能只算线时间。器件内部 Update Rate = 50 kHz（20 µs）相对上述量级可忽略。

**20 Hz 处相位裕度对比**（`kp` 取 20 Hz 交越所需的 158.3 /s）：

| 轮询周期 | T_d | 20 Hz 处 PM | 判定（门槛 ≥45°） |
|---|---|---|---|
| 5 ms（改动前） | 5.05 ms | **32.5°** | ❌ FAIL |
| 2 ms | 2.05 ms | 54.1° | ✅ PASS |
| **1 ms（改动后）** | **1.05 ms** | **61.3°** | ✅ **PASS** |

**一个重要的控制理论事实**：纯延迟 `e^{-jωT_d}` 幅值恒为 1，**只旋转相位、不改变交越频率**。所以降低延迟的收益体现在**相位裕度**上，而不是把带宽数字直接抬高。带宽数字由 `kp` 决定（§8.2）。两项改动缺一不可。

## 9. 实施后段：自查发现的三个自身缺陷与修正（2026-10-28，千问工作助理）

本节记录**我在本轮实施过程中自己引入、又自己发现的缺陷**。如实记录，包括一度损坏源码的事故。

### 9.1 缺陷一：正交解调虚部符号写反（严重）

**现象**：首版实现 `im=(qd_as*qd_tc-qd_ac*qd_ts)/sxx`，在 x=cos(ωt)、y=sin(ωt)（纯 −90° 滞后）工况下算出 **+90°（超前）**。

**为什么严重**：因果闭环系统的跟踪相位**只可能滞后**。若符号反了，全部相位反号，会把「稳定」误判为「不稳定」、把「不稳定」误判为「稳定」——这是会直接导致错误调参决策的缺陷。

**如何发现**：写验证脚本 `control_analysis/scripts/verify_quadrature_demod_sign.py`，用 4 个已知解析解的工况（−90°、0°、−45°、设计点 −118.7°）独立比对。variant A（首版）在 3 个用例上给出超前相位，全部判 WRONG。

**修正**：取共轭 DFT bin `X = xc − j·xs`、`Y = yc − j·ys`，则
`H = Y/X = [yc·xc + ys·xs + j·(yc·xs − ys·xc)]/sxx`
即实部不变、**虚部符号与首版相反**。已改为 `im=(qd_ac*qd_ts-qd_as*qd_tc)/sxx`，并新增 `reject=6`（相位超前即拒绝）作为运行期兜底自检。

### 9.2 缺陷二：单 bin 相干性恒等于 1（严重，永假门槛）

**现象**：首版按 `gamma² = |Sxy|²/(Sxx·Syy)` 计算相干性。但 `H = Sxy/Sxx`，故 `|H|² = |Sxy|²/Sxx²`，代入得

```
gamma² = |H|² · Sxx/Syy = (|Sxy|²/Sxx²)·Sxx/Syy = |Sxy|²/(Sxx·Syy) ≡ 1
```

这是**代数恒等式**，与噪声大小完全无关。数值仿真确认：注入 ±0.3° 噪声、乃至参考与反馈频率完全失配（20 Hz vs 47.9 Hz），单 bin 相干性**始终为 1.0000**。

**为什么严重**：`reject=5`（相干性 <0.9 即拒绝）成了**永假死代码**——反馈被污染时仍报 `valid=1`。这正是工程验收文档 `2026-10-22_闭环整定模块实施方案_规划记录.md:157`「设计频带相干性不低于 0.9」所要防止的「污染数据冒充带宽」。**门槛存在但永不生效，比没有门槛更危险**，因为它给人「已有质量把关」的错觉。

**如何发现**：变异测试 M3（移除相干性门槛）后测试**仍然 PASS** → 说明该门槛无任何用例覆盖 → 追查发现是被测逻辑本身无效，而非测试缺失。

**修正**：改用 **Welch 分段估计**。段长 `seg_len = round(1/(freq·period_s))` 取整数个信号周期（抗泄漏），每段独立估计 `X_i`、`Y_i` 后做跨段平均：

```
H1     = mean(Y_i·conj(X_i)) / mean(|X_i|²)
gamma² = |mean(Y_i·conj(X_i))|² / (mean(|X_i|²)·mean(|Y_i|²))
```

仿真验证（20 段，参考 20 Hz + 反馈含 23.7 Hz 失配分量）：Welch 相干性 **0.2519 < 0.9**，门槛确实生效；同时单 bin 值仍为 1.0000，印证退化。RAM 增量仅 9 个标量。
单 bin 值保留在 `coherence_bin` 字段作为**缺陷留证**，测试断言它恒等于 1——若将来有人把判定改回单 bin 版本，该断言立即失败。
新增 `reject=8`（分段数 <2）。

### 9.3 缺陷三：默认扫频时长导致 valid 恒为 0（静默失效）

**现象**：解调从第 1 个周期结束后才开始（跳过升余弦起振段），故累积周期数 = `dur·freq − 1`。首版默认 `dur = max(2 s, 4 周期)`，在 5~10 Hz 处只累积 9~19 个周期，**低于 20 周期门槛**，导致 `valid` 恒为 0。

**为什么严重**：这是**静默失效**——不报错、不 trip，只是永远测不出结果。比崩溃更难发现，容易被误认为「硬件有问题」。

**修正**：`dur = (MIN_CYCLES+1)/freq`，下限 2 s、上限 60 s。若 60 s 内仍凑不够周期数，`valid` 如实返回 0，**不伪造结果**。

### 9.4 门槛支配关系（如实记录的设计事实）

`seg_len` 恰好等于 1 个信号周期的样本数，而 `cycles = qd_n·freq·period_s = qd_n/seg_len`、`segments ≈ qd_n/seg_len`，两者数值相同。故 `cycles ≥ 20` 必然推出 `segments ≥ 20 ≥ 2`：

**⇒ `reject=8` 被 `reject=4` 严格支配，在当前段长选择下无法单独触发。**

原计划用「分段不足」构造测试用例，实测失败后查明此关系，**没有硬凑成能通过的断言**，而是：① 把用例 7 改为覆盖此前完全未测的 `reject=1`（无样本）路径；② 在固件与测试两侧都注明该门槛属防御性设计（若将来把段长改为多个周期以降低相干性方差，它才会变得可达）。

### 9.5 事故记录：一次自身操作失误损坏源码（已完全恢复）

**经过**：为验证测试有效性做变异测试时，我在同一 shell 会话里用 `$ErrorActionPreference='Stop'` 配合 `& $out 2>&1`。PowerShell 5.1 下原生程序的 stderr 经 `2>&1` 会变成**终止性错误**，导致函数内的还原语句**从未执行**；而 `Get-Content -Raw` + `Set-Content -Encoding UTF8` 又把无 BOM 的 UTF-8 文件按 GBK 读入再写出，造成**全文中文注释乱码**。`output_position.c` 一度同时处于「变异未还原」+「乱码」双重损坏状态。

**恢复**：用变异前的字节级备份 `$env:TEMP\output_position.c.bak2`（时间戳 14:35:13，即上次 `-Werror` 干净通过并 PASS 的那份）做 `ReadAllBytes/WriteAllBytes` 还原，**不经过任何编码转换**。还原后校验：字节完全一致、中文正确、无乱码、因果性/相干性/发布逻辑齐全，重新构建 `-Werror` 干净通过。

**教训与已采取的防护**：
1. PowerShell 5.1 下**禁止**对原生命令用 `2>&1`（stderr 已单独捕获）；
2. 变异测试改为**在隔离临时副本上进行，原文件全程只读不写**，从根本上消除「还原失败」的可能；
3. 变异后逐项校验 `original unchanged : True` 与 `no mojibake : True`；
4. 用 `Start-Process -RedirectStandardOutput/-RedirectStandardError` 分离重定向，替代 `2>&1`。

此事故未影响交付质量（最终源码经字节校验与全量测试确认完好），但过程有风险，如实记录。
