# 2026-10-21 持续速度闭环与15 A保护调试日志

本文件接续《2026-10-21_速度闭环详细工作日志》，不覆盖历史试验。记录后续“高速、速度闭环、持续转动、相电流保护改为15 A”的实现与复核。下文路径除特别说明外，相对于 `software/control_analysis/`。命令由代理执行，用户无需自行操作。

## 1. 结论和边界

持续速度闭环已实现、编译、下载并实机运行：编码器机械速度 → 1 kHz速度PI → Iq给定 → 20 kHz dq电流环 → PWM。位置环不参与；与最初固定电角度0的电流实验不同，旋转时电角度随编码器变化。

新接口是 `g_speed_run`，可在线改rpm给定，没有固定时长结束条件。过流、反馈失效、超速、驱动器故障和人工停机仍关闭输出，不自动清故障或重启。DWT回绕不会让持续运行超时。

已实测2000 rpm跟随，交付前复核已持续超过6分钟。继续提高给定时出现过电流异常尖峰、编码器报警或陈旧反馈保护，**没有达到最高转速，没有证明PI最优**。本轮主要修正运行入口、限幅、计时、换相零位与实时开销，不是完成新的MATLAB最优整定。

表格额定8534 rpm、空载9095 rpm不是当前装配系统已达到的转速。8500 rpm只是软件命令上限。当前装配、母线、电压利用率、负载、热条件及反馈可靠性均会影响可运行最高速度。

## 3. 原先为何没有持续高速转动

原入口是有时限commissioning试验：默认约10 rad/s、约2秒、较低电流限制；电流PI积分输出限幅仅±0.01 pu。单独改速度数值不会同时获得无限运行时间和足够电压。

最初持续入口仍保留0.8 A相电流保护。500 rpm能持续，700 rpm请求在实际约576 rpm、测得0.804445 A时触发保护。后续把运行模式、速度命令、电压及积分限幅、相电流保护和Iq命令上限分别处理。

另发现启动边沿竞争：主循环开头、结尾各读一次enable，调试器在两次之间写1可能被记录成“已见过1”，却未执行启动。改为每轮先读取一次快照，统一用于边沿判断，结束时再结合实际enable，避免吞掉请求。修复后已用非停机写RAM实际启动。

## 5. Watch接口和防误读

| 表达式 | 用法/含义 |
|---|---|
| `g_speed_run.enable` | 写1请求启动，写0关闭输出；启动前检查校准、输出已关闭、功率级安全、无故障及无冲突试验 |
| `g_speed_run.target_rpm` | 有符号机械转速给定，rpm，运行中可改 |
| `.applied_rpm` / `.actual_rpm` | 斜坡后给定 / 编码器实际机械转速 |
| `.turns` / `.elapsed_s` | 本次运行相对圈数 / 秒数 |
| `.iq_reference_a` / `.iq_a` / `.id_a` | 外环Iq命令 / 实测dq电流，A |
| `.uq_pu` | q轴电压命令，pu |
| `.phase_peak_a` | 本次已采样三相电流绝对值最大值；不是外部电流探头测量 |
| `.feedback_status_raw` | 编码器状态，故障时保留用于诊断 |
| `.state` / `.fault` | state=1等待反馈、2运行、3正常结束/人工停止、4故障；正常fault=0 |

故障后速度、圈数、dq电流等遥测可能冻结，不能仅看actual_rpm认定仍在转。需同时看enable、state、fault、PWM及采样更新。多字RAM读取不是高频同步记录，不能用几个Watch点计算电流纹波频谱。

target_rpm=0让速度参考斜坡归零，控制器仍可能输出；关闭输出用enable=0。软件测试覆盖在线反转，但没有进行本轮高速实机反转验收。重启默认enable=0、target=500 rpm、校准未确认，不自行启动；本轮在线2000 rpm与启动默认值不同。

## 6. 文件和实现要点

| 文件（相对software/servo_v1） | 作用 |
|---|---|
| `Servo/Inc/speed_commission.h` | kind=7、限值、speed_run_t接口 |
| `Servo/Src/speed_commission.c` | 连续参考、1 kHz PI、计时、遥测、反馈校验；保留kind1～6 |
| `Core/Src/main.c` | 启动边沿/互锁、参数切换、15 A采样保护、输出联动及退出恢复 |
| `Modules/Encoder/Inc/mt6835_crc.h`、`Src/mt6835.c` | 同语义快速CRC |
| `Modules/Encoder/Inc/spi1_encoder.h` | SPI分频对照说明，最终16分频 |
| `Tests/Host/test_speed_commission.c`、`run_speed_tests.ps1`、`speed_stubs/` | 编译真实速度模块的主机测试 |

计时以64位累加器累计每次32位DWT的无符号差值，避免168 MHz下约25.6秒回绕。64位周期/圈数转浮点移到主循环；短暂关中断只复制两项计数，避免每次20 kHz ADC中断做高开销转换。

连续模式不会因为旧duration到期或recorder满而结束。人工停止产生合法零参考并正常关输出，不再误记成无效参考故障。NaN/越界、超速、无效反馈、过长调度间隔仍拒绝/停机。故障清除不嵌入自动重试流程。

## 8. 电角度零位复核

旧direction=-1、pole_pairs=2、offset=4.17378143 rad来自此前较低电流对齐。重新固定电角度0记录通电稳定末段，得到不同机械角，故未继续把旧值视为充分可靠。

| 证据前缀 | 给定/实际电流 | 通电末20点机械角均值rad | 对应offset rad |
|---|---|---:|---:|
| `continuous_speed_realign` | 给定0.5 A | 6.15516090393 | 6.02713650068 |
| `continuous_speed_align2` | 给定2 A但旧积分限幅使实测仅约0.682 A | 6.14225101471 | 6.00131672224 |
| `continuous_speed_align_headroom` | 给定2 A，积分±0.05 pu；末段实测Id均值2.01423892 A，Iq均值-0.00098747 A | 6.10110461712 | **5.91902392706** |

第二行不能称为完成2 A对齐。第三行才有实测2 A依据。三次均有records.bin、config/start/read日志，3秒、记录分频24、125有效点。取通电末段，不用断电后可能回弹的位置。

对齐记录时编码器默认正方向；随后应用direction=-1，按Encoder_ConfigureMotor角度定义，offset=wrap(2×原始机械角)。最终RAM中direction=-1、pole_pairs=2、offset≈5.91902399（float）、calibration_ok=1。旧新差异约100°电角度量级，且不同保持电流结果也有差别；摩擦、负载和先前状态可能相关，本轮未证明唯一原因。

这不是高精度工厂标定，也未无条件固化为其他电机通用值。改变装配/角度定义、重新上电后应重新校准或复核，不能机械沿用旧位置。

## 9. CRC、SPI与实时性

原CRC为24次逐bit反馈循环，DMA完成路径约1006～1059 cycles。改16字节半字节查表，仍覆盖24位角度+状态、poly0x07、init0。主机穷举全部16,777,216种输入与旧算法比较，完全相同；没有关闭CRC。最终完成路径常见731 cycles，记录最大809 cycles。

SPI尝试分频16→32（10.5→5.25 MHz），CRC/陈旧反馈未改善，恢复16。更慢会增加事务占用和帧龄，不代表一定更可靠。此前日志已有类似对照，本次也没有据此确认硬件唯一根因。

最终高速度故障快照：CRC累计52、alarm1、busy0、transfer error0，事务最大2189 cycles；ISR最大8494 cycles≈50.56 μs，超过50 μs预算累计1次；速度模块所见最大间隔14813 cycles≈88.17 μs。其他优化后片段曾记录ISR最大8258/8391、超时0，但不能据此宣称所有运行严格零超时。累计诊断包含空闲、对齐及调试，不直接等于单次试验误码率。

原厂MT6835说明书状态bit0为转速过高警告。本次status1出现在机械约2244 rpm，远低于手册列出的芯片最大转速能力，不能直接断言真实机械超速；供磁、干扰或其他因素还需进一步证据区分。CRC通过的报警帧不等于可忽略其报警继续使用。CRC、报警和陈旧反馈保护全部保留。

参考：[MT6835 Rev.1.3原厂手册](https://www.magntek.com.cn/upload/pdf/202407/MT6835_Rev.1.3.pdf)，角度输出、SPI/CRC、状态位章节。对于本系统异常的根因仍是待验证，不冒充厂家诊断。

## 10. 保护后恢复与持续运行

3000 rpm尝试停机后，先非停机读TIM1_BDTR确认MOE=0，再连接GDB。控制器/运行时fault_flags均6（无效角度/参考），速度fault4，过流count0；功率级安全，ready/nFAULT无异常。稍后编码器angle/speed/electrical均有效、status0、fault0，转子静止。

仅对这次已检查的编码器故障人工确认恢复：`scripts/ack_recovered_encoder_fault.gdb`。检查输出/预充关闭、MOE=0、故障类型精确匹配、无过流、有效校准/反馈及静止；其他情况拒绝。不嵌入固件、不自动运行，不作为通用清故障脚本。

首次GDB外设访问被默认内存范围拒绝，未执行清除，见 `continuous_speed_recovered_ack.log`。设置 `set mem inaccessible-by-default off` 后重试成功，见 `continuous_speed_recovered_ack_retry.log`。随后设1500 rpm、分离GDB并关闭自建服务，再非停机写enable启动。

`continuous_speed_handoff_1500.json`：斜坡后实际1487.151～1512.136 rpm、state2/fault0、峰值约1.911 A。接着在线改2000，见 `continuous_speed_handoff_2000_command.log`。15:13:22～15:13:25采样时运行407.6～410.8秒、累计相对12791～12898圈，实际1989.598～2018.828、fault0、峰值2.295382 A，见 `continuous_speed_handoff_2000.json`。

无固定结束时间不等于无视故障永远通电。以后再次故障仍自动停机，不进行无限重试。最后交付快照另记于末节。

## 15. PA0/PD2实时示波标记

按后续要求增加两个高速推挽、空闲低电平的实时探针：

| 引脚 | 高电平的精确定义 |
|---|---|
| PA0 | 进入注册的 `MainFoc_OnAdcConversion()` 回调前置高，回调完整返回后置低。它不再包住HAL ADC中断入口、JDR读取和校准样本累计，因此表示FOC业务回调执行窗口。校准收集阶段不会调用FOC，PA0保持低。 |
| PD2 | 在调用异步SPI/DMA启动函数前置高；DMA完成后继续保持高，经过帧解码、CRC、状态报警判断以及有效快照发布，最后释放encoder busy后置低。SPI启动失败立即置低；超时Abort最终也经统一完成回调置低。 |

涉及文件：`Core/Src/gpio.c`、`Core/Src/stm32g4xx_it.c`、`Modules/Current_Sampling/Src/current_sampling.c`、`Modules/Encoder/Src/encoder.c`。使用GPIO BSRR直接置位/复位，避免HAL函数调用使测量窗口增加不确定开销。ADC完整中断周期统计仍由DWT在 `ADC1_2_IRQHandler` 记录，与PA0的纯FOC脉宽定义分开。
