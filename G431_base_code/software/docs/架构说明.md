## 1. 先理解整个系统

当前程序是“主循环处理启动和低速任务，中断执行电机实时控制”的裸机程序，没有 RTOS。
默认控制链由输出轴位置环、电机速度环和 FOC 电流环组成：

```text
输出轴目标角度
  → 位置环（配置1 ms，主循环执行，MPT 输出轴编码器反馈）
  → 电机目标转速
  → 速度环（约 1 kHz，MT6701 电机编码器反馈）
  → Iq 电流给定，Id = 0
  → FOC 电流环（20 kHz，U/V 电流及电角度反馈）
  → 三相 PWM → 栅极驱动 → 电机 → 减速器 → 输出轴
```

两个编码器的用途不同：MT6701 提供电机转子角度和速度；MPT T485 提供减速器输出轴位置。MPT 的角度不直接用于 FOC 换相。

### 统一的用户控制入口

用户通过 [`g_user_control`](../servo_v1/Servo/Inc/user_control.h) 设置 `mode`、对应参数和 `enable`。调试器、上位机和后续通信协议均可使用这一入口。旧的 `g_speed_run`、`g_output_position` 等对象作为内部执行接口保留，使用统一入口时不要同时向旧接口下发命令。

| mode | 控制模式 | 用户参数 | 运行方式 |
| --- | --- | --- | --- |
| 0 / `USER_MODE_VOLTAGE` | 开环电压 | `voltage.ud_v`、`uq_v`、`electrical_hz` | 根据电角频率生成旋转角度，直接输出 D/Q 电压，不依赖编码器 |
| 1 / `USER_MODE_ENCODER_CALIBRATION` | 编码器校准 | `calibration.ud_v`、`uq_v`、`duration_s` | 固定磁场对齐，捕获零点，关闭输出后写 Flash 并立即生效 |
| 2 / `USER_MODE_OPEN_CURRENT` | 开环电流 | `open_current.id_a`、`iq_a`、`electrical_hz` | 根据频率生成旋转角度，用 ADC 闭合 D/Q 电流环，不读取编码器角度 |
| 3 / `USER_MODE_TORQUE` | 转矩 | `torque.id_a`、`iq_a` | 用电机编码器换相，闭合 D/Q 电流环 |
| 4 / `USER_MODE_SPEED` | 速度 | `speed.target_rpm`、`acceleration_rpm_s`、`deceleration_rpm_s`、`forward_limit_rpm`、`reverse_limit_rpm` | 编码器速度环产生 Iq；目标超过正反转速上限时截到上限；反转先减速至零再加速 |
| 5 / `USER_MODE_POSITION` | 位置 | `position.target_deg` | 输出轴位置环 → 电机速度环 → 电流环，支持正反向多圈 |

电压单位 V、电流单位 A；`electrical_hz` 是电角频率，可正可负；`target_rpm` 是电机转速，可正可负。用户速度模式加减速度单位rpm/s，正反转上限均填正数，最大9000 rpm。位置模式使用独立参数：普通默认5500 rpm、300000 rpm/s；有限正弦可由主机显式配置7500 rpm，并在运行期间选用1200000 rpm/s。位置配置允许上限8500 rpm，不等于该转速已实机验收。

位置模式每次重新使能时，以当时输出轴位置为 **0°**。本次使能期间，`720` 表示相对此零点正转两圈，`180` 表示到达半圈位置，`-180` 表示到达反向半圈位置；目标不按 360°取模。运行中从 720 改成 180 是返回半圈位置，而不是再转半圈。跨圈展开使用 64 位累计计数，用户接口为 float，因此累计角度很大时角度分辨率会下降；累计位置不做断电保存。

使用顺序：先写 `enable=0`，等 `status.state=USER_IDLE`，再填写模式与参数，最后写 `enable=1`。速度、位置和 D/Q 给定支持运行中调整；校准参数在启动时锁定。切换模式会先关闭输出，再启动新模式。`enable=0` 立即请求撤去输出，不执行减速停车。

位置Kp、最大转速和死区在位置arm时锁存，须在停机后重新使能才能应用；普通用户目标使用`g_user_control.position.target_deg`。有限扫频由专用脚本管理，不与Watch或其他程序并行写内部控制命令。详细步骤及主机参数默认值差异见[位置环使用说明](位置环调试与使用说明.md)。

例如，让输出轴从本次使能位置正转两圈：

```c
// 先令 enable=0，并等 status.state == USER_IDLE，再提交以下参数。
g_user_control.mode = USER_MODE_POSITION;
g_user_control.position.target_deg = 360.0f * 2.0f;
g_user_control.enable = 1;
// 停止：g_user_control.enable = 0;
```

`status.state`：0 空闲、1 启动中、2 运行、3 校准完成、4 故障。校准完成后保持完成态，不因 enable 仍为 1 而重复校准；重新校准需先关闭再使能，或切换到其他模式。`status.fault`：0 正常、1 参数不合法、2 电流校准/驱动/编码器零点未就绪、3 底层运行故障。状态还包含实际电机转速、当前位置会话的输出角度、Id/Iq、已应用零点及有效标志；没有有效电机速度反馈时实际转速显示 0。

转矩、速度、位置模式要求已有有效编码器零点。电压和无编码器电流模式不要求编码器校准，仍使用电流采样、驱动和 PWM 安全门。重新开关使能不会清除底层锁存故障。电角频率范围 ±300 Hz；实际电压仍受母线配置及调制窗口限制。

默认 `enable=1`、位置模式、目标 0°，保留原有上电校准/加载后位置保持行为；显式关闭使能可取消自动启动。主循环负责接收用户参数、协调切换及保存；ADC 中断执行虚拟角度/转矩给定与 FOC，速度环继续在 PendSV，位置环继续在主循环。

## 3. 上电后依次执行什么

1. `HAL_Init()`、系统时钟和 GPIO 初始化，配置 I2C3、TIM6、TIM1；启动定时器时先保持 MOE 关闭。
2. 初始化 MPT 输出轴通信；当前 USART1 归 MPT 使用，UART 波形上传分支关闭。
3. 初始化 STSPIN32G4 驱动监控，清除上电锁存状态，启动 1 s 监控心跳。
4. 初始化 OPAMP1、OPAMP3、ADC1、FOC 控制器及回调；启动 TIM1 硬件触发的电流采样。
5. 等待 20 ms 模拟链稳定，随后每次上电重新采集 20 帧 U/V 零电流数据，采集约 1 ms；采满且无饱和、异常波动后计算零偏。失败则停止启动，不使用历史零偏代替。
6. `Encoder_Init()` 启动电机编码器采集。独立业务模块 `EncoderCalibration` 从 Flash 读取与方向、极对数匹配且 CRC 正确的零点，立即配置给编码器模块。
7. 若无有效存储值，自动启动流程等待反馈有效后发起一次默认 Ud = 1.5 V、持续 3 s 的固定电角度对齐；已有有效值时跳过对齐。
8. 对齐经已有自举预充电和驱动安全检查开始。结束前捕获受电压约束时的原始角度；输出关闭后将零点写入 Flash，校验后立即应用。写入时控制输出保持关闭。
9. 等待新零位对应的有效反馈，自动发出位置启动命令：记录此刻输出轴角度为目标，速度给定从 0 开始，进入位置保持。

自动启动只尝试一次；故障、取消或等待超时会终止本次启动。主循环同时保留显式停止和故障处理路径。
另外，当前配置三路执行窗口探针：PA0 在完整 ADC/FOC 中断期间为高，PD2 在 TIM1 更新中断期间为高；PB7空闲为高，在SPI DMA接收完成回调期间为低。PA15、PB9 已停用并保持低电平。

入口代码：[main.c](../servo_v1/Core/Src/main.c)、[输出轴位置管理](../servo_v1/Servo/Src/output_position.c)。

### 编码器校准如何使用

业务模块位于 [encoder_calibration.c](../servo_v1/Servo/Src/encoder_calibration.c)，由 `g_encoder_calibration` 独立管理参数、状态、结果和故障。它通过端口调用电压执行器、存储和编码器配置，不直接操作 SPI 或 PWM。

电机停止且输出关闭后，先设置参数，再写启动命令：

```c
g_encoder_calibration.requested.d_voltage_v = 1.5f;
g_encoder_calibration.requested.q_voltage_v = 0.0f;
g_encoder_calibration.requested.duration_s = 3.0f;
g_encoder_calibration.command = 1;  // 开始；2 表示取消
```

合成电压 `sqrt(Ud²+Uq²)` 接受范围为 `(0, 2.8] V`，还须满足当前配置母线电压的 10% 上限；时间范围为 `0.05～10 s`。默认值为 Ud=1.5 V、Uq=0、3 s。参数在启动时锁定，运行中修改 `requested` 只影响下一次校准。非零 Uq 时根据 `atan2(Uq,Ud)` 补偿固定磁场方向；Flash 保存校准零点，原记录中的电压元数据改为合成幅值，保持旧存储记录可读取。

`state`：0 空闲、1 等待启动、2 校准执行、3 已捕获角度/等待关闭输出并保存、4 完成、5 失败。`fault` 为失败原因，`valid` 表示已有可用结果，`offset_rad` 为已应用零点，`loaded_from_storage` 表示本次使用了存储值。

看到 `state=4` 后，可直接使用原来的速度或位置启动命令，无需重启。保存并应用成功后，底层电压执行器自动回到空闲，完成记录仍保存在校准对象中。编码器会用新零点重建反馈，正常控制仍等待反馈有效。再次校准不会自动恢复此前运动；启动自动流程中的首次校准由启动流程衔接运行。

存储使用 Flash 最后两页 `0x0801F000`、`0x0801F800`，由链接文件排除在程序区域外。两页交替写入，完整校验并写入提交标记后新记录才有效；普通上电读取不会擦写 Flash。整片擦除会清除校准记录。

## 4. 一个 50 µs 控制周期如何运行

TIM1 是整个实时链的时间基准。RCR = 1 使更新事件每个完整载波周期发生一次；三相 PWM 比较值在载波谷值一起生效。

```text
时间示意       0 µs                约 4.6 µs       约 20 µs   25 µs            50 µs
TIM1           谷值 ------------------------------------ 峰值 ---------------- 谷值
编码器         启动 SPI1 DMA ------ 线上的 24 位传完
CPU                               DMA 中断：解析并发布
ADC                                             U/V 转换完成
CPU                                             FOC 运算 → 写预装载
PWM                                                                    新 CCR 生效
```

这是一种典型采样位置的示意，不是硬件实测波形：ADC 触发点会随占空比和开关边沿调整；DMA 中断和 FOC 入口还存在 CPU 响应延迟。

### 4.1 编码器：在哪里发起、接收和解析

1. 谷值的 `TIM1_UP_TIM16_IRQHandler()` 调用 `Encoder_OnPwmPeriodIsr()`。
2. MCU 拉低 PB6 的 CSN，启动 SPI1 DMA。当前 MT6701 SSI 没有寄存器读取命令字：DMA 发送 3 字节占位数据以产生 24 个时钟，同时接收 3 字节。
3. SPI1 使用模式 1，PB3 为 SCK、PB4 为 MISO、PB5 为占位 MOSI；硬件只能使用2的幂分频，当前168 MHz / 32 = 5.25 MHz，是最接近目标5 MHz的档位，24位纯传输时间约4.57 µs。
4. RX DMA 完成后进入 `DMA1_Channel1_IRQHandler()`，经 SPI 收尾调用 `Encoder_TransferComplete()`。
5. `Mt6701Ssi_ProcessFrame()` 解析 14 位角度、状态及 CRC6；随后公共编码器层检查数据、展开多圈位置、估算速度、换算电角度。
6. 有效数据发布到 `g_encoder_snapshot`，FOC 读取该快照，不直接读 DMA 缓冲区，也不等待通信完成。

公共接口仍使用 21 位计数格式：MT6701 原始值左移 7 位只是单位适配，真实分辨率仍是 14 位。
快照 `sample_cycle` 记录软件启动事务的时刻，不能把 DMA 完成时刻当成传感器采样时刻；器件内部测角延迟也未由此消除。

当前连续运行通过 `MainFoc_ReadFeedback()` → `SpeedCommission_FastReference()` → `Encoder_ReadSnapshot()` 取得最新电角度，再写入 `foc_input_t`；速度 PI 改在低优先级 PendSV 中计算。
单独的 `NORMAL` 模式则通过 `Encoder_ReadElectricalAngleForFoc()` 取角度。两条路径都不等 SPI，也没有基于数据年龄的电角度外推补偿。

CRC 错误帧不会覆盖上一帧有效角度；是否继续使用旧帧还取决于故障类型、诊断状态与数据年龄。
当前年龄预算默认 10 个控制周期，即 1 ms；超过预算则反馈失效。这是失效判据，不代表允许高速控制长期使用 1 ms 的旧角度。
编码器初始化成功后，采集调度独立于 MOE 和运行模式；电机停止不等于编码器停止通信。

源码：[SPI1 传输](../servo_v1/Modules/Encoder/Src/spi1_encoder.c)、[公共编码器处理](../servo_v1/Modules/Encoder/Src/encoder.c)、[MT6701 解析](../servo_v1/Modules/Encoder/Src/mt6701_ssi.c)。

### 4.2 ADC：硬件触发，序列完成后才执行 FOC

TIM1 CH4 的 OC4REF 经 TRGO2 直接触发 ADC1 注入序列，不需要 TIM1 CC 中断发起采样。
ADC 顺序采集 U、V 两相；W 相由 `-(U + V)` 计算得到。
当前 `ADC1_CS_PROFILE=1`：ADC 时钟 42 MHz，每相 25 个 ADC 时钟，无过采样，两相转换共约 1.190 µs，规划器使用向上取整后的 1.192 µs。

U/V 相在每次上电时先校准零电流 ADC 偏置；偏置只消除零点误差，安培比例使用实物标定常数。2026-10-27 使用 MDO34 的 TCP0030A 电流探头夹在 U 相，先做静止正负点绝对标定，再用 1/2/5 Hz 开环电流旋转波形核对 U/V 链路一致性。当前 U 相为 `0.00681389 A/count`（等效增益 16.89535），V 相为 `0.00656530 A/count`（等效增益 17.53506）。程序规定“从逆变器流入电机相端”为正；标定时电流钳箭头与此方向相反，所以 CH4 和程序读数符号相反。若希望示波器同号，应反转电流钳方向，不应修改 FOC 电流极性。最终 0.5 A 旋转点在 2/5 Hz 的 U 相基波分别为 0.49254 A、0.49323 A。操作方法见[电流校准说明](电流校准说明.md)，详细原始点见[U相物理电流标定日志](log/2026-10-27_U相物理电流标定.md)。

20 kHz 配置优先使完整 ADC 序列在载波峰值前约 5 µs结束，并避开 U/V 低侧有效窗口边界和 W 相开关边沿，为 FOC 和 PWM 提交留出时间。占空比变化可能移动触发位置，因此不是固定采样时刻。

完整序列结束后置 JEOS，调用链是：

```text
ADC1_2_IRQHandler()
  → CurrentSampling_InjectedFastIrq()（普通路径；异常情况走 HAL）
  → MainFoc_OnAdcConversion()
  → 读取电流、检查运行状态
  → FOC_ControllerStep()
  → MainFoc_ReadFeedback()（最新电角度、保护检查、读取已发布 Iq）
  → FOC_AlgorithmStep()
  → MainFoc_WriteVoltage()
  → Tim1Pwm_SetPhaseVoltage()
```

`FOC_AlgorithmStep()` 完成 Clarke / Park、电流 D/Q PI、反变换和调制。
电压对齐阶段改走 `FOC_ControllerVoltageStep()`，使用电压指令，不执行普通 D/Q 电流 PI 路径。
输出尚未 armed、预充电中、反馈无效或控制器已停机时，也不会正常进入电流算法迭代。

源码：[ADC 参数](../servo_v1/Modules/Current_Sampling/Inc/adc1_current_sampling.h)、[中断入口](../servo_v1/Core/Src/stm32g4xx_it.c)、[FOC 接口](../servo_v1/FOC/Src/foc_interface.c)。

### 4.3 PWM：本次算出的结果，在下一个谷值生效

`Tim1Pwm_SetPhaseVoltage()` 同时规划三相 duty 和下一周期的 ADC 触发点，把 CCR1～CCR4 一起写入预装载寄存器。
它们在下一次谷值更新事件一起生效，避免新 PWM 与旧采样位置混用。
提交必须留出约 2 µs 保护时间；若跨过提交时限或没有合法采样窗口，代码拒绝该次写入并走故障关断。

名义上 ADC 序列在峰值前约 5 µs结束，距下一谷值约 30 µs；实际可用预算要扣除中断延迟、抢占、采样点变化和 2 µs提交保护。
“ISR 小于 50 µs”不等于“PWM 一定来得及更新”；应同时看 PWM 提交余量及拒绝计数。

源码：[PWM 写入与时限](../servo_v1/Modules/Three_Phase_Driver/Src/tim1_pwm.c)、[采样窗口规划](../servo_v1/Modules/Three_Phase_Driver/Src/pwm_sampling.c)。

## 5. 三个控制环和后台任务如何分工

| 工作                 | 调度位置                                                   | 周期 / 触发方式            | 产出                          |
| -------------------- | ---------------------------------------------------------- | -------------------------- | ----------------------------- |
| 电机编码器读取       | TIM1 更新中断 + SPI1 DMA 完成中断                          | 50 µs 一次                | 电机角度、速度、电角度快照    |
| 电流环               | ADC JEOS 中断                                              | 名义 50 µs 一次           | D/Q 电压、三相 duty           |
| 连续运行速度环       | `PendSV_Handler()` → `SpeedCommission_OuterService()` | ADC 时间达到约 1 ms 时请求 | 原子发布 Iq；后续电流周期使用 |
| 输出轴位置环         | 主循环的 `OutputPosition_Service()`                      | 配置至少间隔1 ms更新       | 电机目标 rpm                  |
| MPT 编码器通信       | 主循环的 `MptT485_Task()` + 硬件 DMA                     | 配置每1 ms查询一次         | 输出轴位置快照                |
| 启停、对齐、模式切换 | 主循环                                                     | 每轮检查状态               | 输出请求和运行状态            |
| 驱动状态监控         | TIM6 置标志，主循环通过 I2C3 读取                          | 1 s 心跳                   | 驱动状态与诊断                |

位置环按输出轴角度误差计算速度，乘减速比换算为电机rpm；默认Kp=72 /s，电机速度指令上限5500 rpm。
它运行在主循环，可能受其他后台任务延迟，不是独立的1 kHz硬实时中断。本次带盘实验MPT请求率约1 kHz；任务频率不能替代闭环带宽。
连续运行时，ADC 每约 1 ms 锁存外环的采样时间、编码器反馈及抗饱和状态，挂起低优先级 PendSV。ADC 先完成当前电流环和 PWM 提交，再由 PendSV 计算速度 PI 并一次发布 Iq；下一电流周期使用新值。名义新增一拍电流给定延迟，动态响应仍需实机验收。

停止、反馈无效、超速及电流周期超时检查仍逐 ADC 周期执行；外环超过 2 ms 未完成更新也会故障停止。对齐、辨识等有界测试保留原 ADC 调度。

MPT 通信由 MCU 发送 `0x1A` 查询，DMA 接收应答；TIM7 + DMA 控制 RS-485 DE 释放。
主循环检查 IDLE / 接收长度后，在 `finish()` → `MptT485_Decode()` 中校验并解析 11 字节应答。它没有新增串口接收完成中断去抢占 FOC。
连续10帧正确才标记有效；事务等待2 ms超时，位置反馈新鲜度上限为`3×1+2=5 ms`。2 ms是超时门槛，不是器件响应延迟；实际延迟读取`resp_latency_last_us/max_us`，本次R17上电期间最大值约405 µs。

源码：[速度控制](../servo_v1/Servo/Src/speed_commission.c)、[位置控制](../servo_v1/Servo/Src/output_position.c)、[MPT 通信](../servo_v1/Modules/Encoder/Src/mpt_t485.c)。

电流环响应已经按当前物理电流比例重新整定：固定电角度、±0.30 A 测试下，上升时间由约 55 ms 缩短到约 1～2 ms，内部反馈 -3 dB 带宽由低于 10 Hz 提高到约 500～600 Hz。最终正负阶跃的平滑超调约 4%～9.4%，仍有测量噪声和慢漂移。CH4 对 U 相实际电流幅值做了交叉验证。该结果覆盖当前小信号实验，详细曲线、口径与复现方法见[电流环时域与频域优化日志](log/2026-10-27_电流环时域与频域优化.md)。

位置环带盘±2°纯反馈最佳工作点约18.5 Hz，不同起点已测约15～18 Hz，尚未全角度稳定20 Hz。R17的+2°阶跃上升20 ms、2%整定55 ms、超调1.35%。FF=0.6改善跟踪误差，不作为FF=0纯反馈带宽的替代。条件和证据见[10-29调试日志](log/2026-10-29_位置环续调与反馈链路检查.md)。

连续速度/位置快速ADC路径先完成FOC/PWM提交，再对同一电流样本统计相峰值及位置试验RMS；包络窗口边界在前台锁存，避免统计计算占用PWM提交截止余量。原2 µs保护门槛保留。频响在前台按稳态窗口累积；三相RMS统计是观测功能，不新增软件电流限幅。

## 6. 中断优先级与执行时间

数值越小，抢占优先级越高。当前配置如下：

| 中断                      | 优先级 | 工作                                     |
| ------------------------- | ------ | ---------------------------------------- |
| TIM1 更新                 | 0      | 启动电机编码器事务                       |
| SPI1 RX/TX DMA、SPI1 错误 | 0      | 传输收尾、校验、角度和速度发布           |
| ADC1_2                    | 1      | 电流采样处理、FOC、即时保护、PWM 提交    |
| PendSV                    | 14     | 连续运行的约 1 kHz 速度环，可被 ADC 抢占 |
| TIM6、SysTick             | 15     | 后台心跳和毫秒计时                       |

TIM1 和 SPI1 DMA **都能够抢占 ADC/FOC**；同为优先级 0 的中断彼此不抢占。全局关中断的短临界区会暂时推迟所有这些中断。
如果 FOC 跨过下一个谷值，TIM1 启动下一次编码器通信及随后 DMA 收尾可能进一步拉长 FOC 的墙钟耗时；硬件定时器和 ADC 触发仍会继续运行。

观察 `g_encoder_diagnostics.foc_isr_cycles_max` 可知完整 ADC ISR 最大耗时，包含高优先级抢占；168 MHz 下 168 cycles = 1 µs。
`g_tim1_pwm_commit_timing` 和 `g_tim1_pwm_sampling.deadline_rejections` 用于判断 PWM 提交余量及是否错过时限。
当前执行窗口应观察 PA0 / PD2 / PB7，分别对应 ADC/FOC 中断、TIM1 更新中断和 SPI DMA 接收完成回调。原 PA0 / PD2 的通信错误 / CRC 错误锁存输出已停用，避免与执行时间测量互相干扰；PA15 / PB9 保持低电平。

## 7. 软件层次与功能模块

这里的“层次”表示职责分工；现有 `main.c` 仍承载较多调试和模式分支，并非所有逻辑都已经完全拆分。

| 层次               | 目录 / 文件                                         | 定位                                                                      |
| ------------------ | --------------------------------------------------- | ------------------------------------------------------------------------- |
| 应用装配与调度     | `Core/Src/main.c`、中断入口、`control_timing.h` | 初始化、连接回调、主循环、模式和启动流程、统一时基                        |
| 伺服控制与运行管理 | `Servo/`                                          | 输出轴位置环、速度环、对齐、运行命令、状态与故障管理                      |
| 用户控制入口 | `Servo/user_control.*`、`user_control_dispatch.inc`（由 main 装配） | 面向用户的六种模式、参数校验、使能及状态；转换为内部执行命令 |
| 校准业务管理       | `Servo/encoder_calibration.*`                     | 接收电压/时间、锁定参数、捕获校准结果、协调保存和立即生效                 |
| 电机控制算法       | `FOC/`                                            | 控制器接口、Clarke/Park、D/Q PI、调制、电流参数设计；通过端口回调访问硬件 |
| 功能模块           | `Modules/Current_Sampling/`                       | 运放与 ADC 配置、零偏、原始码转安培、采样回调                             |
| 功能模块           | `Modules/Encoder/`                                | SPI/SSI、MPT RS-485、协议解析、角度速度快照和通信诊断                     |
| 功能模块           | `Modules/Three_Phase_Driver/`                     | TIM1 互补 PWM、死区、MOE、采样窗口、同步提交                              |
| 功能模块           | `Modules/Driver_Communication/`                   | I2C3、STSPIN32G4 寄存器、READY/nFAULT 与周期监控                          |
| 芯片支持           | `Drivers/`、Core 的 MSP / 启动文件                | CMSIS、HAL、寄存器与外设基础配置                                          |
| 开发验证           | `Tests/`、`Tools/`                              | 激励、采集、主机测试、构建和调试辅助工具                                  |

数据流的边界是“硬件模块发布反馈 → Servo 生成给定 → FOC 计算 duty → PWM 模块执行”。
FOC 算法不发 SPI/I2C 命令；编码器解析不直接执行 FOC；主循环不承担每个电流周期的 PI 运算。

## 8. 当前使用路径与保留能力

- 当前位置闭环复用 `CURRENT_OPEN_LOOP` 模式中的 `SpeedCommission` 执行路径。这个历史名称不表示运行时没有编码器反馈，也不表示电机处于开环。
- `ServoManager` 状态机用于单独的 `NORMAL` 分支；它并非当前默认位置闭环全部启停逻辑的唯一入口。
- MT6835 后端、SPI3 独立试验、固定角度电流试验、PRBS / 阶跃采集、过调制和 UART 波形功能仍保留；是否使用取决于编译配置或显式命令。
- 当前默认使用 MT6701 的 **SPI1** 链路；文件名带 `spi3_test` 的测试代码不能代表实际电机反馈外设。
- 电流零偏每次上电采集约 1 ms；编码器零点从 Flash 读取或重新校准得到。电压对齐中的母线电压来自配置值，不是实时母线测量。
- CAN / 通用上位机协议、统一参数持久化等仍有预留项，不能按完整产品功能理解。

修改频率、编码器、启动默认值或硬件策略后，应同步更新本文的配置表和时序。详细原因、修改步骤、数据及验证范围统一记入 [log 开发调试日志](log/README.md)。
