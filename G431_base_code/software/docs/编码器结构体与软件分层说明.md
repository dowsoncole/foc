# 编码器结构体与软件分层说明

依据：2026-10-29 当前工作区源码（R17；核对：Codex）。本文说明结构体的职责、关键字段、各层执行时机及所在文件；整体启动和执行时序见[架构说明](架构说明.md)。

当前有两条反馈链：电机端 **MT6701 / SPI1** 提供换相角度和电机速度；输出轴端 **MPT T485 / RS-485** 提供减速器输出位置。

## 1. 先看层次和数据流

可以把编码器处理理解为：先收回数据，再读懂数据，再整理成角度和速度，最后用于控制电机。调试诊断在这些过程中记录通信状态和故障。下表按这些工作分层；现有代码中，一个文件可能同时承担几层的工作。

| 层次 | 代表结构体 | 对应全局变量 | 作用（通俗解释） | 执行时机 |
| --- | --- | --- | --- | --- |
| 外设传输 | HAL 的 `SPI_HandleTypeDef`、`DMA_HandleTypeDef` | SPI：`hspi1`；DMA：`s_hdma_spi1_rx`、`s_hdma_spi1_tx`（spi1_encoder.c 内部），`rx_dma`、`de_dma`（mpt_t485.c 内部） | 把编码器的数据收进 MCU 内存。例如 SPI 发出时钟，DMA 把收到的字节放进接收数组；这一层负责收发是否完成。 | 电机端：每 50 µs 在 PWM 谷值的 TIM1 更新中断中启动 SPI/DMA，接收完成后由 DMA 中断收尾。输出轴端：主循环每 1 ms 发起 MPT 查询，DMA 接收，后续主循环检查完成情况。 |
| 器件协议 | `mt6701_ssi_t`、`mt6835_angle_t`、`mpt_t485_t` | 分别为 `g_mt6701_ssi`；无独立全局实例（使用局部 `frame`）；`g_mpt_t485` | 按编码器规定的格式读懂这些字节，找出角度、报警和校验值，判断这一帧数据是否正确。 | MT6701：正常在 SPI RX DMA 完成回调中立即解析。MPT：主循环发现应答接收完整后解析。 |
| 公共电机反馈 | `encoder_context_t`、`encoder_speed_point_t`、`encoder_snapshot_t` | 分别为 `s_encoder`；`s_encoder.speed_history[]`（成员数组）；`g_encoder_snapshot` | 把电机编码器的读数整理成控制需要的数据：统一正反方向、累计转过的位置、计算速度和电角度，并标明数据是否有效。 | 每次电机帧通过检查后，在同一个 DMA 完成回调中计算并发布快照；控制层读取时再检查是否过期。 |
| 控制消费 | `foc_input_t`、`output_position_t` | 分别为 `g_foc_controller.input`（成员）；`g_output_position` | 使用反馈决定怎样驱动电机：位置环根据位置差给出目标速度，速度环根据速度差给出电流指令，FOC 根据电角度和电流计算三相驱动电压。 | 运行条件满足时：ADC 中断每 50 µs 读取最新电角度并执行 FOC；连续运行的速度环由 ADC 约每 1 ms 请求，在低优先级 PendSV 中计算；位置环在主循环中至少间隔 1 ms 更新。 |
| 校准业务 | `encoder_calibration_t` | `g_encoder_calibration` | 管理“施加多大 D 轴电压、保持多久、得到什么零点、是否保存成功”。与 SPI 收发及速度环的运行状态分开。 | 上电加载存储值；用户命令后执行对齐，ADC 在对齐结束前捕获角度，主循环在输出关闭后保存并应用。 |
| 调试诊断 | `encoder_diagnostics_t`、各类 fault/capture 结构体 | `g_encoder_diagnostics`、`g_encoder_fault_capture`、`g_encoder_logic_trigger`；旧零位诊断：`g_encoder_zero_guard`、`g_encoder_zero_fault_capture` | 记录通信成功或失败次数、执行耗时和出错时的原始数据，帮助查清故障原因；部分故障锁存状态还参与判断是否允许继续运行。 | 随 TIM1 触发、DMA 完成、ADC 控制处理同步统计；检测到异常时立即记录故障现场。主循环处理超时恢复和诊断命令；旧零位诊断当前停用。 |

以电机端读取一帧 MT6701 数据为例：

1. **外设传输负责“收回来”**：TIM1 到达采集时刻后启动 SPI1，DMA 把 3 个字节收进 `s_encoder.rx[]`。此时得到的只是字节数组。
2. **器件协议负责“读明白”**：解析程序从这 3 个字节中取出角度和状态，计算 CRC 并与收到的值比较，把结果放入 `g_mt6701_ssi`。
3. **公共电机反馈负责“整理好”**：结合电机方向、极对数、电角度偏置和之前的读数，算出机械角度、速度及电角度，发布到 `g_encoder_snapshot`。控制层读取时还会检查数据是否过期。
4. **控制消费负责“用起来”**：速度环用反馈速度计算需要多大电流；FOC 使用电角度完成坐标变换，再根据电流误差计算驱动电压。

**调试诊断负责“留下记录”**，贯穿上述过程。例如 CRC 错误时记录错误次数和当时收到的字节，便于之后判断问题发生在哪一步。它不是等 FOC 算完以后才执行的最后一层。

输出轴 MPT 链也是先收字节、再解析角度，但当前代码把通信状态和解析结果集中在 `g_mpt_t485` 中，随后直接交给位置控制模块使用；它不经过电机端的 `g_encoder_snapshot`。

表中“内部”指文件作用域的 `static` 变量，仅由所属模块访问；“成员”指全局对象内的字段，不是独立全局变量。单帧故障结构体对应 `g_encoder_fault_capture.first/last/recent[]/last_alarm` 等成员，旧零位故障单帧对应 `g_encoder_zero_fault_capture.first/last/recent[]`；各自定义和状态见第 4 节。

### 1.1 各层何时执行，代码在哪里

结构体本身不执行代码；下表说明负责更新、处理或读取这些结构体的函数在什么时刻运行。“中断内”表示暂时打断主循环执行，“主循环内”表示在前台反复检查任务是否到期或完成。

| 层次 / 对象 | 执行时机与位置 | 主要函数 | 所在文件 |
| --- | --- | --- | --- |
| 外设传输：启动电机编码器读取 | 每个 PWM 谷值，在 TIM1 更新中断内发起；当前每 50 µs 一次，启动后不等待接收完成 | `TIM1_UP_TIM16_IRQHandler()` → `Encoder_OnPwmPeriodIsr()` → `MT6835_SPI_TransmitReceiveAsync()` | [stm32g4xx_it.c](../servo_v1/Core/Src/stm32g4xx_it.c)、[encoder.c](../servo_v1/Modules/Encoder/Src/encoder.c)、[spi1_encoder.c](../servo_v1/Modules/Encoder/Src/spi1_encoder.c) |
| 外设传输：电机帧接收完成 | SPI/DMA 在硬件中收发；正常 RX 完成后进入 DMA1 通道 1 中断，收尾并调用上层回调 | `DMA1_Channel1_IRQHandler()` → `SPI1_Encoder_DmaRxIrqHandler()` → `MT6835_SPI_AsyncFinish()` | [stm32g4xx_it.c](../servo_v1/Core/Src/stm32g4xx_it.c)、[spi1_encoder.c](../servo_v1/Modules/Encoder/Src/spi1_encoder.c) |
| 器件协议：解析 MT6701 | 正常在上述 DMA 完成回调内，收到完整帧后立即检查 CRC、提取角度和状态，更新 `g_mt6701_ssi` | `Encoder_TransferComplete()` → `Mt6701Ssi_ProcessFrame()` | [encoder.c](../servo_v1/Modules/Encoder/Src/encoder.c)、[mt6701_ssi.c](../servo_v1/Modules/Encoder/Src/mt6701_ssi.c) |
| 公共电机反馈：计算并发布快照 | 同一次完成回调内，帧通过有效性及角度步进检查后，计算多圈位置、速度和电角度，更新 `g_encoder_snapshot` | `Encoder_PublishFrame()`、`Encoder_UpdateSpeed()` | [encoder.c](../servo_v1/Modules/Encoder/Src/encoder.c) |
| 控制消费：读取电机反馈并执行 FOC | ADC 完成 U/V 两相采样后进入 ADC 中断；运行条件满足时读取最新快照并执行本周期控制，名义每 50 µs 一次 | `MainFoc_OnAdcConversion()` → `FOC_ControllerStep()` → `MainFoc_ReadFeedback()` / `FOC_AlgorithmStep()` | [main.c](../servo_v1/Core/Src/main.c)、[foc_interface.c](../servo_v1/FOC/Src/foc_interface.c)、[foc_algorithm.c](../servo_v1/FOC/Src/foc_algorithm.c) |
| 控制消费：电机速度环 | 连续运行时 ADC 每约 1 ms 锁存反馈并挂起 PendSV；ADC 返回后，低优先级 PendSV 计算并发布 Iq，后续电流周期使用。对齐、辨识保留原调度 | `SpeedCommission_FastReference()` → `SpeedCommission_OuterService()` | [speed_commission.c](../servo_v1/Servo/Src/speed_commission.c)、[stm32g4xx_it.c](../servo_v1/Core/Src/stm32g4xx_it.c) |
| 外设传输：输出轴 MPT 查询 | 主循环检查查询间隔，每 1 ms 发起一次；DMA 接收应答，TIM7 + DMA 控制 RS-485 发送使能释放 | `MptT485_Task()` | [mpt_t485.c](../servo_v1/Modules/Encoder/Src/mpt_t485.c) |
| 器件协议：MPT 解析和发布 | 后续主循环检查到串口空闲且接收长度足够时，解析应答并更新 `g_mpt_t485`；不是在接收完成中断内解析 | `MptT485_Task()` → `finish()` → `MptT485_Decode()` | [mpt_t485.c](../servo_v1/Modules/Encoder/Src/mpt_t485.c)、[mpt_t485_protocol.c](../servo_v1/Modules/Encoder/Src/mpt_t485_protocol.c) |
| 控制消费：输出轴位置环 | 主循环调用服务函数，位置运行状态下至少相隔 1 ms 更新一次；读取 MPT 角度并生成电机速度指令 | `OutputPosition_Service()` → `OutputPosition_Update()` | [output_position.c](../servo_v1/Servo/Src/output_position.c)，由 [main.c](../servo_v1/Core/Src/main.c) 调度 |
| 调试诊断：计数、耗时、故障现场 | 随 TIM1 触发、DMA 完成、ADC 中断及故障检测同步更新；故障帧在发现异常时记录，不是单独的周期任务 | `Encoder_CaptureFault()`、`Encoder_RecordFocIsrCycles()` 等 | [encoder.c](../servo_v1/Modules/Encoder/Src/encoder.c)、[stm32g4xx_it.c](../servo_v1/Core/Src/stm32g4xx_it.c) |
| 后台维护：电机编码器恢复与诊断命令 | 主循环反复检查；通信超时后做恢复，并处理诊断捕获命令，正常采样仍由 TIM1 启动 | `Encoder_Service()` | [encoder.c](../servo_v1/Modules/Encoder/Src/encoder.c)，由 [main.c](../servo_v1/Core/Src/main.c) 调用 |

正常电机反馈链在一个 50 µs 周期中的先后关系如下。约 4.6 µs 是当前 5.25 MHz SPI 配置的纯传输时间估算；中断响应有延迟，ADC 触发点也会随占空比调整。ADC 序列优先在载波峰值前约 5 µs 完成，为 FOC 计算和 PWM 提交留出时间。

```text
PWM 谷值                 SPI 接收完成              ADC 序列完成/FOC                PWM 峰值       下一谷值
约 0 µs                  约 4.6 µs                 目标约 20 µs                    约 25 µs       约 50 µs
TIM1 更新中断            DMA 完成中断              ADC 完成中断
启动 SPI/DMA             解析 → 计算反馈 → 发布快照  读快照 → FOC → PWM；随后 PendSV 按需更新 Iq
```

所以，电机编码器的协议解析、测速和快照发布，正常是在同一个 DMA 完成回调中连续完成；ADC 中断随后使用已经发布的数据。各软件层不是各自等待一个独立的定时任务才开始工作。

异常时，TX DMA / SPI 错误中断或主循环超时恢复也可能结束事务并调用完成回调，此时走错误记录和反馈处理路径。输出轴 MPT 则按另一套 1 ms 查询节奏工作，解析和位置计算均依靠主循环处理，可能受前台其他任务影响。

结构体**定义文件**与函数**执行文件**要区分：公共反馈及诊断类型定义在 [encoder.h](../servo_v1/Modules/Encoder/Inc/encoder.h)，实现主要在 encoder.c；`encoder_context_t`、`encoder_speed_point_t` 直接定义在 encoder.c。其余类型的头文件位置见下面各节。初始化时由 main.c 调用模块初始化和参数配置函数，上表描述的是初始化后的正常运行调度。

电机反馈链：

```text
SPI1 + DMA
  → s_encoder.rx[]                         原始接收字节
  → g_mt6701_ssi                           MT6701 解析结果
  → 临时 mt6835_angle_t                    兼容现有公共处理的中间容器
  → s_encoder                             方向、多圈、测速历史和电角零位
  → g_encoder_snapshot                    对外发布的电机反馈
  → Encoder_ReadSnapshot()                复制并检查新鲜度/诊断锁存
  → SpeedCommission_Reference()
  → foc_input_t                           电角度、Id/Iq 给定、电流反馈
  → FOC_AlgorithmStep()
```

输出轴反馈链：

```text
USART1 + DMA
  → mpt_t485.c 内部 rx[]
  → MptT485_Decode()
  → g_mpt_t485
  → g_output_position                     目标位置、实际位置、误差
  → 电机速度给定
  → 速度环 → Iq 给定 → FOC
```

两条链不是同一个快照：`encoder_snapshot_t` 对应电机端；`mpt_t485_t` 对应输出轴端。MPT 角度通过位置环影响速度指令，不直接作为 FOC 电角度。

## 2. 最需要理解的四个结构体

### 2.1 mt6701_ssi_t：MT6701 协议结果与通信观测

定义：[mt6701_ssi.h](../servo_v1/Modules/Encoder/Inc/mt6701_ssi.h)；实例：`g_mt6701_ssi`。

**定位：器件协议层。** 保存本次 SSI 帧、器件原始角度、磁场状态、CRC 结果和通信计数，尚未完成电机方向和电角度换算。

| 字段组 | 含义 |
| --- | --- |
| `rx[3]`、`raw_frame` | 最近一次 HAL_OK 收发的 3 字节及其 24 位组合 |
| `angle_raw`、`angle_deg` | 最近有效角度，原始范围 0～16383，对应一圈 |
| `status`、`magnetic_field_status`、`push_detected`、`loss_of_track` | 器件状态；`status` 保存帧中的整个 4 位 Mg 状态 |
| `crc_received`、`crc_calculated` | 收到的 CRC6 与本地计算值 |
| `sample_valid` | 最近一帧是否通过 CRC 和非全一帧检查；全零角度帧允许有效 |
| `communication_ok`、`consecutive_good` | 连续 3 帧有效后的通信观测状态；不等于整个伺服系统已准备好 |
| `frame_count`、`good_frame_count`、各类错误计数 | 已处理帧、有效帧、SPI/CRC/空帧错误等统计 |
| `last_sample_tick_ms`、`last_good_tick_ms` | 处理帧及最近有效帧的毫秒时间记录 |
| `enabled`、`poll_period_ms` | 独立轮询诊断接口的控制字段 |

当前由 SPI1 DMA 收尾路径调用 `Mt6701Ssi_ProcessFrame()` 更新它。默认闭环采集由 TIM1 调度，不能通过 `poll_period_ms` 改变采样频率，`enabled` 也不是该 DMA 链的总开关。

`Mt6701Ssi_Task()` 是独立轮询诊断接口，不应与当前 Encoder DMA 链同时占用 SPI1。上层控制应读取公共快照，而不是绕过公共检查直接使用 `g_mt6701_ssi.angle_deg`。

### 2.2 encoder_context_t：电机编码器模块的内部工作状态

定义和实例位于 [encoder.c](../servo_v1/Modules/Encoder/Src/encoder.c)；实例：`s_encoder`。

**定位：公共电机反馈层的内部实现。** 它保存“计算反馈需要的工作现场”，不是给 FOC 使用的数据接口。

| 字段组 | 含义 |
| --- | --- |
| `tx[6]`、`rx[6]`、`transfer_busy`、`transfer_start_cycle` | 事务缓冲区、忙状态和启动时间；缓冲区按兼容后端保留 6 字节，当前 MT6701 每帧传输 3 字节 |
| `initialized`、`motor_configured` | 模块和电机换算参数是否已配置 |
| `direction`、`pole_pairs`、`electrical_offset_rad` | 方向、极对数和 MCU 侧电角度偏置 |
| `previous_raw_angle`、`have_previous_angle`、`multi_turn_count` | 跨过单圈边界时连续展开位置 |
| `speed_history[]`、`history_head`、`history_count` | 测速环形历史 |
| `filtered_speed_rad_s`、`last_speed_cycle` | 滤波速度与上次测速更新时间 |
| `max_counts_per_256_cycles`、`previous_trigger_cycle` | 角度步进合理性及触发间隔相关状态 |
| `last_computed_crc`、`last_crc_match` | 最近帧的 CRC 诊断镜像；当前 MT6701 路径填 CRC6 结果 |

该类型没有通过头文件导出。当前 `s_encoder` 定义虽未加 `static`，职责上仍属于模块内部状态，外部应通过 `Encoder_ConfigureMotor()`、读取接口等操作。

### 2.3 encoder_snapshot_t：交给控制层的统一电机反馈

定义：[encoder.h](../servo_v1/Modules/Encoder/Inc/encoder.h)；发布实例：`g_encoder_snapshot`。

**定位：公共反馈层向控制层交接数据的边界。** 协议差异已在下层处理，消费者读取角度、速度、时间和有效性。

| 字段 | 含义和单位 |
| --- | --- |
| `raw_angle` | 未按电机方向转换的单圈原始计数；公共格式为 21 位 |
| `multi_turn_count` | 按方向修正并跨圈累加的 64 位计数；一圈对应 2²¹ 个公共计数 |
| `mechanical_angle_rad` | 方向修正后的单圈机械角，单位 rad |
| `mechanical_speed_rad_s` | 方向修正后的滤波机械速度，单位 rad/s |
| `electrical_angle_rad` | 根据极对数和电角度偏置换算的电角度，单位 rad |
| `sample_cycle` | 本次事务启动时的 DWT CPU 计数；不是 DMA 完成时间，也不是 PWM 周期编号 |
| `sequence` | 发布序号，标识新反馈 |
| `fault_flags`、`status_raw` | 公共故障位及器件状态 |
| `angle_valid`、`speed_valid`、`electrical_angle_valid` | 三种反馈各自的有效标志 |

MT6701 的 14 位原始计数左移 7 位后进入公共格式，因此公共一圈为 2²¹，真实传感器分辨率仍是 14 位。

模块在短临界区发布快照。`Encoder_ReadSnapshot()` 复制后还会检查数据年龄和诊断故障锁存，可能将返回副本判为无效。因此，调试器看到的 `g_encoder_snapshot` 与调用接口得到的有效性不一定相同。

消费者还需要检查自己使用的有效位：刚开始采集时可能角度有效，但测速历史尚未充满，`speed_valid=0`；电机参数未配置时，电角度也不能用于换相。`volatile` 本身不保证整个结构体读取一致，应使用读取接口。

### 2.4 mpt_t485_t：输出轴编码器的反馈与通信状态

定义：[mpt_t485.h](../servo_v1/Modules/Encoder/Inc/mpt_t485.h)；实例：`g_mpt_t485`。

**定位：输出轴器件模块，兼有协议解析、反馈发布和通信统计。** 当前没有再封装为 `encoder_snapshot_t`。

| 字段组 | 含义 |
| --- | --- |
| `frame[16]` | 接收缓冲区内容的镜像；协议有效应答长度为 11 字节 |
| `angle_raw`、`angle_deg` | 有效单圈角度，一圈 131072 个计数，角度单位为度 |
| `turns_raw` | 协议解析得到的圈数；当前位置控制主要依据单圈计数自行展开位置 |
| `status`、`alarm` | 最近接收数据中的状态和报警字节 |
| `initialized`、`enabled` | 初始化状态与查询使能 |
| `valid`、`consecutive_good` | 连续 10 帧正确后有效；遇到接收/解析错误会清零 |
| `last_good_ms`、`sequence` | 最近有效测量的请求时间（毫秒）及成功发布序号 |
| `requests`、`good_frames`、各类错误计数 | 查询、成功帧、CRC/格式/状态/超时/UART 错误统计 |
| `resp_latency_last_us`、`resp_latency_max_us` | 最近响应延迟与本次上电以来最大延迟，使用DWT微秒统计；最大值也可能含启动/前台停顿 |
| `resp_latency_max_ms`、`resp_latency_sum_ms`、`resp_latency_samples` | 毫秒兼容统计；不能据此把亚毫秒响应解释为零延迟 |

由主循环 `MptT485_Task()` 检查 DMA 与串口状态，进入 `finish()` 后解析和发布；位置控制使用其有效性、时间及角度。`status/alarm/frame` 可能来自最近失败帧，`angle_raw/angle_deg` 仍保留上次有效值，读取时必须结合 `valid`。

位置控制还检查距 `last_good_ms` 的时间，不能只看角度数值是否变化。

当前查询/位置周期配置1 ms、响应超时2 ms、反馈年龄上限5 ms；都是前台服务的条件，实际达成率需读计数差验证。R17的`mpt_t485_t`为108字节，新增延迟字段保留在尾部；调试脚本须从匹配AXF获取地址和长度。

## 3. 其他反馈处理与兼容类型

| 类型 | 实例 / 使用位置 | 层次与用途 |
| --- | --- | --- |
| `encoder_speed_point_t` | `s_encoder.speed_history[]`；定义在 encoder.c | 公共反馈层内部测速点，仅含 `position`（连续计数）和 `cycle`（DWT 时间）；用位置差 / 时间差计算速度，再滤波 |
| `mt6835_angle_t` | 旧 MT6835 读取接口；当前 `Encoder_TransferComplete()` 内临时变量 `frame` | 器件帧结果/兼容中间容器，字段为 `angle_raw`、`status`、`crc`、`crc_ok`、`raw[4]` |
| `mt6835_status_t` | `mt6835_angle_t.status` | 是联合体而非结构体：以 `raw` 或位域查看 MT6835 报警；当前 MT6701 兼容路径只赋 `status.raw`，不能按 MT6835 报警位解释 MT6701 状态 |

`mt6835_angle_t` 的名字带 MT6835，但当前 MT6701 分支也会借用它传递 `angle_raw/status/crc_ok`；`crc/raw[]` 在此分支并未作为完整 MT6835 帧填充，不能据此诊断 SSI 原始字节。当前 MT6701 原始帧应看 `g_mt6701_ssi.rx/raw_frame`。

定义：[encoder.c](../servo_v1/Modules/Encoder/Src/encoder.c)、[mt6835.h](../servo_v1/Modules/Encoder/Inc/mt6835.h)。

## 4. 调试诊断结构体

这些结构体解释故障或执行耗时，不是正常的角度交接接口。其中 `encoder_logic_trigger_t` 还参与当前诊断模式的输出许可判断。

| 类型 / 全局实例 | 关键内容 | 定位和当前状态 |
| --- | --- | --- |
| `encoder_diagnostics_t` / `g_encoder_diagnostics` | 触发/完成/忙/传输/CRC/报警次数，事务与 ISR 耗时，读取年龄，重同步、步进异常统计 | 公共反馈层的运行统计；用 `Encoder_GetDiagnostics()` 一致性复制；不同字段由对应路径更新，零值不能单独证明某项已经测量 |
| `encoder_fault_frame_t` | `cycle/reason/previous_angle/spi_status/previous_cycle`、`rx[6]`、`computed_crc/status` | 一次异常事件的现场记录 |
| `encoder_fault_capture_t` / `g_encoder_fault_capture` | `count`、`first`、`last`、`recent[8]`、`last_alarm` | 故障证据容器；首帧冻结，保留最近事件及最近报警 |
| `encoder_logic_trigger_t` / `g_encoder_logic_trigger` | `diagnostic_mode/command/state`、故障原因、DWT 时间、前角度及原始字节 | 一次性诊断触发与锁存；状态为 WAITING / ARMED / FIRED；当前模式 2 下还与反馈需求共同约束输出许可 |
| `encoder_zero_guard_t` / `g_encoder_zero_guard` | 预期/观测零点、校验位、锁存和计数 | 旧 MT6835 零位寄存器监测的兼容记录，当前不主动执行该监测 |
| `encoder_zero_fault_frame_t` | 零点事件的时间、SPI 状态、寄存器地址、收发结果 | 旧零位故障单帧格式，当前停用 |
| `encoder_zero_fault_capture_t` / `g_encoder_zero_fault_capture` | `sequence/count`、`first/last/recent[8]` | 旧零位故障捕获容器，当前停用；字段保留供调试布局兼容 |

以上类型均定义在 [encoder.h](../servo_v1/Modules/Encoder/Inc/encoder.h)。零位诊断结构体为零表示未启用，不能理解为“已经验证零点寄存器正确”；它们与 `s_encoder.electrical_offset_rad` 的 MCU 侧换相零位不是同一件事。

`encoder_fault_flags_t` 也不是结构体，而是 `uint32_t` 位掩码，表示通信、CRC、器件报警、过期、未配置、步进不合理等故障。

时间单位要看具体字段：DWT 耗时除以 `SystemCoreClock` 得到秒，168 MHz 下 168 cycles = 1 µs；但 `ENCODER_MAX_SAMPLE_AGE_CYCLES` 这类配置宏的“cycles”表示载波周期数，模块内部会换算，不能混用。

## 5. 控制层接收后放在哪里

编码器校准由 [encoder_calibration.h](../servo_v1/Servo/Inc/encoder_calibration.h) 定义的 `encoder_calibration_t` 独立管理；使用方法和状态值见[架构说明的编码器校准部分](架构说明.md#编码器校准如何使用)。`encoder_calibration_record_t` 是 Flash 中的持久化记录格式，属于存储层，不能直接拿它执行 FOC。校准完成后仍由 `Encoder_ConfigureMotor()` 更新公共编码器换算参数，再通过 `g_encoder_snapshot` 把新零点下的反馈交给 FOC。

| 类型 / 实例 | 层次定位 | 与编码器的关系 |
| --- | --- | --- |
| `foc_input_t` / 控制器的 `input` | FOC 算法输入 | 接收电角度和 `angle_valid`，以及电流反馈、Id/Iq 给定及各自有效位；不包含 SPI 原始帧、机械速度和输出轴位置 |
| `output_position_t` / `g_output_position` | Servo 输出轴位置控制 | 从 MPT 反馈得到 `actual_deg`，与 `target_deg` 比较得到 `error_deg`，按参数生成 `motor_rpm`；另含运行命令、状态、故障及速度前馈 |
| `output_position_test_t` / `g_output_position_test` | 位置控制的开发验证 | 保存测试轨迹幅度、中心、经过时间、误差统计和测试状态 |
| `output_position_trace_t` / `g_output_position_trace[64]` | 位置试验采集记录 | 每个点保存 `elapsed_s/target_deg/actual_deg/motor_rpm`，用于分析位置跟随 |
| `output_position_sweep_frd_t` / `g_output_position_sweep_frd` | 位置试验频域结果 | 稳态长窗口增益、相位、Welch相干性、周期/分段及有效/拒绝原因；不是编码器协议帧 |

R17参考ABI：`output_position_t`56字节、`output_position_test_t`84字节、FRD40字节；trace每行16字节，64行为1024字节。轨迹结构含三相平方和与`current_samples`，在20 kHz ADC中观测稳态相RMS；连续快速路径统计位于PWM提交之后。FRD在位置前台路径计算。实际读取仍由AXF的`sizeof`决定，不能照抄历史100/101行、52字节位置结构或32字节FRD。

普通位置参数在arm时锁存，用户目标保持为使能会话内角度；单圈MPT角度与累计会话目标不要混读。实测、命令和结果有效性见[位置环调试与使用说明](位置环调试与使用说明.md)。

定义：[foc_algorithm.h](../servo_v1/FOC/Inc/foc_algorithm.h)、[output_position.h](../servo_v1/Servo/Inc/output_position.h)。

当前默认链在 ADC 回调进入 `FOC_ControllerStep()` 后，经 `MainFoc_ReadFeedback()` 调用 `SpeedCommission_Reference()`：读取公共快照、用机械速度执行分频速度环、把电角度及电流给定写入 `foc_input_t`。单独的 NORMAL 分支用 `Encoder_ReadElectricalAngleForFoc()` 取已发布电角度。

`g_speed_test/g_speed_run` 属于速度控制运行管理，它们会记录已消费的编码器反馈、故障和数据年龄；并不代替公共编码器快照。

## 6. 外设句柄和独立试验

| 类型 / 实例 | 定位 |
| --- | --- |
| `SPI_HandleTypeDef` / `hspi1` | HAL 外设配置和运行状态；默认电机反馈链的 SPI1 句柄 |
| `DMA_HandleTypeDef` / `s_hdma_spi1_rx/tx` | SPI1 收发 DMA 句柄；由传输模块拥有，不向控制层发布 |
| `DMA_HandleTypeDef` / mpt_t485.c 内的 `rx_dma/de_dma` | 输出轴接收 DMA，以及 TIM7 触发的 RS-485 DE 释放 DMA |
| `mt6701_spi3_test_t` / `g_mt6701_spi3_test` | Tests 层的独立 SPI3 通信测试，保存轮询参数、帧、角度、CRC 和错误计数；不是当前默认 SPI1 电机反馈 |
| `SPI_HandleTypeDef` / `hspi_mt6701`、`hspi3` | 独立 SSI 轮询接口或 SPI3 试验的句柄，不应与默认 SPI1 DMA 调度混为一条链 |

传输模块还有忙标志、回调指针、缓冲区等散立变量，当前没有统一的“SPI 编码器传输结构体”。外设句柄的定义属于 STM32 HAL，不代表编码器业务数据。

源码：[spi1_encoder.c](../servo_v1/Modules/Encoder/Src/spi1_encoder.c)、[mpt_t485.c](../servo_v1/Modules/Encoder/Src/mpt_t485.c)、[独立 SPI3 测试类型](../servo_v1/Tests/Inc/mt6701_spi3_test.h)。

## 7. 调试时按问题选结构体

| 想确认的问题 | 优先查看 |
| --- | --- |
| MT6701 返回什么、CRC 和磁场状态如何 | `g_mt6701_ssi` |
| SPI 是否还忙、启动时刻、方向和极对数是否正确 | `s_encoder` |
| 控制层能够拿到什么电机反馈 | `Encoder_ReadSnapshot()` 的返回值和副本；Watch 辅看 `g_encoder_snapshot` |
| 为什么反馈失效、耗时是否异常 | `g_encoder_diagnostics`、`g_encoder_fault_capture`、`g_encoder_logic_trigger` |
| 输出轴是否收到有效应答 | `g_mpt_t485` |
| 输出轴实际位置与目标、速度指令是什么 | `g_output_position` |
| FOC 本周期实际使用的角度和给定是什么 | `g_foc_controller.input` |
