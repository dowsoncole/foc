# 客户位置指令幅相测试说明

更新：2026-10-29。新增客户指令测试模式，控制入口仍为位置模式 `mode=5`，位置反馈仍为输出轴 MPT。已结合补充 Excel 增加逐帧模式，脚本默认选用 Excel。后续已连接 J-Link、烧录并完成两轮1～15Hz实测；[实测幅相报告](../control_analysis/results/customer_position_live_20261029/客户位置指令_实测幅相报告.md)给出两轮曲线、限幅标记和最终OFF证据。

## 1. 需求依据与实现口径

来源：用户提供的 `0——20251024 测试问题反馈.docx`，以及 `客户需求PWM给定方式.xlsx`。Word 包含测试时序与文字指令，Excel 的可见表 `PWM table due 1 sec!B2:P301` 给出 1～15 Hz 的逐帧脉宽。两种口径单独保留，避免把冲突来源混成同一个测试。

| 项目 | Excel 逐帧模式 `test_mode=2`（推荐） | Word 文字模式 `test_mode=1` |
|---|---|---|
| 相对位置 | `0→2→0°`，相对开始测试时实际输出轴位置 | 同左 |
| 指令来源 | 原表 4500 个脉宽逐个复制，不重算、不平滑 | `1501→…→1520→…→1500 μs`，40 点/周期 |
| 内部角度映射 | 按示例推定 `1500 μs=0°`、`1520 μs=2°` | 同左 |
| 指令调度 | 每秒 300 帧，保持至下一帧 | 每秒 `40f` 个指令槽 |
| 频率 | 1～15 Hz；原表未给出 16～30 Hz | 1～30 Hz |
| 各组运动时间 | 原表一秒序列重复两次，共 2 秒 | 2 秒 |
| 各组休息时间 | 回测试原点并闭环保持 2 秒 | 同左 |
| 总时长 | 60 秒，包含最后一次休息 | 120 秒，包含最后一次休息 |
| 速度前馈 | 固定为 0 | 同左 |
| 加速度斜坡 | 沿用普通位置的 300000 rpm/s | 同左 |
| 完成后 | 保持原点；脚本随后关闭 PWM | 同左 |

Word 称“类似正弦”，但文字等步长序列是阶梯三角波；附图画成约 ±2° 的正弦，与文字 `0→2→0°` 不一致。Excel 可见逐帧表没有公式，部分幅值点重复、部分跳过，因此逐帧模式严格用单元格数值，不用理想三角波或正弦替换。需要正负 2° 稳态正弦时，使用原有 `test_mode=0`。

文档中“1/30 秒=33 微秒”存在单位错误，本实现按 **33.333 毫秒**计算。

这是**内部位置指令复现**。没有新增外部 PWM 输入捕获，也没有输出 300/333 Hz、3.3–5 V 的电信号，不能据此判断遥控器、PWM 输入接口或输入延迟。Word/Excel 隐藏表使用 333 Hz，Excel 两张可见表使用 300 Hz；逐帧模式采用与具体数值表配套的 **300 Hz**。Word 的完整 40 点/周期在 9 Hz 起超过 333 帧/秒，不能与真实 333 Hz PWM 链路视为等价。

### Excel 核查与数据来源

- `QTY of PWM Signals!B3:B32` 为 300 Hz，`D3:D32` 为每周期可用帧数 `300/f`；`G3:G42` 列出原始 40 点脉宽序列。
- `PWM table due 1 sec!B1:P1` 为 1～15 Hz；`B2:P301` 是每列 300 个实际帧值。例如 15 Hz 的首周期为 `1501,1503,…,1517,1520,1517,…,1501,1500`，共 20 帧。该表没有 16～30 Hz 列。
- 隐藏表 `Данные с расчётами` 使用 333 Hz 和正弦表达式，不能覆盖可见逐帧表的具体数值。
- 隐藏表 `АФЧХ` 含历史幅相示例和边界：1/10/15/20/30 Hz 的幅值下界为 −2/−6/−10/−40/−40 dB，上界均 +1 dB，相位下界为 −30/−120/−135/−270/−270°。未给定中间频点插值规则，本实现不据此自动判定通过。
- 该历史表的相位列公式 `2*PI()*delay*f` 得到弧度，却标为度；延迟列还含 −4 等与秒单位不相称的值，21～30 Hz 的空延迟计算出 0。它们不能当作本机实测或可信的相位标定。本实现直接拟合实际位置基波，不复制这些公式或把空值当零响应。

固件表位于 [customer_pwm_table.h](../servo_v1/Servo/Inc/customer_pwm_table.h)，由[只读导入脚本](../control_analysis/scripts/import_customer_pwm_table.py)提取；[来源清单](../control_analysis/customer_pwm_table_source.json)保存源文件 SHA256、单元格范围及全部 4500 个指令值的校验值。原始 Excel 没有修改。

## 2. 固件接口与 Watch 操作

新增选择器：`g_output_position_customer.test_mode`。

| 值 | 用途 |
|---:|---|
| 0 | 原有 legacy、有限正弦扫频或阶跃测试，参数仍由 `g_output_position_test` 指定 |
| 1 | 本文客户固定流程；频率表、幅值、持续时间、FF 由协议固定 |
| 2 | Excel 可见表逐帧流程，300 Hz、1～15 Hz，固定 60 秒 |

选择器在开始测试时锁存；运行中修改选择器不会改变当前轨迹。上电默认为 0，不会自动执行客户流程。位置模式原有的启动保持行为不变。

推荐由下节脚本启动；Watch 手动使用时：

1. 按[位置环调试与使用说明](位置环调试与使用说明.md)确认板卡、编码器、负载、当前位置和停机状态。先在 OFF 时设置 Kp、转速上限，再进入位置模式；这些控制参数在 arm 时锁存。
2. 进入位置模式 `g_user_control.mode=5` 并使能，确认 `g_output_position.state=1`、速度内环运行、无故障，位置误差不超过 0.1°、电机实际转速不超过 50 rpm。测试起点输出角必须在 **5°～353°** 内。
3. 设置 `g_output_position_customer.test_mode=2`（Excel；Word 文字复现选 1），再设置 `g_output_position_test.command=1`。保持 MCU 运行，不要在运动中设置断点。
4. 观察下列状态和结果表。每组运动结束后发布一行结果，休息期间结果保持不变。
5. 完成后 `g_output_position_test.state=2`，仍在位置保持。主动关闭 `g_user_control.enable`；读回 `TIM1_BDTR.MOE=0` 才确认 PWM 已关闭。

| 变量 | 含义 |
|---|---|
| `g_output_position_customer.frequency_hz` | 当前频率：Excel 1～15，Word 1～30 |
| `g_output_position_customer.resting` | 1=当前为 2 秒原点保持段 |
| `g_output_position_customer.completed` | 已发布到第几行，0～30；可包含失败/中止行，不表示通过数量 |
| `g_output_position_test.elapsed_s` | 总流程已运行秒数 |
| `g_output_position.target_deg / actual_deg / error_deg` | 实际下发位置、输出位置、跟踪误差 |
| `g_output_position_capture.customer[0..29]` | 幅相结果表；Excel 只发布前 15 行，其余行保持未执行 |
| `g_output_position_test.saturated_samples / slew_limited_samples` | 整个流程累计的速度限幅/斜坡限幅样本数 |

C 源码可使用别名 `g_output_position_customer_results[i]`。这是宏，不是独立链接符号；调试器请使用真实的 `g_output_position_capture.customer[i]`。

中止：关闭用户使能，或设置 `g_output_position.command=2`。`g_output_position_test.command=2` 也会中止并记录故障 6。保留故障原因，不自动清除故障或重新启动。若配置了主机心跳保护，必须持续刷新心跳；不要为了运行 120 秒而把保护超时改成 120 秒。

## 3. 上位机运行与输出

脚本入口已扩展，默认不执行运动。**必须使用包含本功能的新固件，并使板上 Flash 与所给 AXF 完整匹配**；脚本会验证，持续不匹配即拒绝 RAM 写入。稀疏块读差异仅在两个独立单字回读均匹配预期后接受，并保存原始差异与整段验证结果。当前新固件与先前 R17 不同，不可拿旧 R17 的 AXF 测试新模式。

仓库根目录 PowerShell，仅检查、不运动：

```powershell
python -B software/control_analysis/scripts/measure_position_response.py software/control_analysis/results/customer_position_check --axf software/servo_v1/MDK-ARM/servo_v1/servo_v1.axf --customer-protocol --customer-source xlsx --kp 72 --max-motor-rpm 5500 --max-phase-peak 15 --max-phase-rms 5
```

执行测试，在上述检查与现场条件满足后使用新的输出目录：

```powershell
python -B software/control_analysis/scripts/measure_position_response.py software/control_analysis/results/customer_position_run --axf software/servo_v1/MDK-ARM/servo_v1/servo_v1.axf --customer-protocol --customer-source xlsx --kp 72 --max-motor-rpm 5500 --max-phase-peak 15 --max-phase-rms 5 --run
```

目录必须不存在，避免覆盖旧证据。默认 J-Link 为 `150710982`，SWD 50 kHz。`--customer-source xlsx` 为默认选择；切换 `--customer-source word` 执行 Word 的 1～30 Hz/120 秒版本。两者均固定 `0→2→0°`、每组 2+2 秒；`--duration`、`--step`、`--compare-feedforward` 不能组合；`--frequencies` 不控制固定频率表。客户模式会强制 FF=0。

`--kp 72` 显式采用当前位置环配方；CLI 普通默认值仍为 80。5500 rpm 是本示例的普通位置上限，发生限幅会在结果中标记，不会为了曲线好看自动提高上限。15 A 峰值与 5 A RMS 是主机试验中止条件，**没有改变 MCU 的硬件 OCP/FLT_MAX 电流策略**。

脚本保持 10 秒 MCU 心跳超时，并在约 0.5 秒间隔检查状态和刷新心跳；正常完成、异常或用户中断都进入停机清理。通信失败时必须现场确认 PWM/供电状态，不能只根据主机异常推定已经停机。

本模式的电流 RMS 是整个流程的累计值，包含静止休息段，不是每个频点的运动 RMS；因此 5 A 整体 RMS 不能证明每一频点或每一瞬间低于 5 A。峰值统计仍取自原有电流观测。

| 文件 | 内容 |
|---|---|
| `summary.json` | 参数、停机结果、幅相结果；异常时保留 cleanup_error |
| `customer_results.bin` | 30 行原始结果表，960 字节 |
| `customer_results.json / .csv` | Excel 15 组或 Word 30 组数值与资格标记 |
| `customer_results.md` | 自动生成的逐频点 Markdown 结果表 |
| `customer_response.png` | 实际幅频、相频图；红叉表示限幅，橙色空圈表示指令漏点 |
| `customer_*_*.bin / .json / .log` | 原始状态、诊断及调试器交互证据 |

离线重新生成报告，不连接硬件：

```powershell
python -B software/control_analysis/scripts/analyze_customer_position_test.py software/control_analysis/results/customer_position_run/customer_results.bin software/control_analysis/results/customer_position_report --source xlsx
```

Word 数据改用 `--source word`；原始结果表本身不存来源标识，离线处理必须与运行参数一致，脚本生成的 `summary.json.arguments.customer_source` 可供核对。也可停机后通过调试器导出 `&g_output_position_capture.customer` 起始的 **960 字节**，再用此命令分析；不得沿用旧 ELF 的绝对地址。完整 capture union 为 1024 字节，离线分析器也接受该长度。

## 4. 幅值、相位和有效性

每组在实际运行的 2 秒窗口内，用实际时间拟合：

```text
reference(t) = DCx + ax·cos(2πft) + bx·sin(2πft)
actual(t)    = DCy + ay·cos(2πft) + by·sin(2πft)
Ax = sqrt(ax²+bx²), Ay = sqrt(ay²+by²)
H = (ay-j·by)/(ax-j·bx)
gain_db = 20·log10(Ay/Ax)
phase_deg = arg(H)              # 主值 (-180°, 180°]，负号表示滞后
```

拟合包含 DC，避免 `0→2→0°` 的非零平均值污染幅相。参考采用**实际已下发、保持的阶梯位置指令**，不是理想正弦。基波幅值是峰值，既不是峰峰值也不是 RMS；Word 模式对应的理想连续 0～2° 三角波基波峰值约 0.811°，Excel 应以各列实际拟合幅值为准，不能把输出基波直接除以 2° 算增益。

**该窗口包括起动暂态。** 每个频点只有 2 秒，1 Hz 只有 2 个周期；没有沿用原稳态正弦 FRD 的至少 20 周期、Welch 相干性等资格门槛。这里的 `estimate_usable` 仅表示短窗口估计通过数值、覆盖和限幅检查，不能直接等同 `g_output_position_sweep_frd.valid`，也不能直接用它宣称 −3 dB 闭环带宽。

结果结构每行 32 字节，包含 `frequency_hz`、`reference_amplitude_deg`、`actual_amplitude_deg`、`gain_db`、`phase_deg`、`samples`、`flags`、`missed_commands`。

| flags 位值 | 原因 | 幅相处理 |
|---:|---|---|
| 1 | 拟合矩阵退化、参考/反馈基波过小或非有限 | 不可用 |
| 2 | 该频点出现速度输出限幅 | 不作为线性幅相证据 |
| 4 | 该频点出现速度斜坡限幅 | 不作为线性幅相证据 |
| 8 | 指令槽被跳过：Excel 为 300 Hz 帧，Word 为 40f 槽 | 可展示实际下发指令的短窗口估计，但没有完整复现选定指令 |
| 16 | 该频点中止 | 不可用 |
| 32 | 未执行、时间窗口不完整或采样不足 | 不可用 |

多个原因按位或组合；`flags & 55 == 0` 且数值有限、样本数 ≥1900 时，离线报告标记 `estimate_usable=true`；在此基础上 `flags==0` 才标记 `protocol_complete=true`。覆盖检查还要求首样本不晚于 2 ms、末样本不早于 1997 ms。未运行行和中止行保留，不插值为有效结果。

Excel 模式以 `floor(elapsed_ms*300/1000)` 定位帧，3.333 ms 理想边界在 1 ms 位置任务中量化为 3/4 ms 保持；调度正常时每组 600 个帧槽均能执行，边界量化误差小于 1 ms。重复脉宽帧也按帧计数，不误判为漏点。原表高频主动跳过的幅值点属于客户给定序列，不是 MCU 漏帧。

Word 模式每周期完整 40 点要求 `40f` 次/秒，因此理想 1 ms 调度下 **26～30 Hz 必然漏点**，25 Hz 也要求每毫秒准时执行。两模式均用绝对时间定位、计数漏槽，避免整数周期取整导致频率漂移。本功能没有修改位置环周期，也没有补造 Excel 未提供的频率列。

## 5. 兼容性与验证记录

- 现有 `g_output_position_test` 仍为 84 字节，普通轨迹接口、位置 PI 参数、电流保护、MPT 反馈和 PWM 写入门槛没有改变。
- 新增 16 字节客户选择/状态结构。30 行客户结果占 960 字节，与原 64 行、1024 字节的轨迹缓冲区共用一个 union；**客户模式不同时保存时域 trace**。开始另一种测试会覆盖前一种 capture，必须先导出结果。
- 源码中的 `g_output_position_trace` 现在是 `g_output_position_capture.trace` 的宏别名。`position_abi.py` 同时支持新 union 和旧冻结 ELF；所有地址与长度从对应 ELF 解析。旧 R17 的冻结产物不随此变更更新。
- 主机 C 回归通过 `-Wall -Wextra -Werror`，包括 Word 完整 120 秒/30 行、五毫秒延迟/半幅/DC 偏置、26～30 Hz 漏点，以及 Excel 完整 60 秒/15 行逐 tick 对照、每组 600 帧无漏点、模式锁存、中止及未知模式拒绝；原位置轨迹测试仍通过。
- Python 幅相/报告回归当前共 22 项通过，新增了逐字Flash双读复核及持续差异拒绝检查，并修正Word120秒流程的RMS计数合理性上限；目标 Keil 编译 0 错误、0 警告。RW+ZI 为 32688 字节，32 KiB SRAM 区仅余 80 字节，已包含配置的 2 KiB 栈区域；这不是运行时栈高水位证明。
- **本日后续已烧录并完成两轮Excel逐帧实测。** 起点约256.437°/256.432°，每频点2000样本、600帧无漏帧，速度限幅0，多点存在斜坡限幅。相位从1Hz约−6°递减至15Hz约−87°；幅值在8～11Hz出现重复性不足的转折，不能直接判带宽或固定共振。最终PWM关闭，runtime/FOC/位置/速度故障均0。完整数据见[实测报告](../control_analysis/results/customer_position_live_20261029/客户位置指令_实测幅相报告.md)。
