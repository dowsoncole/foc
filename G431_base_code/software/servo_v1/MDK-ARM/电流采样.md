## 当前实现说明

以上需求已经落到 `Modules/Current_Sampling/` 模块中。模块分成两部分：

```text
adc1_current_sampling.c/.h
    配置层：配置 OPAMP1、OPAMP3、ADC1 注入组，并启动硬件触发链

current_sampling.c/.h
    业务层：保存采样快照、零点校准、原始码换算和 FOC 反馈接口
```

配置层只负责让硬件正确工作，业务层不直接改 ADC 配置寄存器。这样以后更换 ADC 通道、触发定时器或 MCU 时，业务接口可以保持不变。

### 1. 原始采样数据

当前通道映射已经确认：

| 接口通道 | MCU 引脚 | ADC 通道 | 电机相别 | ADC 数据寄存器 |
|---|---|---|---|---|
| rank 1 | PA2 | ADC1_IN3 | U 相 | `ADC1->JDR1` |
| rank 2 | PB1 | ADC1_IN12 | V 相 | `ADC1->JDR2` |

ADC 使用 12 位转换和 16 倍注入组过采样。由于过采样右移设置为 0，硬件把 16 次转换结果相加后写入 JDR：

```text
单次 ADC 结果：0..4095
JDR 原始累加值：0..4095 × 16 = 0..65520
```

因此，原始接口返回的是累加值，不是普通的 0..4095 ADC 码。业务层如果需要 12 位等效码，应先除以 16。

### 2. `CurrentSampling_GetRaw()`

声明位置：`Modules/Current_Sampling/Inc/current_sampling.h`

```c
uint16_t CurrentSampling_GetRaw(current_sampling_phase_t phase);
```

用法：

```c
uint16_t raw_u = CurrentSampling_GetRaw(CURRENT_SAMPLING_PHASE_U);
uint16_t raw_v = CurrentSampling_GetRaw(CURRENT_SAMPLING_PHASE_V);
```

返回值是最近一次已经完成的 ADC 注入序列结果：

```text
raw_u -> U 相，来自 JDR1
raw_v -> V 相，来自 JDR2
```

该接口只返回原始累加码，不减零点，也不做单位换算，适合调试器观察、记录 ADC 波形和检查硬件是否在转换。

### 3. `CurrentSampling_GetCurrentA()`

声明：

```c
float CurrentSampling_GetCurrentA(current_sampling_phase_t phase);
```

用法：

```c
float current_u_a = CurrentSampling_GetCurrentA(CURRENT_SAMPLING_PHASE_U);
float current_v_a = CurrentSampling_GetCurrentA(CURRENT_SAMPLING_PHASE_V);
```

内部计算过程是：

```text
raw_delta = raw_value - zero_offset
adc_code  = raw_delta / 16
voltage   = adc_code × VREF / 4095
current   = voltage / (RSHUNT × OPAMP_GAIN)
```

当前固定参数为：

```text
RSHUNT     = 0.007 Ω
OPAMP_GAIN = 6.1
VREF       = 3.3 V
```

等价公式为：

```text
I[A] = (raw - offset) × 3.3
       / (16 × 4095 × 0.007 × 6.1)
```

如果以后更换采样电阻、运放增益或参考电压，只需要修改 `g_current_sampling` 中的参数，不需要修改换算流程。

### 4. `CurrentSampling_ReadFeedback()`

声明：

```c
void CurrentSampling_ReadFeedback(float *phase_u_a, float *phase_v_a);
```

用法：

```c
float phase_u;
float phase_v;

CurrentSampling_ReadFeedback(&phase_u, &phase_v);
```

这个接口是给 FOC 端口层使用的。它一次读取两相电流，避免 FOC 直接访问 `ADC1->JDR1/JDR2`、零点变量或换算参数。

FOC 只需要知道“当前 U/V 两相电流是多少”，不需要知道 ADC 使用了哪个寄存器、多少倍过采样或哪个定时器触发。

### 5. `CurrentSampling_RequestCalibration()`

声明：

```c
void CurrentSampling_RequestCalibration(void);
```

调用前提：应用层先把三相功率级设置为零电流校准状态，即三相下管导通。采样模块不会替应用层改变 PWM 或功率级状态。

推荐调用顺序：

```c
/* 应用层完成下管导通和功率级安全检查 */
CurrentSampling_RequestCalibration();
```

该函数不会等待 10 ms，也不会阻塞当前任务。它只清空上一次累加值，记录校准开始时间，并把状态切换为 `CURRENT_SAMPLING_CAL_SETTLING`。

### 6. `CurrentSampling_Service()`

声明：

```c
void CurrentSampling_Service(void);
```

调用位置：主循环或应用任务中周期调用，例如：

```c
while (1)
{
    CurrentSampling_Service();
    /* 其他后台任务 */
}
```

它是一个快速的非阻塞状态机：

```text
IDLE
  │ RequestCalibration()
  ▼
SETTLING：等待 10 ms，让下管导通后的采样电路稳定
  ▼
COLLECTING：收集 1 ms 内的 ADC 样本
  ▼
DONE：计算并保存 U/V 两相零点平均值
```

校准窗口为 1 ms，PWM/ADC 采样频率为 20 kHz，因此目标样本数为：

```text
20 kHz × 1 ms = 20 个样本
```

如果 1 ms 内没有采到任何样本，状态会变为 `CURRENT_SAMPLING_CAL_ERROR`，不会用无效数据覆盖原来的零点。

### 7. `CurrentSampling_GetCalibrationState()`

声明：

```c
current_sampling_cal_state_t CurrentSampling_GetCalibrationState(void);
```

应用层可用它判断校准是否完成：

```c
if (CurrentSampling_GetCalibrationState() == CURRENT_SAMPLING_CAL_DONE)
{
    /* 可以恢复正常电流控制 */
}
```

状态含义：

| 状态 | 含义 |
|---|---|
| `CURRENT_SAMPLING_CAL_IDLE` | 未请求校准 |
| `CURRENT_SAMPLING_CAL_SETTLING` | 已请求，正在等待 10 ms |
| `CURRENT_SAMPLING_CAL_COLLECTING` | 正在收集 1 ms 样本 |
| `CURRENT_SAMPLING_CAL_DONE` | 零点已经更新 |
| `CURRENT_SAMPLING_CAL_ERROR` | 没有采到有效样本 |

### 8. ADC 快照是如何更新的

TIM1_CH4 在 PWM 周期内产生 ADC 触发。该触发启动新一轮两通道注入转换，但 16 倍过采样序列需要约 11.43 µs 才完成。

因此业务层没有在触发瞬间读取“正在转换”的 JDR，而是在 `HAL_TIM_OC_DelayElapsedCallback()` 中读取上一轮已经完成的结果：

```text
TIM1_CH4 触发新转换
    ↓
读取上一轮 JDR1/JDR2
    ↓
保存到 raw_u/raw_v
    ↓
校准状态为 COLLECTING 时加入累加和
```

这样既不会在 ADC 序列中途读取半更新数据，也不会在实时中断中执行浮点换算。浮点换算只在 FOC 读取接口调用时进行。

### 9. 应用层和 FOC 的职责边界

应用层负责：

- 判断驱动器和功率级是否安全；
- 控制三相下管进入校准状态；
- 调用 `CurrentSampling_RequestCalibration()`；
- 轮询 `CurrentSampling_GetCalibrationState()`；
- 校准完成后恢复正常 PWM/FOC 状态。

电流采样模块负责：

- 采集 U/V 两相 ADC 原始值；
- 等待电路稳定并计算零点；
- 保存零点并从原始值中扣除；
- 将 ADC 结果换算为安培；
- 向 FOC 提供 `CurrentSampling_ReadFeedback()`。

FOC 不应该直接访问：

```text
ADC1->JDR1
ADC1->JDR2
ia_offsets / ib_offsets
ADC 时钟、采样时间和过采样寄存器
```

## 后续接口和待实现项

### A. ADC 转换完成后运行 FOC

当前实现先在 TIM1_CH4 回调中保存上一轮已经完成的 JDR 快照，目的是让 ADC 原始数据连续可观察，并完成校准和换算。当前工程还没有把 FOC 控制器启动，也没有在 ADC IRQ 中调用 FOC。

如果正式采用“ADC 转换完成后执行 FOC”，后续需要完成以下改动：

1. 在 ADC 配置层打开 `JEOS` 或注入组转换完成中断；
2. 在 `ADC1_2_IRQHandler()` 中调用 `HAL_ADC_IRQHandler(&hadc1)`；
3. 在 `HAL_ADCEx_InjectedConvCpltCallback()` 中只做固定时间的 FOC 调度；
4. 通过 `CurrentSampling_ReadFeedback()` 获取 U/V 电流；
5. 通过 FOC 的 `foc_port_t` 写回电压指令；
6. 在调试器或示波器上验证 FOC 执行时间小于 PWM 周期余量。

这一步不能简单地把 `FOC_ControllerStep()` 直接塞进当前 `TIM1_CC` 回调，因为 16 倍过采样序列约需 11.43 µs，TIM1_CH4 触发后 ADC 尚未完成。正式切换到 ADC 完成中断前，必须先确认 ADC 完成中断向量、优先级和 FOC 调度策略。

### B. 电流正负号检查

`CurrentSampling_GetCurrentA()` 的正负号由以下因素共同决定：

- 分流电阻两端的实际电流方向；
- OPAMP 同相输入和反相输入的接法；
- PCB 上 U/V 相电流定义；
- 电机端子和 PWM 极性的定义。

代码当前采用有符号差值：

```text
signed_raw = raw_value - zero_offset
```

所以原始值高于零点时返回正电流，低于零点时返回负电流。这个软件逻辑符合 FOC 需要，但“电流流入电机是否一定表现为正值”必须用已知方向的小电流在硬件上验证。若实测方向相反，应在相应通道的换算层乘以 `-1`，不要修改 ADC rank 或 FOC Clarke 变换。

### C. FOC 数据结构

当前采样模块的参数和状态集中在：

```c
current_sampling_t g_current_sampling;
```

其中包括：

- `shunt_resistor_uohm`：采样电阻，当前为 7000 µΩ；
- `opamp_gain`：运放增益，当前为 6.1；
- `vref_mv`：ADC 参考电压，当前为 3300 mV；
- `offset_u`、`offset_v`：U/V 两相零点；
- `raw_u`、`raw_v`：最新 16 倍过采样原始码；
- `calibration_state`：校准状态；
- `sample_sequence`：ADC 快照序号。

FOC 不应直接依赖这个结构体的内部字段，而应通过：

```c
CurrentSampling_ReadFeedback(&phase_u_a, &phase_v_a);
```

读取经过零点校准和单位换算后的电流。这样以后把 ADC 换成 DMA、换 MCU 或调整采样时序时，FOC 接口仍然稳定。

### D. 测试验证建议

建议按以下顺序验证：

1. 无电流时观察 `CurrentSampling_GetRaw()` 是否稳定；
2. 请求校准，确认状态依次经过 `SETTLING`、`COLLECTING`、`DONE`；
3. 用已知小电流验证 `CurrentSampling_GetCurrentA()` 的比例；
4. 改变电流方向，确认返回值正负号符合约定；
5. 检查 U/V 两路是否分别响应正确的相电流；
6. 最后再接入 FOC，并测量 ADC 完成中断到 FOC 返回的最大执行时间。
