## 发现

### [P2] 超时结束校准时，累加值和样本数不是一致快照

位置：Modules/Current_Sampling/Src/current_sampling.c:123–136；ISR 写入位置：60–66。
COLLECTING 可以因截止时间到达而结束，此时样本数可能尚未达到目标。Service 在保持 COLLECTING 状态时分别读取 sum_u/count 和 sum_v/count，中途 ADC ISR 仍能累加并增加计数。
可复核的交错：主循环读到 sum_u=19000（19 个值为 1000 的样本），中断加入第 20 个样本并将 count 更新为 20，主循环再读取 count，则 U 偏置算成 950，V 偏置可能为 1000。这里的问题是多字段不一致，不需要假设 64 位高字发生进位。
建议：在短临界区冻结收集并拷贝两个和及同一个计数，恢复中断后计算；只有成功发布完整结果才进入 DONE。增加超时且不足目标样本时的中断交错测试。

### [P2] 故障清除后控制器仍可自动恢复 running

位置：Core/Src/main.c:317–323；FOC/Src/foc_interface.c:95–110。
故障路径清 running，但没有清除 CAL_DONE 或设置故障锁存。引脚恢复安全后，主循环满足启动条件并再次调用 FOC_ControllerStart，与停止路径注释中的“必须重新校准并由上层显式恢复”不一致。
当前 Tim1Pwm_EnableOutputs 在 main.c:322 被注释，因此确认的是算法自动恢复，不能据此宣称当前版本会自动重新驱动电机。若以后恢复该调用，启动策略需要一并修正。
建议：引入 FAULT_LATCHED 状态及显式复位命令，将校准完成、硬件安全和运行授权分开管理。测试短暂故障恢复后 running 必须保持 0。

### [P2] 待机参数为 0 时不会清除之前的使能位

位置：Modules/Driver_Communication/Src/stspin32g4.c:183–201。
EnterStandby 只在 stby_reg_en 非零时读改写 POWMNG 并置 STBY_REG_EN。若调用前该位已经为 1，传 0 会跳过 POWMNG 更新，实际沿用旧配置，而接口注释将 0 定义为不使能。
建议：两种参数都执行读改写，分别置位或清位并保留其他位；用寄存器 mock 覆盖“初始位为 1、传 0”的场景。硬件跨待机周期是否保留此位需实测，静态缺陷成立的前提是入口时该位为 1。

## 结构优化建议

1. 校准模块提供一次性发布的结果快照，封装中断共享字段，减少应用层直接访问全局状态。
2. 将 STOPPED、CALIBRATING、READY、RUNNING、FAULT_LATCHED 做成显式应用状态机，并统一管理 MOE 与运行授权。
3. 驱动寄存器配置函数应表达目标状态而非仅置位；使用可注入总线接口验证重复调用和错误恢复。
4. 将自有控制逻辑的主机测试与厂商示例测试分开；优先覆盖上述交错、故障恢复和寄存器保持场景。
