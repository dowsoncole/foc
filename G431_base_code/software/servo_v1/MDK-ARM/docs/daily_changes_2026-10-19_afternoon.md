## 3. 控制模式改为运行时统一管理

### 3.1 为什么要改

早期验证代码容易通过宏定义或分散的全局变量决定当前执行哪个流程。这种方式有三个问题：

1. 切换模式需要重新编译，无法在 Watch 或通信命令中动态切换；
2. 每个测试模式各自保存运行状态，功率级启停和故障处理容易不一致；
3. “模式管理对象”和“FOC 算法实例”名称接近，阅读代码时难以区分谁负责业务选择、谁负责实时运算。

因此，本次把三个控制模式统一放入 `foc_control_manager_t`，全局实例正式命名为：

```c
foc_control_manager_t g_global_mode_control;
```

它是应用级的全局模式控制对象；原来的 `g_foc_controller` 保留不变，仍然表示 FOC 算法执行实例。

### 3.2 对象层次

```text
g_global_mode_control                 应用级模式总管
├─ requested_mode                     外部请求进入的模式
├─ active_mode                        安全切换完成后实际生效的模式
├─ switch_count                       成功切换计数
├─ voltage_open_loop                  电压开环参数和运行量
├─ current_open_loop                  电流测试环参数和运行量
├─ normal_loop                        正式模式的指令与真实角度入口
└─ runtime                            三种模式共用的启停、安全和故障状态
   ├─ output_request
   ├─ output_armed
   ├─ output_enabled
   ├─ precharge_in_progress
   ├─ running
   └─ fault_flags

g_foc_controller                      FOC 算法实例
├─ algorithm                          Clarke/Park、PI、逆 Park、调制
├─ port                               反馈读取和 PWM 输出接口
├─ input/output                       当前周期算法输入输出
├─ timing                             采样周期与时序信息
└─ running/fault_flags                算法自身状态
```

这样的划分保证：

- `g_global_mode_control` 决定“现在运行什么模式”；
- `g_foc_controller` 决定“本周期如何计算”；
- `g_servo_manager` 只在正常模式下负责正式启停状态机；
- `g_waveform_generator` 只负责观测，不参与控制决策。

### 3.3 三种模式的职责

| 模式 | 输入 | 角度 | 电流 PI | 用途 |
| --- | --- | --- | --- | --- |
| 电压开环 | 直接给定 D/Q 电压 | 软件自动累加 | 不使用 | 验证坐标变换、SVPWM、相序和功率输出 |
| 电流测试环 | 给定 D/Q 电流 | 软件自动累加 | 使用真实 ADC 反馈闭环 | 验证采样极性、D/Q 解耦、PI 跟随能力 |
| 正常模式 | 正式控制链给定 | 真实编码器/估算角度 | 使用 | 后续速度环、位置环和完整伺服状态机 |

这里代码中的 `CURRENT_OPEN_LOOP` 是“电角度开环”，并不是“电流不闭环”。在该模式下，相电流来自真实 ADC，经过 Clarke/Park 后与 D/Q 电流指令比较，再进入两个 PI；只是角度暂时不用编码器，而由软件按给定电频率自动推进。

### 3.4 安全切换方法

程序或调试器只修改：

```c
g_global_mode_control.requested_mode = FOC_CONTROL_MODE_VOLTAGE_OPEN_LOOP;
g_global_mode_control.requested_mode = FOC_CONTROL_MODE_CURRENT_OPEN_LOOP;
g_global_mode_control.requested_mode = FOC_CONTROL_MODE_NORMAL;
```

不要直接写 `active_mode`。主循环发现请求变化后会：

1. 撤销输出允许并关闭 MOE；
2. 停止当前算法或正式状态机；
3. 清除 PI 积分和实时故障；
4. 复位电压斜坡、电角度和周期计数；
5. 加载目标模式参数；
6. 更新 `active_mode` 和 `switch_count`；
7. 保持输出关闭，等待新的显式 `output_request`。

该过程避免把上一个模式的积分量、角度或 PWM 状态直接带入下一个模式。

## 4. 电流测试环的组织方式

### 4.1 实时链路

```text
TIM1 触发 ADC 注入转换
    ↓
读取 U/V 相电流，重构 W = -(U + V)
    ↓
Clarke：UVW → αβ
    ↓
Park：αβ + 虚拟电角度 → Id/Iq
    ↓
Id_ref - Id、Iq_ref - Iq
    ↓
D/Q 两个 PI
    ↓
Ud/Uq 限幅
    ↓
逆 Park + SVPWM
    ↓
TIM1 三相 CCR/PWM
```

初始参数采用保守值：D 轴电流给定较小，Q 轴电流给 0，指令和 PI 输出都有约束。测试时应从低限流电源开始，先确认电流反馈方向和量纲，再逐步整定 PI。

### 4.2 建议验收顺序

1. 保持功率输出关闭，确认电流零点标定完成，三相静态值接近 0 A；
2. 选择电流测试模式，确认虚拟电角度连续变化；
3. 波形选择 D/Q 电流指令与反馈；
4. 设置很小的 `Id_ref`，保持 `Iq_ref = 0`；
5. 显式请求输出，观察 Id 是否同方向跟随、Iq 是否保持在 0 附近；
6. 若反馈方向相反或某相明显偏小，立即停止，不要靠增大 PI 增益掩盖采样问题；
7. 采样比例与相位关系确认后，再做阶跃响应、带宽和 PI 参数整定。

## 5. 波形输出层完成硬件解耦

### 5.1 分层关系

```text
ADC/FOC 中断
  └─ MainWaveform_Publish()
       └─ 发布 waveform_source_snapshot_t 完整同步快照
            ↓
       WaveformGenerator_PublishFromIsr()
       ├─ 根据模式选择通道
       ├─ 20 kHz → 1 kHz 降采样
       └─ 复制到内存队列，不访问 UART
            ↓
主循环 WaveformGenerator_Task()
       ├─ V2 帧编码
       ├─ CRC8
       └─ waveform_transport_t.send()
            ↓
当前：USART1/RS485 端口
未来：CAN、另一串口或 485 端口
```

控制中断不直接等待串口发送，因此通信阻塞不会被放进 20 kHz FOC 关键路径。更换通信介质时，只需实现新的 `send(context, data, length)`，不用修改波形选择、队列或帧编码逻辑。

### 5.2 波形管理对象

`g_waveform_generator` 统一保存：

- `requested_mode/active_mode`：请求和已生效的波形模式；
- `custom_channels[]`：自定义 1～4 个通道；
- `selection_revision`：自定义配置提交版本，避免读取半写入配置；
- `active_channels[]`：当前实际编码的通道；
- `published_samples/sent_frames`：发布样本与成功帧计数；
- `queued_samples/dropped_samples`：队列深度与丢样统计；
- `transport_errors/selection_errors`：通信和配置错误计数。

当前预设：

| 波形模式 | 通道 |
| --- | --- |
| 电压开环波形 | U、V、W 三相电流 |
| 电流测试环波形 | D 电流指令、D 电流反馈、Q 电流指令、Q 电流反馈 |
| 自定义波形 | 从 14 种业务变量中选择 1～4 个 |

可选变量包括三相电流、D/Q 电流指令与反馈、D/Q 电压输出、三相 duty、电角度和母线电压。

## 6. USART1 V2 波形协议

当前链路参数：USART1/RS485、921600 baud、8-N-1、小端序，源采样率 20 kHz，默认发送率 1 kHz。

V2 帧不是固定三相电流格式，而是可变长度帧：

```text
frame_length = 12 + 5 × N，N = 1..4
```

| 偏移 | 长度 | 内容 |
| ---: | ---: | --- |
| 0 | 2 | 帧头 `A5 5A` |
| 2 | 1 | 协议版本 2 |
| 3 | 1 | 波形模式 |
| 4 | 1 | 通道数量 N |
| 5 | 2 | 16 位帧序号 |
| 7 | 4 | 32 位 ADC 源采样序号 |
| 11 | N | N 个通道 ID |
| 11+N | 4×N | N 个小端 `int32` 数值 |
| 最后 | 1 | CRC8，多项式 `0x07` |

所有业务浮点值在固件内乘 1000 后编码。PC 端除以 1000，再根据通道 ID 解释为 A、pu、rad、V 或无单位 duty。三相电流帧为 27 字节，D/Q 指令反馈帧为 32 字节。

详细协议和解析示例见 [pc_waveform_protocol.md](pc_waveform_protocol.md)。

## 9. U/V 不平衡的判断与解决路径

### 9.1 已确认的信息

原理图中 U/V 两路采样网络的标称器件相同：两路分流电阻均标为 R010，输入、反馈和滤波阻容值一致。因此原理设计没有给 U/V 设置不同增益，但实物阻值、焊接、放大器通道和 ADC 输入仍可能存在偏差。

代码当前把 `shunt_resistor_uohm` 配置为 7000，而原理图标注 R010 通常表示 10 mΩ。这个共同比例误差会使“显示的安培值”整体不准，应在后续通过实测分流电阻和模拟增益校准；但它同时作用于 U/V，单独不能解释 12.3% 的 U/V 比值差。

当前 U/V 由 ADC1 注入组按两个 rank 顺序转换，并使用 16 倍过采样。两路采样中心相隔约 5.7 µs。对于 4 Hz 基波，该延迟只相当于约 0.008°，不会直接产生 6.5° 的基波相位差；但相对于 20 kHz PWM 周期约相差 41°，可能让两个 rank 采到不同位置的开关纹波，从而在拟合后表现为幅值或相位偏差。

### 9.2 第一优先级实验：交换 ADC rank

保持物理电路和相定义不变，只交换注入转换顺序：

```text
原配置：rank1 = U，JDR1 → raw_u；rank2 = V，JDR2 → raw_v
测试配置：rank1 = V，JDR1 → raw_v；rank2 = U，JDR2 → raw_u
```

判断方法：

- 若“幅值偏小”从 V 相转移到 U 相，问题主要跟 ADC rank、建立时间或 PWM 采样时刻有关；
- 若偏小仍固定在 V 相，优先检查 V 相模拟链路、功率桥、电机绕组或连接；
- 若差异明显减小但未消失，说明采样时序和硬件增益可能同时存在问题。

这是当前信息量最大、改动最小的实验，应在电流 PI 调优之前完成。

### 9.3 第二优先级：外部仪器区分“真实电流”和“测量电流”

同步观察：

- PA2/PB1 对应的 U/V 电流采样模拟输出；
- U/V 相外部电流探头或精密串联测量；
- PWM duty 和 ADC 触发位置。

如果外部探头显示三相接近平衡，而 ADC 结果不平衡，问题在采样链；如果外部探头也显示相同不平衡，则应转向功率桥、相线、电机绕组和开环电压矢量。

### 9.4 第三优先级：相线轮换

按循环方式轮换电机 U/V/W 接线并重复同一低压开环实验：

- 不平衡跟随板端桥臂：排查 MOSFET、栅极驱动、分流电阻和 PCB；
- 不平衡跟随电机绕组：排查电机和相线；
- 不平衡跟随 ADC 通道：排查采样网络、运放/内部 PGA、ADC rank 与采样时刻。

### 9.5 不建议直接做的处理

不建议现在直接给 V 相乘约 1.14 的经验系数。它只能临时修正幅值，无法解决约 6.5° 的相位误差；如果根因是 PWM 纹波或采样时序，静态比例补偿还会随 duty、母线电压和转速变化。

若最终确认问题主要来自同一 ADC 的顺序转换，稳健方案是使用双 ADC 同步采样 U/V，使两路采样中心一致；在硬件架构调整前，也可先优化触发点、采样时间和 RC 建立时间。

## 12. 下一步建议

建议按以下顺序继续，避免在输入数据不可信时直接调 PI：

1. **保持低电压、低限流，完成 ADC rank 交换实验。** 先判断 U/V 差异是否跟随转换顺序。
2. **用外部电流探头核对真实相电流。** 将“电机真实不平衡”和“采样结果不平衡”分开。
3. **校准电流物理比例。** 核实 R010 分流电阻、放大器增益和代码中的 `shunt_resistor_uohm`。
4. **确认 U/V/W 极性与相序。** 正向 Id 给定必须得到同方向 Id 反馈，Iq 应接近 0。
5. **开始电流测试环。** 从很小的 D 轴电流指令开始，Q 轴为 0，使用 D/Q 指令和反馈波形观察稳态误差、超调和振荡。
6. **整定 PI。** 先 P 后 I，逐步提高带宽，并记录阶跃响应和饱和情况。
7. **接入编码器。** 完成电角零位、方向、极对数和速度观测后，再切换到正常模式。

## 13. 下午里程碑结论

下午完成的不只是“多打印几条波形”，而是把后续调试所需的三层基础设施建立起来：

1. 控制层可以在电压开环、电流测试环和正常模式之间运行时安全切换；
2. 观测层可以独立选择 1～4 个控制变量，不与 UART/RS485 硬件绑定；
3. PC 端可以根据每帧携带的模式和通道 ID 自动解释波形，并用自动化测试保护协议行为。

当前工程已经具备开展小电流 D/Q 测试环验证的程序条件。真正进入 PI 调优前，还需要先解决或定位 U/V 相电流约 12.3% 的幅值差和约 6.5° 的相位偏差。首选动作是交换 ADC 注入 rank；该实验能最快判断问题是否来自顺序采样与 PWM 纹波。
