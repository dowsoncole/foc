## 1. 系统在做什么

一句话：**STM32G431 通过 STSPIN32G4 栅极驱动芯片，用 20 kHz 的 FOC 电流环驱动一台三相永磁电机。**

### 1.1 主数据流

```text
                      ┌────────── 20 kHz 硬件节拍（不依赖 CPU）──────────┐
                      │                                                │
   TIM1 计数器 ──► CH4 比较匹配 ──► OC4REF ──► TRGO2 ──► ADC1 注入组触发
   ARR = 4199                                            2 通道 × 16 倍过采样
                      │                                                │
                      │                                    JEOS → ADC1_2 中断
                      │                                                ▼
                      │                              current_sampling 发布原始码快照
                      │                                                ▼
                      │                                  MainFoc_OnAdcConversion()
                      │                                                ▼
                      │                        FOC 算法：Clarke → Park → PI → 反 Park → SVPWM
                      │                                                ▼
                      └────── CCR1/2/3 + CCR4 ◄──── Tim1Pwm_SetPhaseVoltage()
                                        │
                                        ▼  （仅当 BDTR.MOE = 1）
                              PE8~PE13 六路栅极信号
                                        ▼
                                STSPIN32G4 栅极驱动
                                        ▼
                              三相 MOSFET 半桥 ──► 电机
```

关键理解：**CCR4 与 CCR1~3 在同一个谷值一起更新**，所以下一个周期的 ADC 采样时刻是
由本周期算出的三相占空比决定的——采样点会跟着 PWM 波形跑，而不是固定在某个位置。

### 1.2 关键参数速查

### 2.2 分层与依赖方向

```text
L6  Core/Src/main.c ────────────── 初始化编排 · 主循环 · 跨层仲裁 · 端口回调实现
        ↓
L5  Servo/servo_manager     FOC/foc_interface      Tests/*
    （正常模式状态机）      （控制器调度）        （验证与观测）
        ↓  servo_manager_port_t   ↓  foc_port_t
L4  Modules/Three_Phase_Driver/tim1_pwm  ← 功率级业务（MOE、CCR、预充电）
    Modules/Current_Sampling/current_sampling ← 采样业务（校准、换算）
    Modules/Driver_Communication/drv_monitor  ← 驱动健康状态机（独占 I2C）
        ↓
L3  Modules/Driver_Communication/stspin32g4   ← 器件寄存器语义
    Modules/Encoder/mt6835                    ← 器件寄存器语义
        ↓
L2  Modules/Three_Phase_Driver/pwm_sampling   ← 纯算法规划器（无 HAL）
    FOC/foc_modulation · foc_algorithm        ← 纯算法（无 HAL）
        ↓
L1  外设配置：i2c3_bus · tim6_heartbeat · adc1_current_sampling
              spi1_encoder · gpio · tim1_pwm(MX_TIM1_Init) · stm32g4xx_hal_msp
        ↓
L0  Core/Src/stm32g4xx_it.c ← 中断向量，只做分发，不含业务
        ↓
    STM32 HAL / CMSIS / 芯片寄存器
```

**六条铁律**（改动前必读）：

1. **下层不得调用上层**；配置层不得调用业务层（HAL 的 MSP 回调除外，它本身属配置层）。
2. `i2c3_bus.c`、`tim6_heartbeat.c`、`gpio.c`、`adc1_current_sampling.c`、`spi1_encoder.c`
   **不得 `#include "main.h"`，也不得调用 `Error_Handler()`**——初始化失败靠返回值上交。
3. `FOC/` 下所有文件**不得包含任何 HAL / GPIO / 定时器 / 器件头文件**，
   硬件访问只能经 `foc_port_t` 的四个函数指针。`Servo/servo_manager.c` 同理，走 `servo_manager_port_t`。
4. **I2C 只允许出现在 `drv_monitor.c` 的后台任务里**，禁止进任何 ISR。
   （例外：`main.c` 主循环在首次引脚异常后会直接读一次 STATUS 寄存器做故障留证。）
5. `HAL_TIM_PeriodElapsedCallback` **全工程只能有一个定义**（工程设
   `USE_HAL_TIM_REGISTER_CALLBACKS = 0`，走弱符号覆盖），当前定义在 `drv_monitor.c`，
   内部按 `htim->Instance` 分发。新模块要挂周期事件，请用
   `Tim1Pwm_SetPeriodCallback()` 注册，不要重复定义同名回调。
6. **电流环必须跑在 ADC 注入完成中断里**，不能放主循环——主循环没有确定性周期。

## 3. 三条时间线（最重要）

整个固件就是三条时间线在跑。看懂这三条，就看懂了框架。

### 3.1 上电初始化：一次性，允许阻塞

`main()` 从头到尾顺序执行，每步失败都进 `Error_Handler()`（关中断死循环）。

```text
HAL_Init() → SystemClock_Config()            168 MHz + ADC12 内核时钟 = SYSCLK
  ↓
MX_GPIO_Init()                               PE7 WAKE 初始化为低（默认不唤醒）
MX_I2C3_Init() · MX_TIM6_Init()
MX_TIM1_Init()                               20 kHz PWM 跑起来，但 MOE 保持 0
WaveformUart1Port_Init() · WaveformGenerator_Init()
  ↓
Tim1Pwm_EmergencyStop()                      ★ 上电第一件事：确保硬件关断
  ↓
DrvMonitor_Init()                            清 STSPIN32G4 上电锁存故障 + 启动 1 s 心跳
                                             （必须清：不写 CLEAR 芯片一直不动作）
  ↓
MX_OPAMP1_Init() · MX_OPAMP3_Init()          ★ 运放必须先于 ADC：ADC 采的是运放输出脚
MX_ADC1_Init(0U)                             参数 0 = 用硬件触发 T1_TRGO2
  ↓
Tim1Pwm_ConfigureCurrentSampling(11430 ns, &duty_min, &duty_max)
                                             把采样序列耗时交给规划器，
                                             并回写调制层可用的 duty 上下限
FOC_ControllerInit(&g_foc_controller, ...)   装入 foc_port 四个回调
ServoManager_Init(&g_servo_manager, ...)     装入 servo_manager_port 八个回调
CurrentSampling_SetConversionCallback(MainFoc_OnAdcConversion, &g_foc_controller)
                                             ★ 这一行把 20 kHz 实时链路接通
  ↓
CurrentSampling_Start()                      运放先启动、ADC 后启动
MainFoc_IsPowerStageSafe() 检查              READY / nFAULT 必须都正常
HAL_Delay(20 ms)                             CURRENT_SAMPLING_MOE_GUARD_MS：
                                             模拟链路与驱动器稳定时间，期间 MOE 仍为 0
CurrentSampling_RequestCalibration()         请求零点校准（异步，不阻塞）
  ↓
MX_SPI1_Encoder_Init() · MT6835_PowerUpWait() · Mt6835Verify_Start()
  ↓
while(1) { … }                               进入主循环
```

**为什么校准能在 MOE = 0 时完成？** 因为 ADC 触发走的是 `OC4REF → TRGO2` 这条**内部信号链**，
不经过 MOE。详见 [第 7 节](#7-moe-与-ch4-到底谁管谁勘误)。这正是「采样链」与「控制链」
分离的设计意图：采样链先跑起来拿到零点，控制链等校准确认后才放行。

### 3.2 20 kHz 实时链路：每 50 µs 一次，绝不可阻塞

```text
TIM1 CH4 比较匹配 → OC4REF 上升沿 → TRGO2 → ADC1 注入组启动
  ↓ 两通道各 16 倍过采样，共 11.43 µs
JEOS 置位 → ADC1_2_IRQHandler（优先级 1）
  ↓  GPIOA->BSRR = PIN_0            ← PA0 拉高，时序探针起点
HAL_ADC_IRQHandler(&hadc1)
  ↓
HAL_ADCEx_InjectedConvCpltCallback()          [current_sampling.c]
  ├─ raw_u = ADC1->JDR1，raw_v = ADC1->JDR2   发布快照
  ├─ sample_sequence++
  ├─ 若正在校准 → 累加到 calibration_sum，且【不】调用 FOC 回调
  └─ 否则 → s_conversion_callback(context)
       ↓
MainFoc_OnAdcConversion(&g_foc_controller)    [main.c]
  ├─ CurrentSampling_ReadFeedback_A()         取三相安培值
  ├─ WaveformGenerator_PublishFromIsr()       模式选通、降采样入队（不碰外设）
  ├─ 非 NORMAL 模式 → 读 GPIOE->IDR 做快速引脚安全门 + 故障计数
  └─ 按 active_mode 分三条路（见第 5 节）
       ↓
Tim1Pwm_SetPhaseVoltage(a, b, c)              [tim1_pwm.c]
  ├─ PwmSampling_Plan() 算出本周期可行的 CCR4 与低侧窗口
  ├─ 置 UDIS → 一次写 CCR1/2/3/4 → 清 UDIS    保证四个值同谷值生效
  └─ 若窗口不足或提交过晚 → 返回 HAL_ERROR，上层锁存故障并关 MOE
  ↓  GPIOA->BSRR = PIN_0 << 16        ← PA0 拉低，探针终点
中断返回，等下一个 50 µs
```

**PA0 探针**：`stm32g4xx_it.c` 在 `ADC1_2_IRQHandler` 入口/出口翻转 PA0，
用示波器量高电平宽度即为「ADC 完成 → CCR 提交」的全部软件耗时。
2026-10-19 实测约 35 µs，周期余量约 15 µs。

### 3.3 主循环后台：无截止时间，可阻塞数十 µs

```text
while (1)
{
  CurrentSampling_Service()        推进零点校准状态机（SETTLING → COLLECTING → DONE/ERROR）
  MainFoc_ServiceModeSwitch()      检测 requested_mode 变化，执行安全切换（见 5.2）

  /* 测试模式（非 NORMAL）的输出请求处理 */
  output_request == 1 且校准 ERROR → 撤销请求 + 锁存 CURRENT_INVALID
  output_request == 0 且仍 armed   → 停控制器 / 急停 + 斜坡归零 + 清 armed
  output_request == 1 且未 armed   → Tim1Pwm_BootstrapPrecharge()
                                     → 中性矢量稳定 20 ms（期间持续查安全门）
                                     → armed = 1（电流模式还要 ClearFaults + ControllerStart）
                                     任一步不安全 → 急停 + 撤销请求 + 锁存 POWER_STAGE

  首次引脚异常后 → 直接读一次 STSPIN32G4 STATUS，存 first_fault_status_raw

  WaveformGenerator_Task()         编码波形帧并经 USART1 发送
  Mt6835Verify_Task()              推进编码器通讯验证
  DrvMonitor_Task()                心跳未到立即返回；到点才做一次 I2C 轮询 + 状态机
  if (active_mode == NORMAL) ServoManager_Service(&g_servo_manager)
}
```

**分工原则**：ISR 只做「必须在 50 µs 内完成」的事（采样快照、算法、写 CCR、快速安全门）；
一切慢速、可阻塞、需通讯的工作都留给主循环。

## 4. 模块逐个讲

每节格式统一：**它管什么 → 它拥有哪些外设 → 它对上给什么接口 → 谁调它、它调谁 → 坑在哪**。

### 4.1 `Core/` 板级支撑与应用编排

**管什么**：中断向量分发、GPIO/时钟/NVIC 配置、应用入口与全局对象定义、跨层仲裁。

| 文件                         | 职责                                                                                                                  |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `Src/main.c`               | 全部初始化编排、主循环、`g_foc_controller` / `g_servo_manager` / `g_global_mode_control` 定义、两个端口结构体的回调实现 |
| `Src/gpio.c`               | PE7 WAKE（输出，初始低）、PE14 READY、PE15 nFAULT（输入上拉）、PA0 时序探针（高速推挽）                               |
| `Src/stm32g4xx_it.c`       | 四个中断向量，只转发给 HAL，不含业务；ADC 向量里夹 PA0 翻转                                                           |
| `Src/stm32g4xx_hal_msp.c`  | 把外设实例与具体硬件绑定：时钟使能、引脚复用、NVIC 优先级                                                             |
| `Inc/stm32g4xx_hal_conf.h` | HAL 裁剪，`TICK_INT_PRIORITY = 15`、`USE_HAL_TIM_REGISTER_CALLBACKS = 0`                                          |

**它调谁**：所有下层公开接口。
**谁调它**：没有人——它是顶层。

**坑**：

- `SystemClock_Config()` 里必须显式选 `RCC_ADC12CLKSOURCE_SYSCLK`。ADC12 的复位时钟源是
  `NONE`，只开总线时钟的话 `ADEN`/`JADSTART` 能置位但**转换永不完成**，表现为 JEOS 不置位、
  JDR 不更新、`sample_sequence` 恒为 0，且不报任何错。
- SYSCLK 刻意锁 168 MHz：20 kHz 载波、500 ns 死区、TIM6 的 1 s 心跳（÷16800）、I2C 时序字
  全部由它派生。改主频会静默破坏全部时序常量，所以 `MX_TIM1_Init()` 里加了
  `HAL_RCC_GetPCLK2Freq()` 检查。

### 4.2 `Modules/Current_Sampling/` 电流采样

**管什么**：把两个分流器上的电压变成「减去零点后的物理安培值」，并负责零点校准。

**拥有的外设**：OPAMP1、OPAMP3、ADC1 注入组、PA1/PA2/PA3、PB0/PB1/PB2。

分两个文件，配置与业务分离：

| 文件                        | 层次    | 职责                                                                                                                             |
| --------------------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `adc1_current_sampling.c` | L1 配置 | 配 OPAMP1/3（跟随放大）、ADC1 注入组 2 通道、16 倍过采样、触发源选择；`CurrentSampling_Start()` 按「运放先、ADC 后」接通信号链 |
| `current_sampling.c`      | L4 业务 | JEOS 回调发布快照、异步零点校准状态机、原始码 → 安培换算、给 FOC 的 S16/浮点反馈接口                                            |

**对上接口**：

```c
void CurrentSampling_RequestCalibration(void);   /* 请求一次异步零点校准 */
void CurrentSampling_Service(void);              /* 主循环周期调用，推进状态机 */
current_sampling_cal_state_t CurrentSampling_GetCalibrationState(void);
float    CurrentSampling_GetCurrentA(current_sampling_phase_t phase);
void     CurrentSampling_ReadFeedback_A (float *, float *, float *);    /* 物理安培 */
void     CurrentSampling_ReadFeedback_s16(int16_t *, int16_t *, int16_t *); /* 标定 S16 */
void     CurrentSampling_SetConversionCallback(cb, void *context);      /* 注册 20 kHz 回调 */
extern current_sampling_t g_current_sampling;
```

**谁调它**：`main.c`（初始化、主循环 Service、ISR 里读反馈）、FOC 端口回调 `MainFoc_ReadFeedback`。
**它调谁**：只调 L1 的 `adc1_current_sampling` 接口和读 `ADC1->JDR1/JDR2`。

**校准状态机**（非阻塞，全在主循环推进）：

```text
IDLE ──RequestCalibration()──► SETTLING（等 10 ms 让模拟链路稳定）
                                  ↓ Service() 检测到期
                              COLLECTING（目标 20 个样本 = 20 kHz × 1 ms）
                                  ↓ 样本够 或 1 ms 窗口到期
                        有样本 → DONE（offset_u/v = 累加和 ÷ 样本数）
                        无样本 → ERROR（说明 ADC 根本没在触发）
```

校准期间 `HAL_ADCEx_InjectedConvCpltCallback` **不调用 FOC 回调**，
避免用未标定的零点去跑控制环。

**坑（三个都踩过）**：

1. `JDR` 读出的是 **16 次转换的累加值**（满量程 4095 × 16 = 65520，`RightBitShift = NONE`）。
   零点相减必须在**同一数值空间**做，不能提前除 16；只有换算成物理安培时才除
   `oversampling_ratio`。
2. W 相没有传感器，由 `-(ia + ib)` 推出。这也决定了 FOC 输入结构体只需要两相电流。
3. `polarity_u/v` 用于板级反相。若正 Id 给定导致 Id 反馈持续往负方向涨，先查这里的极性和相序。

### 4.3 `Modules/Three_Phase_Driver/` 三相 PWM

**管什么**：把「三相占空比」翻译成栅极信号，掌管 MOE 这道硬件总闸，并逐周期规划 ADC 采样点。

**拥有的外设**：TIM1、PE8~PE13。

| 文件               | 层次      | 职责                                                                         |
| ------------------ | --------- | ---------------------------------------------------------------------------- |
| `tim1_pwm.c`     | L1 + L4   | `MX_TIM1_Init()` 配置；`Tim1Pwm_*` 功率级业务；自举预充电；CCR4 同步提交 |
| `pwm_sampling.c` | L2 纯算法 | 在计数域里算「本周期能不能塞下完整采样序列」，不含 HAL、不碰寄存器           |

**TIM1 配置要点**：

| 项             | 值                              | 说明                                                                                      |
| -------------- | ------------------------------- | ----------------------------------------------------------------------------------------- |
| 计数模式       | 中央对齐模式 1                  | 计数器 0 → 4199 → 0                                                                     |
| ARR / RCR      | 4199 / 1                        | 168 MHz ÷ (2 × 4200) = 20 kHz，每载波周期恰好一次更新事件                               |
| CH1~3          | PWM 模式 1，高有效 + 互补高有效 | 比较值越大，**高侧**导通越久                                                        |
| CH4            | PWM 模式 2，初值 = 4199 − 959  | 只用于产生 OC4REF，**不映射到任何引脚**                                             |
| TRGO           | `TIM_TRGO_UPDATE`             | —                                                                                        |
| TRGO2          | `TIM_TRGO2_OC4REF`            | ADC 注入组的实际触发源                                                                    |
| 死区           | DTG = 84 → 500 ns              | tDTS 编码段上限 127；更长死区要换 0x80~0xBF 段                                            |
| OSSR / OSSI    | 关闭                            | MOE = 0 时引脚交给栅极驱动自己的上下拉                                                    |
| Break / Break2 | **禁用**                  | PE15 在本 MCU 上没有 TIM1 复用功能，保护改由 `drv_monitor` 走 I2C + 芯片自身 VDS/热保护 |
| MOE            | 初始化后**保持 0**        | 配置只准备硬件，不接通功率                                                                |

**对上接口**：

```c
/* 配置线 */

void HAL_TIM_MspPostInit(TIM_HandleTypeDef *htim);   /* 在 MSP 层实现，配 PE8~PE13 */

/* 业务线 */
HAL_StatusTypeDef Tim1Pwm_SetPhaseDuty(uint32_t channel, uint16_t duty);  /* 0..1000，测试层用 */
HAL_StatusTypeDef Tim1Pwm_SetPhaseVoltage(float a, float b, float c);     /* 0..1，FOC 用 */
void     Tim1Pwm_SetNeutral(void);            /* 三相 50%：零净电压 + 刷新自举电容 */
void     Tim1Pwm_EnableOutputs(void);         /* 置 MOE */
void     Tim1Pwm_EmergencyStop(void);         /* 清 MOE，立即同时拉无效电平 */
uint8_t  Tim1Pwm_IsOutputEnabled(void);       /* 回读 BDTR.MOE */

/* 采样规划 */
HAL_StatusTypeDef Tim1Pwm_ConfigureCurrentSampling(uint32_t sequence_ns, float *min, float *max);
HAL_StatusTypeDef Tim1Pwm_GetCurrentSamplingDutyBounds(uint32_t sequence_ns, float *min, float *max);

```

**谁调它**：`main.c`、`Servo/`（经端口回调）、FOC（经 `write_voltage` / `disable_output`）、`Tests/`。

**`Tim1Pwm_SetPhaseVoltage()` 做了什么**（这是实时链路的核心）：

```text
1. 校验三相 duty 都是有限值且在 0..1，否则整体拒绝，一相都不写
2. PwmSampling_Plan()：在 U/V 都稳定的低侧窗口里找位置，
   优先让 11.43 µs 序列在载波峰值处完成，窗口变窄就向后挪到最早可行点
3. 找不到完整窗口 → window_rejections++，返回 HAL_ERROR
4. 进临界区（保存 PRIMASK）→ 先看提交时刻：
   若 UDIS 已被别人置着，或距下次谷值不足 COMMIT_GUARD(2 µs) + 1 计数
   → deadline_rejections++，恢复中断，返回 HAL_ERROR
5. 置 CR1.UDIS → 一次写 CCR1/CCR2/CCR3/CCR4 → 清 UDIS
   ★ 四个寄存器必须同谷值生效，否则新触发点会作用在旧 PWM 上
6. 写完再复查一次计数位置：若期间跨过谷值（after < before）或已逼近截止点
   → ★ 立即 __HAL_TIM_MOE_DISABLE_UNCONDITIONALLY() 自己清掉 MOE ★
   然后返回 HAL_ERROR
```

第 6 步很关键：**这一层不只报错，它会自己动手关功率级**。因为此刻新的三相 PWM
已经写进寄存器、却错过了同步生效的时机，继续留着 MOE 就会出现「新占空比配旧触发点」
的错拍，所以宁可立即断电。上层拿到 HAL_ERROR 后再锁存 `FOC_FAULT_PWM_WRITE`。

> 注意这里刻意**不产生 UG**（软件更新事件），因为 UG 会打乱载波与重复计数器的相位。

`Tim1Pwm_OnCurrentSample()` 返回**两次实际触发之间的间隔**（不是 ISR 耗时）。
因为 CCR4 每周期都在动，PI 的积分周期必须用真实间隔，否则积分增益会随采样点漂移。

**坑（占空比换算，两个都致命）**：

```c
#define TIM1_PWM_DUTY_TO_COMPARE(duty) \
  (((uint32_t)(duty) * TIM1_PWM_COMPARE_FULL_SCALE) / TIM1_PWM_DUTY_SCALE)
```

1. **比较值与占空比成正比，不是反比。** 别把这个映射取反。
2. **必须按比较带 4200 缩放，不能按整周期 8400。** 超过 ARR 的比较值**不会扩大占空比范围，
   而是彻底停止翻转**——计数器永远到不了那个值，输出一直停在有效电平。误按整周期缩放的话，
   占空比一过 50% 就全部饱和到接近 100%。

| CCR  | 高侧占空比    | duty |
| ---- | ------------- | ---- |
| 0    | 0.0000 %      | 0    |
| 2100 | 50.0000 %     | 500  |
| 2520 | 60.0024 %     | 600  |
| 4199 | 99.9881 %     | 1000 |
| 4200 | 100 %（饱和） | —   |

**两个端点都不能当空闲值**：`duty = 1000` 让低侧整周期不导通，`duty = 0` 让低侧整周期导通，
两者都会使该半桥**自举电容无法刷新**；`duty = 0` 还会通过低侧对电机制动。空闲请用 `SetNeutral()`。

**另一个坑**：`Tim1Pwm_EmergencyStop()` 必须用 `__HAL_TIM_MOE_DISABLE_UNCONDITIONALLY()`。
普通的 `__HAL_TIM_MOE_DISABLE()` 只在所有通道的 `CCxE`/`CCxNE` 都已清零时才生效，
**在运行中的功率级上它会悄无声息地什么都不做**。

### 4.4 `Modules/Driver_Communication/` 栅极驱动通讯与监控

**管什么**：MCU 与 STSPIN32G4 之间的全部往来，以及回答一个问题——**「功率级现在能不能开？」**

**拥有的外设**：I2C3（PC8/PC9）、TIM6、PE7/PE14/PE15。

模块内部四层：

```text
drv_monitor.c      L3 监控服务：判定驱动健康，全工程唯一允许发起 I2C 的模块
      ↓
stspin32g4.c       L2 器件驱动：屏蔽寄存器细节、LOCK 解锁时序、命令特殊写法
      ↓
i2c3_bus.c         L1 配置：配好 I2C3，交出 hi2c3
tim6_heartbeat.c   L1 配置：配好 TIM6，交出 htim6（不启动，启动由 L3 负责）
```

**控制脚语义**（两个方向脚极性相反，务必记牢）：

| 信号                 | 方向        | 有效电平         | 含义                                  |
| -------------------- | ----------- | ---------------- | ------------------------------------- |
| `GD_WAKE` (PE7)    | MCU → 驱动 | 高               | 退出待机；上电初始化为低 = 默认不唤醒 |
| `GD_READY` (PE14)  | 驱动 → MCU | 高               | 驱动器可工作                          |
| `GD_NFAULT` (PE15) | 驱动 → MCU | **低有效** | 0 = 有故障                            |

**对上接口**：

```c
/* L3 */
HAL_StatusTypeDef DrvMonitor_Init(void);      /* 清上电锁存故障（最多重试 3 次）+ 启动 TIM6 */
void              DrvMonitor_Task(void);      /* 主循环每轮调用；心跳未到立即返回 */
drv_state_t       DrvMonitor_GetState(void);
uint8_t           DrvMonitor_IsPowerStageSafeFast(void);   /* ★ 只读 GPIO，恒定耗时 */
HAL_StatusTypeDef DrvMonitor_GetSnapshot(drv_monitor_t *);  /* 短临界区整体拷贝，ISR 也安全 */
void              DrvMonitor_PostRequest(drv_request_t);    /* 非阻塞投递，任何上下文可调 */

/* L2 */
HAL_StatusTypeDef STSPIN32G4_ReadRegister / WriteRegister / Init / ClearFaults / Wake / EnterStandby
uint8_t STSPIN32G4_IsReady(void);            /* 读引脚，不碰 I2C */
uint8_t STSPIN32G4_IsFault(void);            /* 读 nFAULT 原始低有效电平 */
uint8_t STSPIN32G4_PinsAllowSwitching(void); /* ★ 一次读 GPIOE->IDR，READY=1 且 nFAULT=1 */
```

**两条互补的故障检测路径**（这是本模块的设计精髓）：

| 路径 | 手段                                     | 频率                  | 负责什么                                                        |
| ---- | ---------------------------------------- | --------------------- | --------------------------------------------------------------- |
| 快速 | 读 PE14/PE15（`IsPowerStageSafeFast`） | 每 PWM 周期（20 kHz） | 快速关断判据，执行时间恒定                                      |
| 慢速 | I2C 读 STATUS(0x80)                      | 1 s                   | 故障**原因**：VCC 欠压 / 过温 / VDS 过流 / 复位；通信重试 |

为什么分两条：I2C 传输有不可预测的等待时间，放进 20 kHz 电流环会直接破坏 PWM 时序。
所以监控走「低频后台任务 + 快照发布」模式，实时路径只读两个 GPIO。

`PinsAllowSwitching()` 一次读 `GPIOE->IDR` 就能拿到两个引脚的**同一时刻快照**
（两脚同端口），不会出现「读到一半引脚翻转」。

**状态机**：`INIT` → `STANDBY` / `READY` / `FAULT` / `COMM_LOST`，判定自上而下短路：

```text
comm_errors >= 3                         → COMM_LOST
fault.active                             → FAULT
(非 STANDBY) && (nFAULT==0 || READY==0)  → FAULT
(非 STANDBY)                             → READY
(是 STANDBY)                             → 保持 STANDBY
```

待机时不轮询 I2C（此时 I2C 接口已关，轮询只会产生虚假通信错误），但引脚电平照常采样。

**STATUS(0x80) 位含义**（与 DS13630 Table 25 对应）：

| 掩码     | 含义                                             |
| -------- | ------------------------------------------------ |
| `0x01` | VCC 欠压                                         |
| `0x02` | 过温关断                                         |
| `0x04` | VDS 保护（过流）                                 |
| `0x08` | 驱动器复位状态                                   |
| `0x80` | LOCK 位（正常状态就只有这一位，即快照 `0x80`） |

**坑**：

- 写保护寄存器需先解锁 `LOCK = 0xA5`；`STSPIN32G4_WriteRegister()` 内部已自动处理。
- `EnterStandby(stby_reg_en = 1)` **只在 MCU 随后立即进 Stop 模式时才成立**：待机稳压器最多
  供 6 mA，G431 跑 168 MHz 远超此值，否则触发过流保护复位芯片。且这是序列中**最后一次**
  I2C 访问，之后不能再尝试重新上锁（必然超时），重新上锁由 `Wake()` 完成。
- `STSPIN32G4_Init()` 返回 `HAL_BUSY` 表示引脚尚未稳定，**调用者应重试而非判死**。
- `GD_READY` 高有效却配上拉，意味着芯片没接或没上电时会读到「就绪」的假象。
  当前靠 I2C 轮询 + STATUS 交叉校验兜底。

### 4.6 `FOC/` 控制算法

**管什么**：电流环算法本身。全工程分层最干净的一层。

**拥有的外设：无。** 这是刻意的——换 MCU、换驱动芯片、换编码器，本目录一行都不用改。

四个文件，从下往上：

```text
foc_modulation.c    L2 纯算法：SVPWM + 两段过调制 + 六步极限，查表补偿基波增益
                    实时路径无 atan2、无数值积分、无静态可变状态
      ↓
foc_algorithm.c     L2 纯算法：Clarke / Park / dq PI / 反 Park / 电压限幅
                    另含开环电压算法 FOC_AlgorithmVoltageStep()
      ↓
foc_interface.c     L5 调度：控制器生命周期、running 标志、故障锁存
                    经 foc_port_t 四个函数指针接触硬件
      ↓
foc_control_manager.h  纯头文件：三模式统一管理对象的类型定义
```

**算法数据流**（`FOC_AlgorithmStep`）：

```text
Clarke:  alpha = ia
         beta  = (ia + 2·ib) × 0.5773502692        （= 1/√3）
Park:    id =  alpha·cosθ + beta·sinθ
         iq = -alpha·sinθ + beta·cosθ
若三个 valid 标志任一为 0 → 复位积分器与输出，返回
PI(d):   error = clamp(d_ref, ±current_limit) - id
PI(q):   error = clamp(q_ref, ±current_limit) - iq
限幅:    若 √(vd² + vq²) > voltage_limit → 按比例整体缩放，置 saturated
反 Park: valpha = vd·cosθ - vq·sinθ
         vbeta  = vd·sinθ + vq·cosθ
      ↓
FOC_ModulationCompute() → 三相 duty + 扇区 + 调制区域
```

**调制模块的量纲约定**（极易搞错）：
输入 α/β 和 `voltage_limit` 都是**相对母线电压 Vdc 的标幺值**，不是伏特。

| 常量                            | 值                   | 含义                           |
| ------------------------------- | -------------------- | ------------------------------ |
| `FOC_MODULATION_LINEAR_MAX`   | 0.5773502692 = 1/√3 | 线性区上限                     |
| `FOC_MODULATION_SIX_STEP_MAX` | 0.6366197724 = 2/π  | 六步极限，基波相电压峰值 / Vdc |

调制区域：`LINEAR` → `OVM1`（径向投影到六边形）→ `OVM2`（压缩相邻矢量）→ `SIX_STEP`。
`duty_min`/`duty_max` 由功率级与采样窗口决定，收窄后按跨度降额——
**不得为了提高母线利用率而放宽低侧采样窗口或自举刷新约束**。

**开环电压算法**（`FOC_AlgorithmVoltageStep`）用**物理伏特**，字段一律带 `_v` 后缀：

```text
Ud_pu = d_voltage_v / dc_bus_voltage_v
      → 电压斜坡（每周期最多 ramp_rate × Ts）
      → 电角度推进 Δθ = 2π × fe × Ts，超 2π 回绕
      → 反 Park → FOC_ModulationCompute()
```

> 🔑 **这个 `_v` 后缀是血的教训。** 早期版本 Watch 里的 `d_voltage = 0.2` 被算法当成标幺值，
> 实际输出 0.2 × 24 V = 4.8 V；开环又绕过电流 PI 没有软件限流，低阻电机在低电角频率下
> 直接把实验电源推到 4 A 限流。根因不是 0.2 V 产生了 4.8 V，而是**字段单位定义与调试者理解不一致**。

**控制器接口**：

```c
void FOC_ControllerInit(foc_controller_t *, const foc_parameters_t *, const foc_port_t *);
void FOC_ControllerStart(foc_controller_t *);      /* 只置 running = 1，不碰硬件 */
void FOC_ControllerStop(foc_controller_t *);       /* 复位算法 + 写零输出 + 关功率级 */
void FOC_ControllerStep(foc_controller_t *);       /* ★ 必须在 20 kHz ADC 回调里调 */
void FOC_ControllerClearFaults(foc_controller_t *);/* 只允许停止状态下由 Servo Manager 调 */
foc_fault_flags_t FOC_ControllerGetFaults(const foc_controller_t *);
const foc_output_t *FOC_ControllerGetOutput(const foc_controller_t *);
```

`foc_controller_t` 的关键字段：

| 字段                    | 含义                                                                                |
| ----------------------- | ----------------------------------------------------------------------------------- |
| `running`             | 软件算法门：0 时 `ControllerStep()` 直接返回                                      |
| `feedback_ready`      | ISR 在「输入全有效 + 算法完成 + CCR 已写入」后才发布                                |
| `fault_flags`         | 电流环只**锁存**快速故障，恢复策略归 Servo Manager                            |
| `timing.pwm_period_s` | 名义周期；`sample_period_s` 由 `Tim1Pwm_OnCurrentSample()` 逐周期更新为真实间隔 |

**故障标志位**（`foc_fault_flags_t`，与 Servo 层一一对应）：

| 位 | 宏                              | 含义                              |
| -- | ------------------------------- | --------------------------------- |
| 0  | `FOC_FAULT_CURRENT_INVALID`   | 电流反馈无效（多半是校准没完成）  |
| 1  | `FOC_FAULT_ANGLE_INVALID`     | 电角度无效                        |
| 2  | `FOC_FAULT_REFERENCE_INVALID` | dq 给定无效                       |
| 3  | `FOC_FAULT_POWER_STAGE`       | READY / nFAULT 异常               |
| 4  | `FOC_FAULT_PORT_CONFIG`       | 端口回调没注册全                  |
| 5  | `FOC_FAULT_ALGORITHM`         | 算法返回失败                      |
| 6  | `FOC_FAULT_PWM_WRITE`         | 写 CCR 被拒（窗口不足或提交过晚） |

> 调试时看到 `fault_flags = 8` 就是 bit3，即功率级 READY/nFAULT 异常——
> 这说明**算法在正常跑，缺波形的原因是 MOE 被安全门关掉了**，别去查算法。

### 4.7 `Servo/` 正常模式状态机

**管什么**：只在 `FOC_CONTROL_MODE_NORMAL` 下工作。负责 Servo ON/OFF 时序、
**正常打开 MOE 的唯一入口**、故障锁存与显式复位。

**拥有的外设：无。** 经 `servo_manager_port_t` 八个回调接触硬件。

**状态机**：

```text
        INIT
          │  StopOutput()
          ▼
    CALIBRATING ──is_calibration_done()──► READY
                                            │  servo_on_request && 校准完成
                                            │  && 功率级安全 && 无锁存故障
                                            ▼
                                        STARTING
                                  prepare_output() → SetNeutral()
                                  FOC_ControllerStart() → running = 1
                                            │  feedback_ready && running && 功率级安全
                                            ▼
                                  enable_output()  ★ 临界区内置 MOE
                                            │  回读确认 MOE 真的置上了
                                            ▼
                                        RUNNING
                                            │  servo_on_request = 0 → StopOutput() → READY
                                            │  MOE 意外掉了 → FAULT(OUTPUT_DISABLED)
                                            ▼
                                          FAULT
                                  StopOutput() + 锁存 + notify_fault()
                                            │  fault_reset_request
                                            │  && servo OFF && 校准完成 && 功率级安全
                                            ▼
                                          READY
```

**为什么要 `STARTING` 这个中间态**：`FOC_ControllerStart()` 只置 `running`，
算法要先跑起来、`feedback_ready` 被 ISR 发布之后，才允许开 MOE。
否则 MOE 打开的瞬间 CCR 里还是上一次的残值，会产生一个非对称脉冲。

**`MainServo_EnableOutput()` 是全工程正常打开 MOE 的唯一入口**，内部用临界区保护：

```c
__disable_irq();
if (running && feedback_ready && IsPowerStageSafe() && !IsOutputEnabled())
    Tim1Pwm_EnableOutputs();
__enable_irq();   /* 按进入前的 PRIMASK 恢复 */
```

临界区防止「检查 feedback_ready」和「置 MOE」之间被 ADC ISR 打断；
区内只读内存/引脚并写一个寄存器，不做通讯、不等待。

**故障哲学**：故障即关断，**恢复必须显式请求**。引脚电平自己恢复了也不会自动重开 MOE，
必须先 `RequestOff()` → `RequestFaultReset()`。这是刻意的安全选择。

## 5. 三种控制模式

三种模式**全部编译进同一个固件**，运行时通过写 `requested_mode` 切换，不用宏裁剪、不用重新下载。

### 5.1 模式对照

|                     | 电压开环                               | 电流开环（台架测试）                                                                       | 正常模式                                                                            |
| ------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| 枚举                | `FOC_CONTROL_MODE_VOLTAGE_OPEN_LOOP` | `FOC_CONTROL_MODE_CURRENT_OPEN_LOOP`                                                     | `FOC_CONTROL_MODE_NORMAL`                                                         |
| 电流反馈            | 不参与控制                             | ✅ ADC 实际电流                                                                            | ✅ ADC 实际电流                                                                     |
| 电流 PI             | 不运行                                 | ✅ 运行                                                                                    | ✅ 运行                                                                             |
| 电角度              | 虚拟角度，算法自行推进                 | 虚拟角度，`main.c` 推进                                                                  | 正式角度接口（**尚未接入**）                                                  |
| 算法入口            | `FOC_AlgorithmVoltageStep()`         | `FOC_ControllerStep()`                                                                   | `FOC_ControllerStep()`                                                            |
| 是否走 ServoManager | ❌                                     | ❌                                                                                         | ✅                                                                                  |
| MOE 由谁打开        | ADC ISR 内部                           | ADC ISR 内部                                                                               | ServoManager（主循环，带临界区）                                                    |
| 默认 PI 参数        | —                                     | Kp 0.05、Ki 2.0、积分 ±0.02、`current_limit` 0.5 A、`voltage_limit` 0.02 pu、线性调制 | Kp 0.1、Ki 5.0、积分 ±0.95、`current_limit` 10 A、`voltage_limit` 2/π、过调制 |

「电流开环」沿用测试命名；从算法角度看它是**电流闭环 + 角度开环**。

**默认配置**（`main.c` 里 `g_global_mode_control` 的初始化）：

```text
requested_mode = active_mode = FOC_CONTROL_MODE_CURRENT_OPEN_LOOP
电压开环：Ud = 0.20 V，Uq = 0 V，Vdc = 24 V，fe = 2 Hz，斜坡 0.5 V/s
电流开环：Id* = 0.10 A，Iq* = 0 A，Vdc = 24 V，fe = 2 Hz
正常模式：Id* = Iq* = 0，angle_valid = 0，reference_valid = 0
runtime.output_request = 0     ★ 上电默认不输出
```

`angle_valid` 和 `reference_valid` 默认为 0，是为了**不会误用假角度启动**。

### 5.2 模式切换：强制走安全边界

程序或调试器**只写 `requested_mode`**，绝不直接改 `active_mode`。
主循环 `MainFoc_ServiceModeSwitch()` 检测到变化后依次执行：

```text
1. output_request = 0，output_armed = 0
2. precharge_in_progress = 1        阻止 ISR 继续写 PWM
3. ServoManager_RequestOff()        正常模式还要立刻 Service() 一次
4. FOC_ControllerStop() + Tim1Pwm_EmergencyStop()
5. 短临界区内：ClearFaults → 装新模式 PI 参数 → 清 PI 积分与算法输出
6. 复位虚拟角度、周期计数、开环斜坡
7. 更新 active_mode，switch_count++
8. precharge_in_progress = 0，保持输出关闭，等新模式再次显式启动
```

所以切换**不会把上一模式的占空比、PI 积分或输出请求带进下一模式**。
切换后必须重新写 `output_request = 1`（或正常模式重新 Servo ON）才会输出。

## 6. 从上电到电机通电：六道门

这是本固件最重要的安全设计。**任何一道门没过，栅极就拿不到 PWM。**

| # | 门                 | 类型                 | 判据                                                                       | 谁来开                                                   |
| - | ------------------ | -------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------- |
| 1 | 零点校准完成       | 软件                 | `calibration_state == CAL_DONE`                                          | `CurrentSampling_Service()` 自动推进                   |
| 2 | 功率级安全         | **硬件引脚**   | PE14 READY = 1 且 PE15 nFAULT = 1                                          | 由驱动器芯片决定，软件只能读                             |
| 3 | 显式输出请求       | 软件                 | 测试模式 `runtime.output_request = 1`；正常模式 `servo_on_request = 1` | **必须人或上位机主动写**，上电默认 0               |
| 4 | 预充电与稳定完成   | 软件 + 延时          | `output_armed = 1`，且 `precharge_in_progress = 0`                     | 主循环执行 `BootstrapPrecharge()` + 20 ms 中性矢量稳定 |
| 5 | 算法运行且反馈有效 | 软件                 | `g_foc_controller.running = 1` 且 `feedback_ready = 1`                 | `FOC_ControllerStart()` + ISR 发布                     |
| 6 | **MOE**      | **硬件寄存器** | `TIM1->BDTR.MOE = 1`                                                     | `Tim1Pwm_EnableOutputs()`                              |

**第 3 道门为什么存在**：防止复位、重新下载、调试器重新运行时电机突然自动带电。
上电后算法可以自由运行（`running = 1`、角度在转、CCR 在更新），
但功率级纹丝不动，直到调试者明确写 `output_request = 1`。

**第 4 道门为什么存在**（`Tim1Pwm_BootstrapPrecharge()`）：

```text
1. EmergencyStop()                     无条件关 MOE
2. 三相 CCR 预装为低侧导通矢量          输出关着的时候装，MOE 一开就是低侧
3. HAL_Delay(1 ms)                     等预装值经谷值进入活动寄存器
4. __HAL_TIM_MOE_ENABLE() + 10 ms      低侧导通把 OUTx 钳到 PGND，
                                       自举电容经内部二极管充电
5. SetNeutral() + HAL_Delay(1 ms)      切到三相 50% 零电压矢量
```

**没有这一步会怎样**：MOE 首次置起时高侧栅极驱动电压不足，MOSFET 工作在线性区、
Rds(on) 很大，从而触发芯片的 VDS 保护（DS13630 §5.3）。表现为「一使能就报 fault_flags = 8」。

**关断路径有两条，一快一慢**：

| 路径 | 触发点                             | 动作                                                                                                                                                                                    |
| ---- | ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 快   | 20 kHz ADC ISR 里读 `GPIOE->IDR` | 不安全 → 立即 `Tim1Pwm_EmergencyStop()` 清 MOE + 锁存 `FOC_FAULT_POWER_STAGE` + 记 `first_unsafe_pin_levels`、`unsafe_sample_count`、`ready_low_count`、`nfault_low_count` |
| 慢   | 主循环 1 s `DrvMonitor_Task()`   | I2C 读 STATUS 查故障**原因**，状态机转 FAULT / COMM_LOST；`main.c` 再做一次跨层仲裁兜底                                                                                         |

快路径**不等主循环轮询发现**——20 kHz 下每 50 µs 就检查一次，
最坏情况一个周期内关断。慢路径负责回答「为什么关的」。

## 7. MOE 与 CH4 到底谁管谁（勘误）

> 这一节纠正一个此前流传的不准确说法：「MOE 只管 CH1~3 的输出，不管 CH4」。

### 7.1 准确表述

**MOE 是 TIM1 输出级（output stage）到引脚的总开关，对所有已使能的通道生效——包括 CH4。**
只要某通道通过 `CCER.CCxE` / `CCxNE` 使能并映射到了引脚，MOE = 0 就会把它的引脚拉到无效电平。
所以「MOE 是整个定时器输出的开关」这个观察是**对的**。

**但 MOE 不管内部信号。** 下列全部在 MOE = 0 时照常工作：

- 计数器继续跑（`CR1.CEN` 与 MOE 无关）
- `OC4REF` 继续按 CCR4 翻转
- `TRGO` / `TRGO2` 继续产生
- 更新事件、比较事件、比较中断继续发生
- **由 `T1_TRGO2` 触发的 ADC 注入转换继续执行**

MOE 位于「比较逻辑 → 输出级 → 引脚」这条链的**输出级**上；
`OC4REF → TRGO2 → ADC` 是从比较逻辑**分叉出去的另一条内部链**，不经过输出级。

### 7.2 为什么在本工程里两者看起来「分离」

**因为 CH4 在本工程根本没有映射到引脚。**

`HAL_TIM_MspPostInit()` 只配置 PE8~PE13，即 CH1N/CH1/CH2N/CH2/CH3N/CH3 六个栅极脚。
CH4 只用来产生 `OC4REF`，从未接到任何 GPIO。所以：

- MOE 对 CH4 **没有可观察的影响**——它没有引脚可关。
- 「MOE 只管 CH1~3」这句话在**本板的观察层面**成立，但它是「CH4 没引脚」的结果，
  **不是 MOE 位的功能边界**。若哪天把 CH4 映射到引脚并置 `CC4E`，MOE 一样会关掉它。

### 7.3 工程内部的实证

这条不是推测，本固件的运行事实就证明了它：

```text
main.c:539   Tim1Pwm_EmergencyStop()          ← MOE = 0
main.c:578   MX_ADC1_Init(0U)                 ← 参数 0 = 用硬件触发 T1_TRGO2
main.c:633   CurrentSampling_Start()          ← ADC 注入组开始等触发
main.c:643   HAL_Delay(20 ms)
main.c:644   CurrentSampling_RequestCalibration()
主循环       CurrentSampling_Service()        ← 校准推进到 CAL_DONE
```

`adc1_current_sampling.c` 里明确写着：

```c
if (software_trigger_flag != 0U)
    sConfigInjected.ExternalTrigInjecConv = ADC_INJECTED_SOFTWARE_START;
else
    /* 明确选择 TRGO2 = OC4REF 上升沿，每个中心对齐周期只触发一次。
       CC4 比较事件不能当作 REF 电平的上升沿使用。 */
    sConfigInjected.ExternalTrigInjecConv = ADC_EXTERNALTRIGINJEC_T1_TRGO2;
```

`main.c` 传的是 `0U`，所以运行时走的是 **TRGO2 硬件触发**。
而零点校准是在 MOE = 0 的情况下跑到 `CAL_DONE` 的
（`daily_changes_2026-10-19.md` §10 记录了实机 `CAL_DONE`）。

**如果 MOE 能切断 `OC4REF → TRGO2 → ADC` 这条链，`sample_sequence` 会恒为 0，
校准永远拿不到样本，状态机会走到 `CAL_ERROR`。** 事实是它走到了 `CAL_DONE`——
这就是 MOE 不影响内部触发链的直接证据。

### 7.4 一个容易混淆的细节：CC4 事件 ≠ OC4REF 边沿

代码里特意选了 `T1_TRGO2`（= `OC4REF`）而**不是** `T1_CC4`：

- `CC4` 是**比较匹配事件**，中央对齐下一个周期会发生**两次**（上数一次、下数一次）。
- `OC4REF` 是**参考电平**，PWM 模式 2 下它的上升沿一个周期只有**一次**。

用 CC4 事件当边沿触发源会导致每个载波周期触发两次 ADC，采样率变成 40 kHz 且时序错位。
这也是 `TIM1_CC_IRQHandler` 里那句注释的由来：「CC4 interrupt is disabled:
OC4REF through TRGO2 triggers the injected ADC in hardware」。

### 7.5 结论

| 说法                                       | 对不对                                                                       |
| ------------------------------------------ | ---------------------------------------------------------------------------- |
| MOE 是硬件寄存器位（`TIM1->BDTR` bit15） | ✅ 对，不是软件标志                                                          |
| MOE 是整个定时器**引脚输出**的总开关 | ✅ 对，不限于 CH1~3                                                          |
| MOE 只管 CH1~3，不管 CH4                   | ❌ 不准确。准确说法是「CH4 在本工程没有引脚输出，所以 MOE 对它无可观察影响」 |
| MOE = 0 时 ADC 仍能被 OC4REF/TRGO2 触发    | ✅ 对，本工程靠这一点在关断状态下完成零点校准                                |
| MOE 会被硬件刹车自动清零                   | ❌ 本工程 Break/Break2 都禁用了，MOE 完全靠软件显式操作                      |

最后一条要特别注意：**没有任何硬件兜底会自动关 MOE**。
「功率级不安全 → 清 MOE」这个动作完全依赖 20 kHz ISR 里的快速引脚安全门。
这也是为什么那道门必须只读 GPIO、必须恒定耗时、绝不能走 I2C。

## 8. 中断与优先级

| 中断向量                     | 优先级     | 频率   | 派发到                                 | 当前用途                                                        |
| ---------------------------- | ---------- | ------ | -------------------------------------- | --------------------------------------------------------------- |
| `TIM1_CC_IRQHandler`       | 0（最高）  | —     | `HAL_TIM_OC_DelayElapsedCallback`    | **CC4 中断已禁用**，向量保留                              |
| `ADC1_2_IRQHandler`        | 1          | 20 kHz | `HAL_ADCEx_InjectedConvCpltCallback` | ★ **实时链路主入口**：采样快照 + FOC + 写 CCR + PA0 探针 |
| `TIM1_UP_TIM16_IRQHandler` | 1          | 20 kHz | `HAL_TIM_PeriodElapsedCallback`      | 周期边界，当前仅做一次实例判断                                  |
| `TIM6_DAC_IRQHandler`      | 15（最低） | 1 s    | `HAL_TIM_PeriodElapsedCallback`      | 驱动监控心跳，只置标志                                          |
| `SysTick_Handler`          | 15         | 1 kHz  | `HAL_IncTick()`                      | HAL 时基                                                        |

**设计意图**：

```text
ADC1_2 / TIM1_UP (1)  ← 实时链路，可被 TIM1_CC(0) 抢占
TIM6 / SysTick  (15)  ← 后台与时基，绝不抢占实时链路
```

`HAL_TIM_PeriodElapsedCallback` 被 TIM6 与 TIM1_UP **共用同一个定义**（在 `drv_monitor.c`，
按 `htim->Instance` 过滤），因为工程设了 `USE_HAL_TIM_REGISTER_CALLBACKS = 0`，
走的是弱符号覆盖模式，**全工程只能有一个定义**。

**两条隐含约束**：

1. 实时中断（优先级 1）若执行超过 1 ms，SysTick（优先级 15）会被阻塞，
   `HAL_GetTick()` 停止推进，进而让所有基于 tick 的超时失效
   （`DrvMonitor` 的 I2C 超时、`Tim1PwmVerify` 的 `HAL_Delay`、校准状态机的时间窗）。
   当前实测约 35 µs / 50 µs，有约 15 µs 余量；**接入正式电流环后必须重新测量最大脉宽与抖动**。
2. `TIM1_UP` 以 20 kHz 触发但当前无实际工作，每 50 µs 白花一次中断进入 + 一次实例比较。
   这是为周期边界预留骨架的刻意代价，正式闭环接入后应赋予其真实用途或直接关闭。

## 9. 依赖倒置：两个端口结构体

这是本框架「算法与硬件解耦」的落地方式。**两个端口，两套回调，都不含硬件头文件。**

### 9.1 `foc_port_t`（FOC ↔ 硬件）

```c
typedef struct {
    uint8_t (*is_power_stage_safe)(void *context);
    void    (*read_feedback)(void *context, foc_input_t *input);
    uint8_t (*write_voltage)(void *context, const foc_output_t *output);
    void    (*disable_output)(void *context);
    void *context;
} foc_port_t;
```

`main.c` 里的实际绑定：

| 回调                    | 绑定到                                                                               | 硬约束                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| `is_power_stage_safe` | `MainFoc_IsPowerStageSafe` → `DrvMonitor_IsPowerStageSafeFast()`                | **只读两个 GPIO，绝不走 I2C**，20 kHz 下执行时间必须恒定         |
| `read_feedback`       | `MainFoc_ReadFeedback` → `CurrentSampling_ReadFeedback_A()` + 按模式取角度/给定 | 每周期先把三个 valid 清 0 再重新判定，**禁止沿用上一周期的标志** |
| `write_voltage`       | `MainFoc_WriteVoltage` → `Tim1Pwm_SetPhaseVoltage()`                            | 成功返回 1；返回 0 会锁存 `FOC_FAULT_PWM_WRITE` 并关 MOE             |
| `disable_output`      | `MainFoc_DisableOutput` → `Tim1Pwm_EmergencyStop()`                             | 清 MOE                                                                 |

### 9.2 `servo_manager_port_t`（Servo ↔ 硬件）

```c
typedef struct {
    uint8_t (*is_calibration_done)(void *context);
    uint8_t (*is_calibration_error)(void *context);
    uint8_t (*is_power_stage_safe)(void *context);
    uint8_t (*is_output_enabled)(void *context);
    void    (*prepare_output)(void *context);
    void    (*enable_output)(void *context);
    void    (*disable_output)(void *context);
    void    (*notify_fault)(void *context, servo_fault_mask_t active, servo_fault_mask_t latched);
    void *context;
} servo_manager_port_t;
```

`ServoManager_PortReady()` 会检查**前七个回调全部非空**，缺一个就进
`SERVO_FAULT_FOC_CONFIG`。`notify_fault` 是后台上报接口，
**不会在 ISR 中调用**，未来 CAN/UART 协议层挂在这里。

### 9.3 为什么值得这么做

- 换 MCU / 换驱动芯片 / 换编码器，`FOC/` 和 `Servo/` **一行都不用改**，只换 `main.c` 里的回调实现。
- `FOC/` 和 `Servo/` 可以在主机上跑单元测试（`Tests/Host/`），不需要硬件。
- 空指针风险被显式管理：`FOC_ControllerStep()` 的安全门分支**先判空再调用**
  `disable_output`——早期版本无条件调用，而进入该分支的原因之一恰恰可能就是
  `disable_output == 0`，结果是空指针解引用 → HardFault。

## 10. 全局对象速查

本节中的“全局对象”不是同一层次的一组变量。它们分别承担应用编排、控制算法、
状态管理、硬件业务状态和测试观测职责。理解层次后，才能知道一个字段应该由谁写、
在哪里读，以及为什么不能在 Watch 窗口里随意改所有值。

### 10.1 对象层次与依赖关系

```text
应用编排层（Core/main.c）
│
├─ g_global_mode_control                 运行模式和测试模式总入口
│  ├─ voltage_open_loop          电压开环命令与遥测
│  ├─ current_open_loop          电流测试环命令与遥测
│  ├─ normal_loop                正式环路的给定与角度入口
│  └─ runtime                    三种模式共用的功率输出状态和快速故障记录
│
├─ g_servo_manager               正式模式状态机（只在 NORMAL 模式接管启停）
│  └─ foc ─────────────────────┐  指向 g_foc_controller
│                              │
└─ g_foc_controller ◄──────────┘  FOC 控制器实例
   ├─ algorithm.parameters         PI、限流、调制参数
   ├─ algorithm.output             最近一次算法输出和遥测
   ├─ port                         FOC 到硬件的四个回调
   ├─ input                        最近一次完整输入快照
   └─ timing                       实时环周期和执行次数

硬件业务状态层
├─ g_current_sampling            ADC 电流采样、零点校准和原始值
├─ g_tim1_pwm_sampling           PWM 低侧窗口及 ADC 触发点规划结果
└─ s_mon                         STSPIN32G4 后台监管快照

测试与观测层
├─ g_waveform_generator          波形发布、排队、发送和丢帧统计
└─ g_mt6835_verify              MT6835 SPI 链路自检结果
```

核心关系如下：

- `g_global_mode_control` 是**应用级总管**，决定当前运行哪一种模式，并保存三个模式各自的
  命令和遥测；它不替代 FOC 算法本身。
- `g_foc_controller` 是**算法执行实例**，持有 PI、变换、调制、输入输出和硬件端口。
  电流开环测试和正式模式共用这个实例，不能各自再建一套积分器。
- `g_servo_manager` 是**正式模式的安全状态机**，内部通过 `foc` 指针操作
  `g_foc_controller`。测试模式绕过它，但仍受 `g_global_mode_control.runtime` 和功率级
  快速安全门保护。
- `g_current_sampling` 和 `g_tim1_pwm_sampling` 位于控制器下方：前者生产电流反馈，
  后者保证采样落在有效 PWM 窗口。它们不是控制模式配置对象。
- `s_mon` 是后台 I2C 监管结果；20 kHz 快速关断不等它更新，而是直接调用
  `DrvMonitor_IsPowerStageSafeFast()` 读取 READY/nFAULT 引脚。
- `g_waveform_generator` 只负责观测数据的降采样和传输统计，不参与控制决策。

### 10.2 `g_global_mode_control`：应用级控制模式总管

**类型/定义**：`foc_control_manager_t`，定义于 `Core/Src/main.c`，类型位于
`FOC/Inc/foc_control_manager.h`。

这是调试和上位机控制时最先接触的对象。其字段分为四组：

| 子对象/字段           | 作用                                                | 谁可以写                              | 典型用法                                              |
| --------------------- | --------------------------------------------------- | ------------------------------------- | ----------------------------------------------------- |
| `requested_mode`    | 请求切换到的模式                                    | 调试器、上位机、应用层                | 写入模式枚举；主循环安全切换                          |
| `active_mode`       | 当前实际生效的模式                                  | 仅 `MainFoc_ServiceModeSwitch()`    | 只读；判断 ISR 当前走哪条分支                         |
| `switch_count`      | 已完成的模式切换次数                                | 模式切换服务                          | 只读；确认请求确实被处理                              |
| `voltage_open_loop` | dq 电压命令、虚拟电角度、斜坡和输出遥测             | 命令字段可由应用写，状态字段由 ISR 写 | 电压开环验证 SVPWM、功率级与相序                      |
| `current_open_loop` | dq 电流命令、虚拟电角度、测量 dq 电流和 PI 输出电压 | 参考值/频率可写，遥测只读             | 不接编码器测试真实电流闭环                            |
| `normal_loop`       | 正式模式的 dq 电流给定与真实电角度入口              | 未来速度环/位置环/编码器层            | `angle_valid` 和 `reference_valid` 都有效后才运行 |
| `runtime`           | 公共启停、安全门、MOE 状态和故障现场                | 应用服务与 ADC ISR 共同维护           | 测试模式开关输出、定位功率级故障                      |

三个模式的含义：

- `FOC_CONTROL_MODE_VOLTAGE_OPEN_LOOP`：直接给 `d_voltage_v/q_voltage_v`，跳过电流 PI，
  使用内部递增的电角度生成 PWM。
- `FOC_CONTROL_MODE_CURRENT_OPEN_LOOP`：名称中的“开环”指**角度开环**；电流本身使用
  ADC 实测反馈和 dq PI 闭环。
- `FOC_CONTROL_MODE_NORMAL`：电流、角度和给定都走正式接口，由 `g_servo_manager`
  管理 Servo ON/OFF、MOE 与故障恢复。

模式切换只能这样做：

```c
g_global_mode_control.requested_mode = FOC_CONTROL_MODE_CURRENT_OPEN_LOOP;
```

不要直接写 `active_mode`。主循环发现请求变化后，会依次撤销输出请求、停止控制器、
清 MOE、清 PI、复位开环角度/斜坡，最后才更新 `active_mode` 和 `switch_count`。

测试模式启停输出：

```c
g_global_mode_control.runtime.output_request = 1U; /* 请求预充电并启动 */
g_global_mode_control.runtime.output_request = 0U; /* 请求立即停止 */
```

`output_request` 只是命令，不能单独证明 PWM 已经送到功率级。状态推进关系是：

```text
output_request = 1
        ↓ 功率级安全、校准完成（电流模式）
自举预充电 + 中性矢量等待
        ↓ 预充电函数已置 TIM1 MOE
output_armed = 1
        ↓ ADC ISR 完成一次有效算法和 PWM 写入，替换启动矢量
output_enabled = Tim1Pwm_IsOutputEnabled()
```

这里的 `output_armed` 表示算法已经获准接管 CCR，不表示“此刻才打开 MOE”。当前
`Tim1Pwm_BootstrapPrecharge()` 为了给高侧自举电容充电会开启 MOE，并在返回前切到
50% 中性矢量；`output_armed` 随后才允许实时环把中性矢量替换为算法结果。

`runtime` 中常用字段：

| 字段                                                | 含义和判断方法                                                       |
| --------------------------------------------------- | -------------------------------------------------------------------- |
| `running`                                         | 算法链是否正在执行；不等价于 MOE 已开启                              |
| `output_request`                                  | 外部输出请求；测试模式允许应用/调试器写                              |
| `output_armed`                                    | 预充电和启动检查已经通过，等待/允许 ISR 正式提交输出                 |
| `precharge_in_progress`                           | 主循环正在执行自举预充电或中性矢量等待，ISR 不得覆盖启动 CCR         |
| `power_stage_safe`                                | ADC 周期内最近一次 READY/nFAULT 快速检查结果                         |
| `output_enabled`                                  | 软件记录的输出生效状态；排障时同时核对 `Tim1Pwm_IsOutputEnabled()` |
| `fault_flags`                                     | 测试模式快速故障锁存，位定义使用 `FOC_FAULT_*`                     |
| `power_stage_pin_levels`                          | 最近一次安全检查读取到的 GPIO 输入寄存器原值                         |
| `first_unsafe_pin_levels`                         | 第一次不安全时保存的 GPIO 现场，故障后不要手工覆盖                   |
| `unsafe_sample_count`                             | 快速安全门失败总次数                                                 |
| `ready_low_count` / `nfault_low_count`          | 两个故障来源分别累计，便于区分 READY 与 nFAULT                       |
| `fault_status_capture_pending`                    | ISR 已记录引脚故障，等待主循环通过 I2C 读取 STATUS                   |
| `fault_status_valid` / `first_fault_status_raw` | 首次故障 STATUS 是否有效及原始寄存器值                               |

### 10.3 `g_foc_controller`：FOC 算法执行实例

**类型/定义**：`foc_controller_t`，定义于 `Core/Src/main.c`，接口位于
`FOC/Inc/foc_interface.h`。

它是“控制器本体”，由 ADC 注入转换完成回调以 20 kHz 驱动。不要在主循环中直接
调用 `FOC_ControllerStep()`，否则采样周期不确定，PI 的时间尺度也会错误。

| 一级字段                 | 二级字段                                          | 作用/用法                                               |
| ------------------------ | ------------------------------------------------- | ------------------------------------------------------- |
| `algorithm.parameters` | `sample_period_s`、`pwm_period_s`             | PI 使用的实际采样周期和名义 PWM 周期                    |
|                          | `voltage_limit`、`current_limit`              | 算法输入与输出限幅；单位分别为相对 Vdc 的标幺值、A      |
|                          | `d_controller/q_controller`                     | dq 两轴 `kp/ki/integral/integral_min/max`             |
| `algorithm.output`     | `d_current/q_current`                           | Clarke/Park 后的实测 dq 电流，单位 A                    |
|                          | `d_voltage/q_voltage`                           | PI 或测试入口产生的标幺 dq 电压                         |
|                          | `fundamental_*`                                 | 过调制情况下的基波目标和限制值                          |
|                          | `phase_*_duty`                                  | 最终三相占空比，范围应在 0～1                           |
|                          | `sector/modulation_region`                      | SVPWM 扇区和线性/过调制区域                             |
|                          | `valid/saturated`                               | 本次输出是否有效、是否发生限幅                          |
| `port`                 | 四个函数指针 + `context`                        | 连接功率级安全门、电流/角度输入、PWM 写入和紧急关断     |
| `input`                | 电流、角度、dq 给定及三个 valid                   | 最近一次从端口回调装入的完整输入快照；通常只读          |
| `running`              | —                                                | 控制器是否接受下一次 Step；通过 Start/Stop API 改变     |
| `feedback_ready`       | —                                                | 本周期输入有效、算法完成且 CCR 写入成功后的发布标志     |
| `fault_flags`          | —                                                | FOC 层锁存故障；正式模式由 Servo Manager 转换为伺服故障 |
| `timing`               | `pwm_period_s/cycle_count/last_sample_sequence` | 控制周期、算法执行次数和最近消费的 ADC 序号             |

推荐通过接口控制实例，而不是直接修改内部状态：

```c
FOC_ControllerStart(&g_foc_controller);
FOC_ControllerStop(&g_foc_controller);
FOC_ControllerClearFaults(&g_foc_controller); /* 只能在停止状态 */
```

PI 参数可以在停止状态下修改 `algorithm.parameters` 后调用
`FOC_AlgorithmReset()` 清积分。运行中直接改 `integral`、`output`、`input.valid` 或
`feedback_ready` 会破坏本周期数据一致性，不应作为正常控制手段。

### 10.4 `g_servo_manager`：正式模式安全状态机

**类型/定义**：`servo_manager_t`，定义于 `Core/Src/main.c`，接口位于
`Servo/Inc/servo_manager.h`。

它只在 `FOC_CONTROL_MODE_NORMAL` 下由主循环调用，测试模式不使用它控制启停。

| 字段                        | 作用/用法                                                                   |
| --------------------------- | --------------------------------------------------------------------------- |
| `foc`                     | 指向 `g_foc_controller`，由初始化绑定，不要在运行中更换                   |
| `port`                    | 校准、安全门、MOE、故障通知等板级回调                                       |
| `servo_on_request`        | ON/OFF 请求的内部表示；应使用 Request API，不直接写                         |
| `fault_reset_request`     | 故障复位请求；由状态机消费                                                  |
| `pending_faults`          | ISR 发布、等待后台合并的故障位                                              |
| `state`                   | `INIT → CALIBRATING → READY → STARTING → RUNNING`，异常进入 `FAULT` |
| `active_faults`           | 当前仍存在的故障                                                            |
| `latched_faults`          | 已锁存故障，即使物理条件恢复也保留，直到合规复位                            |
| `fault_sequence`          | 新故障事件序号；变化说明又捕获了一次故障                                    |
| `reported_fault_sequence` | 已经通过 `notify_fault` 上报到后台的序号                                  |

正式模式的正确调用方式：

```c
ServoManager_RequestOn(&g_servo_manager);
ServoManager_RequestOff(&g_servo_manager);
ServoManager_RequestFaultReset(&g_servo_manager); /* 先 OFF，再复位 */
```

`ServoManager_Service()` 只能放在主循环/后台任务，不能放进 ADC ISR；其中可能执行状态
推进、输出准备和故障通知，不属于 20 kHz 硬实时链路。

### 10.5 `g_current_sampling`：电流采样与校准状态

**类型/定义**：`current_sampling_t`，定义于
`Modules/Current_Sampling/Src/current_sampling.c`。

| 字段组       | 代表字段                                                                                                             | 作用/用法                                                   |
| ------------ | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 硬件换算配置 | `shunt_resistor_uohm`、`opamp_gain`、`vref_mv`、`adc_full_scale`、`oversampling_ratio`、`sample_rate_hz` | ADC 原始值换算为 A 的依据，板级参数确认后通常不在运行中修改 |
| 零点与极性   | `offset_u/v`、`polarity_u/v`                                                                                     | 校准得到零点；极性用于适配采样链方向                        |
| 实时原始值   | `raw_u/raw_v`、`sample_sequence`                                                                                 | JEOS ISR 更新；序号应约以 20000/s 增长                      |
| 校准状态     | `calibration_state`、`calibration_sample_count`、`calibration_target_samples`、`calibration_deadline_ms`     | 观察异步零点校准进度和超时                                  |
| 校准累加     | `calibration_sum_u/v`                                                                                              | 校准内部累加器，只用于排障，不应手改                        |

业务代码应使用 `CurrentSampling_ReadFeedback_A()` 获取一致的三相安培值，而不是分别
读取 `raw_u/raw_v` 自行换算。W 相当前由 `-(U + V)` 重构。请求校准用
`CurrentSampling_RequestCalibration()`，进度由主循环中的 `CurrentSampling_Service()`
推进。若 `sample_sequence` 恒为 0，说明 ADC 注入序列没有完成；若序号递增但
`calibration_state` 不到 `DONE`，再检查零电流条件、样本数和超时。

### 10.6 `g_tim1_pwm_sampling`：PWM 同步采样规划遥测

**类型/定义**：`volatile tim1_pwm_sampling_status_t`，定义于
`Modules/Three_Phase_Driver/Src/tim1_pwm.c`。

该对象只用于观察逐周期采样点规划，不用于下发占空比：

| 字段                     | 含义                                              |
| ------------------------ | ------------------------------------------------- |
| `planned_trigger`      | 为下一次 ADC 采样规划的 TIM1 CCR4 位置            |
| `planned_sequence_end` | 预计 ADC 注入序列完成所在的计数位置               |
| `low_window_start/end` | 本周期可用于双低侧采样的有效窗口                  |
| `sampled_trigger`      | 已经实际触发本次 ADC 的 CCR4 位置                 |
| `window_rejections`    | 因不存在足够采样窗口而拒绝 PWM 更新的累计次数     |
| `deadline_rejections`  | 因新 CCR 提交太晚、可能错过更新截止点而拒绝的次数 |
| `sample_period_s`      | 相邻两次有效电流快照的实际间隔，交给 PI 使用      |

正常情况下 `planned_trigger` 会随占空比变化，`sampled_trigger` 滞后一周期反映实际采用值。
拒绝计数持续增长通常表示占空比/最小脉宽/采样建立时间组合不可实现，而不是 ADC
随机失效。该对象由 PWM/ADC 实时路径维护，代码和调试器都应只读。

### 10.7 `s_mon`：功率驱动器后台快照

**类型/定义**：`drv_monitor_t`，定义于
`Modules/Driver_Communication/Src/drv_monitor.c`。

`state/status/fault/READY/nFAULT/comm_errors/uptime_s/last_fault_s` 用于判断 STSPIN32G4
后台监管状态。`status.raw == 0x80` 通常表示只有 LOCK 位，保护位未触发；仍要结合
READY 和 nFAULT 判断是否允许开功率级。

⚠ `s_mon` 声明为非 `static` 只是为了 Watch 可见。业务代码不要直接读，尤其不能在
中断中读；应调用 `DrvMonitor_GetSnapshot()` 获得无撕裂副本。20 kHz ISR 的快速安全门
则调用 `DrvMonitor_IsPowerStageSafeFast()`，它只读 GPIO，不进行 I2C 通信。

### 10.8 全局管理结构体的层次、职责与用法

“全局管理结构体”不是把所有变量堆进一个超级对象，而是每个业务域只有一个明确的
状态所有者。上层管理器可以读取下层发布的状态并调用下层 API，但不能跨层直接改写
下层内部状态。当前主要对象可以理解成下面的层次：

```text
应用/生命周期层
├─ g_servo_manager                 正常伺服启停、故障与状态机
└─ g_global_mode_control           FOC 模式选择、测试模式命令与公共运行状态
      │
      ├─ g_foc_controller          FOC 算法实例、端口、输入输出、实时故障
      │    └─ algorithm.parameters/output
      │
      ├─ g_current_sampling        ADC 原始值、校准、物理量换算
      └─ g_tim1_pwm_sampling       PWM 同步采样规划遥测

测试验证层（旁路观察，不反向控制上述对象）
├─ g_waveform_generator            选择要打印的业务信号、降采样、队列和统计
└─ g_mt6835_verify                 编码器 SPI 链路验证
```

#### 10.8.1 为什么要分成多个全局对象

- **所有权清楚**：电流零点只归 `g_current_sampling`，FOC 输出只归
  `g_foc_controller`，波形选择只归 `g_waveform_generator`。
- **命令与状态分离**：外部写 `requested_*` 或调用 API；模块处理后发布
  `active_*`、`running`、`fault_flags` 等只读状态。
- **中断与主循环分离**：20 kHz ISR 只做固定时间的算法、快照和入队；初始化、模式
  切换、通讯发送和故障策略在主循环执行。
- **避免双重真相**：同一状态只在一个对象中保存权威值。其他对象需要时读取快照或
  通过接口获得，不能再复制一套可写配置。

#### 10.8.2 `g_global_mode_control`：控制模式总入口

**类型**：`foc_control_manager_t`。这是 FOC 业务模式的最高层管理对象。

| 子结构/字段 | 作用 | 正确用法 |
|---|---|---|
| `requested_mode` | 外部请求的控制模式 | 调试器/协议可写 |
| `active_mode` | 已安全切换完成的模式 | 只读，不能强改 |
| `voltage_open_loop` | D/Q 电压指令、母线电压、频率、角度与斜坡状态 | 电压开环模式使用 |
| `current_open_loop` | D/Q 电流指令、虚拟角度、反馈和 PI 输出遥测 | 电流测试模式使用 |
| `normal_loop` | 正常闭环的角度与电流指令 | 正常伺服模式使用 |
| `runtime` | 输出请求、预充电、安全门、MOE 状态和故障现场 | 命令只写 `output_request`；其余原则上只读 |

模式切换必须写 `requested_mode`，由 `MainFoc_ServiceModeSwitch()` 完成“关 MOE → 停控制器
→ 清积分/故障 → 装载模式参数 → 发布 active_mode”。直接写 `active_mode` 会绕过这些安全步骤。

#### 10.8.3 `g_foc_controller`：实时算法实例

它位于模式管理器之下，持有 `algorithm.parameters`、最近输入、最近输出、硬件抽象端口、
实时运行标志和故障。`g_global_mode_control` 决定它按哪种业务模式运行，但不复制 PI
积分器和算法输出。业务层通过 `FOC_ControllerStart/Stop/ClearFaults()` 管理生命周期，
通过 `FOC_ControllerGetOutput()` 读取输出；不要直接改 `algorithm.output`、`feedback_ready`
或 `fault_flags`。

#### 10.8.4 `g_servo_manager`：正常模式生命周期管理

它负责正常伺服的 OFF/STARTING/RUNNING/FAULT 等状态，以及“何时允许启动 FOC、何时允许
打开功率级、故障后如何复位”。测试模式的参数放在 `g_global_mode_control`，正常伺服启停
则必须使用 `ServoManager_RequestOn/Off/FaultReset()`，两者不能互相绕过。

#### 10.8.5 `g_current_sampling` 与 `g_tim1_pwm_sampling`：实时数据发布者

前者拥有 ADC 原始值、零点校准和安培换算；后者拥有 PWM 同步采样窗口的规划遥测。
它们向 FOC 和测试层发布数据，但不关心控制模式或打印模式。业务代码应使用
`CurrentSampling_ReadFeedback_A()` 等接口，不能从波形模块反向修改采样原始值。

#### 10.8.6 `g_waveform_generator`：波形业务管理对象

**类型/定义**：`waveform_generator_manager_t`，定义于
`Tests/Src/waveform_generator.c`。它是测试验证层的全局管理对象，职责包括：

1. 解释预设模式或自定义通道；
2. 从 ISR 发布的完整 `waveform_source_snapshot_t` 中选择 1～4 个值；
3. 20 kHz 到 1 kHz 降采样并入队；
4. 主循环编码带通道 ID 的 V2 帧；
5. 通过 `waveform_transport_t` 发送，不依赖具体 UART/CAN。

它只“旁路观察”控制数据，不得改变 FOC 指令、反馈或 MOE。

| 字段组 | 字段 | 读写规则 |
|---|---|---|
| 模式命令 | `requested_mode` | 可写；选择关闭、电压开环UVW、电流开环DQ或自定义 |
| 模式状态 | `active_mode`、`active_channel_count`、`active_channels[]` | 模块发布，只读 |
| 自定义命令 | `custom_channel_count`、`custom_channels[]` | 建议由 `WaveformGenerator_ConfigureCustom()` 写 |
| 配置提交 | `selection_revision`、`applied_selection_revision` | Watch 手改自定义配置后递增前者；后者只读 |
| 运行开关 | `enabled` | 初始化后为1；通常通过模式 `DISABLED` 停止，不直接清它 |
| 队列统计 | `queued_samples`、`published_samples`、`dropped_samples` | 只读，用于判断实时发布和主循环消费能力 |
| 发送统计 | `sent_frames`、`transport_errors` | 只读，用于判断传输层健康 |
| 选择错误 | `selection_errors` | 只读；非法模式、数量或通道 ID 时增长 |
| 固定配置 | `config.source_rate_hz/output_rate_hz` | 初始化配置，运行中不要直接修改 |

两个预设模式：

```text
WAVEFORM_OUTPUT_VOLTAGE_OPEN_LOOP_UVW_CURRENT -> IU, IV, IW
WAVEFORM_OUTPUT_CURRENT_OPEN_LOOP_DQ          -> Id_ref, Id, Iq_ref, Iq
```

代码中切换使用 `WaveformGenerator_SelectMode()`。自定义使用
`WaveformGenerator_ConfigureCustom()`。如果在 Keil Watch 中手动配置自定义通道，必须先写
`custom_channel_count/custom_channels[]`，再写 `requested_mode=CUSTOM`，最后递增
`selection_revision`；最后一步是提交标志，避免 ISR 看到半更新数组。

模式切换后的新样本会携带自己的模式和通道 ID。队列中已存在的旧模式帧仍会正常发送，
上位机按每帧元数据解析即可，不需要清队列，也不会把旧数据误标成新模式。

#### 10.8.7 `g_mt6835_verify`：编码器链路测试对象

它是编码器 SPI 链路自检对象，不是正式角度反馈。关注 `state`、`fail_reason`、`samples`、
`comm_errors`、`crc_errors`、`angle_min/max`、`status_raw`、`crc_ok` 和 `last_frame`。
验证通过只代表 SPI 帧和 CRC 可信，不代表极对数、方向和机械零位已经配置正确。

#### 10.8.8 `g_measurement_manager` 的历史状态

`measurement_manager.h` 是旧 MOS 驱动测量设计，当前没有对应全局实体，也不参与现行
FOC 控制链。当前控制入口是 `g_global_mode_control`，波形入口是
`g_waveform_generator`。不要重新定义一个同名实体把两种职责混在一起；若未来恢复整板
测量管理器，应让它只编排测试生命周期，并继续调用现有控制/波形 API。

### 10.9 HAL 外设句柄不是业务状态对象

`htim1`、`hadc1`、`hopamp1`、`hopamp3`、`hi2c3`、`htim6`、`hspi1`、`huart1` 也是
全局符号，但它们属于 HAL 外设资源句柄。模块通过它们访问寄存器、DMA/中断状态和 HAL
运行状态；上层不应把命令或算法状态塞进这些句柄，也不要通过直接改句柄字段实现模式
切换。排查外设初始化时可以观察 `Instance`、`State`、`ErrorCode`，业务调试仍应优先看
前述分层对象。

### 10.10 上电健康状态与常用操作

**上电后的健康状态应该是**：

```text
g_current_sampling.calibration_state = CURRENT_SAMPLING_CAL_DONE
g_current_sampling.sample_sequence   持续递增（约 20000/s）
g_global_mode_control.active_mode            = FOC_CONTROL_MODE_CURRENT_OPEN_LOOP
g_global_mode_control.runtime.output_request = 0（★ 默认不输出，这是正常的）
g_global_mode_control.runtime.running        = 0（电流测试模式尚未 Start，这是正常的）
g_foc_controller.running             = 0
g_global_mode_control.runtime.output_enabled = 0
g_global_mode_control.runtime.fault_flags    = 0
DrvMonitor_GetState()                = DRV_STATE_READY
STSPIN32G4 STATUS 快照               = 0x80（仅 LOCK 位）
```

⚠ `output_request/output_armed/output_enabled` 为 0 是**停止输出后的安全状态**，
在当前默认的电流测试模式下，`output_request=0` 时算法确实不会执行，因而
`runtime.running=0` 和 `current_open_loop.cycle_count` 不变是预期行为。置
`output_request=1` 并成功通过校准、功率级检查和预充电后，才应看到 `running=1`、
`cycle_count` 与 `electrical_angle_rad` 持续变化。电压开环不同：即使不请求 MOE 输出，
算法仍可持续计算，所以该模式下要结合 `runtime.running` 和角度判断算法链是否活动。

**常用调试操作**：

```text
开输出（测试模式）：g_global_mode_control.runtime.output_request = 1
关输出（测试模式）：g_global_mode_control.runtime.output_request = 0    ← 立即清 MOE，斜坡归零
切模式           ：g_global_mode_control.requested_mode = <枚举值>       ← 不要直接写 active_mode
正常模式 Servo ON：ServoManager_RequestOn(&g_servo_manager)
故障复位         ：先 RequestOff()，再 RequestFaultReset()
```

最后再强调字段读写边界：

- 可以作为外部命令写入：`requested_mode`、当前测试模式的参考值/频率、
  `runtime.output_request`；正式模式使用 `ServoManager_Request*()`。
- 原则上只读：`active_mode`、所有 `*_count`/`*_sequence`、算法 `output`、采样原始值、
  `output_armed/output_enabled`、故障现场和测试统计。
- 通过 API 修改：控制器 Start/Stop/ClearFaults、Servo ON/OFF/Reset、校准请求、驱动器请求。
- 禁止运行中手改：PI `integral`、输入 valid、已发布快照 `s_mon`、PWM 采样规划和 HAL
  句柄内部字段。强行修改可能让 Watch 数值看似“正常”，但实际破坏跨 ISR/主循环一致性。

### 12.2 功能待办

1. **正式闭环还没有角度反馈。** MT6835 驱动与通讯验证已完成，但缺
   「机械角 × 极对数 + 编码器零位 + 方向」这一层，`normal_loop.angle_valid` 恒为 0。
2. **`dc_bus_voltage_v` 是固定 24 V**，不是 ADC 实时母线采样。母线波动会造成标幺比例误差。
3. **对外协议栈（CAN / UART）未实现。** `MainServo_NotifyFault()` 当前是空实现，
   `main.c` 里有 TODO 注释。原理图 `5_通讯电路.SchDoc` 画的是这一路，固件侧无对应源码。
4. **电压开环没有电流闭环保护**，`current_limit` 不限制直接电压给定，
   实验电源限流仍是必要的外部保护。
5. **PA0 需继续记录最大脉宽与周期抖动**；正式电流环接入后必须重新测量。
6. **电角频率与机械转速的关系**还没有结合极对数正式管理。
7. 当前「电机能转」只验证了电压开环的方向与链路，
   **不等于相序、编码器方向、电角度零偏已满足闭环要求**。
8. 下一阶段建议顺序：先完成电流偏置标定与相电流比例核对 → 恢复 `ServoManager` →
   逐步接入 dq 电流闭环。**不要从当前电压开环直接跳到高电压运行。**
