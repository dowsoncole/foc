# 电流采样模块说明（易读版）

> 阅读顺序：先看总体架构，再看接口和伪代码，最后回到源码深入验证。

## 一句话理解

这个模块把分流电阻上的微小电压，经 OPAMP 放大、ADC 采样和零点校准，变成 FOC 可以直接使用的三相电流。硬件只采 U/V 两相，W 相由 `W = -(U + V)` 推出。FOC 的主计算空间是带符号 S16（`-32768..32767`），另提供安培单位接口供调试和上层使用。

## 总体架构

```text
电机电流 → 分流电阻 → OPAMP1/3 → ADC1 注入组 → JDR1/JDR2
                                      ↑
                              TIM1_CH4 周期触发
                                      ↓
                         ADC 完成中断保存快照
                                      ↓
                    减零点 → 换算安培 → FOC
```

模块分为两层：

| 层 | 文件 | 作用 |
|---|---|---|
| 配置层 | `adc1_current_sampling.c/.h` | 配置 OPAMP、ADC、注入序列、16 倍过采样和启动顺序 |
| 业务层 | `current_sampling.c/.h` | 由 `g_current_sampling` 统一保存配置参数和运行参数，完成快照、校准零点、处理正负号和单位换算 |

FOC 应调用 `CurrentSampling_ReadFeedback_s16()`，不要直接访问 `ADC1->JDR1/JDR2`。需要物理量时调用 `CurrentSampling_ReadFeedback_A()`。

## 先看一次完整流程

```text
TIM1_CH4 触发 ADC
  → ADC1 对 U/V 两通道各转换 16 次并累加
  → 完整注入序列结束，进入 HAL_ADCEx_InjectedConvCpltCallback()
  → 读取 JDR1/JDR2，更新 raw_u/raw_v 和 sample_sequence
  → 正常运行时调用已注册的 FOC 回调
  → 业务层扣除 U/V 零点并按各相 polarity 修正方向
  → 计算 W = -(U + V)
  → FOC 通过 CurrentSampling_ReadFeedback_s16() 得到三相 S16 值
```

JDR 不是普通的 0~4095 数字，而是 16 次结果的累加值，范围约为 0~65520；换算时必须除以 `oversampling_ratio`。

注意：这里的“除以 16”只适用于从累加码换算 ADC 等效电压和安培值。零点校准值 `offset_u/offset_v` 与实时 `raw_u/raw_v` 都处于同一个 16 倍累加空间，校准平均和零点扣除都不能除以 16。FOC 的 S16 接口也直接使用扣零点后的累加差值，不经过安培换算。

## 接口速查

- `CurrentSampling_GetRaw(phase)`：读取最近一次原始累加码，只适合调试，不减零点。
- `CurrentSampling_GetRaw(phase)`：读取最近一次原始累加码，只适合底层调试。
- `CurrentSampling_ReadFeedback_s16(&u, &v, &w)`：扣零点、修正方向并返回三相 S16，FOC 推荐入口。
- `CurrentSampling_ReadFeedback_A(&u, &v, &w)`：扣零点、修正方向并返回三相安培值。
- `CurrentSampling_RequestCalibration()`：请求异步校准。
- `CurrentSampling_Service()`：在主循环推进校准状态机。

安培换算关系：

```text
raw_delta = (raw - offset) × polarity
I = raw_delta × Vref
    / (过采样倍率 × ADC满量程 × 采样电阻 × 运放增益)
```

## 校准状态机（伪代码）

```text
RequestCalibration:
    清空 sum_u/sum_v 和样本计数
    记录“10 ms 后”时间点
    状态 = SETTLING

Service:
    SETTLING 到时间 → COLLECTING，开始 1 ms 收集窗口
    COLLECTING 每次 ADC 完成就累加 raw
    样本够了或 1 ms 到期：
        有样本 → offset = sum / count，状态 = DONE
        无样本 → 状态 = ERROR，不覆盖旧零点
```

## 用 C 基本语法读代码

### `struct`：把配置参数和运行状态放进一个盒子

```c
typedef struct {
    uint32_t shunt_resistor_uohm;
    float opamp_gain;
    uint16_t offset_u;
    volatile uint16_t raw_u;
} current_sampling_t;
```

工程使用唯一的总对象 `g_current_sampling` 管理电流采样模块：采样电阻、运放增益、参考电压、过采样倍率和极性属于配置参数；零点、最新原始码、校准状态、累加和和采样序号属于运行参数。`g_current_sampling.raw_u` 中的 `.` 表示访问结构体成员。

### `enum`：用名字表示状态

`CURRENT_SAMPLING_CAL_IDLE` 比数字 `0` 更容易理解，也避免把状态写错。

### 指针：把结果写回调用者

```c
void Read(float *u) {
    if (u != NULL) *u = 1.0f;
}
```

`float *u` 是地址，`*u = ...` 会修改调用者的变量；传 `NULL` 表示该输出不需要。

### `static`、`volatile` 和回调

- `static`：变量只在当前 `.c` 文件可见。
- `volatile`：变量可能被中断修改，例如 `raw_u`，每次都从内存读取。
- 函数指针回调：应用层注册一个函数，ADC 完成时由采样模块调用，实现 FOC 与硬件解耦。

### `s_conversion_callback(s_conversion_context);` 是什么语法

这行代码是通过函数指针调用回调函数：

```c
s_conversion_callback(s_conversion_context);
```

它等价于：

```c
(*s_conversion_callback)(s_conversion_context);
```

两种写法含义相同，第一种更常见。

回调函数类型在头文件中定义为：

```c
typedef void (*current_sampling_conversion_callback_t)(void *context);
```

逐部分理解：

```text
void                         回调没有返回值
(*current_sampling_conversion_callback_t)  这是一个函数指针类型
(void *context)              回调接收一个通用上下文指针
```

因此，`s_conversion_callback` 是一个函数指针变量，能够保存任何符合下面形式的函数地址：

```c
void SomeCallback(void *context);
```

注册回调时：

```c
CurrentSampling_SetConversionCallback(MainFoc_OnAdcConversion,
                                      &g_foc_controller);
```

采样模块内部保存两部分：

```c
s_conversion_callback = MainFoc_OnAdcConversion;
s_conversion_context  = &g_foc_controller;
```

当 ADC 注入序列完成后，代码执行：

```c
if (s_conversion_callback != NULL)
{
    s_conversion_callback(s_conversion_context);
}
```

这表示：

```text
如果应用层注册了回调
    ↓
调用这个回调函数
    ↓
把注册时保存的 context 指针传给它
```

在当前工程中，实际调用关系是：

```text
HAL_ADCEx_InjectedConvCpltCallback()
    ↓
s_conversion_callback(s_conversion_context)
    ↓
MainFoc_OnAdcConversion(&g_foc_controller)
    ↓
FOC_ControllerStep(&g_foc_controller)
```

这里的 `s_conversion_context` 不是 ADC 数据，也不是 ADC 寄存器，而是注册回调时由应用层传入的上下文对象。本工程传入的是 `g_foc_controller` 的地址，所以回调函数可以通过 `context` 找到 FOC 控制器。

这个设计还意味着采样模块不需要直接包含 FOC 的头文件，也不需要知道 FOC 控制器的具体类型。它只负责在 ADC 转换完成后通知“已经注册的函数”。

需要强调：这行代码位于 ADC 转换完成回调链路中，与 `HAL_TIM_OC_DelayElapsedCallback()` 没有关系。TIM1_CH4 只负责触发 ADC；只有 ADC 完整转换结束后，才会执行该函数指针回调。

## 深入理解：关键设计原因

1. **为什么在 ADC 完成回调读取 JDR？** 触发时转换还没结束，完成回调时 JDR1/JDR2 才同时有效。
2. **为什么只采两相？** Clarke 变换只需两相，第三相由电流和为零推出。
3. **为什么参数集中在 `g_current_sampling`？** 换采样电阻、运放增益或参考电压时，只改参数，不改算法。
4. **为什么校准由应用层安排功率级？** 采样模块不应偷偷改变 PWM；安全状态由应用层决定。
5. **为什么中断里不做复杂计算？** 中断必须短而稳定；快照和计数在中断中完成，安培换算通过读取接口完成。

## 推荐初始化和使用方式

```c
MX_OPAMP1_Init();
MX_OPAMP3_Init();
MX_ADC1_Init(0U);  // 0 表示 TIM1_CH4 外部触发
CurrentSampling_SetConversionCallback(MainFoc_OnAdcConversion, NULL);
CurrentSampling_Start();
```

```c
void MainFoc_OnAdcConversion(void *context)
{
    int16_t iu, iv, iw;
    CurrentSampling_ReadFeedback_s16(&iu, &iv, &iw);
    /* FOC 使用 S16 电流空间；具体控制器可直接接收三相值。 */
    FOC_ControllerStep(iu, iv);
}
```

主循环中调用 `CurrentSampling_Service()`；不要在 ADC 中断中打印日志、延时或做阻塞操作。

## 当前实现说明

以上需求已经落到 `Modules/Current_Sampling/` 模块中。模块分成两部分：

```text
adc1_current_sampling.c/.h
    配置层：配置 OPAMP1、OPAMP3、ADC1 注入组，并启动硬件触发链

current_sampling.c/.h
    业务层：保存采样快照、零点校准、原始码换算和 FOC 反馈接口
```

配置层只负责让硬件正确工作，业务层不直接改 ADC 配置寄存器。这样以后更换 ADC 通道、触发定时器或 MCU 时，业务接口可以保持不变。

### 1. 原始采样数据

当前通道映射已经确认：

| 接口通道 | MCU 引脚 | ADC 通道 | 电机相别 | ADC 数据寄存器 |
|---|---|---|---|---|
| rank 1 | PA2 | ADC1_IN3 | U 相 | `ADC1->JDR1` |
| rank 2 | PB1 | ADC1_IN12 | V 相 | `ADC1->JDR2` |

ADC 使用 12 位转换和 16 倍注入组过采样。由于过采样右移设置为 0，硬件把 16 次转换结果相加后写入 JDR：

```text
单次 ADC 结果：0..4095
JDR 原始累加值：0..4095 × 16 = 0..65520
```

因此，原始接口返回的是累加值，不是普通的 0..4095 ADC 码。业务层如果需要 12 位等效码，应先除以 16。

### 2. `CurrentSampling_GetRaw()`

声明位置：`Modules/Current_Sampling/Inc/current_sampling.h`

```c
uint16_t CurrentSampling_GetRaw(current_sampling_phase_t phase);
```

用法：

```c
uint16_t raw_u = CurrentSampling_GetRaw(CURRENT_SAMPLING_PHASE_U);
uint16_t raw_v = CurrentSampling_GetRaw(CURRENT_SAMPLING_PHASE_V);
```

返回值是最近一次已经完成的 ADC 注入序列结果：

```text
raw_u -> U 相，来自 JDR1
raw_v -> V 相，来自 JDR2
```

该接口只返回原始累加码，不减零点，也不做单位换算，适合调试器观察、记录 ADC 波形和检查硬件是否在转换。

### 3. `CurrentSampling_GetCurrentA()`

声明：

```c
float CurrentSampling_GetCurrentA(current_sampling_phase_t phase);
```

用法：

```c
float current_u_a = CurrentSampling_GetCurrentA(CURRENT_SAMPLING_PHASE_U);
float current_v_a = CurrentSampling_GetCurrentA(CURRENT_SAMPLING_PHASE_V);
```

内部计算过程是：

```text
raw_delta = raw_value - zero_offset
adc_code  = raw_delta / 16
voltage   = adc_code × VREF / 4095
current   = voltage / (RSHUNT × OPAMP_GAIN)
```

当前固定参数为：

```text
RSHUNT     = 0.007 Ω
OPAMP_GAIN = 6.1
VREF       = 3.3 V
```

等价公式为：

```text
I[A] = (raw - offset) × 3.3
       / (16 × 4095 × 0.007 × 6.1)
```

如果以后更换采样电阻、运放增益或参考电压，只需要修改 `g_current_sampling` 中的参数，不需要修改换算流程。

### 4. 三相反馈接口

FOC 使用 S16 计算空间：

```c
void CurrentSampling_ReadFeedback_s16(int16_t *phase_u_s16,
                                      int16_t *phase_v_s16,
                                      int16_t *phase_w_s16);
```

该接口内部依次完成：

```text
raw_u - offset_u → 乘 polarity_u → U S16
raw_v - offset_v → 乘 polarity_v → V S16
W S16 = -(U S16 + V S16)
```

结果会限制在 `-32768..32767`。它是 FOC 电流环的推荐入口。

需要实际物理量时使用：

```c
void CurrentSampling_ReadFeedback_A(float *phase_u_a,
                                    float *phase_v_a,
                                    float *phase_w_a);
```

该接口同样先扣零点、修正方向，再将 U/V 转换为安培，并按三相平衡关系计算 W。

### 5. `CurrentSampling_RequestCalibration()`

声明：

```c
void CurrentSampling_RequestCalibration(void);
```

调用前提：应用层先把三相功率级设置为零电流校准状态，即三相下管导通。采样模块不会替应用层改变 PWM 或功率级状态。

推荐调用顺序：

```c
/* 应用层完成下管导通和功率级安全检查 */
CurrentSampling_RequestCalibration();
```

该函数不会等待 10 ms，也不会阻塞当前任务。它只清空上一次累加值，记录校准开始时间，并把状态切换为 `CURRENT_SAMPLING_CAL_SETTLING`。

### 6. `CurrentSampling_Service()`

声明：

```c
void CurrentSampling_Service(void);
```

调用位置：主循环或应用任务中周期调用，例如：

```c
while (1)
{
    CurrentSampling_Service();
    /* 其他后台任务 */
}
```

它是一个快速的非阻塞状态机：

```text
IDLE
  │ RequestCalibration()
  ▼
SETTLING：等待 10 ms，让下管导通后的采样电路稳定
  ▼
COLLECTING：收集 1 ms 内的 ADC 样本
  ▼
DONE：计算并保存 U/V 两相零点平均值
```

校准窗口为 1 ms，PWM/ADC 采样频率为 20 kHz，因此目标样本数为：

```text
20 kHz × 1 ms = 20 个样本
```

如果 1 ms 内没有采到任何样本，状态会变为 `CURRENT_SAMPLING_CAL_ERROR`，不会用无效数据覆盖原来的零点。

### 7. `CurrentSampling_GetCalibrationState()`

声明：

```c
current_sampling_cal_state_t CurrentSampling_GetCalibrationState(void);
```

应用层可用它判断校准是否完成：

```c
if (CurrentSampling_GetCalibrationState() == CURRENT_SAMPLING_CAL_DONE)
{
    /* 可以恢复正常电流控制 */
}
```

状态含义：

| 状态 | 含义 |
|---|---|
| `CURRENT_SAMPLING_CAL_IDLE` | 未请求校准 |
| `CURRENT_SAMPLING_CAL_SETTLING` | 已请求，正在等待 10 ms |
| `CURRENT_SAMPLING_CAL_COLLECTING` | 正在收集 1 ms 样本 |
| `CURRENT_SAMPLING_CAL_DONE` | 零点已经更新 |
| `CURRENT_SAMPLING_CAL_ERROR` | 没有采到有效样本 |

### 8. ADC 快照是如何更新的

TIM1_CH4 在 PWM 周期内产生 ADC 触发。该触发启动新一轮两通道注入转换，但 16 倍过采样序列需要约 11.43 µs 才完成。

因此业务层不会在 TIM1_CH4 触发回调中读取“正在转换”的 JDR。只有 ADC 注入序列完成后，才在 `HAL_ADCEx_InjectedConvCpltCallback()` 中读取本轮结果：

```text
TIM1_CH4 硬件触发新转换
    ↓
ADC 完整注入序列完成
    ↓
HAL_ADCEx_InjectedConvCpltCallback()
    ↓
读取本轮 JDR1/JDR2
    ↓
保存到 raw_u/raw_v，并在需要时加入校准累加和
```

这样既不会在 ADC 序列中途读取半更新数据，也不会在实时中断中执行浮点换算。浮点换算只在 FOC 读取接口调用时进行。

### 9. 应用层和 FOC 的职责边界

应用层负责：

- 判断驱动器和功率级是否安全；
- 控制三相下管进入校准状态；
- 调用 `CurrentSampling_RequestCalibration()`；
- 轮询 `CurrentSampling_GetCalibrationState()`；
- 校准完成后恢复正常 PWM/FOC 状态。

电流采样模块负责：

- 采集 U/V 两相 ADC 原始值；
- 等待电路稳定并计算零点；
- 保存零点并从原始值中扣除；
- 将 ADC 结果换算为安培；
- 向 FOC 提供三相 `CurrentSampling_ReadFeedback_s16()` 和 `CurrentSampling_ReadFeedback_A()`。

FOC 不应该直接访问：

```text
ADC1->JDR1
ADC1->JDR2
ia_offsets / ib_offsets
ADC 时钟、采样时间和过采样寄存器
```

## 后续接口和待实现项

### A. ADC 转换完成后运行 FOC

当前实现只在 ADC 注入序列完成回调中保存本轮 JDR 快照，并由该回调链路调度 FOC。TIM1_CH4 只提供 ADC 硬件触发，与 FOC 执行没有调用关系。

如果正式采用“ADC 转换完成后执行 FOC”，后续需要完成以下改动：

1. 在 ADC 配置层打开 `JEOS` 或注入组转换完成中断；
2. 在 `ADC1_2_IRQHandler()` 中调用 `HAL_ADC_IRQHandler(&hadc1)`；
3. 在 `HAL_ADCEx_InjectedConvCpltCallback()` 中只做固定时间的 FOC 调度；
4. 通过 `CurrentSampling_ReadFeedback_s16()` 获取 U/V/W 电流；
5. 通过 FOC 的 `foc_port_t` 写回电压指令；
6. 在调试器或示波器上验证 FOC 执行时间小于 PWM 周期余量。

`FOC_ControllerStep()` 不能放入 `HAL_TIM_OC_DelayElapsedCallback()` 或 TIM1_CC 回调，因为 TIM1_CH4 触发后 ADC 尚未完成。FOC 只能由 ADC 注入序列完成中断调度，并且必须确认 ADC 完成中断向量、优先级和执行时间。

### B. 电流正负号检查

`CurrentSampling_GetCurrentA()` 的正负号由以下因素共同决定：

- 分流电阻两端的实际电流方向；
- OPAMP 同相输入和反相输入的接法；
- PCB 上 U/V 相电流定义；
- 电机端子和 PWM 极性的定义。

代码当前采用有符号差值：

```text
signed_raw = raw_value - zero_offset
```

所以原始值高于零点时返回正电流，低于零点时返回负电流。这个软件逻辑符合 FOC 需要，但“电流流入电机是否一定表现为正值”必须用已知方向的小电流在硬件上验证。若实测方向相反，应在相应通道的换算层乘以 `-1`，不要修改 ADC rank 或 FOC Clarke 变换。

### C. FOC 数据结构

当前采样模块的参数和状态集中在：

```c
current_sampling_t g_current_sampling;
```

其中包括：

- `shunt_resistor_uohm`：采样电阻，当前为 7000 µΩ；
- `opamp_gain`：运放增益，当前为 6.1；
- `vref_mv`：ADC 参考电压，当前为 3300 mV；
- `offset_u`、`offset_v`：U/V 两相零点；
- `raw_u`、`raw_v`：最新 16 倍过采样原始码；
- `calibration_state`：校准状态；
- `sample_sequence`：ADC 快照序号。

FOC 不应直接依赖这个结构体的内部字段，而应通过：

```c
CurrentSampling_ReadFeedback_A(&phase_u_a, &phase_v_a, &phase_w_a);
```

读取经过零点校准和单位换算后的电流。这样以后把 ADC 换成 DMA、换 MCU 或调整采样时序时，FOC 接口仍然稳定。

### D. 测试验证建议

建议按以下顺序验证：

1. 无电流时观察 `CurrentSampling_GetRaw()` 是否稳定；
2. 请求校准，确认状态依次经过 `SETTLING`、`COLLECTING`、`DONE`；
3. 用已知小电流验证 `CurrentSampling_GetCurrentA()` 的比例；
4. 改变电流方向，确认返回值正负号符合约定；
5. 检查 U/V 两路是否分别响应正确的相电流；
6. 最后再接入 FOC，并测量 ADC 完成中断到 FOC 返回的最大执行时间。
