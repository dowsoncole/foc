## 2. 当天结果概览

今天的功能改动围绕三个问题展开：

1. 上层 Servo ON、控制器运行、反馈有效性和硬件输出开关不能用同一个布尔量表达。
2. 调制算法应支持从线性 SVPWM 连续进入过调制，但必须明确电压单位、基波增益和 PI 饱和行为。
3. 电流 ADC 必须在有效导通窗口内完成采样，不能只因为数学上能生成占空比就认为硬件能测到电流。

最终交付包含独立 Servo Manager、独立调制模块、独立采样时刻规划器、更新后的
FOC 端口与故障链路、主机测试和工程文件注册。

## 4. 与基线的主要差异

比较基线时需要准确区分原来已有的能力。

基线 `275aca8` 的 `foc_algorithm.c` 已包含三相 min/max 零序平移：

```c
zero_sequence = 0.5f - 0.5f * (maximum + minimum);
duty_a = clamp(phase_a + zero_sequence, 0.0f, 1.0f);
```

因此，今天不是把完全没有 SVPWM 的工程首次变成 SVPWM。主要变化是明确其单位、
重整模块职责、实现非线性过调制和硬件采样约束。基线应用中 `voltage_limit` 为
`0.95f`，今天的中间版本曾采用 `1/sqrt(3)` 的线性圆形限制；最终版本改为以
基波峰值定义上限，并同时接受调制模式和板级占空比跨度约束。

| 基线行为/结构 | 最终行为/结构 |
| --- | --- |
| `input.enabled` 单一输入开关 | `current_valid`、`angle_valid`、`reference_valid` |
| 主循环散布启动和安全条件判断 | `ServoManager_Service()` 统一管理状态转换 |
| 没有独立的软件故障锁存接口 | FOC 快速故障位 + Servo 故障状态及锁存 |
| `write_voltage` 返回 `void` | 返回成功/失败，失败进入故障链路 |
| PI 输出与积分共用同一对限幅边界 | 积分独立限幅，最终基波能力由调制器限制 |
| 调制代码嵌在 FOC 数学文件中 | `foc_modulation.c/h` 独立纯算法 |
| 固定初始 CCR4/CC4 触发路径 | `TRGO2=OC4REF` 上升沿，CCR4 动态规划 |
| float duty 先量化为 1000 级再转 CCR | FOC float duty 直接量化为 CCR |
| 当前周期成功计算/写入没有独立握手 | `feedback_ready` 成功写入后才发布 |
| 缺少本轮业务路径的主机覆盖 | 增加调制、故障、PI 和采样规划测试 |

## 5. 最终模块组织与依赖

```text
Core/Src/main.c：初始化、应用回调绑定、主循环调度
  ├─ Servo/：状态转换、Servo ON/OFF、故障锁存与复位
  ├─ FOC/Src/foc_interface.c：实时控制器、有效性检查、快速停环
  │    └─ FOC/Src/foc_algorithm.c：Clarke/Park、PI、抗饱和
  │         └─ FOC/Src/foc_modulation.c：基波 αβ → 三相 duty
  ├─ Modules/Current_Sampling/：ADC/OPAMP、原始码、校准和反馈
  └─ Modules/Three_Phase_Driver/Src/tim1_pwm.c：TIM1 与输出接口
       └─ Modules/Three_Phase_Driver/Src/pwm_sampling.c：纯计数域采样规划
```

职责约束：

1. 调制器不读 GPIO，不访问 ADC/TIM，不修改 running 或 MOE。
2. 采样规划器不包含 HAL，只处理计数和区间，便于在主机上穷举。
3. 硬件可用占空比由应用从 PWM 层取得，再交给纯算法；FOC 不反向包含硬件头文件。
4. Servo Manager 不承担高频数学计算，状态机在后台调用。
5. ADC 完成回调内不得加入 I2C、延时、日志或无界循环。
6. `main.c` 作为组合入口，负责把这些模块接成一条业务链路。

## 6. 标志位与参数管理

### 6.1 各标志的准确含义

| 字段/信号 | 拥有者 | 含义 | 不能替代什么 |
| --- | --- | --- | --- |
| `servo_on_request` | Servo Manager | 上层请求运行 | 不代表数据已准备好 |
| `running` | FOC Controller | 高频控制器允许运行计算 | 不代表 MOE 已打开 |
| `current_valid` | 当前周期反馈提供者 | 本周期电流反馈可用 | 不代表角度或给定有效 |
| `angle_valid` | 当前周期反馈提供者 | 电角度业务链路可用 | 不能因角度变量等于 0 就置真 |
| `reference_valid` | 当前周期参考提供者 | d/q 给定由上层有效发布 | 不代表电流反馈可用 |
| `power_stage_safe` | 驱动监控接口 | 驱动器当前允许功率输出 | 不代替 Servo ON 或数据检查 |
| `output.valid` | FOC Algorithm | 本次数学/调制输出有效 | 不代替硬件写入成功 |
| `feedback_ready` | FOC 实时周期 | 输入有效、算法有效且下一组 CCR 写入成功 | 是软件握手，不是波形已由示波器确认 |
| `MOE` | TIM1 功率级 | 硬件最终输出闸门 | 不应作为上层运行命令使用 |

`feedback_ready` 不表示预装载值已经生效；当前实现采用“下一组值准备完成”的握手。
首次放行 MOE 的具体载波相位和预装载生效关系仍应上板核对。

### 6.2 输入有效性生命周期

每个运行周期开始时，控制器先撤销 `feedback_ready`，再把三类输入有效标志清零。
应用的 `read_feedback` 回调重新填充当前数据并发布对应标志，禁止沿用上一周期的真值。

`FOC_InputIsValid()` 除检查三类标志外，还检查电角度和 d/q 给定是否为有限值。
电流本身使用 `int16_t` 表示，不存在浮点 NaN，但仍依赖采样和校准逻辑保证其来源有效。

当前应用的实际行为：

- `current_valid` 由零点校准是否为 `CAL_DONE` 决定。
- d/q 给定当前都为 0，`reference_valid=1`，属于应用明确发布的零给定。
- 电角度暂置 0，但 `angle_valid` 保持 0，控制器不能据此正常打开输出。
- 校准完成标志不是完整的采样新鲜度、ADC 过载或物理可信度诊断；这部分没有全部补齐。

### 6.3 参数实例

`g_foc_controller.algorithm.parameters` 持有 PI、限幅、调制模式和周期参数。
`g_foc_controller.input` 是最近一次周期输入；算法输出由
`g_foc_controller.algorithm.output` 提供。没有增加一套独立的隐含 PI 全局参数。

当前应用默认配置包括：

| 参数 | 值/来源 | 单位或说明 |
| --- | --- | --- |
| `voltage_limit` | `FOC_MODULATION_SIX_STEP_MAX` | `2/pi`，基波相电压峰值/Vdc |
| 调制模式 | `FOC_MODULATION_OVERMODULATION` | 允许进入 OVM，仍受硬件跨度降额 |
| `duty_min/max` | 由采样配置函数计算后写入 | 初始化列表中的 0..1 不是最终板级运行范围 |
| `current_limit` | `10.0f` | 当前反馈为 S16 标度，不能把此值直接称作 10 A |
| d/q `kp` | `0.1f` | 演示配置，未完成实机整定 |
| d/q `ki` | `5.0f` | 演示配置，积分乘实际采样间隔 |
| d/q 积分范围 | `-0.95f..0.95f` | 积分状态自身边界，不是最终调制能力 |
| 初始周期 | `1/20000 s` | 运行中实际采样周期由 ADC 回调更新 |

## 7. Servo Manager 状态机

新增 `Servo/Inc/servo_manager.h` 和 `Servo/Src/servo_manager.c`。

| 状态 | 正常作用 | 主要去向 |
| --- | --- | --- |
| `INIT` | 关断输出并进入校准等待 | `CALIBRATING` |
| `CALIBRATING` | 等待零点校准完成 | `READY` 或故障 |
| `READY` | 功率级保持受控，等待显式 Servo ON | 条件满足后 `STARTING` |
| `STARTING` | 开始 FOC 计算，等待新的有效周期与写入握手 | 成功使能后 `RUNNING`；OFF 回 `READY` |
| `RUNNING` | 正常运行，监控 OFF、驱动条件和输出状态 | OFF 回 `READY`；异常进 `FAULT` |
| `FAULT` | 停环、关断、保持故障锁存 | 显式复位且条件恢复后 `READY` |

正常启动时序：

```text
上层 RequestOn
  → 校准完成、驱动安全、没有故障锁存
  → prepare_output：准备中性点
  → FOC_ControllerStart：清旧握手，设置 running
  → 下一次 ADC 完成：重新读取有效数据、计算并写入下一组 CCR
  → feedback_ready=1
  → 后台服务复核条件，在短临界区中放行 MOE
```

正常开输出由 Servo Manager 的端口链路管理；底层 PWM 测试/校准接口仍存在，
不能把软件组织上的约定理解成硬件上不可能有其他调用者。应用应避免不同业务
同时争用同一组三相输出。

复位接口要求 Servo OFF、校准完成、没有校准错误且驱动安全。恢复故障不自动
等同于 Servo ON。当前实现也没有规定所有故障都必须重新校准；是否强制重校准
是后续可按故障类别进一步细化的策略。

`FOC_DEMO_AUTO_SERVO_ON` 默认保持 `0U`。当前没有加入上电自动输出转矩的默认行为。

## 8. 故障链路与对外报警边界

### 8.1 FOC 快速故障位

| 位 | 名称 | 触发含义 |
| --- | --- | --- |
| 0 | `FOC_FAULT_CURRENT_INVALID` | 电流有效性未发布 |
| 1 | `FOC_FAULT_ANGLE_INVALID` | 电角度有效性未发布 |
| 2 | `FOC_FAULT_REFERENCE_INVALID` | 给定有效性未发布 |
| 3 | `FOC_FAULT_POWER_STAGE` | 功率级快速安全条件失效 |
| 4 | `FOC_FAULT_PORT_CONFIG` | 必需端口回调缺失 |
| 5 | `FOC_FAULT_ALGORITHM` | 数值输入、算法配置或调制输出无效 |
| 6 | `FOC_FAULT_PWM_WRITE` | 输出写入、采样窗口或提交截止检查失败 |

Servo Manager 映射上述故障，并另外表达校准失败、输出意外关闭等状态。
`SERVO_FAULT_FOC_ALGORITHM` 和 `SERVO_FAULT_PWM_WRITE` 分别使用位 7、位 8；
其余已有含义见 `Servo/Inc/servo_manager.h`。

### 8.2 快速处理与后台处理

实时周期发现故障后，撤销 running/就绪握手并调用快速关断端口。后台服务收集
FOC 故障、驱动条件和校准条件，进入 `FAULT`，更新锁存并触发后台通知接口。
不能等一秒级 I2C 轮询才处理实时数据失效。

`FOC_ControllerStop()` 先关硬件输出，再清状态和积分，最后才尝试写入复位值。
停机后的补写返回值不用于重新使能输出。端口缺失时仍先判空，避免关断回调自身
为空引发异常。

当前 `active_faults` 的实现是 OR 累积并在显式复位时清除，不能把它当成会随
物理故障消失而自动清零的实时传感器快照。`latched_faults` 同样保持到复位。
`fault_sequence/reported_fault_sequence` 用于避免后台重复发布相同事件。

`MainServo_NotifyFault()` 仍是预留回调，当前只保留内存中的故障状态；没有新增
CAN/UART 报警协议，也没有实现用户界面的故障弹窗。因此准确表述为“具备故障
锁存和后台通知接缝”，不能宣称“已经通过通讯告知用户”。

## 9. FOC 数学公式及单位

### 9.1 Clarke 变换

沿用两相电流输入并假设 `ia+ib+ic=0`。等幅值形式为：

```text
iα = (2/3)·(ia - ib/2 - ic/2) = ia
iβ = (2/3)·(√3/2)·(ib - ic) = (ia+2ib)/√3
```

代码中的 `0.5773502692f` 是 `1/sqrt(3)`，不是 PI 增益或经验系数。
本次修正了注释中推导式缺少 `2/3` 的问题；实际简化公式一直是 `iα=ia`、
`iβ=(ia+2ib)/sqrt(3)`。

等功率形式把前系数改为 `sqrt(2/3)`。无零序时，其 αβ 数值比等幅值形式大
`sqrt(3/2)`。等幅值形式计算三相瞬时功率时有 `3/2` 因子；等功率形式使用
匹配的电压/电流变换后可保持内积。切换形式必须重新核对给定、反馈、PI 单位、
电流限幅和电压反变换，不能只改一个常数。

电流反馈当前是校准后的 S16 值，不直接是安培。物理安培换算仍由电流采样模块
的独立接口负责，本次没有改变它的原始码尺度或 16 倍累加定义。

### 9.2 Park 与逆 Park

```text
id =  iα·cosθ + iβ·sinθ
iq = -iα·sinθ + iβ·cosθ

vα = vd·cosθ - vq·sinθ
vβ = vd·sinθ + vq·cosθ
```

θ 必须是与电流样本对齐的电角度，不能直接拿未处理的机械角或固定测试角作为
正式反馈。本次只保留角度接缝，没有实现极对数、电角度零位和时间对齐业务。

## 10. 独立调制模块与 ST 写法的关系

新增 `FOC/Inc/foc_modulation.h`、`FOC/Src/foc_modulation.c`，接口为：

```c
uint8_t FOC_ModulationCompute(
    const foc_modulation_parameters_t *parameters,
    float voltage_limit, float alpha, float beta,
    foc_modulation_output_t *output);
```

返回 1 表示输出有效；非法参数或数值失败返回 0，并保持 `output.valid=0`。
函数没有可变的静态控制状态，可用于独立数值测试。

线性区计算：

```text
va = vα
vb = -vα/2 + √3·vβ/2
vc = -vα/2 - √3·vβ/2
v0 = -(max(va,vb,vc)+min(va,vb,vc))/2
di = 1/2 + vi + v0
```

三相投影在这里用于产生 SVPWM，占空比由注入零序后的结果决定，不是简单把
未注入零序的三相电压直接当成 PWM 输出。

在线性区域、相序/极性/标度相同的条件下，min/max 零序注入与六扇区 T1/T2/T0
表达可以等价。显式扇区不是生成线性 SVPWM 的必要条件，但对采样调度和诊断有用。
最终模块仍输出标准逆时针 `sector=1..6`，通过三相投影排序获得，无需额外 `atan2`。
扇区边界可归相邻区，不能假定编号与所有厂商实现完全一致。

当天用户提供的 ST 风格代码用于比较。该片段带有硬编码周期、直接 CCR 写入、
被注释的 ADC 采样回调，以及正常路径未初始化的返回值，不能直接视为未修改的
ST 官方完整驱动。本次未将片段原样拷入工程，也没有引入 ST 代码中的定点标度。

## 11. 过调制区域与基波补偿

### 11.1 电压定义与区域

αβ 输入和 `voltage_limit` 定义为目标相电压基波峰值除以直流母线电压。
设 `s=duty_max-duty_min`：

| 区域 | 目标基波范围 | 实现 |
| --- | --- | --- |
| 线性 | `0..s/√3` | min/max 零序注入 |
| OVM1 | `s/√3..0.6056966996s` | 参考轨迹超出六边形时径向投影 |
| OVM2 | `0.6056966996s..2s/π` | 逐步展开相邻矢量的驻留时间差 |
| 六步极限 | `2s/π` | 六个有效矢量轨迹，换相点保留等时间混合 |

OVM1 发生 `T1+T2>1` 时，令 `T1'=T1/(T1+T2)`、`T2'=T2/(T1+T2)`，零矢量时间
为 0。等价于按三相投影最大最小差值缩放，保留方向，避免盲目逐相截断。

OVM2 使用中间相占空比 q：

```text
q' = clamp(0.5 + (q-0.5)/(1-h), 0, 1)
```

h 从 0 增加到 1，混合区逐步收窄至六步。h=1 单独处理，避免除以零；换相点
允许相邻矢量等时间混合。此处六步是三相两电平逆变器的六个有效矢量，不是
某一相悬空的梯形 BLDC 换相方案。

### 11.2 查表与生成工具

新增 `FOC/Tools/generate_modulation_lut.py`，使用独立扇区驻留时间参考公式和
Simpson 积分生成基波增益表。OVM1 表 65 项，OVM2 表 129 项，积分分段数 8192。
结果存入 `FOC/Src/foc_modulation_lut.h`。

表以调制参数均匀取点、基波严格递增存放，实时路径二分查找并线性插值，求
达到目标基波所需的调制参数。实时路径没有数值积分、堆分配或额外 `atan2`。
这是本实现的驻留时间展开参数，不能把 ST SDK 的另一套保持角参数直接套入。

增益表对应恒幅匀速旋转输入；快速瞬态不能用“本周期幅值等于目标基波”来解释。
`--check` 会从参考公式重新计算，并核对已提交表头，防止手工改表后缺少追踪。

### 11.3 实际电压与基波目标分开

最终输出由真实 duty 重构每 PWM 周期平均电压：

```text
vα = (2da-db-dc)/3
vβ = (db-dc)/√3
```

`alpha_voltage/beta_voltage` 和转换后的 `d_voltage/q_voltage` 表达这一实际周期
输出，包含过调制的低次谐波。`fundamental_d_voltage/fundamental_q_voltage`
单独表达限幅后的目标基波。不能拿后者冒充当前周期实际电压。

`modulation_region` 表示工作区域，`sector` 提供扇区，`valid` 表示有效性。
独立调制结果中的 `limited` 表示请求超过配置/硬件基波能力；FOC 的 `saturated`
则在限幅或进入 OVM 时置位，二者含义并不完全相同。

## 12. PI 限幅与条件积分抗饱和

原 PI 把积分边界同时作为输出边界，容易把积分器能力与逆变器电压能力混为一谈。
最终保留 `integral_min/integral_max` 对积分状态的限制，移除这对边界对 PI 总输出
的重复钳位；实际输出能力交给调制器。

计算过程：

1. 保存 d/q 旧积分，计算本周期候选积分及 PI 电压请求。
2. 调制器按模式、配置限幅和占空比跨度限制目标基波。
3. 将限制后的基波回到 dq，得到请求与能力的差值。
4. 若积分增量与超限方向的内积为正，撤销本次 d/q 积分增量，并重新调制。
5. 若积分是在向饱和区内退回，允许其更新；积分自身的边界仍有效。

这里采用基波能力判断，不把每周期实际电压中的畸变全部反馈去抵消，否则会
破坏过调制需要的非正弦电压。当前策略是成对撤销 d/q 本次增量，没有实现更复杂
的电流环解耦、弱磁优先级或转矩优先分配。

参数有限性、周期、积分边界、电流限幅和调制配置检查失败时，算法复位输出并
使 `output.valid=0`，控制器随后停环，不继续下发旧的有效标志。

## 13. 电压利用率的单位与当天结论修正

### 13.1 理想全范围比较

三相两电平逆变器的相电压基波峰值与线电压基波 RMS 是不同量：

| 方式 | 相电压基波峰值/Vdc | 线电压基波 RMS/Vdc |
| --- | --- | --- |
| 线性正弦 PWM | `0.5` | 约 `0.61237` |
| 线性 SVPWM | `1/√3≈0.57735` | `1/√2≈0.70711` |
| 六步极限 | `2/π≈0.63662` | 约 `0.77970` |

这里比较的 RMS 只指基波，不是包含所有谐波的总有效值。当前只采两路电流，
电机仍为三相功率输出，不能将“两相采样”理解为两个独立 H 桥。

### 13.2 不能重复计算的增益

当天讨论中曾把六边形顶点 `2Vdc/3` 与圆形边界 `Vdc/√3` 的瞬时比值，误表述为
还可以提高 15.47% 的正弦基波利用率。最终已纠正：

- 线性 SVPWM 相比普通线性 SPWM 的最大正弦基波提高约 15.47%。
- 从最大线性 SVPWM 进入六步极限，基波再提高约 10.2658%。
- `2Vdc/3` 是有效矢量顶点的瞬时幅值，不等于六步基波峰值。
- 六边形内瞬时指令可线性合成，不意味着恒幅旋转矢量超过内切圆后仍可无畸变运行。

### 13.3 当前板级不是理想全范围

板级必须为低侧电流采样留窗口。当前最大基波约为 `0.45245475Vdc`，对应的
线电压基波 RMS 约为 `0.55414166Vdc`。前者是相电压峰值、后者是线电压 RMS，
不能放在同一列当作同一指标比较。

该上限来自本实现的统一占空比跨度策略和预留时间，不是所有可能采样、预测、
电流重构或 PWM 脉冲调整策略的绝对最优证明。

## 14. 保留 16 倍过采样的硬件约束

### 14.1 保持不变的参数

| 项目 | 值 |
| --- | --- |
| ADC 时钟 | 42 MHz |
| 分辨率 | 12 bit |
| 单次采样与转换 | `2.5+12.5=15` 个 ADC 周期 |
| 硬件过采样 | 16 倍，`ADC_RIGHTBITSHIFT_NONE` |
| 注入通道 | rank 1：U；rank 2：V |
| 单通道 16 倍耗时 | 约 5.714 µs |
| 完整两路序列耗时 | 约 11.428 µs |
| 原始数据 | 右对齐累加码，约 `0..65520` |
| 第三相电流 | 由 `iw=-(iu+iv)` 推导 |

本轮只改变采样触发安排，不修改硬件过采样倍率、ADC 采样档位、两路顺序、
原始码换算、零点数值空间或 S16 反馈尺度。

低侧分流器需要相应下管导通才有可用电流。U/V 传感器位置固定，软件不能凭借
扇区判断凭空获得 W 相独立测量。两路顺序过采样之间约 5.714 µs 的时间偏差仍然
存在，本次没有把它变成同步双 ADC 采样。

### 14.2 为什么只移动时刻没有显著电压增益

以原来的对称公共窗口为例，若序列已经以峰值附近的稳定低侧窗口为中心，向前
或向后移动不会增加下管导通时间。完整序列长度不变，高占空比端总会遇到窗口
放不下的问题。

因此，最终实现的收益是明确每个周期的有效起点、在低调制比时更早完成转换、
避免 W 边沿干扰和发现不可行输出，而不是宣称电压能力从 `0.452` 跳到 `0.637`。
此前关于“只移动采样点就能显著提高利用率”的口头表述过于乐观，不能作为最终
设计结论。本记录以代码和测试结果为准。

## 15. 动态采样规划器

### 15.1 模型与坐标

新增 `Modules/Three_Phase_Driver/Inc/pwm_sampling.h` 和对应 `.c`。
以谷值 `CNT=0`、向上计数为时间原点。令 `P=ARR`，完整轨迹为 `0→P→0`，
时间坐标跨度为 `2P`。只允许在向上计数阶段产生触发，因此 `1≤trigger≤P-1`。

规划器输入为峰值 P、完整序列 S、保护间隔 G 和下一组三相比较值。假设 PWM1
高侧占空比随 CCR 增大，U/V 公共低侧稳定区间为：

```text
C = max(CCR_U, CCR_V)
窗口 = [C+G, 2P-C-G]
可行起点 = [C+G, 2P-C-G-S] ∩ [1,P-1]
```

这里保守要求整个序列处于稳定区，包括 SAR 转换时间。实际采样保持电路的
精细孔径可能允许其他优化，但本次没有用未经实测的孔径假设放宽上限。

### 15.2 排除 W 边沿与选点

W 不参与电流测量，但其开关可能干扰运放，因此也检查 W 的两个边沿：

```text
edge1 = CCR_W
edge2 = 2P-CCR_W
```

对每个边沿，允许完整序列在其保护区前结束，或在保护区后开始；最多两个边沿
把可行起点分为最多三段。W 为静态电平时不制造不存在的开关边沿；CCR=ARR
仍按峰值处的极窄切换保守处理。

优先起点是 `P-S`，即完整序列在载波峰值完成。若不在可行集合中，选与其最近
的有效点。不是所有调制比都固定强行使用这个起点。

该过程只有有界的小循环，不在中断中做逐 tick 穷举。穷举只用于主机验证。

| 最小高侧 CCR | 85 | 1 µs 最小脉宽及取整约定 |
| 统一最大 CCR | 3070 | `P-G-ceil(S/2)` |

## 16. TIM1/ADC 硬件接线与提交时序

### 16.1 触发路径

最终明确配置为：

```text
TIM1 CH4 PWM2 的 OC4REF
  → TIM_TRGO2_OC4REF
  → ADC_EXTERNALTRIGINJEC_T1_TRGO2
  → 上升沿触发完整注入序列
  → ADC JEOS 中断
```

中心对齐时，上数比较点形成一次上升沿，下数比较点形成下降沿。选择 REF
上升沿用于每完整载波周期触发一次；不能把直接 CC4 比较事件和 REF 电平边沿
当成同一概念。原来无业务的 CC4 中断已禁用，保留向量入口不意味着继续从它
调度 FOC。

RCR=1 在计数器启动前配置，按当前 RM0440 的语义更新位于谷值；载波峰值
`CNT=ARR` 不能再被称作该配置下的周期更新事件。

### 16.2 CCR1..4 同批预装载

`Tim1Pwm_SetPhaseVoltage()` 的步骤是：

1. 检查三相输入均为有限的 `0..1`。
2. 直接把浮点 duty 量化为 CCR，避免中间的 1000 级量化。
3. 用这组 CCR 规划下一周期 ADC 触发点；没有窗口则拒绝，不写新三相输出。
4. 在短临界区中检查距离谷值更新的提交余量。
5. 暂置 `UDIS`，连续写入 CCR1、CCR2、CCR3、CCR4，完成后恢复。
6. 检查是否跨过截止点或余量不足；异常时返回失败并走停环/关断链路。
7. 更新调试状态和指令占空比影子值。

CCR1..4 都使用预装载，运行中不发 UG，避免重置重复计数器和打乱载波相位。
`TIM1_PWM_COMMIT_GUARD_NS=2000` 是软件提交保护参数，不能等同于已完成 WCET
测量或硬件截止检测认证。

`Tim1Pwm_ConfigureCurrentSampling()` 只供 ADC 尚未启动且 MOE=0 的初始化阶段
调用。旧的整数 PWM 测试接口保留原有用途，不承诺其任意波形都能满足 FOC
电流采样要求，不能与正常 FOC 同时争用输出。

### 16.3 载波计数约定

工程目标频率为 20 kHz，现有宏得到 ARR=4199，占空比映射仍使用 `ARR+1=4200`。
动态时间坐标使用 `2×ARR=8398` 个时钟，故该模型的周期约 49.988095 µs。
这是时间轨迹与既有占空比标度的不同约定，本次没有顺带重写整套 ARR/频率宏。
绝对 PWM 频率和端点占空比仍应以定时器规则及波形实测复核。

### 16.4 CubeMX 工程边界

当前 `.ioc` 并未完整维护 TIM1/ADC1，相关初始化仍是现有手工 L1 源码。
本次没有虚构一份缺少引脚/资源配置的 IOC 变更。后续不能用该 IOC 重新生成后
直接覆盖运行配置；应先把真实硬件配置补齐并复核所有 USER CODE 接缝。

## 17. 动态采样间隔与实时调用链

当 CCR4 逐周期变化时，采样数据不再严格每 50 µs 到来。应用在本次 ADC 回调里，
写下一组 PWM 之前读取当前触发位置，计算：

```text
Δt = (2P + 当前trigger - 上次trigger) / TIM1时钟
```

当前连续样本调用 `Tim1Pwm_OnCurrentSample(sample_sequence)` 更新
`algorithm.parameters.sample_period_s`。算法优先使用该实际周期；未提供时才回退
到名义 `pwm_period_s`。校准暂停回调后，首个周期重新按名义周期起算，避免沿用
旧的触发点差值。

这不是 ADC 中断入口延时或处理耗时的测量；也不能依靠原始样本计数自动发现
所有可能丢失的硬件触发。未来角度快照应和这些实际采样时刻对齐。

最终实时调用链为：

```text
TIM1 TRGO2/OC4REF 上升沿
 → ADC1 U/V 16倍注入序列
 → ADC1_2_IRQHandler → HAL_ADC_IRQHandler
 → HAL_ADCEx_InjectedConvCpltCallback
 → 发布 raw_u/raw_v、sample_sequence
 → MainFoc_OnAdcConversion
 → 记录当前采样周期
 → FOC_ControllerStep
 → 端口检查、驱动安全检查、有效反馈读取
 → FOC_AlgorithmStep
 → Clarke/Park → PI → 逆Park → FOC_ModulationCompute
 → MainFoc_WriteVoltage
 → Tim1Pwm_SetPhaseVoltage → PwmSampling_Plan
 → CCR1..4 同批预装载
 → feedback_ready=1
```

校准 SETTLING/COLLECTING 阶段不调用正常 FOC 回调，但仍收集 ADC 原始码。
后台则按原应用调度驱动监控、校准服务和 `ServoManager_Service()`。

### 19.2 采样规划测试

### 20.2 运行能力边界

1. 正式电角度快照、极对数、电角度零位和同步链路尚未接入，`angle_valid` 保持 0。
2. 当前零电流给定与默认 PI 参数不代表实机转矩闭环已经整定。
3. 母线电压采样/动态归一化没有新增；PI 仍直接输出标幺电压。
4. 运放建立时间、模拟噪声、死区实际波形和电流相序没有在本轮重新实测。
5. 16 倍序列仍约 11.43 µs，保守统一范围下没有获得显著电压利用率增益。
6. 上板需验证动态触发后角度对齐、顺序 U/V 时间偏差和采样噪声变化。
7. ADC 停止/漏触发、回调停止但 MOE 保持的超时保护尚未形成完整闭环；本轮不能宣称所有采集失效都已覆盖。
8. ISR 和后台共享状态的全部并发交错没有穷举，`pending_faults` 等发布/消费接口仍需进一步审查。
9. `feedback_ready` 发布与预装载生效、首次 MOE 放行的硬件时序尚未做波形验证。
10. 软件提交保护有逻辑检查，但没有测量完整 ISR 的最坏执行时间和所有异常上下文。
11. TIM1 Break 输入配置没有在本轮改成硬件联锁；仍沿用既有驱动保护与软件安全接口。
12. CAN/UART 故障协议、参数保存、外部控制命令和量产恢复策略没有在本轮完成。

准备交付前核对 `origin/main` 与本地基线一致；提交后使用普通 fast-forward
push。若远程同时出现新提交，应重新获取并处理分叉，不能用 force push 跳过。

核对某个实际交付版本：

```powershell
git log -1 --oneline
git show --stat HEAD
git ls-remote origin refs/heads/main
git status --short
```

最后一个命令仍可能列出本地编译产物或 IDE 私人设置；这不等于今天的业务源码
没有提交。应以提交文件清单和远程 SHA 判断交付，而不是通过删除本地文件强行
让工作区变空。
