## 1. 结构体总览

## 2. `encoder_snapshot_t` — 公告板（最重要）

```c
typedef struct
{
  uint32_t raw_angle;
  int64_t multi_turn_count;
  float mechanical_angle_rad;
  float mechanical_speed_rad_s;
  float electrical_angle_rad;
  uint32_t sample_cycle;
  uint32_t sequence;
  encoder_fault_flags_t fault_flags;   /* = uint32_t */
  uint8_t status_raw;
  uint8_t angle_valid;
  uint8_t speed_valid;
  uint8_t electrical_angle_valid;
} encoder_snapshot_t;
```

### 逐字段说明

| 字段 | 类型 | 含义 | 取值范围 / 单位 | 备注 |
|---|---|---|---|---|
| `raw_angle` | u32 | 传感器原始 21 位角度码 | 0 ~ 2^21-1 (2097151) | 未做方向翻转的裸值 |
| `multi_turn_count` | **i64** | 累计多圈计数（带方向的圈数积分） | 无界 | 速度估算用它差分，不是用 `raw_angle` |
| `mechanical_angle_rad` | float | 机械角度 | 0 ~ 2π rad | = `directed_raw × (2π/2^21)`；direction<0 时做了镜像翻转 |
| `mechanical_speed_rad_s` | float | 滤波后机械转速 | rad/s | 窗口差分 + 一阶低通，见 §2.2 |
| `electrical_angle_rad` | float | **电角度**（FOC 实际用的量） | -π ~ π rad | = `pole_pairs × mechanical_angle + electrical_offset`，再取模 2π |
| `sample_cycle` | u32 | 采样时刻的 DWT 周期计数 | — | **取的是"DMA 启动时刻"（谷值 UEV），不是回调完成时刻** |
| `sequence` | u32 | 发布序号，每次成功发布 +1 | — | 上层可据此判断"有没有新数据" |
| `fault_flags` | u32 | 故障标志位（按位） | 见 §7 表 | 可为多位置位（如 STALE 是读取时补加的） |
| `status_raw` | u8 | 传感器原始 STATUS[2:0] | 0~7 | 与角度同帧锁存，不会错位 |
| `angle_valid` | u8 | 角度有效位 | 0/1 | 为 0 时 FOC 拿不到角度 → 停机关 MOE |
| `speed_valid` | u8 | 转速有效位 | 0/1 | 速度窗口未满 20 点时为 0 |
| `electrical_angle_valid` | u8 | 电角度有效位 | 0/1 | `Encoder_ConfigureMotor()` 成功前恒为 0 |

### 2.1 时间戳为什么取"启动时刻"

`Encoder_PublishFrame(&frame, transfer_start_cycle)`（encoder.c:326 调用处）传入的是
**本次 DMA 启动那一刻**的周期计数。原因：角度在 CSN 下降沿（= 启动时刻 = TIM1 谷值）就被
传感器锁存，它代表的是那一刻的转子位置。若用回调完成时刻，FOC 侧算出的"数据龄期"会
少掉片选到解析之间的传输及软件耗时，掩盖真实的控制延迟；该耗时会随分频变化。

**直接后果**：FOC 在 t≈25 µs（载波峰值、ADC 序列完成）读取时，拿到的是 t=0（谷值）的角度，
固有滞后约 25 µs = 半个控制周期。诊断量 `foc_sample_age_cycles_max` 就是量这个的。

### 2.2 速度是怎么算出来的（`Encoder_UpdateSpeed`，encoder.c:144-190）

```
speed_history[20] 环形窗口，每点存 {position(i64), cycle(u32)}

窗口未满 20 点：只存不算 → mechanical_speed = 0, speed_valid = 0
窗口已满：
    oldest = history[head]（即将被覆盖的最老点）
    覆盖写入当前点，head 前进
    dt        = (sample_cycle - oldest.cycle) / 168e6        ← 窗口跨度
    raw_speed = (position - oldest.position) × (2π/2^21) / dt
    update_dt = (sample_cycle - last_speed_cycle) / 168e6    ← 更新间隔（≠窗口跨度）
    alpha     = update_dt / (0.010 + update_dt)              ← τ = 10 ms
    filtered += alpha × (raw_speed - filtered)
    speed_valid = 1
```

**关键设计**：差分窗口（20 点 ≈ 1 ms）与滤波更新间隔是**两个不同的时间尺度**
（encoder.c:175 注释明说）。窗口差分抗单帧噪声，一阶低通（τ=10 ms）再平滑。

**代价**：τ=10 ms 意味着速度反馈有约 10 ms 的响应延迟，整定速度环带宽时必须计入。

**坏帧保护**：CRC/报警/步长错误时**不更新** `previous_raw_angle` 与多圈历史
（encoder.c:250 附近注释），短间隔恢复时用真实 Δt 计算，超过消歧间隔则重新锚定并撤销
多圈连续性——保证单帧坏数据不会污染后续所有速度计算。

## 3. `encoder_diagnostics_t` — 账本（诊断专用）

全部字段均为 `uint32_t`。按用途分三组。

### 3.1 计数类

| 字段 | 含义 | 健康值 | 异常时说明什么 |
|---|---|---|---|
| `trigger_count` | TIM1 周期中断触发次数 | ≈20000/s 递增 | 不涨 = 定时器/中断没跑 |
| `completed_count` | 成功发布的帧数 | ≈trigger_count | 与 trigger 差距大 = 大量帧被闸门拦下 |
| `busy_trigger_count` | 触发时上一帧仍未完成 | **必须为 0** | 涨 = 事务超 50 µs，正在丢帧 |
| `start_error_count` | DMA 启动失败次数 | 0 | 涨 = 快路径与 HAL 路径都失败 |
| `transfer_error_count` | 传输失败（含超时 abort） | 0 | 涨 = 看 `last_busy_spi_sr` |
| `crc_error_count` | CRC 校验失败次数 | 0 | 涨 = 见 §8 排查链 |
| `alarm_count` | 传感器报警次数 | 0 | 涨 = 看 `last_alarm.status` 的具体位 |
| `angle_step_error_count` | 角度跳变不合理次数 | 0 | 涨 = 数据被破坏（CRC 过也不代表数据真值） |
| `foc_reads_while_busy` | FOC 读取时传输仍忙 | 少量正常 | 大量 = 传输耗时逼近周期 |
| `foc_deadline_overrun_count` | FOC ISR 耗时 ≥50 µs 的次数 | 0 | 判据是 `cycles >= 8400`（encoder.c:567） |
| `spi_resync_count` | SPI 复位恢复**成功**次数 | 0 | 每帧都涨 ≈ 20000/s = 确定性判据错误 |
| `spi_resync_refused_count` | 恢复被守卫**拒绝**次数 | **必须为 0** | 涨 = SPI 坏状态滞留，无法自愈 |

### 3.2 耗时类（单位：cycles，**÷168 = µs**）

| 字段 | 覆盖区间 | 说明 |
|---|---|---|
| `transaction_cycles_latest/min/max` | DMA 启动 → 回调结束 | **你实测的 24 µs 就是这个量**（÷168） |
| `start_cycles_latest/max` | 仅启动 DMA 那段 | 正常 <1 µs |
| `completion_cycles_latest/max` | 完成回调内（解码+五闸门+发布） | **含被抢占前的全部工作**，是 FOC 预算里被偷走的部分 |
| `foc_read_cycles_latest/max` | FOC 读角度那一小段 | 应远小于 1 µs |
| `foc_sample_age_cycles_latest/max` | 快照龄期（FOC 入口时刻 − sample_cycle） | **÷168 = 角度滞后 µs，高速问题必看** |
| `foc_isr_cycles_latest/max` | 完整 ADC ISR（含 FOC 全部计算） | 由 `Encoder_RecordFocIsrCycles()` 写入 |
| `spi_resync_cycles_latest/max` | 一次 RCC 复位恢复的耗时 | 这段在关中断临界区内，直接偷 FOC 时间 |

### 3.3 间隔类

| 字段 | 含义 | 健康值 |
|---|---|---|
| `trigger_interval_latest/min/max` | 相邻两次触发的周期间隔 | **恒为 8400**（50 µs）；出现 **16800 = 跳了一整帧** |
| `last_busy_cycle` | 最近一次 busy 触发的时刻 | 配合 `busy_trigger_count` 定位 |
| `last_busy_spi_sr` | 那一刻的 `SPI1->SR` 快照 | 看 BSY/OVR/MODF 位判断卡在哪 |

## 4. `encoder_fault_frame_t` — 单次故障现场

```c
typedef struct {
  uint32_t cycle, reason, previous_angle, spi_status, previous_cycle;
  uint8_t rx[6], computed_crc, status;
} encoder_fault_frame_t;
```

| 字段 | 含义 | 排查用途 |
|---|---|---|
| `cycle` | 故障时刻 DWT 计数 | ÷168 = µs；与 `previous_cycle` 相减 = 两帧实际间隔 |
| `reason` | 触发的是哪道闸门 | 取值即 §7 的故障位：`1`通讯 / `2`CRC / `4`报警 / `32`步长。**注意 `8`(STALE) 与 `16`(未配置) 不进本结构** |
| `previous_angle` | 上一帧**已通过校验**的原始角度 | 与当前帧角度反算真实步长，区分"真跳变"与"多圈回绕误判" |
| `spi_status` | 故障时 `SPI1->SR` 完整快照 | `BSY=1` 传输未完；`OVR=1` 接收溢出；`MODF`/`CRCERR` 一眼可查 |
| `previous_cycle` | 上一份有效快照的 `sample_cycle` | 正常差值 ≈8400；远超说明中间跳帧 |
| `rx[6]` | DMA 实际收到的原始 6 字节 | **全 0xFF = MISO 未被驱动**（mt6835.h:117-118 已注明），属硬件/接线问题 |
| `computed_crc` | 本地重算的 CRC-8 | 与 `rx[5]` 比对：相等 = 传感器数据完整、公式无误 |
| `status` | `rx[4] & 0x07`，即 STATUS[2:0] | reason=4 时指明具体报警；reason≠4 而它为 0 = 传感器自认正常 |

### 4.1 `rx[6]` 各字节的物理含义

一次事务是 48 SCK 的 burst angle read（mt6835.c:144-146），CSN 全程保持低：

| 索引 | 内容 | 说明 |
|---|---|---|
| `rx[0]` | `0xA0` 回显 | 命令高字节（1010 + 地址高位） |
| `rx[1]` | `0x03` 回显 | 命令低字节（地址 0x003） |
| `rx[2]` | 寄存器 0x003 | ANGLE[20:13] |
| `rx[3]` | 寄存器 0x004 | ANGLE[12:5] |
| `rx[4]` | 寄存器 0x005 | ANGLE[4:0]<<3 \| STATUS[2:0] |
| `rx[5]` | 寄存器 0x006 | 传感器算出的 CRC |

CRC 覆盖的 24 位是 `(rx[2]<<16) | (rx[3]<<8) | rx[4]`（encoder.c:59-60），
多项式 0x07，**初值代码取 0x00**。

> ⚠ **已知未验证假设**（mt6835.h:80-81 原文）：手册未给出 CRC 寄存器初值，代码按常规取
> 0x00；注释明确写了"若实测校验恒不通过，优先尝试把初值改为 0xFF 再验证"。
> 项目内的手册提取件 `tmp/file-read/MT6835.md` 中确实只有寄存器地址说明，**没有初值**。

### 4.2 `Encoder_CaptureFault()` 的记录规则（encoder.c:50-68）

```
count == 0            → 写入 first（首次现场永久冻结，不滚动）
reason == 传感器报警   → 额外写入 last_alarm
任何情况              → 覆盖 last；写入 recent[count & 7]（8 槽环形）；count++
```

`recent[8]` 的用途：判断"是偶发一次还是连续同一种错"——8 个槽全是同一个 reason，
基本可确认是确定性问题而非随机干扰。

## 5. `encoder_fault_capture_t` — 故障现场容器

```c
typedef struct {
  uint32_t count;
  encoder_fault_frame_t first, last, recent[8], last_alarm;
} encoder_fault_capture_t;
```

| 字段 | 用途 |
|---|---|
| `count` | 累计故障次数（也是 `recent[]` 的写入索引来源） |
| `first` | **第一次**故障的完整现场（冻结不变） |
| `last` | **最近一次**故障现场 ← 排查从这读起 |
| `recent[8]` | 最近 8 次环形缓冲 |
| `last_alarm` | 最近一次 `SENSOR_ALARM` 的现场（专门留一条，因为报警信息最易被 CRC 闸门遮蔽） |

## 6. `encoder_context_t` — 模块私有状态（static，不对外）

```c
typedef struct {
  encoder_speed_point_t speed_history[20];   /* {int64 position; uint32 cycle;} */
  uint8_t tx[6];                             /* 预构建的读角度命令，DMA 直接访问 */
  uint8_t rx[6];                             /* DMA 接收缓冲，故障捕获从这里拷 */
  uint8_t history_head, history_count;
  volatile uint8_t initialized;
  volatile uint8_t transfer_busy;            /* 串行保护：一帧未完不启下一帧 */
  uint8_t have_previous_angle;               /* 多圈解包的前提 */
  volatile uint8_t motor_configured;
  volatile int8_t direction;                 /* 只能 +1 / -1 */
  volatile uint16_t pole_pairs;              /* 必须 > 0 */
  volatile float electrical_offset_rad;      /* 标定过的电角零位 */
  uint32_t previous_raw_angle;
  int64_t multi_turn_count;
  float filtered_speed_rad_s;                /* 低通滤波器的状态（跨帧保留） */
  uint32_t last_speed_cycle;
  volatile uint32_t transfer_start_cycle;    /* 快照时间戳的来源 */
  uint32_t max_counts_per_256_cycles;        /* 步长合理性阈值，Init 时算好 */
  uint32_t previous_trigger_cycle;
} encoder_context_t;
```

**`max_counts_per_256_cycles` 的来历**（`Encoder_Init` 内）：

```
= (2^21 × 12000rpm ÷ 60 × 256) / 168e6 + 1  ≈ 640
```

步长合理性判据（`encoder_frame_guard.h`）：

```
allowed = (interval_cycles × max_counts_per_256_cycles) >> 8 + 256
```

按此式核算各转速下的余量（interval = 8400 cycles）：

| 转速 | 每帧实际步长 | 允许值 | 余量 |
|---|---|---|---|
| 8500 rpm（命令上限 `SPEED_RUN_MAX_RPM`） | 14855 | 21256 | 43% |
| 9072 rpm（跳闸点 `SPEED_RUN_OVERSPEED_RAD_S`=950 rad/s） | 15854 | 21256 | 34% |
| 12000 rpm（包络定义点 `ENCODER_PLAUSIBILITY_MAX_RPM`） | 20972 | 21256 | 1.35% |

**结论**：正常转速范围内该判据不会误触发。若 `reason=32` 出现，说明**数据被破坏了**，
不是转速超限（encoder.c:330 注释已明说"CRC8 alone can accept a corrupt payload"）。

**丢帧自动放宽**：`interval_cycles` 取的是 `transfer_start_cycle − snapshot.sample_cycle`，
未成功发布时时间戳不前进，间隔翻倍 → 允许值翻倍。所以偶发丢帧不会引发步长误判。

## 7. 两组位定义对照

### 7.1 `encoder_fault_flags_t`（encoder.h:14-20）— 软件判据

| 宏 | 值 | 触发位置 | 容错策略 |
|---|---|---|---|
| `ENCODER_FAULT_NONE` | 0 | — | — |
| `ENCODER_FAULT_COMMUNICATION` | 1<<0 | 闸门① DMA 失败 / 超时 abort | 立即发布无效 |
| `ENCODER_FAULT_CRC` | 1<<1 | 闸门③ `crc_ok==0` | **3 周期宽限**（150 µs 内保留旧角度） |
| `ENCODER_FAULT_SENSOR_ALARM` | 1<<2 | 闸门④ `status & 0x07 != 0` | **零宽限**，单帧即失效 |
| `ENCODER_FAULT_STALE` | 1<<3 | 读取时龄期 >150 µs | 三个 valid 位全清零 |
| `ENCODER_FAULT_NOT_CONFIGURED` | 1<<4 | 未调 `ConfigureMotor()` | 电角度恒无效 |
| `ENCODER_FAULT_IMPLAUSIBLE` | 1<<5 | 闸门⑤ 步长超包络 | 3 周期宽限 |

> **闸门顺序即优先级**：CRC(③) 排在报警(④) 之前。**CRC 恒错时永远看不到报警位**，
> 即使传感器完全正常——这是排查时最误导人的地方。

### 7.2 `mt6835_status_t`（mt6835.h:62-66）— 传感器自报

| 宏 | 位 | 含义 | 高速相关性 |
|---|---|---|---|
| `MT6835_STATUS_OVERSPEED` | bit0 | 转速 > **120000 rpm** | 无（工程上限 8500 rpm，可排除） |
| `MT6835_STATUS_WEAK_FIELD` | bit1 | 外加磁场太弱 | **高**（振动 / 气隙变化） |
| `MT6835_STATUS_UNDERVOLTAGE` | bit2 | 芯片供电欠压 | **高**（大电流拉垮电源） |

## 8. 换算关系与排查速查

### 8.1 单位换算

```
SystemCoreClock = 168 MHz
cycles ÷ 168      = µs
cycles ÷ 168e6    = 秒
8400 cycles       = 50 µs  = 一个控制周期（20 kHz）
16800 cycles      = 100 µs = 跳了一帧
```

### 8.2 关键时间预算

| 项 | 值 | 占 50 µs |
|---|---|---|
| SPI 线上（48 SCK ÷ **10.5 MHz**，当前源码） | 4.571 µs（理论） | 9.1% |
| 旧 /64 档 SPI 线上（48 SCK ÷ 2.625 MHz） | 18.286 µs（理论） | 36.6% |
| 启动 + DMA 中断 + 解码/五闸门/发布 | 需按当前固件重新测量 | — |
| **事务总宽（PA0 完整事务探针）** | **包括软件开销，不能用纯时钟时间代替** | — |
| 角度固有滞后（谷值锁存 → 峰值使用） | ≈25 µs | 50% |

> 2026-10-22 按用户要求将硬件 SPI 改为 **16 分频 = 10.5 MHz**，并将 MSP 中
> PA5/PA6/PA7 的 GPIO 速率改为 **VERY_HIGH**。纯时钟窗口由 18.286 µs 缩为
> 4.571 µs；VERY_HIGH 影响 MCU 驱动的 SCK/MOSI 边沿，不会改变传感器的 MISO
> 输出驱动。MISO 保持 NOPULL，未因“非输出时高阻”而推定其为开漏输出。
> 这是缩短通信窗口的优化，不能仅凭分频变化宣称 EMI 或启动 CRC 已修复。
> CRC 校验、报警检查、角度步长检查及原有 150 µs 有效期均保留；实机结果见
> `software/control_analysis/results/crc_spi16_*`，最高转速需要单独验收。

### 8.3 排查顺序（缩小范围，不单凭计数器断言根因）

```
① g_encoder_fault_capture.last.reason
   ├─ 1  COMMUNICATION → 查 start_error_count / last_busy_spi_sr
   ├─ 2  CRC           → 转 ②
   ├─ 4  SENSOR_ALARM  → 查 last_alarm.status 的 bit1/bit2（振动 or 欠压）
   └─ 32 IMPLAUSIBLE   → 数据被破坏（非转速超限），本质仍是信号完整性

② CRC 错时看 last.rx[0..5]
   ├─ 全 0xFF                       → 核查 MISO 高阻/接线、CS/SCK 及供电，不能只凭字节定因
   ├─ 有数据，computed_crc != rx[5] → 对照固件与独立离线重算，再核查通信时序/信号完整性
   │      静止大量帧已通过 CRC 时，不应因少数坏帧而改 CRC 初值或掩掉低位
   │      CRC XOR 可记录失配特征，但不能唯一反推受干扰的数据位
   └─ status == 0 却 CRC 错         → 整帧未通过校验，STATUS 同样不能当作可信报警结论

③ 看速率型诊断
   spi_resync_count ≈ 每帧都涨  → 坏帧持续存在，需区分格式/时序/信号问题，不证明 CRC 初值错误
   spi_resync_refused_count 涨  → 恢复被守卫拒绝，SPI 坏状态滞留
   busy_trigger_count 涨        → 事务超 50 µs，丢帧连锁

④ 看物理量
   foc_sample_age_cycles_max ÷168 → 角度滞后是否随转速拉大
   trigger_interval_max == 16800  → 确认有整帧被跳过
```

### 8.4 容错设计的一处不对称（值得注意）

- CRC 闸门：3 周期（150 µs）宽限，靠 `ENCODER_MAX_SAMPLE_AGE_CYCLES = 3`
- 报警闸门：**零宽限**，单次 STATUS 命中即 `PublishInvalid`

高速下振动导致的一次瞬时 `weak_field` 位，就足以触发一次锁存停机。
若 `reason` 读出为 4，应先确认 CRC 有效的报警帧及对应磁场/供电条件。
单次报警导致停机是现有安全策略，不能据此排除硬件问题；是否允许连续 N 次才停机，
需要另行评估欠压、弱磁时反馈不可信的风险，本次不放宽。

### 8.5 一个已记录的恢复手段局限

`spi1_encoder.c:331-333` 注释原文记录：SPE off/on 单独不足以恢复捕获到的持续坏帧状态，
**RCC SPI1 复位有效，但验证条件是"电机 PWM OFF"**，且未复位传感器。

2026-10-22 的 `/16 + VERY_HIGH` 实际使能测试中，恢复路径仍未阻止反馈过期保护停机。
因此不能把“电机 PWM OFF 时复位有效”外推成带电运行时一定恢复，也不能用更多重试
替代对通信时序、信号完整性及供电的核查。

### 8.6 独立的编码器观测/开环拖转调试（kind=8）

该模式是**电角度开环、真实 ADC 电流闭环**，不是速度闭环，也不是把坏编码器帧标为有效。
`Encoder_TransferComplete()`、CRC 校验、故障捕获、恢复及 150 µs 有效期全部不变；
编码器照常采集、计数和报错，仅 `kind=8` 的换相角度与给定不依赖编码器。
正常 `g_speed_run.enable=1` 仍启动 `kind=7`，保持原有反馈失效停机策略。

默认设置与硬限制：

| 项 | 设置/行为 |
|---|---|
| 入口 | `g_speed_test.command=4`，只在输出关闭、无运行/控制器故障时接受 |
| 默认电流给定 | 旋转坐标系 `Id=0.10 A`、`Iq=0`，以 0.20 A/s 斜坡进入 |
| 电角度 | 首先固定 250 ms，再按不超过 1 Hz/s 的斜坡升到 0.50 Hz |
| 自定义上限 | 电角频率 1 Hz，电流给定及电流环参考限幅 0.30 A，最长 5 s |
| 电压限幅 | 0.01 pu（相对于配置母线电压），PI 积分边界同步收紧 |
| 采样过流 | 任意相绝对值超过 0.80 A 关闭输出；不受 kind=7 的过流旁路宏影响 |
| 其他停机条件 | 驱动器 READY/nFAULT、ADC/算法无效、采样间隔超过 500 µs、人工停止及超时 |

后台同时监视调试 ADC 心跳：首次回调等待超过 200 ms 或运行中回调间隔超过 500 µs 时结束
调试并请求关闭输出，避免 ADC 回调停止后其内部时限检查也停止。该检查依赖主循环继续执行，
不能替代硬件保护或在 CPU 被调试器暂停时提供关断保证。

这里的 0.30 A 是**参考限幅**，不保证任意瞬态实际电流均小于该值；0.80 A 是独立的采样
过流阈值。电角频率是软件旋转磁场的频率，不是已测得的机械转速；低电流/低电压可能不足
以克服摩擦或负载，不能保证转子跟随。达到时限后关闭功率输出，不代表转子已机械停止。

Keil Watch 操作（固件默认不启动）：

1. 下载并复位后，确认 `g_speed_run.enable=0`、功率输出关闭、ADC 校准完成、
   驱动器正常；当前模式与请求模式均为 `CURRENT_OPEN_LOOP=1`，阶段均为 `DQ_PI=2`。
   若已有运行/控制器故障，先在输出关闭状态处理，不要通过本调试入口强行清除。
2. **只写 `g_speed_test.command=4`**。主循环检查互锁后装载默认参数并请求预充电，
   进入 `active.kind=8`，随后最长运行 5 s；不会自动重试或循环启动。
3. 观察 `g_encoder_diagnostics.crc_error_count`、`g_encoder_fault_capture`、
   `g_speed_test.feedback_fault`/`feedback_age_cycles`。这些仍是实际编码器诊断，
   不会因调试模式而清零或伪装有效。`g_speed_test.angle` 为合成电角度，
   `reference` 为当前合成电角频率（Hz），不应解释为实测速率。
4. 提前停止写 `g_speed_test.command=2`，或令
   `g_global_mode_control.runtime.output_request=0`。正常完成 `state=3`，故障停止 `state=4`；
   状态保留，只有再次明确发启动命令才会运行。运行中不要暂停 CPU 或打断点；
   必须先关闭输出，人工紧急断电不依赖调试器命令。

需要更短或更低给定时，在输出关闭状态设置 `g_speed_test.requested` 后写 `command=1`：
`kind=8`，`duration_s` 为 0.05~5，`amplitude` 为非负 Id 且不超过 `current_limit_a`，
`current_limit_a` 为大于 0 且不超过 0.30，`frequency_hz` 为 0~1，`kp=ki=bias=0`。
其余字段保持 `command=4` 的默认值，禁止修改 `active` 或直接伪造反馈 valid 位。
`command=4` 每次都重新装载固定默认值，不使用这些自定义给定。

若启动被互锁拒绝，`g_speed_test.fault=12`，原因见
`g_encoder_debug_start_block_mask`（位定义复用 `SPEED_START_*`）。输出、驱动器、ADC、模式、
阶段及测试互斥检查均保留；仅不要求编码器就绪或电角度标定。
主机故障注入覆盖编码器六类故障的全部非空组合、NaN 角度/速度、默认 5 s 超时与 DWT 回绕、
电流/频率/时长越界、过流及正常速度闭环回归；它们不替代实机拖转验收。
