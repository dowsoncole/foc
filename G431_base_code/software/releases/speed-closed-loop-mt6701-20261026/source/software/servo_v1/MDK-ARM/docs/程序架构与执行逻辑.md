# 程序架构与执行逻辑

> 依据当前源码整理。目标是快速说明：上电后做什么、控制环由谁触发、什么情况下会驱动电机。

## 1. 一句话概览

程序采用“**主循环管理状态，中断执行实时控制**”的结构：

- 主循环负责校准、模式切换、启停、安全监控和通信；
- TIM1 产生 20 kHz PWM，同时触发 ADC 和编码器采集；
- ADC 采样完成中断是 FOC 电流环的真正入口；
- 只有收到输出请求且所有安全条件满足后，程序才允许打开 MOE 驱动电机。

## 2. 软件分层

| 层级 | 主要目录 | 职责 |
| --- | --- | --- |
| 应用调度 | `Core/Src/main.c` | 上电初始化、模式管理、主循环和各模块连接 |
| 伺服管理 | `Servo/` | 正常模式的启停状态机、故障管理、速度调试 |
| FOC 控制 | `FOC/` | 坐标变换、PI、电压计算、SVPWM 和控制器生命周期 |
| 硬件模块 | `Modules/` | PWM、电流采样、编码器、驱动芯片监控 |
| 测试与观测 | `Tests/` | 电流测试、波形采集和串口上传 |

核心原则：FOC 算法不直接访问硬件，而是通过 `foc_port_t` 回调读取电流/角度、写入 PWM、紧急关断。

## 3. 上电执行顺序

```text
复位
  ↓
HAL、168 MHz 时钟、GPIO
  ↓
I2C3、TIM6、TIM1 初始化
  ├─ TIM1 开始 20 kHz 计数
  └─ MOE 保持关闭，三相功率输出被屏蔽
  ↓
USART1 波形上传模块初始化
  ↓
STSPIN32G4 初始化，清除锁存故障，启动 1 s 监控心跳
  ↓
OPAMP1/3、ADC1、电流采样、FOC、Servo Manager 初始化
  ↓
启动 ADC 注入采样，等待 20 ms 后请求零电流偏置校准
  ↓
初始化 MT6835 编码器及 SPI1 DMA
  ↓
进入 while(1) 主循环
```

校准期间 ADC 仍按 20 kHz 采样，但不会调度 FOC。校准完整采集 400 个 U/V 样本后计算零点偏置。

## 4. 三条运行链路

### 4.1 FOC 实时链路（20 kHz）

```text
TIM1 CH4 硬件触发 ADC1 注入组
  ↓
完成 U、V 两相采样，产生 JEOS
  ↓
ADC1_2_IRQHandler()
  ↓
HAL_ADCEx_InjectedConvCpltCallback()
  ├─ 读取 JDR1/JDR2
  ├─ 更新采样序号
  └─ 调用 MainFoc_OnAdcConversion()
       ├─ 换算 U/V/W 三相电流
       ├─ 检查过流及驱动安全状态
       ├─ 根据当前模式运行控制算法
       ├─ 计算三相占空比并更新 CCR1/2/3
       └─ 发布波形数据
```

`FOC_AlgorithmStep()` 的正式调用链为：

```text
MainFoc_OnAdcConversion()
  → FOC_ControllerStep()
    → 读取电流、角度和指令
    → 校验输入及功率级状态
    → FOC_AlgorithmStep()
    → MainFoc_WriteVoltage()
    → Tim1Pwm_SetPhaseVoltage()
```

它不会无条件执行。控制器必须已由 `FOC_ControllerStart()` 置为运行状态，并且当前模式已进入需要正式电流环的阶段。

### 4.2 编码器链路（20 kHz）

```text
① TIM1 周期边界（每 50 us）
   → TIM1_UP_TIM16_IRQHandler()
   → HAL_TIM_PeriodElapsedCallback()
   → Encoder_OnPwmPeriodIsr()

② MCU 发起 SPI 通信
   → CSN 拉低，MT6835 锁存当前角度
   → HAL_SPI_TransmitReceive_DMA() 启动 SPI1 双向 DMA
   → MCU 发送 A0 03 00 00 00 00，共 6 字节/48 个 SCK
   → MT6835 同时返回角度、状态和 CRC

③ MCU 收到完整数据
   → DMA1_Channel1_IRQHandler()（RX DMA 完成）
   → HAL_SPI_TxRxCpltCallback()
   → CSN 拉高，调用 Encoder_TransferComplete()

④ MCU 解析并发布
   → MT6835_DecodeAngleResponse()：提取 21 位角度、状态和 CRC
   → 检查通信、CRC 和编码器报警
   → Encoder_PublishFrame()：计算方向、多圈、机械角、速度和电角度
   → 原子更新 g_encoder_snapshot

⑤ ADC 稍后完成采样，进入 FOC
   → MainFoc_OnAdcConversion()
   → FOC_ControllerStep()
   → MainFoc_ReadFeedback()
   → Encoder_ReadElectricalAngleForFoc()
   → 复制最近一次有效的 g_encoder_snapshot
   → 把 electrical_angle_rad 写入 FOC 输入
   → FOC_AlgorithmStep()
```

SPI1 当前工作在硬件模式 3、10.5 MHz，并使用 DMA。6 字节总线传输的理论时间约为 4.6 us，加上中断和解析开销后仍应早于本周期的 ADC/FOC 计算完成。

编码器角度的锁存时刻和 ADC 数据的完成时刻并不相同。TIM1 更新事件位于中央对齐载波的谷值，编码器在此时拉低 CSN 并锁存角度；ADC 注入序列安排在同一载波周期靠近峰值的有效低侧窗口内。当前 `ADC1_CS_PROFILE = 5`，U/V 两路 16 倍过采样序列总时长约 19.05 us，理想情况下在载波峰值附近完成。因此，编码器时间戳相对 ADC 序列完成和 FOC 入口约早 25 us，也就是约半个 50 us 控制周期。但 ADC 是一段采样窗口而不是单一瞬时点，且 CCR4 会根据三相占空比动态调整，所以不能认为编码器固定比每一个 ADC 样本都早 25 us。

SPI 与 FOC 不互相阻塞：

- SPI DMA 正在传输时，CPU 可以继续执行其他代码；
- DMA 完成中断优先级为 0，高于 ADC/FOC 的优先级 1，可及时发布角度；
- FOC 不直接读取 SPI 接收缓冲区，也不会等待当前通信结束，只读取已经发布的快照；
- 若本次 SPI 尚未完成或 CRC 错误，旧快照不会被半包数据覆盖；旧数据最多允许保留 3 个控制周期，即 150 us；
- 快照超时、电角度未配置或数据无效时，正常模式会判定角度反馈无效、停止 FOC 并关闭 MOE。

正常模式使用电角度前，必须通过 `Encoder_ConfigureMotor()` 配置方向、极对数和电角零位。当前默认的电流调试模式始终给 FOC 使用固定电角度 0，编码器虽然仍以 20 kHz 通信和解析，但角度不会交给该模式的 FOC 运算。

### 4.3 主循环后台链路

```text
while (1)
  ├─ CurrentSampling_Service()       推进零点校准
  ├─ MainFoc_ServiceModeSwitch()     安全切换控制模式
  ├─ MainCurrentTest_Service()       处理调试命令和启停请求
  ├─ 处理输出预充电、启动和停止
  ├─ WaveformUart1Port_Service()     串口发送
  ├─ WaveformGenerator_Task()        波形组帧
  ├─ Encoder_Service()               编码器超时恢复
  ├─ DrvMonitor_Task()               每 1 s 读取驱动状态
  └─ ServoManager_Service()          正常模式状态机
```

主循环没有固定周期，因此不能把 FOC 电流环放到主循环中。

## 5. 当前控制模式

| 模式 | 主要行为 |
| --- | --- |
| 电压开环 | 直接生成旋转 D/Q 电压并计算 SVPWM，不运行电流 PI |
| 电流调试 | 支持固定 D 轴电压、D 轴 P 环、D/Q PI 三个阶段 |
| 正常模式 | 使用编码器电角度和 D/Q 电流指令运行完整 FOC，由 Servo Manager 管理启停 |

当前上电默认值为：

- 模式：电流调试模式；
- 阶段：D/Q PI；
- D/Q 电流指令：0 A；
- `output_request = 0`；
- FOC 控制器未启动，MOE 关闭。

因此，**仅上电不会驱动电机，也不会执行 `FOC_AlgorithmStep()`**。ADC 和编码器中断仍会运行，用于采样、校准和状态更新。

## 6. 输出启动条件

收到输出请求后，程序依次检查：

1. 电流零点校准完成；
2. STSPIN32G4 的 READY 和 nFAULT 均正常；
3. 当前没有 FOC、采样或功率级故障；
4. 模式和测试阶段允许启动；
5. 完成自举预充电和中性矢量稳定；
6. 启动 FOC，并在产生第一组有效 CCR 后允许功率输出。

运行中若出现电流越限、反馈无效、PWM 写入失败、READY/nFAULT 异常或算法错误，会立即调用 `Tim1Pwm_EmergencyStop()` 清除 MOE，并锁存故障。

## 7. MOE 当前实际行为

当前代码并不是“全过程不使能 MOE”：

- 普通上电、ADC 校准及无输出请求时，MOE 始终为 0；
- 收到合法输出请求后，`Tim1Pwm_BootstrapPrecharge()` 会短暂使能 MOE完成自举预充电；
- 随后控制模式会继续保持或使能 MOE，向电机输出 PWM；
- 停止、切换模式或发生故障时立即清除 MOE。

如果目标仍是“任何情况下都不使能 MOE”，则当前启动路径与该要求不一致，需要禁止 `Tim1Pwm_BootstrapPrecharge()` 和所有 `Tim1Pwm_EnableOutputs()` 调用。

## 8. 调试时优先观察

| 变量 | 含义 |
| --- | --- |
| `g_current_sampling.calibration_state` | 电流校准是否完成 |
| `g_global_mode_control.active_mode` | 当前实际模式 |
| `g_global_mode_control.runtime.output_request` | 是否请求输出 |
| `g_global_mode_control.runtime.output_armed` | 启动联锁是否通过 |
| `g_foc_controller.running` | FOC 控制器是否运行 |
| `g_foc_controller.feedback_ready` | 是否已完成一次有效计算和 CCR 更新 |
| `g_global_mode_control.runtime.fault_flags` | 应用层故障 |
| `g_foc_controller.fault_flags` | FOC 控制器故障 |
| `TIM1->BDTR & TIM_BDTR_MOE` | 功率输出是否真正使能 |

若调试时不进入 `FOC_AlgorithmStep()`，先检查前三项：`output_request`、`output_armed` 和 `g_foc_controller.running`。默认上电时它们均为 0，这是当前程序的正常行为。
