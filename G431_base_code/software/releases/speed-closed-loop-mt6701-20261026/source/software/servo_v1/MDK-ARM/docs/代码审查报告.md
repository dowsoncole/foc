## 二、🔴 严重问题

### S1. FOC PI 输出限幅复用了积分限幅，比例项被截断 ✅

- **位置：** `FOC/Src/foc_algorithm.c:27`
- **事实：** `foc_pi_step()` 末尾 `return foc_clamp(output, controller->integral_min, controller->integral_max);`，其中 `output = kp*error + integral`（第 26 行）。输出上限直接用了积分限幅 `integral_max`。
- **后果：** 当 `kp*error` 较大（启动、突变负载、大误差瞬态）时，即使积分器远未饱和，比例贡献也会被 `integral_max` 削平。电流环等效增益被压低、带宽下降，动态响应变差，极端情况下大误差无法快速纠正。
- **建议方向：** 输出限幅应独立于积分限幅——用电压上限（如 `voltage_limit` 或 SVPWM 前的相电压幅值上限）作为 PI 输出钳位；积分 anti-windup 只作用于 `integral` 本身（第 24 行那处保留）。

## 三、🟠 中等问题

### M1. 串口发送异常时波形队列可能永久卡死 📋

- **位置：** `Tests/Src/waveform_generator.c:108-112`、`129-132`
- **事实：** Task 入口 `HAL_UART_GetState() != HAL_UART_STATE_READY` 即 return；且仅当 `HAL_UART_Transmit() == HAL_OK` 才推进 `s_tail`。
- **后果：** 若 UART 因噪声/溢出进入 ERROR 或卡在 BUSY_TX 且不自恢复，Task 每轮 return、`s_tail` 永不推进；ISR 侧继续 1 kHz 写入，约 32 ms 后队列满、之后全部丢新样本，**波形数据流永久中断**，即便物理层已恢复。不影响功率级安全，但调试观测能力丧失。
- **建议方向：** 检测到非 READY 时调用 `HAL_UART_Abort()` 复位状态机；或发送失败分支也推进 `s_tail`（丢帧优于卡死）。

### M2. RS485 DE 的 TC 等待超时起点设在发送之前 📋

- **位置：** `Tests/Src/waveform_generator.c:127-138`
- **事实：** `transmit_start = HAL_GetTick()`（128 行）在 `HAL_UART_Transmit`（129 行，超时 2 ms）**之前**取时基；随后的 TC 等待循环（133-137 行）用同一 2 ms 预算。
- **后果：** 若 `HAL_UART_Transmit` 因被高优先级中断打断而耗时接近 2 ms，返回后 TC 循环零次迭代即退出、DE 立即拉低；若此时移位寄存器尚未移出最后一字节，RS485 收发器切回接收态会**截断最后一字节**，上位机收到残缺帧、CRC 失败。实际发生需 Transmit 异常耗时，概率低；严重度取决于所用 HAL 版本的 `Transmit` 是否已在内部等 TC。
- **建议方向：** 把 TC 等待的超时起点改到 `HAL_UART_Transmit` **返回之后**，或给 TC 等待单独一个短超时（如 1 ms）。

### M3. `g_measurement_manager` 是孤立的 extern 声明 📋✅

- **位置：** `Tests/Inc/measurement_manager.h`（extern 声明处）
- **事实：** 全工程 `.c` 文件中无 `g_measurement_manager` 的定义，仅头文件 extern。当前 `main.c` 未引用它，`tim1_pwm_verify.c` 通过参数传入 manager 指针，故链接不报错（未被引用的 extern 不触发 undefined symbol）。
- **后果：** 旧架构遗留。任何新代码包含该头并引用此符号，链接即报 undefined symbol，属埋雷。
- **建议方向：** 删除该 extern 声明，或在某个 `.c` 中补定义。

### M4. 电角度硬编码为 0，编码器角度尚未接入 FOC 📋

- **位置：** `Core/Src/main.c`（`input->electrical_angle_rad = 0.0f` 处，约 98 行）
- **事实：** Park/反 Park 始终在角度零点工作，d/q 轴与 α/β 重合。
- **后果：** 这是编码器接入前的预期状态，本身不是 bug。但 MT6835 模块已就绪，一旦接入却漏改此处，FOC 会退化为固定坐标系控制、电机无法产生有效转矩。
- **建议方向：** 接入时用 `mt6835` 角度 × 极对数换算电角度写入该字段；建议在 `foc_input_t` 增 `angle_valid` 标志，算法层在角度无效时拒绝输出，防止漏接。

### M5. 校准门控：重复校准期间 FOC 反馈含旧偏置 📋

- **位置：** `Modules/Current_Sampling/Src/current_sampling.c:69-74`
- **事实：** 注入回调仅在 `CAL_SETTLING`/`CAL_COLLECTING` 状态下跳过 FOC 回调；`main.c` 的 FOC 启动门控是 `CAL_DONE && running==0`。
- **后果：** 正常上电流程安全（FOC 只在 CAL_DONE 后启动，此时 offset 已有效）。风险仅在**运行中再次 `RequestCalibration()`**：进入 SETTLING 前若 FOC 已在跑，会用上一次的旧 offset 做减法数个周期，反馈短暂失真、污染积分器。属边界场景。
- **建议方向：** 重复校准前先停 FOC，或在回调中增加"offset 本轮有效"门控。

### M6. I2C3 无总线恢复/重试机制 📋

- **位置：** `Modules/Driver_Communication/Src/i2c3_bus.c`、`stspin32g4.c`
- **事实：** I2C3 初始化只配时序与滤波器，无总线复位（SCL toggle）逻辑；STSPIN32G4 读写直接透传 HAL 返回值，无重试。`drv_monitor` 的连续失败计数（`DRV_COMM_ERR_LIMIT`）部分弥补。
- **后果：** 24 V 功率板 EMI 较重，若 SDA 被从机锁死，`HAL_I2C_Mem_Read` 会持续 timeout，无法自恢复，驱动器配置/状态读取长期失效。
- **建议方向：** 增加 I2C 总线复位（手动 toggle SCL 9 次 + STOP）作为最后恢复手段。

### M7. `foc_controller_t.running` 缺 volatile 📋

- **位置：** `Core/Src/main.c:292` 读取；`FOC/Src/foc_interface.c`（中断内可清零）
- **事实：** `running` 在主循环读、在 ADC 中断里可被 `FOC_ControllerStep()` 清零，类型为 `uint8_t`（Cortex-M4 单字节读写原子，不会撕裂）。
- **后果：** 无 volatile，编译器优化可能让主循环缓存旧值，延迟感知停环事件。
- **建议方向：** `running` 声明为 `volatile uint8_t`。

## 五、确认正确 / 值得肯定的设计

- ✅ **MT6835 协议实现准确**（`mt6835.c`）：24 bit 帧组包（4 bit 命令 + 12 bit 地址 + 8 bit 数据）匹配手册图-18；连读角度事务 CSN 全程拉低、rx 对齐 0x003~0x006；`0x005` 高低位剥离（`>>3` 取角度、`&0x07` 取状态）正确；21 bit 角度拼装无字节序错误。
- ✅ **CRC-8 算法正确**：反馈位取 `crc>>7`、多项式 0x07、覆盖 24 bit、ANGLE[20] 最先移入；初值 0x00 已在注释标注为假设并给出 0xFF 备选排查路径。
- ✅ **片选上电时序正确**（`spi1_encoder.c`）：先配 PA4 推挽输出并立即释放（置高）片选，再 `HAL_SPI_Init`，避免 CSN 意外拉低触发角度锁存。
- ✅ **测试判定顺序正确**（`mt6835_verify.c:97-104`）：STATUS 报警判定门控在 `frame.crc_ok != 0U` 之后，MISO 悬空读到 0xFF 伪造的 STATUS=0x07 不会被误判为真实报警。**（此项为审查者上一轮怀疑、本轮亲自复核后确认不成立，见第六节。）**
- ✅ **SPSC 环形队列实现正确**（`waveform_generator.c`）：head 仅 ISR 写、tail 仅主循环写，先写数据再更新 head、先读数据再更新 tail，满/空判断无 off-by-one，共享变量均 volatile。
- ✅ **MOE 无条件关断**（`tim1_pwm.c`）：用 `__HAL_TIM_MOE_DISABLE_UNCONDITIONALLY`，规避条件版在 CCxE 未全清时静默失效的陷阱。
- ✅ **故障快速路径恒定耗时**：`IsPowerStageSafeFast()` 单次原子读同端口 IDR，适合 20 kHz 中断。
- ✅ **电流符号/零点处理安全**：`GetSignedDelta()` 全程 int32 运算，无 uint 下溢回绕；S16 反馈有钳位。
- ✅ **ADC 溢出保护**：`Overrun = ADC_OVR_DATA_PRESERVED`，宁旧勿裂。
- ✅ **中断优先级合理**：TIM1_CC=0 > ADC1_2=1 > TIM6=15；ADC 注入回调（FOC + SampleTick）在优先级 1，不被 TIM6 打扰；SysTick=15，`HAL_GetTick` 在 ISR 中只读计数安全。
- ✅ **快照发布临界区正确**：`drv_monitor` 用 `__get_PRIMASK()` 保存/条件恢复，避免嵌套关中断误开。
- ✅ **编译期安全网**：死区编码范围、CH4 提前量下溢、比较寄存器宽度均在预处理阶段拦截。

## 六、审查过程中的澄清（推翻的怀疑）

- **MT6835 测试判定顺序**：审查者上一轮曾怀疑"CRC 未通过的帧上仍判 STATUS，会把垃圾状态位误报为 ALARM"。本轮亲自读 `mt6835_verify.c:97-104` 核实：STATUS 判定确实先门控在 `frame.crc_ok != 0U`（第 100 行），CRC 失败的帧不会进入报警判定。**怀疑不成立，代码此处正确。** 此前 Watch 截图中 `status_raw=0x07 + crc_ok=0 + FAIL_ALARM` 的组合，反映的是当轮运行的是**旧版固件**（回环判据时期），非当前源码行为。

## 七、优先修复建议

1. **先修 S1**（FOC PI 输出限幅）——必然影响每一次大误差瞬态的控制性能，且改动局部、风险低。
2. **上功率级实测前修 M4**（电角度接入）——否则编码器接通也无法产生转矩。
3. **调试观测依赖串口时修 M1/M2**（队列卡死、DE 截断）——保障波形流稳定。
4. M3/M5/M6/M7 与全部 L 级问题可在后续迭代逐步处理，不阻塞当前开发。
