# 编码器使用说明

更新：2026-10-24。本说明对应当前 MT6835、10 kHz/100 μs源码候选实现。
最新显式启动初值见第28节，尚未编译/下载；默认10周期见第27节，可调CRC容错见第26节，10 kHz时基见第24节，
固化板级校准参数的来源见第23节。新版本上电就绪后会自动请求500 rpm运行。
PA0仍测整个ADC IRQ，PD2仍测软件发起SPI至DMA接收IRQ末尾；本轮未操作目标板。
0 μs直接触发版已由用户烧录，其单点试跑记录见SPI诊断第41节；不能把该旧镜像
实测当作本次PD2修改的验证。此前10 μs镜像及待机验证见第18节。

## 1. 当前实现

编码器已从一次性通信测试改为持续运行模块：

```text
TIM1 周期边界（10 kHz，采集武装后）
  → TIM1更新中断清除UIF后直接启动SPI1 DMA，不等待（0 μs软件延时）
  → MT6835 锁存并返回角度、状态和 CRC
  → DMA 完成中断解析数据
  → 跨圈处理、速度估算、电角度换算
  → 发布一致快照
  → FOC 在 ADC 完成时读取上一份快照
```

原来的 `mt6835_verify.c/.h` 已删除。正式运行期间不再出现“采满 256 帧后停止”的行为。

模块职责：

| 文件 | 职责 |
|---|---|
| `spi1_encoder.c` | SPI1、DMA1 Channel 1/2、CS 和异步传输 |
| `mt6835.c` | MT6835 命令、响应解码、状态和 CRC |
| `encoder.c` | 连续采样、有效性、跨圈、速度、电角度、快照和耗时统计 |
| `main.c` | 正常模式下把编码器电角度交给 FOC |

## 2. 使用前必须配置

初始化已经在 `main()` 中自动执行：

```c
if (Encoder_Init() == 0U)
{
    Error_Handler();
}
```

上层完成方向、极对数和电角零位标定后，在功率输出关闭状态调用：

```c
Encoder_ConfigureMotor(direction, pole_pairs, electrical_offset_rad);
```

参数含义：

- `direction`：机械正方向，取 `+1` 或 `-1`。
- `pole_pairs`：电机极对数，必须大于 0。
- `electrical_offset_rad`：标定得到的电角零位，单位 rad。

2026-10-23 校准诊断更新：上电仍配置 direction=-1、pole_pairs=2 以支持原始
读角诊断，但历史 5.3988 rad 零位不再自动获得 `g_speed_test.calibration_ok=1`。
速度闭环必须在 OFF 状态显式应用已验证的 RAM 校准；重启不保留其有效性。
kind 9 是 3 A 上限、12 s 的整机械圈正反向诊断，不是传感器 EEPROM 自校准，
也不会自动应用拟合零位。离线分析返回 `accepted=false` / 退出码 2 时不得应用。

未配置前仍会持续读取机械角度，但 `electrical_angle_valid=0`，正常 FOC 不会把机械角误当电角度使用。修改配置会清空跨圈和速度历史，需要重新积累约 1 ms 的速度窗口。

## 3. 上层接口

头文件：`Modules/Encoder/Inc/encoder.h`。

```c
uint8_t Encoder_ReadSnapshot(encoder_snapshot_t *snapshot);
uint8_t Encoder_ReadElectricalAngleForFoc(float *electrical_angle_rad);
void Encoder_GetDiagnostics(encoder_diagnostics_t *diagnostics);
```

`Encoder_ReadSnapshot()` 用于速度环、位置环、通信和调试。主要字段：

| 字段 | 含义 |
|---|---|
| `raw_angle` | MT6835 的 21 位单圈原始角度 |
| `multi_turn_count` | 软件跨圈后的有符号累计计数，断电不保存 |
| `mechanical_angle_rad` | 统一方向后的单圈机械角，范围 `[0, 2π)` |
| `mechanical_speed_rad_s` | 机械角速度，单位 rad/s |
| `electrical_angle_rad` | 极对数和零位换算后的电角度 |
| `sample_cycle` | CS 拉低附近的 DWT 周期计数 |
| `sequence` | 有效帧序号 |
| `fault_flags` | 通信、CRC、报警、过期或未配置 |
| `angle_valid` | 当前机械角有效且没有过期 |
| `speed_valid` | 速度窗口已经建立 |
| `electrical_angle_valid` | 电机参数已配置且当前角度有效 |

返回值为 1 表示当前机械角有效。速度和电角度仍应检查各自有效位。数据超过 3 个 FOC 周期，也就是187.5 μs未更新，会被判定为过期；断线不会被伪装成零速度。

FOC 使用 `Encoder_ReadElectricalAngleForFoc()`。该接口只复制内存快照和检查时间，不启动 SPI，也不等待 DMA。

## 4. 速度计算

每个有效角度样本先进行跨圈修正，再进入16点窗口：

```text
机械速度 = 窗口内累计角度变化 / 窗口实际时间
```

通信槽频率为16 kHz，速度窗口覆盖约1 ms；零点配置检查会偶尔占用角度槽，
速度始终使用实际时间差而不是假定等间隔。随后使用时间常数 10 ms 的一阶低通。
启动零点检查通过后或重新配置后，前16个有效角度样本只有角度有效，速度尚未有效。

当前硬件没有把 MT6835 的 A/B 脉冲接回 MCU，因此这里使用 SPI 绝对角度差分，不是经典 AB 脉冲 M/T 法。

## 5. 编码器在什么时刻通信

当前源码在 TIM1 更新中断中直接启动SPI/DMA，不再由TIM16延时调度，
通信槽频率16 kHz、周期62.5 μs；正常角度事务如下：

```text
TIM1 更新中断：清除UIF，直接启动SPI/DMA
     ↓ 无人为相位等待；仍有中断响应及启动开销（见第19节）
SPI：CS 拉低并开始传输
     ↓ 48 个 SCK
DMA 完成：释放 CS，解析并发布快照
     ↓
ADC 注入转换完成：FOC 读取最近完整快照
```

SPI1 时钟为 10.5 MHz，一帧 6 字节、48 个 SCK，理论线上时间：

```text
48 / 10.5 MHz = 4.57 μs
```

当前源码的DMA完成/SPI中断优先级为0，ADC/FOC为1，编码器完成处理可以抢占FOC。
因此不能仅按整个PWM周期估算计算余量，还要核对ADC采样完成到下一次PWM提交
截止的时间。若读取时DMA仍忙，FOC使用上一份有效快照并记录`foc_reads_while_busy`。

## 6. 如何测量对 FOC 的影响

使用：

```c
encoder_diagnostics_t diagnostics;
Encoder_GetDiagnostics(&diagnostics);
```

使用 Keil Watch 时也可以直接观察只读镜像 `g_encoder_snapshot` 和
`g_encoder_diagnostics`；业务代码仍应调用接口，禁止直接写这两个对象。

周期数除以 `SystemCoreClock` 得到秒；当前 168 MHz 下，周期数除以 168 得到微秒。

重点字段：

| 字段 | 判断内容 |
|---|---|
| `transaction_cycles_latest/min/max` | 从启动到 DMA 完成回调的实际通信墙钟时间 |
| `start_cycles_latest/max` | TIM1 ISR 中启动 DMA 的 CPU 开销 |
| `completion_cycles_latest/max` | DMA 回调解析、测速和发布快照的 CPU 开销 |
| `foc_read_cycles_latest/max` | FOC 读取快照增加的 CPU 开销 |
| `foc_sample_age_cycles_latest/max` | FOC 使用的角度距离采样时刻有多旧 |
| `foc_isr_cycles_latest/max` | 完整 ADC/FOC ISR 的执行时间 |
| `foc_deadline_overrun_count` | FOC ISR 是否达到或超过62.5 μs |
| `busy_trigger_count` | 新周期到来时上一次通信是否仍未结束 |
| `crc_error_count` | CRC 错误数量 |
| `transfer_error_count` | DMA/SPI 错误或超时数量 |

判断标准：

1. `foc_deadline_overrun_count` 必须保持 0。
2. `foc_isr_cycles_max` 必须明显小于 `168 MHz / 16 kHz = 10500 cycles`。
3. `busy_trigger_count` 正常应为 0。
4. `transaction_cycles_max` 应明显小于10500 cycles；理论线传输约768 cycles。
5. `foc_read_cycles_max` 应只占62.5 μs预算的一小部分。
6. 持续观察 `crc_error_count` 和 `transfer_error_count`，不能只看一瞬间。

当前源码的PD2在所有profile下标记软件发起SPI至DMA接收IRQ末尾，包含帧解析。
PA0在所有profile下标记整个ADC IRQ，包含FOC、CCR写入和IRQ内诊断；不再输出故障
锁存电平。软件首错记录和停机门控保留。本次源码修改与采集口径见第22节。

## 7. 故障行为

- SPI/DMA 失败、CRC 错误或 MT6835 报警：立即撤销角度、速度和电角度有效性。
- 超过 100 μs 未完成的事务由后台服务中止并记录通信错误。
- 超过187.5 μs没有新样本：读取时增加 `ENCODER_FAULT_STALE`。
- ZERO_POS 未完成启动检查或已经不匹配：增加 `ENCODER_FAULT_ZERO_CONFIG`，见下一节。
- 正常 FOC 读取不到有效电角度时，现有 FOC 安全逻辑锁存 `FOC_FAULT_ANGLE_INVALID` 并关闭输出。

详细实现决策和回溯记录见 [编码器实现日志](encoder_analysis_log_2026-10-20.md)。

## 8. ZERO_POS 零点配置监测（2026-10-23 候选）

本板已审计的 MT6835 ZERO_POS 为 0。它和电机电角校准偏置是两个不同参数；
编码器返回 CRC 正确，不代表内部零点配置未变化。

启动按高字段/角度/低字段/角度顺序读取 0x009 和 0x00A；两字段通过前反馈无效。
正常运行每个字段每128槽读取一次，16 kHz下正常调度约8 ms。一共约1/64的角度槽
改成 24-bit 寄存器只读事务，不连续跳过两个角度槽，不更新时间戳来掩盖缺样；
新鲜度仍按3槽限制，16 kHz下为187.5 μs。存在轮询检测延迟，不能把它当作零点绝不变化的保证。

只读 Watch 镜像 `g_encoder_zero_guard`（32 字节）：

| 字段 | 含义 |
| --- | --- |
| `expected_zero` / `observed_zero` | 本板期望值 0 / 最近高低字段合成的 12-bit 值 |
| `verified_mask` | bit0 高字段、bit1 低字段已经读取；正常为 3 |
| `latched` | 配置不匹配或已启动读取的传输错误后锁存为 1 |
| `checks` / `read_errors` / `mismatches` | 完成检查、读取错误、不匹配计数 |
| `last_check_cycle` | 最近检查的 DWT 时间戳 |

故障位 `ENCODER_FAULT_ZERO_CONFIG=0x40` 会撤销机械角、速度和电角度有效性。
后续 CRC 正确、寄存器恢复或重新应用 RAM 电角校准都不能清除锁存；
必须 OFF 下查明并纠正配置，重新初始化后重新验收，不自动恢复电机输出。
寄存器单字节读取没有 CRC，链路错误也可能导致保守锁存，不能作为独立角度基准。

固件仅监测，不自动写零点或 EEPROM。专用恢复脚本只用于当前已确认零点=0
这块板的人工修复，要求匹配镜像、OFF、暂停采集及准确的旧零点证据。
固件已实板验证拒绝 0x70F，易失零点恢复回读为 0。后续重启和 60 秒待机、
一次 3 A / 12 秒低速往返均未出现新的 CRC/零点故障；但往返校准质量未通过，
`calibration_ok` 仍为 0，不能将此视作高速问题根治。当前在板镜像还包含另一项
SPI3 临时时序诊断，其采集已停用；与单独保存的候选固件不要混用符号地址。
证据及完整镜像标识见 [SPI 诊断第 23 节](spi_logic_analysis_2026-10-22.md)。

## 9. ZERO_POS 故障原始证据（2026-10-23 诊断候选）

新增独立只读镜像 `g_encoder_zero_fault_capture`（328 字节），原有 32 字节
监测结构及快照/诊断 ABI 不变。不增加正常轮询频率、不放宽反馈新鲜度，
不写传感器零点、EEPROM，也不自动清除锁存。

发生不匹配或寄存器传输错误时，保存首次事件、最后事件和最近 8 次事件。
每帧 32 字节，记录完成/启动周期、SPI 状态、更新前/后的合成零点、期望零点、
寄存器地址、HAL 状态、原因和 3 个原始接收字节。原因 1 为字段不匹配，
原因 2 为传输错误。首次事件在本次初始化内保持不变。

读完整块前后分别读取 `sequence`：只有两次相等且为偶数才能解释为一致快照；
奇数表示固件正在更新。`count` 是异常读取事件数，不是已证明的零点改写次数。
单字节寄存器读本身没有 CRC；原始记录可以区分错误来源线索，仍不能替代
示波器上的 CS/SCK/MOSI/MISO 命令边界证据。

## 10. PA0 故障触发与等待采集专用版（2026-10-23）

本节所述停机专用目标定义 `ENCODER_FAULT_TRIGGER_DIAGNOSTIC=1`，用于停机捕获
MT6835 内部零点变化前后的总线命令。上电 PA0 低、采集 WAIT，所有固件
功率输出开启路径被禁用；不会在下载后自动启动采集或电机。
这不是高速测试镜像。恢复运行版须移除此定义或设为 0，重新构建并重新验证。

接线 CH0=CS、CH1=SCK、CH2=MOSI、CH3=MISO、CH4=PA0、共用信号 GND。
建议 100 MS/s、200 ms 总窗口、80% 预触发、CH4 上升沿、单次采集。
等操作者明确确认分析仪已等待触发，才允许 `encoder_logic_capture.py --arm`。
默认不加 `--arm` 只做回读；两者均验证完整 Flash 和 WAIT 状态，不做电机启动。

只允许主机写 48 字节 `g_encoder_logic_trigger` 中的 `command` 字段：
`0x43415031` 在 OFF/WAIT 接受一次，进入 ARMED 并开始读角/读零点。
CRC、角度跳变、报警、传输失败、零点不匹配的首次检测令 PA0 高并保持，
state=FIRED，证据冻结；采样继续保留后触发窗口。边沿标记检测而非物理发生
时刻，尤其零点轮询有约 6.4 ms 延迟。不能只保留触发后的数据。
重复命令会拒绝，不能拿它清除故障或重新武装。

当前已下载镜像、恢复易失零位操作及两次 WAIT 回读的记录见
[SPI 诊断第 27 节](spi_logic_analysis_2026-10-22.md#27-pa0-单次故障触发版已下载等待用户采集2026-10-23)。
旧节记载的 SPI3 timing 在板状态是历史记录，不再是当前镜像。

## 11. 带首错停机的运行触发版（2026-10-24 当前目标）

当前 Keil 定义为 `ENCODER_FAULT_TRIGGER_DIAGNOSTIC=2`。仍上电 WAIT，并需要
OFF 下单次 CAP1 才进入 ARMED；PA0 沿用单次故障上升沿，不做自检脉冲。
与第 10 节不同的是，ARMED 时允许后续单独下发的电机命令通过原有门禁；
首次编码器错误立即清 MOE、锁存无效反馈和 PA0 高电平，禁止重新开启输出。
重复 CAP1 或 RAM 应用校准不能重置这个状态。

`encoder_logic_capture.py --motion-capable --arm` 只启动读取；运动应通过
`run_triggered_commission.py alignment|speed` 使用已验证镜像、独立截止时间
或主机看门狗，并保存触发/零位块。不要向旧 profile-1 镜像套用本模式。
断电/复位后回到 WAIT，校准无效；必须重新确认基准和热量种子，不能把
上一次校准或旧有效标志直接沿用。
当前具体固件、回读状态和未完成项见 [SPI诊断第35节](spi_logic_analysis_2026-10-22.md)。

## 12. 校准电流口径更新（2026-10-24，历史电流校准镜像）

用户最新指定等效5 A RMS校准，对应等幅值Clarke/Park的 Id=7.07107 A，
并非 Id=5 A。此前 Id=3 A 实际约为2.12132 A RMS；静止时各相直流值不同，
这里的RMS指三相电流平方平均口径。

新镜像在 `control_analysis/results/mt6835_alignment_5arms_20261024/`，已下载并
完整回读。静态kind1：约2秒缓升，最长5秒，保持20 rad/s和15 A故障门槛。
旧kind9的12秒往返仍为≤3 A Id，未扩大；速度模式及I²t配置不变。
主机必须明确使用 `--alignment-rms-current 5`、5秒及近位起步参数，
并校验 `g_speed_alignment_profile_version=2`；原 `--alignment-current 3`
仍表示Id幅值。采集profile仍为2，是另一个独立版本字段。

用户确认采集后已单次CAP1武装，并执行5 A RMS静态试验；当前不是WAIT。
旧3 A Id的19点静态配对残差6.29°，未通过也未应用其均值。5 A RMS也必须
通过完整正反向配对验收，不能仅凭某一个点停稳或电流增大就开启高速。
本轮19点全部完成后，同位置重复差0.17401°，但位置残差仍为6.18524°，
超过3°门槛；未应用估计零位，校准仍无效，功率输出OFF。CRC/零点错误为0，
PA0低，未进行新的高速试验。详见 [SPI诊断第32节](spi_logic_analysis_2026-10-22.md)。

WAIT专用模式在SPI尚未启动时完成原ADC零点标定，本板实测CAP1启动SPI后
会出现约0.1 A量级的直流偏移。`paired_static_alignment.py` 现在先调用
`calibrate_adc_zero_off.py`，在健康ARMED、功率OFF、静止且电角校准无效时，
采集两段连续ADC窗口并有界修正U/V偏置，再用第三段独立窗口复核残差。
不符合噪声、稳定性、偏置范围或残差门槛就停止，不开始校准激励。
该流程只修改RAM电流采样偏置，不写MT6835零点、EEPROM或电角校准均值；
不是上电持久化修复，复位后须重新执行。SPI相关ADC噪声仍待进一步定位。

## 13. 电压校准方法：Ud=1 V、Uq=0；旧20 kHz镜像实测（2026-10-24）

本节实测使用 `mt6835_alignment_voltage1v_20261024`，kind10电压契约版本1。
直接电压调制绕过两路电流PI；电流仅用于记录和保护。按名义24 V母线换算，
2秒缓升到1 V，单点总时长5秒；没有实际保持5 A的电流指令。
15 A瞬时相电流、额定6 A等效RMS超限、20 rad/s、限时及编码器首错均会停机。

`SPEED_RUN_BOOT_AUTO_START=1`：默认目标仍为500 rpm。为避免未采集时就报0x400，
`enable`不直接静态初始化为1，而是在反馈角度、速度、电角度及采集状态就绪后置1。
主循环随后调用原启动检查、预充电和FOC启动流程，不直接打开MOE。
等待最长200 ms；若已锁存编码器故障或等待超时，只提交一次原启动检查请求，
由原门控拒绝并记录阻断原因，不清故障、不重复启动。已有操作请求会取消待发的
自动请求；调试器可在等待阶段将main局部变量`boot_speed_pending`置0取消。
`SPEED_RUN_BOOT_AUTO_START=0`可在构建时取消默认速度启动；OFF-only诊断模式1
始终不自动请求运动。自动采集独立保留，正常模式2首次CRC故障停机规则不变。

注意：本版本不再等逻辑分析仪就绪后才采集；需要捕获上电过程时应提前设置采集。
旧`encoder_logic_capture.py --arm`用于干净WAIT，不能对已经ARMED的板重复执行。
10 kHz时基、0 μs SPI相位及PA0/PD2探针不变。本轮未运行回归、编译、下载或启动
目标板，仅修改源码并做静态检查；自动启动流程仍待用户下载后验证。

## 26. 速度运行参数化的CRC有界容错（源码候选，2026-10-24）

新增`g_speed_run.encoder_tolerance_cycles`，默认3，范围1～10。该字段追加到结构体
末尾（偏移60，结构体总长64字节），原60字节字段偏移不变。旧主机脚本读取的60字节
前缀仍可解析，但不包含此新字段；调试器必须使用重新构建的匹配符号。

仅在停机状态下修改，下一次速度启动请求通过`Encoder_ConfigureFeedbackTolerance`
将参数锁存到`s_feedback_tolerance_cycles`。运行中改公开字段不改变本次有效限值。
0或大于10均拒绝启动，`start_block_mask`增加0x800，仍使用启动拒绝fault=10。
配置不刷新旧样本时间戳、不改序号、不清故障。上电自动启动默认使用3。

这里的“周期数”是上一有效反馈的最大年龄，不是连续坏帧个数，也不是CPU时钟数。
10 kHz下3周期为300 μs，10周期为1 ms；判断仍为年龄严格大于限值时失效。
寄存器巡检槽、传输及中断延迟也占用这个预算，因此不保证能连续容忍恰好N个坏帧。
1～2周期可能在正常寄存器巡检间隔产生超时；默认3，增大数值的高速适用性未验收。

模式2中CRC失败只记录到`g_encoder_fault_capture`及错误计数，丢弃坏帧，不再单独
触发`g_encoder_logic_trigger`的FIRED/MOE关断。窗口内只保留上一有效角度和原时间戳，
不使用错误帧角度。持续错误或无新反馈使窗口到期时，速度/FOC原有无效反馈检查仍
停机，且不自动重启。传感器报警、通信故障、零位配置变化、不合理角度跳变的首错
停机仍保留；诊断模式1的CRC首错捕获行为不变，模式0沿用原有坏帧丢弃路径。

这项修改不是CRC根因修复，亦不是全故障屏蔽；最大1 ms旧角度窗口不代表已通过高速
验证。本轮同步了相关测试源码但未运行回归、编译、下载或实板测试，仅做静态检查。
