## 1. 分层与结构体总览

速度闭环跨三层，各层结构体职责分明：

```
┌─ 调度层 ─────────────────────────────────────────┐
│ servo_manager_t        状态机 + 故障锁存 + 输出使能  │
└──────────────┬─────────────────────────────────┘
               │ RequestOn / Service / RaiseFaultFromIsr
┌─ 速度环层 ────▼─────────────────────────────────┐
│ speed_commission_t     测试状态机 + 速度PI + 记录器 │
│ speed_run_t            连续运行模式的遥测出口       │
│ speed_test_config_t    一次测试的参数集            │
│ speed_test_record_t    记录器的一行                │
└──────────────┬─────────────────────────────────┘
               │ 写 in->q_reference / 读 algorithm.output
┌─ 电流环层 ────▼─────────────────────────────────┐
│ foc_controller_t       控制器实例（算法+端口+时序）  │
│ foc_port_t             与硬件的唯一接缝（4个函数指针）│
│ foc_parameters_t       电流环参数（含 d/q 两个 PI） │
│ foc_input_t            本周期输入 + 三个有效位      │
│ foc_output_t           本周期输出 + 遥测量          │
│ foc_pi_t               PI 控制器本体（仅电流环用）   │
└─────────────────────────────────────────────────┘
```

| 结构体                  | 全局实例                               | 定义位置                 | 层次           |
| ----------------------- | -------------------------------------- | ------------------------ | -------------- |
| `servo_manager_t`     | 由 main.c 持有                         | servo_manager.h:47-59    | 调度           |
| `speed_commission_t`  | `g_speed_test`                       | speed_commission.h:57-74 | 速度环         |
| `speed_run_t`         | `g_speed_run`                        | speed_commission.h:36-45 | 速度环（遥测） |
| `speed_test_config_t` | 嵌于 `g_speed_test.requested/active` | speed_commission.h:47-53 | 速度环（参数） |
| `speed_test_record_t` | 嵌于记录器 union                       | speed_commission.h:54-56 | 速度环（记录） |
| `foc_controller_t`    | `g_foc_controller`                   | foc_interface.h:45-62    | 电流环         |
| `foc_port_t`          | 嵌于 controller                        | foc_interface.h:35-42    | 电流环（接缝） |
| `foc_parameters_t`    | 嵌于 algorithm                         | foc_algorithm.h:8-20     | 电流环（参数） |
| `foc_input_t`         | 嵌于 controller                        | foc_algorithm.h:22-34    | 电流环（输入） |
| `foc_output_t`        | 嵌于 algorithm                         | foc_algorithm.h:36-70    | 电流环（输出） |
| `foc_pi_t`            | 嵌于 parameters（d/q 各一个）          | foc_pi.h:6-13            | 电流环（PI）   |

> ⚠ **重要认知**：**速度环的 PI 不使用 `foc_pi_t`**。速度环 PI 是内联实现在
> `SpeedCommission_Reference()`（speed_commission.c:212-218）里的，积分状态存在
> `g_speed_test.integral`，增益存在 `active.kp/ki`。`foc_pi_t` 只服务电流环的 d/q 两个轴。
> 这一点在排查速度环饱和/积分问题时最容易找错地方。

## 2. `speed_run_t` — 连续运行遥测（`g_speed_run`）

**只在连续速度模式（kind=7）下有意义**，是上位机 Watch/读取的主界面。
全部业务字段都是 `volatile`，因为它在 20 kHz ISR 里被写、后台被读。

```c
typedef struct {
  volatile uint32_t enable;
  volatile float target_rpm;
  volatile float applied_rpm, actual_rpm, turns, elapsed_s;
  volatile float iq_reference_a, iq_a, id_a, uq_pu;
  volatile uint32_t state, fault;
  volatile float phase_peak_a;
  volatile uint32_t feedback_status_raw;
  volatile uint32_t start_block_mask;
} speed_run_t;
```

| 字段                    | 单位   | 含义                                                           | 备注                                                                |
| ----------------------- | ------ | -------------------------------------------------------------- | ------------------------------------------------------------------- |
| `enable`              | —     | **操作开关**：0=撤除输出；1=在停机状态下请求一次全新启动 | 是"请求"语义，不是"当前已使能"                                      |
| `target_rpm`          | rpm    | **实时命令**，负值反转                                   | 初值 500.0（speed_commission.c:8）；上限 ±8500                     |
| `applied_rpm`         | rpm    | 斜坡后的**实际下发**转速指令                             | = `ref / SPEED_RPM_TO_RAD_S`                                      |
| `actual_rpm`          | rpm    | 编码器反馈的实际转速                                           | 来自 `e.mechanical_speed_rad_s`，**已含 τ=10 ms 低通延迟** |
| `turns`               | 圈     | 累计转数                                                       | = `run_delta_count / 2097152.0`（2^21）                           |
| `elapsed_s`           | s      | 连续运行累计时间                                               | 由后台 `PublishRunTelemetry()` 换算，不在 ISR 里做                |
| `iq_reference_a`      | A      | 速度环 PI 输出的 q 轴电流指令                                  | 受 `current_limit_a` 与 5 A 双重限幅                              |
| `iq_a`                | A      | 实测 q 轴电流                                                  | 取自 `foc_output_t.q_current`                                     |
| `id_a`                | A      | 实测 d 轴电流                                                  | 取自 `foc_output_t.d_current`；速度环恒令 `d_reference=0`       |
| `uq_pu`               | 标幺   | q 轴电压输出（÷Vdc）                                          | 判断是否触及电压限幅的关键量                                        |
| `state`               | —     | **`g_speed_test.state` 的镜像**（0~4，见 §4）         | 便于上位机只读一个结构体                                            |
| `fault`               | —     | **`g_speed_test.fault` 的镜像**（1~9，见 §5）         | 同上                                                                |
| `phase_peak_a`        | A      | 启动以来相电流绝对值最大值                                     | 用于判断是否曾接近过流                                              |
| `feedback_status_raw` | —     | 最后一次编码器 STATUS[2:0]                                     | **速度故障时冻结**（speed_commission.c:131）                  |
| `start_block_mask`    | 位掩码 | 上一次启动被拒（fault 0x0A）的原因                             | 见 §6                                                              |

### 2.1 遥测为什么放在后台算

`SpeedCommission_PublishRunTelemetry()`（speed_commission.c:15-27）注释明说：
**昂贵的 int64→float 转换属于后台，不属于 20 kHz ADC 中断**。ISR 里只做
`run_cycles += gap`（u64 累加）与 `run_delta_count = multi_turn_count - run_start_count`，
后台用短关中断拷贝两个计数器后再换算。

另注：DWT 每约 25.6 s 回绕一次，所以 `run_cycles` **只累加无符号差值**（:9-10 注释），
不在 ISR 里做秒换算。

## 3. `speed_test_config_t` — 参数集

同一类型有两份实例：`requested`（上位机写入的草稿）与 `active`（启动时固化的执行版）。
**启动成功后 `active = requested`**（speed_commission.c:106），之后改 `requested` 不影响运行中的测试——与波形模块的"草稿/正式版"是同一套思路。

```c
typedef struct {
  uint32_t kind;
  float duration_s, amplitude, bias, frequency_hz, angle_end_rad;
  float kp, ki, current_limit_a, speed_limit_rad_s;
  uint32_t record_divider;
  uint32_t prbs_bit_ms;
} speed_test_config_t;
```

| 字段                  | 含义                                        | 合法范围（启动时校验，:82-105）              |
| --------------------- | ------------------------------------------- | -------------------------------------------- |
| `kind`              | 测试类型，见下表                            | 1 ~ 7                                        |
| `duration_s`        | 测试时长                                    | 0.05 ~ 12.0 s（连续模式不受限）              |
| `amplitude`         | 幅值（含义随 kind 变：电流 A 或转速 rad/s） | 有限值；kind≤2 时 ≤ `current_limit_a`    |
| `bias`              | 偏置                                        | 有限值                                       |
| `frequency_hz`      | 正弦激励频率                                | 0 ~ 30 Hz                                    |
| `angle_end_rad`     | 对齐测试的终角                              | \|·\| ≤ 6.3 rad                            |
| `kp`                | **速度环比例增益**                    | 0 ~ 0.2                                      |
| `ki`                | **速度环积分增益**                    | 0 ~ 2.0                                      |
| `current_limit_a`   | q 轴电流指令上限                            | >0；连续模式 ≤5 A，对齐 ≤2 A，其他 ≤0.5 A |
| `speed_limit_rad_s` | 超速跳闸阈值                                | >0；连续模式 ≤950 rad/s，其他 ≤20 rad/s    |
| `record_divider`    | 每多少个 1 ms 外层节拍记一行                | 1 ~ 100（PRBS 模式**必须为 8**）       |
| `prbs_bit_ms`       | PRBS 每位持续毫秒                           | 只允许 16 / 32 / 64                          |

### 3.1 kind 取值（speed_commission.h:48 注释）

| kind        | 名称               | 是否用速度 PI | 说明                                                              |
| ----------- | ------------------ | ------------- | ----------------------------------------------------------------- |
| 1           | 对齐（alignment）  | ✗            | 直接给 d 轴电流，按时间比例推进角度                               |
| 2           | Iq 阶跃            | ✗            | `iq_reference = clip(amplitude, limit)`，开环电流               |
| 3           | 转速阶跃           | ✓            | `ref = elapsed<0.2s ? 0 : amplitude`                            |
| 4           | 转速正弦           | ✓            | `ref = bias + amplitude·sin(2π·f·t)`                        |
| 5           | Iq PRBS            | ✗            | 伪随机电流激励，用于电流环辨识                                    |
| 6           | 转速 PRBS          | ✓            | 伪随机转速激励，用于速度环辨识                                    |
| **7** | **连续运行** | ✓            | `SPEED_CONTINUOUS_KIND`，**永不因记录器满或时间到而终止** |

### 3.2 当前工程的出厂默认值（speed_commission.c:29-35）

```c
g_speed_test = { .direction=1, .pole_pairs=2,
  .requested = { .kind=3, .duration_s=2.0, .amplitude=10.0,
                 .angle_end_rad=1.570796327, .kp=0.032, .ki=1.0,
                 .current_limit_a=0.30, .speed_limit_rad_s=20.0,
                 .record_divider=8, .prbs_bit_ms=16 } };
```

> 注释标注这些是 **legacy bounded test defaults（旧的有界测试默认值）**，
> 连续运行走 `g_speed_run`。

### 3.3 板级标定常量（speed_commission.h:21-24）

```c
#define SPEED_BOARD_ENCODER_DIRECTION  (-1)
#define SPEED_BOARD_ENCODER_OFFSET_RAD 5.91902392706f
```

注释原文：*"Measured on this 2409 motor/encoder assembly at 2 A alignment.
Recalibrate after mechanically moving/replacing the encoder or changing phase wiring."*

即：**这两个值是针对当前这台 2409 电机+编码器组件、在 2 A 对齐电流下实测得到的**。
机械上动过编码器、或改过相线接线，都必须重新标定。`SpeedCommission_LoadBoardCalibration()`
（:40-47）在启动时把它们写入 `g_speed_test` 并调 `Encoder_ConfigureMotor()`。

## 4. `speed_commission_t` — 速度环主体（`g_speed_test`）

```c
typedef struct {
  volatile uint32_t command, state, fault, count;
  speed_test_config_t requested, active;
  volatile uint32_t calibration_command, calibration_ok;
  int32_t direction;
  uint32_t pole_pairs;
  float electrical_offset_rad;
  float elapsed, integral, iq_reference, reference, angle;
  uint32_t first_cycle, last_cycle, tick_cycle, ticks, record_ticks;
  uint32_t max_interval_cycles;
  uint32_t feedback_fault, feedback_age_cycles;
  uint32_t ready_cycle, ready_count;
  uint8_t prbs_sequence[127];
  union {
    speed_test_record_t records[128];
    struct { float time_s, iq_command_a, speed_rad_s; } prbs_records[336];
  };
} speed_commission_t;
```

### 4.1 命令与状态

| 字段        | 含义                                                                                                       |
| ----------- | ---------------------------------------------------------------------------------------------------------- |
| `command` | **一次性命令字**：1=启动、2=停止（触发 fault 1）、3=清除故障回 idle。`Service()` 读到即清零（:68） |
| `state`   | 状态机，见下表                                                                                             |
| `fault`   | 故障码 1~9，见 §5                                                                                         |
| `count`   | 记录器已写入的行数                                                                                         |

**`state` 取值**（speed_commission.h:58 注释：`0 idle,1 armed,2 run,3 done,4 fault`）：

| 值 | 名称            | 含义                             | 转出条件                                           |
| -- | --------------- | -------------------------------- | -------------------------------------------------- |
| 0  | idle            | 空闲，`Reference()` 直接返回 0 | `command=1` 且校验通过 → 1                      |
| 1  | **armed** | 已武装，**等待反馈稳定**   | 连续 100 帧有效反馈 → 2；200 ms 未就绪 → fault 8 |
| 2  | run             | 正常运行，PI 生效                | 时间到 → 3；任何判据失败 → 4                     |
| 3  | done            | 正常结束，输出置零               | `command=3` → 0                                 |
| 4  | fault           | 故障，输出置零                   | `command=3` → 0                                 |

**armed 阶段（state=1）的行为很关键**（:134-145）：

```
ready_count 需要连续 100 帧满足：
    valid && angle_valid && speed_valid && isfinite(mechanical_speed_rad_s)
任一帧不满足 → ready_count 归零（重新数）
期间强制 d_reference = q_reference = 0，angle = 0（不给激励）
超过 200 ms（SystemCoreClock/5）仍未就绪 → fail(8)
```

`Reference()` 在 20 kHz ADC ISR 中被调用，所以 100 帧 = **5 ms**。这是速度环启动前
"确认编码器反馈已经稳定"的门槛。

### 4.2 PI 与运行时状态

| 字段             | 单位  | 含义                                             |
| ---------------- | ----- | ------------------------------------------------ |
| `integral`     | A     | **速度环积分器状态**（抗饱和逻辑见 §4.3） |
| `reference`    | rad/s | 斜坡后的转速指令                                 |
| `iq_reference` | A     | 限幅后的 q 轴电流指令，写入 `in->q_reference`  |
| `angle`        | rad   | 当前使用的电角度（取自编码器快照）               |
| `elapsed`      | s     | 自 `first_cycle` 起的运行时间                  |

### 4.3 速度环 PI 与抗饱和（speed_commission.c:212-218）

**执行节拍：1 kHz**（`(now - tick_cycle) >= SystemCoreClock/1000`），
但函数本身在 20 kHz ISR 中被调用——即每 20 次调用才推进一次 PI。

```c
float err      = ref - e.mechanical_speed_rad_s;
float proposed = clip(s->integral + ki*err*dt, current_limit_a);   /* 预积分并限幅 */
float u        = kp*err + proposed;

if ((u >  limit && err > 0) ||          /* 输出已饱和且误差仍在同方向推 */
    (u < -limit && err < 0))
    u = kp*err + s->integral;           /* → 不提交新积分，用旧积分算输出 */
else
    s->integral = proposed;             /* → 提交积分 */

s->iq_reference = clip(u, current_limit_a);
```

这是**条件积分（conditional integration）型抗饱和**：只在"输出饱和方向与误差方向一致"
时冻结积分器，避免积分继续朝饱和方向堆积。

注意 `dt` 用的是**实测的 tick 间隔**（`(now - tick_cycle)/SystemCoreClock`），
不是名义 1 ms——所以节拍抖动不会造成积分误差。

### 4.4 连续模式的转速斜坡（:201-208）

```c
target = g_speed_run.target_rpm;
if (!isfinite(target) || fabsf(target) > 8500.0f ||
    fabsf(target)*0.1047197551f >= speed_limit_rad_s)
    return fail(9);
ref = s->reference + clip(target*SPEED_RPM_TO_RAD_S - s->reference,
                          SPEED_RUN_RAMP_RPM_S * SPEED_RPM_TO_RAD_S * dt);
```

斜坡速率 `SPEED_RUN_RAMP_RPM_S = 300 rpm/s`，即从 0 到 8500 rpm 需约 **28.3 s**。

### 4.5 时间戳与周期诊断

| 字段                    | 含义                                                      |
| ----------------------- | --------------------------------------------------------- |
| `first_cycle`         | 进入 run 状态的时刻                                       |
| `last_cycle`          | 上一次 `Reference()` 被调用的时刻                       |
| `tick_cycle`          | 上一次 PI 推进的时刻（1 kHz 节拍基准）                    |
| `ticks`               | PI 推进次数                                               |
| `record_ticks`        | 上一次记录的 `elapsed_ms / record_divider` 值，用于去重 |
| `max_interval_cycles` | **历史最大调用间隔**，÷168 = µs                   |

**`gap > SystemCoreClock/2000`（即 >500 µs）直接 `fail(6)`**（:156）——
这是"电流环 ISR 被严重拖延"的检测。正常应为 50 µs。

同时每个 tick 会把实测间隔回写给电流环（:158-161）：

```c
g_foc_controller.algorithm.parameters.sample_period_s = (float)gap / SystemCoreClock;
```

注释说明：**电流环 PI 必须按实际流逝时间积分，包括被延迟触发的情况**。

### 4.6 反馈质量镜像

| 字段                    | 含义                                                                |
| ----------------------- | ------------------------------------------------------------------- |
| `feedback_fault`      | 直接拷自 `encoder_snapshot_t.fault_flags`（每周期更新，:132）     |
| `feedback_age_cycles` | `DWT->CYCCNT - e.sample_cycle`，即**角度龄期**，÷168 = µs |

这两个字段是**速度环侧观察编码器健康度的窗口**，与编码器文档 §3.2 的
`foc_sample_age_cycles_max` 互为印证。

### 4.7 标定接口

| 字段                      | 含义                                                                                   |
| ------------------------- | -------------------------------------------------------------------------------------- |
| `calibration_command`   | 置 1 请求写入标定值；`Service()` 仅在 **输出关闭且非 armed/run** 时消费（:62） |
| `calibration_ok`        | `Encoder_ConfigureMotor()` 的返回值；**kind≠1 的测试要求它为真**（:100）      |
| `direction`             | 写入前的方向值（校验：`pole_pairs==2 && fabsf(offset)<7.0`）                         |
| `pole_pairs`            | 极对数，出厂默认 2                                                                     |
| `electrical_offset_rad` | 电角零位                                                                               |

### 4.8 记录器与 PRBS

```c
uint8_t prbs_sequence[127];   /* MATLAB 生成的二进制 PRBS，仅在停机状态下上传 */
union {
  speed_test_record_t records[128];                          /* 8 字段/行 */
  struct { float time_s, iq_command_a, speed_rad_s; } prbs_records[336];
};
```

- **union 复用同一块 RAM**，注释明确"modes are mutually exclusive"（模式互斥）。
- PRBS 序列校验（:75-80）：每项必须 ≤1，且 1 的个数必须在 **20~107** 之间，
  否则 `fail(3)`——防止上传了空序列或全 1 序列。
- kind≥5 的记录上限是 **1365 行**（:243），其他 kind 是 128 行。
- 记录节拍独立于 PI 节拍（:239 注释："Recorder runs independently of PI cadence"），
  且**数值未经显示滤波**。
- kind=6 记的是转速指令（rad/s），kind=5 记的是 Iq 指令（A）——同一字段不同含义（:246-248）。

## 5. `fault` 故障码对照表（1~9）

全部由 `fail(reason)` 产生（:37-39，同时置 `state=4`）：

| 码          | 触发位置          | 条件                                                            | 含义与排查方向                                                                                                                         |
| ----------- | ----------------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **1** | :69               | `command == 2`                                                | 收到停止命令。**这是正常停机路径，不是真故障**                                                                                   |
| **2** | :70               | `!off \|\| state==2`                                            | 启动时输出未关闭，或已在运行中                                                                                                         |
| **3** | :74,77,80,105,242 | 配置校验失败                                                    | 参数越界 / PRBS 序列非法 / **标定缺失**（kind≠1 且 `calibration_ok==0`）/ 连续模式前置条件不满足 / kind≥5 时电流环测试未空闲 |
| **4** | :147              | `!valid \|\| !angle_valid \|\| !speed_valid \|\| !isfinite(speed)`  | **编码器反馈无效**。转去看 `feedback_fault` 与编码器文档 §8.3                                                                 |
| **5** | :148              | `fabsf(speed) > active.speed_limit_rad_s`                     | **超速跳闸**。950 rad/s = **9072 rpm**                                                                                     |
| **6** | :156              | `gap > SystemCoreClock/2000`（>500 µs）                      | 电流环 ISR 被严重拖延。查 `max_interval_cycles`                                                                                      |
| **7** | :173              | kind≠1 且 `!electrical_angle_valid`                          | 电角度无效 → `Encoder_ConfigureMotor()` 未成功                                                                                      |
| **8** | :137              | armed 状态超 200 ms 未凑够 100 帧有效反馈                       | 启动前反馈不稳定。查 `ready_count` 为何反复归零                                                                                      |
| **9** | :205              | `target_rpm` 非有限 / >8500 / 换算后 ≥ `speed_limit_rad_s` | **连续模式的命令值非法**。检查上位机下发的 `target_rpm`                                                                        |

> 注：`start_block_mask` 对应的启动拒绝在上位机侧表现为 **fault 0x0A（=10）**，
> 由 main.c 的启动前置检查产生，不在本文件的 1~9 序列内。

### 5.1 与编码器故障的联动

速度环的 fault 4/5/7 都直接源自编码器状态：

```
编码器闸门④（报警，零宽限）→ angle_valid=0 → 速度环 fail(4) → state=4 → 撤输出
编码器速度超 950 rad/s      → 速度环 fail(5)
ConfigureMotor 未成功       → electrical_angle_valid=0 → fail(7)
```

**所以"高速时停机"的根因常常在编码器侧**，速度环只是执行者。排查顺序应是：
先读 `g_speed_run.fault`，若是 4/7 → 转编码器文档 §8.3；若是 5 → 查是否真超速
（可能是电流环振荡导致的转速冲高，而非命令过高）。

## 7. `speed_test_record_t` — 记录器行格式

```c
typedef struct {
  float time_s, reference, speed, id, iq, iq_reference, angle, voltage_q;
} speed_test_record_t;
```

| 字段             | 单位  | 来源                                           |
| ---------------- | ----- | ---------------------------------------------- |
| `time_s`       | s     | `s->elapsed`                                 |
| `reference`    | rad/s | `s->reference`（斜坡后的转速指令）           |
| `speed`        | rad/s | `e.mechanical_speed_rad_s`（编码器滤波速度） |
| `id`           | A     | `foc_output_t.d_current`                     |
| `iq`           | A     | `foc_output_t.q_current`                     |
| `iq_reference` | A     | `in->q_reference`（速度环 PI 的输出）        |
| `angle`        | rad   | `e.mechanical_angle_rad`                     |
| `voltage_q`    | 标幺  | `foc_output_t.q_voltage`                     |

写入条件（:264-271）：`count < 128` 且（首行 或 `record > record_ticks`）。
`record = elapsed_ms / record_divider`，所以 `record_divider=8` 表示每 8 ms 记一行，
128 行覆盖约 1.02 s。

**用途**：这 8 列足以在 MATLAB 里重构完整的速度阶跃响应（指令 vs 反馈 vs 电流 vs 电压），
是整定 `kp/ki` 的主要数据来源。

## 8. 电流环侧结构体（速度环的下游）

### 8.1 `foc_input_t` — 速度环写、电流环读

```c
typedef struct {
  float phase_a, phase_b;            /* 两相电流反馈，物理安培 */
  float electrical_angle_rad;        /* 电角度 */
  float d_reference, q_reference;    /* d/q 电流给定 */
  uint8_t current_valid, angle_valid, reference_valid;  /* 三个独立有效位 */
} foc_input_t;
```

**速度环只写后 5 个字段**（`SpeedCommission_Reference(foc_input_t *in)`）：

```c
in->d_reference = 0;                      /* 速度环恒令 d 轴指令为 0 */
in->q_reference = s->iq_reference;        /* ← 速度环 PI 的唯一输出 */
in->electrical_angle_rad = s->angle;
in->angle_valid = in->reference_valid = 1;
```

`phase_a/phase_b/current_valid` 由 `read_feedback` 回调（绑定 ADC 采样层）填充。

> foc_interface.h:28-31 的约定：`read_feedback` 每周期先填 phase_a/phase_b、
> electrical_angle_rad、d/q_reference（安培），再分别设置三个 valid 位。
> **任一无效都禁止输出。**

### 8.2 `foc_output_t` — 速度环读的关键遥测

速度环实际消费的只有三个字段（:222-228）：`q_current`、`d_current`、`q_voltage`。
完整字段列表（foc_algorithm.h:36-70）：

| 分组     | 字段                                                                                       | 说明                                                                           |
| -------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| 反馈     | `d_current`, `q_current`                                                               | Park 变换后的实测 d/q 电流                                                     |
| 指令     | `applied_d_reference`, `applied_q_reference`                                           | **向量限幅后**的实际指令（性能测量用）                                   |
| 误差/PI  | `d_current_error`, `q_current_error`, `d_pi_command`, `q_pi_command`               | 同一 ADC 周期内锁存，避免 Watch 跨周期读取误判控制方向；PI 命令单位为 Vdc 标幺 |
| 限幅标志 | `reference_limited`, `integral_limited`                                                | 指令/积分是否触及限幅                                                          |
| 电压     | `d_voltage`, `q_voltage`, `alpha_voltage`, `beta_voltage`                          | dq 与 αβ 电压                                                                |
| 基波     | `fundamental_d_voltage`, `fundamental_q_voltage`, `fundamental_voltage_limit`        | **过调制时实际电压含谐波**，基波目标单独提供给调参与抗饱和               |
| 三相     | `phase_a/b/c_voltage`（仅遥测）, `phase_a/b/c_duty`（**PWM 硬件消费的是 duty**） |                                                                                |
| 状态     | `modulation_region`, `sector`, `valid`, `saturated`                                | 调制区、扇区、有效位、饱和位                                                   |

### 8.3 `foc_parameters_t` — 速度环会改它的一个字段

```c
typedef struct {
  float sample_period_s;      /* 实际两次电流快照间隔 ← 速度环每 tick 回写 */
  float pwm_period_s;         /* 名义 PWM 周期，后备值 */
  float voltage_limit;        /* 基波相电压峰值/Vdc，最大 2/π */
  foc_modulation_parameters_t modulation;
  float current_limit;
  foc_pi_t d_controller;      /* d 轴 PI */
  foc_pi_t q_controller;      /* q 轴 PI */
} foc_parameters_t;
```

`foc_pi_t`（foc_pi.h:6-13）：

```c
typedef struct { float kp, ki, integral, integral_min, integral_max; } foc_pi_t;
```

**只有 5 个字段**：增益两个、积分器状态一个、积分限幅上下界两个。
接口只有三个：`FOC_PI_IsValid()` / `FOC_PI_Step(controller, error, period_s)` / `FOC_PI_Reset()`。

> 再次强调：**这是电流环的 PI，不是速度环的**。速度环的积分状态在
> `g_speed_test.integral`，增益在 `g_speed_test.active.kp/ki`，抗饱和逻辑也是独立实现的。

### 8.4 `foc_modulation_parameters_t`

```c
typedef struct {
  foc_modulation_mode_t mode;   /* LINEAR_ONLY(0) / OVERMODULATION(1) */
  float duty_min, duty_max;     /* 由功率级/采样层提供 */
} foc_modulation_parameters_t;
```

注释里的硬约束（foc_modulation.h:26-27）：`duty_min/max` 收窄后按跨度降额，
**"不得仅为提高利用率放宽低侧分流器采样窗口或自举刷新约束"**。

两个上限常量：

```c
FOC_MODULATION_LINEAR_MAX   = 0.5773502692f   /* 1/√3，线性区上限 */
FOC_MODULATION_SIX_STEP_MAX = 0.6366197724f   /* 2/π，六步极限 */
```

连续模式的 `SPEED_RUN_VOLTAGE_LIMIT_PU = 0.30f` 远低于线性区上限，
所以正常运行不会进入过调制区。

### 8.5 `foc_controller_t` 与 `foc_port_t`

```c
typedef struct {
  foc_algorithm_t algorithm;          /* parameters + output */
  foc_port_t port;                    /* 4 个函数指针 + context */
  foc_input_t input;                  /* 最近一次输入 */
  uint8_t running;
  volatile uint8_t feedback_ready;    /* 输入全有效+算法完成+CCR已写入 后发布 */
  volatile foc_fault_flags_t fault_flags;  /* ISR 只锁存快速故障 */
  struct {
    float pwm_period_s;
    uint32_t cycle_count;
    uint32_t last_sample_sequence;
  } timing;
} foc_controller_t;
```

`foc_port_t` 是**依赖倒置的接缝**（foc_interface.h:17-34 有完整注释）：本层不 include
任何芯片/外设头文件，所有硬件往来通过 4 个函数指针完成，换硬件只需替换回调实现。

| 回调                    | 绑定到                                | 约束                                                                               |
| ----------------------- | ------------------------------------- | ---------------------------------------------------------------------------------- |
| `is_power_stage_safe` | `DrvMonitor_IsPowerStageSafeFast()` | **必须只读引脚、绝不走 I2C**，因为在 20 kHz 电流环里被调用，执行时间必须恒定 |
| `read_feedback`       | ADC 采样层                            | 每周期填 phase_a/b、电角度、d/q 给定，再设三个 valid 位                            |
| `write_voltage`       | 定时器层                              | 把算好的三相占空比交给 PWM；失败返回 0 并锁存故障                                  |
| `disable_output`      | `Tim1Pwm_EmergencyStop()`           | 安全关断                                                                           |

## 9. `servo_manager_t` — 调度层

```c
typedef struct {
  foc_controller_t *foc;
  servo_manager_port_t port;
  volatile uint8_t servo_on_request;
  volatile uint8_t fault_reset_request;
  volatile servo_fault_mask_t pending_faults;
  servo_state_t state;
  servo_fault_mask_t active_faults;
  servo_fault_mask_t latched_faults;
  uint32_t fault_sequence;
  uint32_t reported_fault_sequence;
} servo_manager_t;
```

### 9.1 状态机（servo_manager.h:8-16）

`INIT(0) → CALIBRATING(1) → READY(2) → STARTING(3) → RUNNING(4)`，任何状态可进 `FAULT(5)`。

**故障分两类**，这是本层最重要的设计：

| 字段                                             | 含义                                                        |
| ------------------------------------------------ | ----------------------------------------------------------- |
| `active_faults`                                | **当前**存在的故障（条件消失即清）                    |
| `latched_faults`                               | **锁存**故障（必须显式 `RequestFaultReset()` 才清） |
| `pending_faults`                               | ISR 里置位、等 `Service()` 处理的故障（volatile）         |
| `fault_sequence` / `reported_fault_sequence` | 故障事件序号，两者不等说明有未上报的故障                    |

**分工原则**（foc_interface.h:53 注释）：*"电流环 ISR 只锁存快速故障；恢复策略由
Servo Manager 决定。"* 而 `ServoManager_RaiseFaultFromIsr()` 的注释更严格：
*"调用者必须先完成本地快速关断；本函数只发布故障事件。"*

即：**ISR 负责立刻切断输出，Manager 负责事后决策**——实时性与策略分离。

### 9.2 故障位（servo_manager.h:20-29）

| 宏                                | 位   | 对应 FOC 侧                     |
| --------------------------------- | ---- | ------------------------------- |
| `SERVO_FAULT_CURRENT_INVALID`   | 1<<0 | `FOC_FAULT_CURRENT_INVALID`   |
| `SERVO_FAULT_ANGLE_INVALID`     | 1<<1 | `FOC_FAULT_ANGLE_INVALID`     |
| `SERVO_FAULT_REFERENCE_INVALID` | 1<<2 | `FOC_FAULT_REFERENCE_INVALID` |
| `SERVO_FAULT_POWER_STAGE`       | 1<<3 | `FOC_FAULT_POWER_STAGE`       |
| `SERVO_FAULT_FOC_CONFIG`        | 1<<4 | `FOC_FAULT_PORT_CONFIG`       |
| `SERVO_FAULT_CALIBRATION`       | 1<<5 | （Manager 独有）                |
| `SERVO_FAULT_OUTPUT_DISABLED`   | 1<<6 | （Manager 独有）                |
| `SERVO_FAULT_FOC_ALGORITHM`     | 1<<7 | `FOC_FAULT_ALGORITHM`         |
| `SERVO_FAULT_PWM_WRITE`         | 1<<8 | `FOC_FAULT_PWM_WRITE`         |

## 11. 数据流：一次速度环迭代的完整路径

```
20 kHz ADC ISR
  │
  ├─ read_feedback 回调 → 填 foc_input_t 的 phase_a/b、current_valid
  │
  ├─ SpeedCommission_Reference(&controller.input)
  │    ├─ state != 1 && != 2 → return 0（不干预）
  │    ├─ Encoder_ReadSnapshot(&e)          ← 读编码器公告板
  │    ├─ feedback_fault / feedback_age_cycles 更新
  │    ├─ state==1：数 ready_count，够 100 帧 → state=2
  │    ├─ 校验：valid/angle_valid/speed_valid/isfinite → 否则 fail(4)
  │    ├─ 校验：|speed| ≤ speed_limit_rad_s → 否则 fail(5)
  │    ├─ 校验：gap ≤ 500 µs → 否则 fail(6)
  │    ├─ 回写 algorithm.parameters.sample_period_s = gap/168e6
  │    ├─ 每 1 ms（tick）：
  │    │    ├─ 算 ref（kind=7 走 300 rpm/s 斜坡）
  │    │    ├─ 速度 PI：err → proposed → 条件积分抗饱和 → iq_reference
  │    │    └─ kind=7：刷新 g_speed_run 的 applied/actual/iq/id/uq
  │    ├─ in->d_reference = 0; in->q_reference = iq_reference
  │    ├─ in->electrical_angle_rad = s->angle
  │    └─ 记录器：按 record_divider 写一行 speed_test_record_t
  │
  ├─ FOC_ControllerStep() → 电流环 PI（foc_pi_t ×2）→ SVPWM → write_voltage
  │
  └─ 任一安全条件失效 → disable_output() + 锁存 fault_flags

主循环（后台）
  ├─ SpeedCommission_Service(output_off)   ← 消费 command、处理标定请求
  ├─ SpeedCommission_PublishRunTelemetry() ← int64→float 换算（不占 ISR）
  └─ ServoManager_Service()                ← 状态迁移、故障上报、复位策略
```

## 12. 排查速查表

| 现象           | 先读                                         | 判读                                                                   |
| -------------- | -------------------------------------------- | ---------------------------------------------------------------------- |
| 启动不了       | `g_speed_run.start_block_mask`             | 按 §6 位定义逐条对照；最常见是 bit9（标定缺失）                       |
| 启动后立刻停   | `g_speed_test.fault`                       | 8=反馈迟迟不稳定；3=参数校验没过；7=电角度无效                         |
| 高速时停机     | `g_speed_test.fault`                       | 4/7 → 转编码器文档 §8.3；5 → 查是真超速还是电流环振荡导致转速冲高   |
| 转速跟不上指令 | `g_speed_run.uq_pu`                        | 接近 `SPEED_RUN_VOLTAGE_LIMIT_PU`(0.30) = 电压限幅，不是 PI 参数问题 |
| 转速抖动/振荡  | `g_speed_test.integral` + `iq_reference` | 积分器是否长期贴限幅；注意速度反馈含 **τ=10 ms 低通延迟**       |
| 响应慢         | 编码器 `mechanical_speed_rad_s` 的 τ      | **速度滤波器时间常数 10 ms 是固有延迟**，整定带宽时必须计入      |
| PI 不推进      | `g_speed_test.ticks`                       | 不涨 = 1 kHz tick 条件没满足，查 `tick_cycle`                        |
| ISR 被拖延     | `max_interval_cycles` ÷168                | 正常 50 µs；>500 µs 会直接 fail(6)                                   |
| 记录数据异常   | `count` / `record_ticks`                 | count 不涨 = `record_divider` 设置或 elapsed_ms 计算问题             |
| PRBS 无法启动  | `prbs_sequence[]` 中 1 的个数              | 必须在 20~107 之间，否则 fail(3)                                       |

### 12.1 单位换算备忘

```
SystemCoreClock = 168 MHz
cycles ÷ 168   = µs
8400 cycles    = 50 µs  = 电流环周期（20 kHz）
168000 cycles  = 1 ms   = 速度环 PI 周期（1 kHz）
SPEED_RPM_TO_RAD_S = 0.1047197551（2π/60）
950 rad/s = 9072 rpm（超速跳闸）
8500 rpm  = 890 rad/s（命令上限）
```
